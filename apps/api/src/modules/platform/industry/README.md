# platform/industry: industry templates

The eight seed templates of `12-INDUSTRY-TEMPLATES.md`, stored fully materialized (ADR-076). A template key is data (ADR-097): the format lives in contracts, and whether a key exists is a database check.

- **Entity:** `IndustryTemplate` (platform database, tenancy NONE, versioned). `industryTemplateKey` is unique and immutable. `allowedModuleKeys` lists CORE and OPTIONAL modules only; SYSTEM modules are always on and are not listed.
- **Configuration** holds contact roles, relations, resource types, terms, custom fields, settings defaults, optional modifier seeds, knowledge starters, website template keys and bot defaults. Money in seeds is integer minor units. The meaning of terms, fields and setting values is checked by the cards that own those registries: 2.2 (terms in the resolver), 2.3 (the field engine) and 2.4 (the settings registry). This module does not build those registries.
- **Seed:** `infrastructure/seeds/<key>.json`, one file per template, with the common terms, knowledge starters, handoff topics and settings copied into each file (no inheritance). FCOMMERCE and RETAIL are PUBLISHED; the other six are DRAFT (ADR-075). `EnsureSeedIndustryTemplatesUseCase` inserts only a key that is missing and never overwrites an edited template. Run it with `npm run seed:industry-templates -w @banijjik/api`. Startup runs the same use case.
- **Reader:** `CachedIndustryTemplateReader` implements the entitlement port. It returns modules, kinds and `version` for every status, including DRAFT and RETIRED, and caches each key for 30 seconds. Card 2.1b bumps `version`, and the config cache key includes `templateVersion`, so an edit reaches tenants within 30 seconds. A missing row throws `errors.industry_template_missing` and never allows every module.
- **Signup:** `MongoIndustryTemplateAvailability` answers true only for PUBLISHED on the cheap read before the transaction. Inside the transaction `reserveForSignup` increments `referenceVersion` only while the row is still PUBLISHED (`timestamps: false`, and `version` stays). A miss is `422 INDUSTRY_TEMPLATE_NOT_AVAILABLE`, so a retire that committed first wins (ADR-101).
- **Read API:** `GET /industry-templates` (signed-in admin user, published only, both languages, cap 100) and `GET /platform/industry-templates` plus `GET /platform/industry-templates/{industryTemplateId}` (`platform.industry.read`).
- **Write API** (`platform.industry.write`, SUPER_ADMIN, mandatory `reason`): `POST /platform/industry-templates` creates a DRAFT, or clones kinds, modules and configuration from any status. `PATCH …/{industryTemplateId}` replaces the given fields and moves `version` (409 when stale). The key and the status never change through PATCH. `POST …/publish` (DRAFT or RETIRED) and `POST …/retire` (PUBLISHED). The same status is 200 with no write and no audit.
- **Additive rule:** a template that is PUBLISHED, RETIRED, or used by at least one organization may only gain a kind, module, custom field, SELECT option, term, contact role, relation or resource type. A removal is `422 INDUSTRY_TEMPLATE_CHANGE_NOT_ADDITIVE` with every removed item in `details.removed`. An unused DRAFT may change freely.
- **Organization move:** `POST /platform/organizations/{organizationId}/change-industry-template`. The use case lives in `core/organization`; this module decides whether the move is additive (`buildIndustryTemplateMove`). An unknown key is 404. A RETIRED target is `422 INDUSTRY_TEMPLATE_STATUS_INVALID`. A DRAFT target is allowed. The same key is 200 with no write.
- **Public API** (`index.ts`): `registerIndustryModels`, `industryManifest`, `buildIndustryTemplateReader`, `buildIndustryTemplateAvailability`, `buildEnsureSeedIndustryTemplatesUseCase`, `buildPublishedIndustryTemplateRouter`, `buildIndustryPlatformRouter`, `buildIndustryTemplateMove`, `buildChangeIndustryTemplateRouter`, `buildIndustryCustomFieldReader`.
