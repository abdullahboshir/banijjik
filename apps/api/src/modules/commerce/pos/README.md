# pos (OPTIONAL)

The counter: paired devices, a register per device, one-transaction sales, held carts, price overrides, due collections, cash returns and the numbered Z-report (card 3.9 Parts A1 & A2, ADR-146). No screens yet (Part B).

- **Device pairing.** A manager creates a device for a location (`POST /pos/devices`) and gets an 8-digit code, shown once, valid 10 minutes, stored only as an HMAC. A signed-in member pairs the browser with `POST /pos/devices/pair`: the answer sets the httpOnly cookie `pos_device` (32 random bytes; only their SHA-256 is stored). A wrong, expired or reused code is the same `400 errors.pos_pairing_invalid`; 10 attempts per member per hour.
- **Device limit.** Creating a device takes the organization limit lock, counts ACTIVE devices (waiting and expired codes included; REVOKED excluded) and refuses with `422 LIMIT_REACHED` at the package's `posDevices`. `GET /pos/devices/usage` returns that count for the whole organization. Existing devices keep working after a downgrade; only a new create is refused.
- **Location scope.** List and revoke stay inside the caller's locations (`allowedLocationIds`). A `?locationId=` outside that set, or a revoke of another location's device, is `403 LOCATION_FORBIDDEN`. Usage stays organization-wide.
- **`requirePosDevice`.** Every till route reads the device from the cookie and takes the location from it, never from the body. A device of another location, another organization, or a revoked one is `403 errors.pos_device_required`. Closing a register needs the session, not the device, so a revoked till's open register can still be counted.
- **Register.** One OPEN session per device (a unique partial index). Open it with a float; read it (`GET /pos/sessions/current`) or page sessions (`GET /pos/sessions`); close it with the counted cash. `expectedCash = openingFloat + CASH in - CASH refunds` of the session only (`domain/expected-cash.ts`); card, bKash, Nagad, bank and store credit never enter the drawer.
- **Sale & price override.** `POST /pos/sales` prepares the instant order (sales `InstantSaleService`), checks the tender (`domain/tender.ts`), then writes the register mark, the order, the store-credit use and every payment in ONE unit of work. `unitPriceOverride` on a line needs `pos.price.override` and, when lower than the list price, an ADR-121 `PRICE_OVERRIDE` approval token for `(list - override) * quantity`. A shortfall (including a zero-payment credit sale) is a due only with `pos.allowCreditSale` and a contact.
- **Held carts, collections & returns.** `POST/GET/DELETE /pos/held-carts` parks up to 20 unpriced carts per device for 24 hours (TTL index). `POST /pos/collections` collects dues (order, booking, enrollment) at the device's location in one transaction (`Σ payments === Σ allocations`). `POST /pos/returns` creates a sales return whose refund carries `posSessionId`, lowering expected cash when refunded in `CASH`.
- **Close vs sale.** Every sale, collection and POS return writes `lastSaleAt` on the session document first, and the close writes it too, so one of them hits a write conflict and retries: a till write lands in the report or is refused with `409 errors.pos_session_required`, never lost.
- **Z-report.** Sales totals come from orders with that `posSessionId`; per-method totals, collections (IN payments not allocated to the session's own sales) and returns come from the session's payments; the number is the GAPLESS `ZREPORT` sequence, taken in the close transaction.
- **Catalog snapshot.** `GET /pos/catalog-snapshot` pages the sellable variants of the device's location (keyset cursor, at most 500 offerings a page); `since` returns changed rows and the variants that are no longer sellable.
- Emits `pos.register.closed`. Permissions: `pos.device.manage`, `pos.session.open`, `pos.sale.create`, `pos.price.override`, `pos.register.close`, `pos.report.read`. Settings: `pos.requireShift`, `pos.allowCreditSale`, `pos.receiptFooter`.
