# pos (OPTIONAL)

The counter: paired devices, a register per device, one-transaction sales and the numbered Z-report (card 3.9 Part A1, ADR-146). No screens yet (Part B); held carts, price override, collecting dues and cash refunds at the till come in Part A2.

- **Device pairing.** A manager creates a device for a location (`POST /pos/devices`) and gets an 8-digit code, shown once, valid 10 minutes, stored only as an HMAC. A signed-in member pairs the browser with `POST /pos/devices/pair`: the answer sets the httpOnly cookie `pos_device` (32 random bytes; only their SHA-256 is stored). A wrong, expired or reused code is the same `400 errors.pos_pairing_invalid`; 10 attempts per member per hour.
- **`requirePosDevice`.** Every till route reads the device from the cookie and takes the location from it, never from the body. A device of another location, another organization, or a revoked one is `403 errors.pos_device_required`. Closing a register needs the session, not the device, so a revoked till's open register can still be counted.
- **Register.** One OPEN session per device (a unique partial index). Open it with a float; close it with the counted cash. `expectedCash = openingFloat + CASH in - CASH refunds` of the session only (`domain/expected-cash.ts`); card, bKash, Nagad, bank and store credit never enter the drawer.
- **Sale.** `POST /pos/sales` prepares the instant order (sales `InstantSaleService`), checks the tender (`domain/tender.ts`), then writes the register mark, the order, the store-credit use and every payment in ONE unit of work. `payments[].amount` is what is applied to the bill; the cash handed over is `cashTendered`, and the change is returned, never stored as money. A shortfall is a due only with `pos.allowCreditSale` and a contact.
- **Close vs sale.** Every sale writes `lastSaleAt` on the session document first, and the close writes it too, so one of them hits a write conflict and retries: a sale lands in the report or is refused with `409 errors.pos_session_required`, never lost.
- **Z-report.** Totals come from the payment index (sums by method and direction, order allocations) and one query on the orders those payments allocate to; the number is the GAPLESS `ZREPORT` sequence, taken in the close transaction. The finished report is stored on the session.
- **Catalog snapshot.** `GET /pos/catalog-snapshot` pages the sellable variants of the device's location (keyset cursor, at most 500 offerings a page); `since` returns changed rows and the variants that are no longer sellable.
- Emits `pos.register.closed`. Permissions: `pos.device.manage`, `pos.session.open`, `pos.sale.create`, `pos.register.close`, `pos.report.read`. Settings: `pos.requireShift`, `pos.allowCreditSale`, `pos.receiptFooter`.
