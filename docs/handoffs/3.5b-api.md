## Deviations (each with its reason)

1. **Cross-location returns read as 404, not 403.** Location-owned rows are invisible outside the caller's locations (tenancy LOCATION), as order reads already do. The test asserts 404. Plan test: "a return at another location's order is 403".
2. **The race test asserts 409 or 422.** Under snapshot transactions the loser retries and then fails the quantity check (amendment 2).
3. **The posting test is in the accounting unit tests, not the API.** The worker runs the handler, and the handler is tested with the real Mongo journal and the trial balance (`post-sales-returns.test.ts`). The API suite does not run the worker.
4. **`returnWindowDays` has no "no limit" value.** INTEGER 0–3650, default 7 (amendment 2).
5. **Routes:** `/orders/:orderId/returns` and `/sales/returns` (amendment 2).
6. **`completedAt`** is a new order field, set at completion. Old rows fall back to `businessDate` (amendment 2).
7. **The approval subject** is `orderApprovalSubject(orderId)` = `order:<id>` (amendment 2).
8. **Optional body field `refundExternalReference`** (amendment 2, required for BKASH and NAGAD).
9. **`Order.findById` reads inside the caller's transaction** (session), which the race guarantee needs.
10. **Return adjustments in commission reuse `REFUND_ADJUSTMENT`** with `refundedTotalSeen` 0 (amendment 2, ADR-135 note).
