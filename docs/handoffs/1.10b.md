## Deviations

- `grantOperator` is typed as `z.input` of `platformOperatorCreateRequestSchema` and sends the identifier string. The schema output is `{ kind, value }`, and posting that object makes the API return `validation.invalid_type`. Sign-in already validates with the schema and sends the raw string, because the server runs the same schema. The sheet test expects `identifier: "ada@example.com"`.
- Operator status tone is a private function in `operators-page.tsx`. Putting it in `status-tones.ts` would make `lib` import the operators feature.
- Field keys are `platform.field.operatorIdentifier` and `platform.field.operatorRoles` (and their hints). `platform.field.reason` already existed.
- `OperatorFormSheet` is split into `saveForm`, `OperatorFormFields` and `RoleChecksField` so each function stays within 60 lines.
- Permission denied is asserted in the browser flow, not in a unit test of the server page.
- The support operator signs in through `openPage` (a new browser context). `openSiblingPage` shares the platform cookies, so that sign-in replaced the super admin session and disable returned 403.
