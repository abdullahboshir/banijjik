- **Deviations from plan (and why):**
  1. **Snake_case keys (owner-approved).** The plan's field/section/consent/reason keys were written in camelCase (`dateOfBirth`, `expectedPartner`, `guardianConsent`, `falseInformation`), but the seed schema the plan mandates rejects them: `FIELD_KEY_PATTERN` and the directory section/consent/reason patterns are `/^[a-z][a-z0-9_]{1,39}$/`. Every key is therefore snake_case. Full mapping (plan → data): `dateOfBirth→date_of_birth`, `maritalStatus→marital_status`, `heightCm→height_cm`, `bloodGroup→blood_group`, `permanentAddress→permanent_address`, `presentAddress→present_address`, `grewUpIn→grew_up_in`, `educationMethod→education_method`, `highestEducation→highest_education`, `monthlyIncomeRange→monthly_income_range`, `fatherOccupation→father_occupation`, `motherOccupation→mother_occupation`, `familyEconomicStatus→family_economic_status`, `dailyPrayers→daily_prayers`, `quranRecitation→quran_recitation`, `marriageViews→marriage_views`, `partnerAgeRange→partner_age_range`, `partnerDistricts→partner_districts`, `partnerEducation→partner_education`, `partnerQualities→partner_qualities`, `guardianName→guardian_name`, `guardianRelationship→guardian_relationship`, `guardianPhone→guardian_phone`, `contactEmail→contact_email`, `fullName→full_name`, `ownPhone→own_phone`; section `expectedPartner→expected_partner`; consents `guardianConsent→guardian_consent`, `adultAge→adult_age`, `termsAccepted→terms_accepted`, `islamicEligibility→islamic_eligibility`; reasons `guardianConsentMissing→guardian_consent_missing`, `ownNumberInGuardianField→own_number_in_guardian_field`, `unclearAnswers→unclear_answers`, `falseInformation→false_information`; report reasons `fakeProfile→fake_profile`, `alreadyMarried→already_married`, `inappropriateContent→inappropriate_content`, `contactMisuse→contact_misuse`.
  2. **Common terms added.** The plan's terms (decision 3) list only `listing` and `contact.RELATED`. Every existing seed also carries the seven base nouns (contact, offering, order, booking, enrollment, resource, location) — the seeds test "keeps the common terms in every file" enforces it — so both templates include them (with `offering.SERVICE`). Data-only, matches neighbouring templates (e.g. CLINIC carries them with enrollment off).
  3. **Required-but-unspecified config filled.** The seed schema requires `knowledgeSeed` (≥1), `websiteTemplateKeys` (≥1) and `botDefaults`; the plan was silent. Filled with neutral values that only the seed pattern validates: `websiteTemplateKeys: ["matrimony-simple"]` (the storefront, M.6, ships the real key), `botDefaults.personaKey: RESPECTFUL_MANAGER`, and a few FAQ `knowledgeSeed` topics. No code path depends on these for the directory.
