- **Deviations from plan (and why):**
  1. **HOSTEL seed** (approved by the lead): it has a required link field `guardian`, which the new rule "a link needs `RELATED`" would reject. HOSTEL gets role `RELATED`, its four contact fields `["CUSTOMER"]` and the term `contact.RELATED` (অভিভাবক / Guardian).
  2. **Seed rollout:** `EnsureSeedIndustryTemplates` never overwrites rows (ADR-076), so existing databases need an operator PATCH per template; the exact changes are listed in ADR-113 (the plan sentence "applies them to the published rows" was wrong, the lead corrects the plan).
  3. **Status of invalid templates:** schema failures are `400 VALIDATION_ERROR` (the API convention), not the plan's "422" (tests pin 400 at `configuration.customFields` and `configuration.contactRoleKeys`).
  4. **Update can clear roles:** a definition update takes `appliesToContactRoles: null` to go back to every role; the plan did not say how to undo a choice.
  5. **`/me/config` carries `contactRoleKeys`** (lead's request, replaces my first version where the admin sheet offered all four roles): the template's list, next to `terms` and `fields`. Files: `IndustryTemplateView.contactRoleKeys` (entitlement port, filled by the cached template reader), `ResolvedOrgConfig.contactRoleKeys`, the resolver, `GetMyConfig` and `ResolvedOrgConfigResponse`. The admin field sheet offers only those roles. Test fixtures that build a template view or a config response gained the property (`org-config-resolver.sources.test.ts`, `contract-template-reader.ts`, admin `test-fixtures.ts`, `banner-state.test.ts`).
  6. **Role text in admin:** the admin sheet names a role by the business term `contact.<ROLE>` through `termLabel`, falling back to the catalog `contactRole.<ROLE>` (screens catalog); the platform editor uses `platform.contactRole.<ROLE>`.
  7. **Role check on update** runs only when `contactRoles` is in the request, so a role the template dropped later does not block other edits.
