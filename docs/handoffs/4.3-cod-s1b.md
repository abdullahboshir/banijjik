## Tests (named `it(...)`)

`apps/api/src/modules/commerce/sales/presentation/delivery-zone-api.test.ts`:

- **Happy path:** `creates, reads, lists, and updates a delivery zone`
- **Validation:** `refuses empty or duplicate areaCodes and a negative or non-integer fee`
- **Overlap / uniqueness:** `refuses overlapping ACTIVE areaCodes as a rule error and as an index conflict`; `lets a new ACTIVE zone claim an area after the previous zone is INACTIVE`; `unique index refuses a second concurrent ACTIVE zone claiming the same areaCode`
- **Permission denied:** `refuses every delivery-zone route without permission sales.deliveryZone.manage`
- **Cross-location:** `refuses a member whose permission is held at one location only on every zone route`
- **Cross-org:** `hides another organization's delivery zones with 404`
- **Concurrency:** `refuses a stale version with 409`
- **Pagination:** `refuses a list limit above 100 and defaults to 50`
- **Idempotency:** `the same Idempotency-Key returns the first create and writes nothing twice`; `the same Idempotency-Key returns the first update and writes nothing twice`; `refuses a replay of the same Idempotency-Key with a changed body` (create and update); `requires an Idempotency-Key for create and update`

## Deviations from plan (and why)

1. List/id schemas (`deliveryZoneListQuerySchema` default 50, `deliveryZoneIdParamsSchema`) were appended to S1a-owned `sales-delivery-schemas.ts`. The plan did not list that file; every other tenant router imports query/params schemas from `@banijjik/validation`. Add-only, no S1a behaviour change.
2. No separate `delivery-zone.controller.ts`. `DeliveryZoneController` + `DeliveryZoneHttpController` live next to the router, as the plan required (“no controller file”).
3. ISO `createdAt`/`updatedAt` mapping is `toResponse` in the use case (same shape as `sales-views.ts` for orders), not a second mapper in the router.
4. Entitlement and me-config menu tests (not named in the S1b file list) gained `sales.deliveryZones` so pinned owner menus stay green.
5. Overlap “rule error” is the existing schema `400 VALIDATION_ERROR` for duplicate codes in one body. A second ACTIVE zone claiming the same area is unique-index `409 CONFLICT`. No new overlap rule key was invented (S1a did not name one).
6. `iconKey: "truck"` — the plan left the icon unspecified; inventory already uses that key.
7. Delivery `errors.*` catalog strings from S1a were left in place (no-op, not duplicated/reordered).
