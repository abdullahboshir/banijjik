  - **Module classes (plan gap):** the plan says "grouped by module class" and "grantable modules" but nothing delivers classes. Added `MODULE_CLASS_BY_KEY` to contracts (single source) with a consistency test against the manifests. Grantable = OPTIONAL only (CORE is always on, SYSTEM/PLATFORM are refused by the API). Owner to confirm.
  - **Probe module in the browser test (plan gap):** the production registry has no OPTIONAL module, so no module can be granted against `dist/main.js`. The test stack starts `src/test-support/probe-api.mjs`: the built API started like `main.ts`, plus one probe manifest (`bookkeeping`, no routes). Drop it when the first real optional module exists.

  - **Paging:** the API answers `hasNext` only, so previous / page n / next, not numbered pages.
  - **Package key field:** the create request requires `packageKey`, which the plan did not list; the form has it.
  - **Status badges:** the ui `StatusBadge` tone table is pinned to docs/11 section 12, which has no organization, subscription or package rows. A local `StatusPill` uses the same tone classes. Candidate for ui once the doc has rows.
