# Card 3.6b Part A2 — event sessions API

Date: 2026-10-23. Branch: `s/3.6b-api-event-sessions`. Tier: T2.

## Built

- Contracts/validation/IDs: session status and rule keys, four event-session permission keys and BN/EN labels, strict create/update/cancel/list schemas, and EventSessionId.
- Booking domain: versioned EventSession with audit fields, valid time bounds, capacity versus sold-seat checks, time locking after sales, and cancellation.
- Persistence: location-owned event_sessions registration, organization-leading location/time and offering/time indexes, paginated projected reads, caller-location intersection, and optimistic updates. The atomic write also requires seatsSold <= capacity, or seatsSold = 0 when times change; a seat-sale race returns the same 422 business rule as the domain precheck. Stale versions still return 409.
- Application/presentation: session create/list/get/update/cancel, resource-location validation, permission enforcement, manifest route registration, and the existing tenant/entitlement pipeline.
- Narrow EVENT reader: active offering, active variant, and offering/variant availability at the location, using only catalog/index.ts exports.
- R1: fixed permission-count assertions, explicit repository location filtering, atomic seat-sale guards, named refusal cases, and records. Both A1 and A2 README/index/manifest additions were preserved during rebase.
