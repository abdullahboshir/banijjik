- **Deviations from plan (and why):**
  1. **20 error codes, not 22.** The table in `14-API.md` §3 has 20 codes (counted twice, grouped rows `INSUFFICIENT_STOCK / SLOT_UNAVAILABLE / CAPACITY_FULL` expanded). The plan says 22; no other doc lists more. I followed the doc. If two codes are intended, a PLAN session must name them.
  2. **Dependency majors moved:** `pino@^10.4.0` (plan: ^9) and `pino-http@^11.0.0` (plan: ^10). Others as planned: `express@^5.3.0`, `cors@^2.8.6`, `supertest@^7.3.1`, `@types/express@^5.0.6`, `@types/cors@^2.8.19`, `@types/supertest@^7.2.1`. Workspace deps `@banijjik/contracts` and `@banijjik/ids` added to `apps/api` (and tsconfig references) so turbo builds them first.
  3. **`errorHandler` arity:** Express detects error handlers by `function.length === 4`, but lint rule `max-params` (3) forbids declaring four parameters and no disable comments or rule changes are allowed. `handleError` takes `(error, ...[request, response, next])` and `Object.defineProperty(handleError, "length", { value: 4 })` sets the arity (documented in a why-comment; covered by the INTERNAL and NOT_FOUND tests). Reviewer: decide whether a scoped lint exception would be cleaner.
  4. **Small interface additions for testability** (all optional): `createLogger({ level, destination? })`, `buildApp({ config, logger, v1Router? })`, `registerShutdown({ ..., onTimeout?, exit? })` returning a function that removes the signal listeners, and `setRootLogger()` (called by `buildApp`) so `getLogger()` has its root logger. `getLogger()` before the root logger is set throws `AppError(INTERNAL)`.
  5. **Shutdown timeout** also calls `exit(1)` (default `process.exit`) after `onTimeout`, so a hung task cannot keep the process alive; the plan said "exit code 1".
  6. **Request id for the access log** is read from the `X-Request-Id` response header (set by the middleware) because the pino-http `finish` callback may run outside the ALS context. I tested the context after body parsing (200 KB body): it survives, so no re-binding middleware was needed.
  7. `main.ts` also catches a failed `listen` (e.g. port in use): logs `api.start_failed` at fatal and sets exit code 1.
  8. Test helpers live in `src/test-support/` (compiled into `dist` with the rest of `src`, like the existing tests).
