## 5. Must-fix

### 5.1 BLOCKER — PLACED/CONFIRMED method switch to PICKUP skips the contact-phone rule

- **File:** `apps/api/src/modules/commerce/sales/application/use-cases/update-order.use-case.ts:140`
- **Severity:** must-fix
- **Scenario:** Staff create a COURIER draft with an address and **no** contact (`PlaceOrderUseCase` only demands a phone on PICKUP, `place-order.use-case.ts:82-86`). Place succeeds. PATCH `{ version, fulfillmentMethod: "PICKUP" }`.
- **What happens:** `assertDeliveryEdit` allows it (PICKUP + null address). `assertContentOfPlacedOrder` returns early because it reads **`existing.fulfillment.method`** (still COURIER), not the next method. `applyEdit` then sets PICKUP and clears the address. Result: a **PLACED PICKUP order with no contact and no recipient** — the invariant the same function's comment still states ("a PICKUP order keeps a contact the shop can call — the same rule place enforces").
- **Fix:** Judge the contact rule on the **next** method (`body.fulfillmentMethod ?? existing.fulfillment.method`). Add a named test: place a contactless COURIER order, PATCH to PICKUP → 422 `CONTACT_PHONE_REQUIRED`; the same PATCH with a phone-bearing contact → 200 and `delivery: null`.

### 5.2 BLOCKER — PATCH can turn a counter draft into INSTANT

- **File:** `apps/api/src/modules/commerce/sales/application/use-cases/update-order.use-case.ts:152-158` (no call to `resolveFulfillmentMethod`); helper at `sales-transition-shared.ts:52-63`
- **Severity:** must-fix
- **Scenario:** `POST /orders` with `fulfillmentMethod: "INSTANT"` is 422 `FULFILLMENT_METHOD_UNSUPPORTED` (D5 / S1c tests). PATCH a PICKUP **DRAFT** `{ version, fulfillmentMethod: "INSTANT" }`.
- **What happens:** Update never calls `resolveFulfillmentMethod`. S1c is what added `fulfillmentMethod` to `orderUpdateRequestSchema` (`z.enum(FULFILLMENT_METHOD)` includes INSTANT). The draft becomes INSTANT, can be placed, then confirmed and completed on the normal path — bypassing `InstantOrderUseCase` (atomic invoice + complete in one transaction).
- **Fix:** Reuse `resolveFulfillmentMethod` for a method change on a counter draft (served = PICKUP), or refuse `INSTANT` explicitly. Named test: PATCH DRAFT → INSTANT is 422 `FULFILLMENT_METHOD_UNSUPPORTED`. Instant create remains the only INSTANT write.
