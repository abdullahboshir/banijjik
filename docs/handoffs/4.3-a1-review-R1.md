## 2. Numbered Findings (Follow-up Items)

### Finding 1: Unanchored regex on unindexed fields in public offerings search
- **File & line:** `apps/api/src/modules/commerce/catalog/infrastructure/mongo-public-catalog.reader.ts:49–55`
- **Severity:** `must-fix` (follow-up)
- **Rule:** `RUN-WITHOUT-CLAUDE.md` §7 ("User input in `$regex` is escaped and anchored. No unbounded case-insensitive search"), `parallel-sessions-guide.md` §11 item 15.
- **Scenario:** `buildOfferingFilter` constructs an unanchored regex `contains = new RegExp(escapeRegExp(raw), "i")` and adds `{ name: contains }` and `{ synonyms: contains }` to the `$or` filter alongside anchored prefix queries on `nameSearch` and `searchTerms`.
- **Fix:** Remove `{ name: contains }` and `{ synonyms: contains }` from `buildOfferingFilter` so search strictly uses anchored prefix regexes against the indexed `nameSearch` and `searchTerms` fields.

### Finding 2: Per-category `countDocuments` queries in `findPublicCategories`
- **File & line:** `apps/api/src/modules/commerce/catalog/infrastructure/mongo-public-catalog.reader.ts:240–256`
- **Severity:** `must-fix` (follow-up)
- **Rule:** `AGENTS.md` ("No N+1 queries. lean() + projection on reads"), `RUN-WITHOUT-CLAUDE.md` §7.
- **Scenario:** `findPublicCategories` executes `countDocuments` per category inside `Promise.all`.
- **Fix:** Replace the per-category `countDocuments` loop with a single MongoDB `$match` + `$unwind: "$categoryIds"` + `$group` aggregation pipeline.

### Finding 3: 404 error message key when offering is not found
- **File & line:** `apps/api/src/modules/commerce/catalog/presentation/catalog-storefront.router.ts:24–29, 76`
- **Severity:** `must-fix` (follow-up)
- **Rule:** `AGENTS.md` ("Single source of truth"), `docs/05-CONVENTIONS.md`.
- **Scenario:** When an offering slug is not found, `catalog-storefront.router.ts` throws `messageKey: "errors.storefront_not_available"` instead of `"storefront.catalog.offering_not_found"`.
- **Fix:** Throw `new AppError({ code: ERROR_CODE.NOT_FOUND, messageKey: "storefront.catalog.offering_not_found" })` when `result === null`.

### Finding 4: Reading `request.query` / `request.params` with `as unknown as` casts
- **File & line:** `apps/api/src/modules/commerce/catalog/presentation/catalog-storefront.router.ts:50, 68–69`
- **Severity:** `must-fix` (follow-up)
- **Rule:** ADR-012, `RUN-WITHOUT-CLAUDE.md` §7 ("No `as unknown as` or other casts in production code").
- **Scenario:** The router reads `request.query as unknown as PublicOfferingsQueryInput` and `request.params as unknown as PublicOfferingParamsInput` instead of `response.locals["validated"]`.
- **Fix:** Read validated query and params from `response.locals["validated"]`.

### Finding 5: Hardcoded `"BDT"` fallback currency in `computeStartingPrice`
- **File & line:** `apps/api/src/modules/commerce/catalog/infrastructure/mongo-public-catalog.reader.ts:77, 79`
- **Severity:** `minor`
- **Fix:** Derive currency from the first variant's currency or organization currency instead of a `"BDT"` literal.

### Finding 6: Optional `locationId` query filter on `GET /categories`
- **File & line:** `apps/api/src/modules/commerce/catalog/presentation/catalog-storefront.router.ts:82`
- **Severity:** `minor`
- **Fix:** Validate optional `locationId` query parameter and forward it to `getCategories.execute`.
