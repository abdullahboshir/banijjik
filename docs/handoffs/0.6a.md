- **Deviations from plan (and why):**
  1. **R22 uses `regex`, not a negated `group`** (decision 5f). I measured that the `ignore` library behind `group` cannot re-include `@banijjik/contracts` once `*` matched the parent `@banijjik`, so the plan's `["*", "!@banijjik/contracts", ...]` flagged the two allowed packages too. The `regex` option of the same built-in rule is the same allow-list: every source is banned except `@banijjik/contracts`, `@banijjik/ids` and relative paths (`./`, `../`, at any depth). Domain test files are exempt (they import vitest).
  2. **`RETRY_LATER` is exempt from the J1 `>= 500` rule.** Decision 2 says an AppError with status >= 500 is reported and answered as generic INTERNAL; decision 4 says `RETRY_LATER` (503) reaches the client with `Retry-After: 1`. I read it as: all 5xx except `RETRY_LATER`. Exhausted retries are still reported to the log by `withTransaction`.
  3. **Backoff:** "plus full jitter (random 0 to 100% of that value)" is implemented as `base + floor(random * base)` with `base = min(800, 50 * 2^(attempt-1))`, so a delay lies in `[base, 2 * base)`.
  4. **J5a/J5b import bans match kernel paths** (`**/kernel`, `**/kernel/**`), not every module: with `importNames`, ESLint reports any `import * as x` from a matching source, so a catch-all group would have banned every namespace import (`zod`, `React`) in module code. A namespace import of a kernel file is reported by both R26 and R27 (fixture documents it).
  5. **Plan said the registry test would use "the existing test-support reset"; none exists.** Vitest isolates modules per test file, so `models.test.ts` seals the registry through its normal `initializeModels()` and checks the throws; no reset helper was added.
  6. **`npm run lint` now passes `--max-warnings 0`** (root `package.json`, one line). With `noInlineConfig`, ESLint reports an ignored `eslint-disable` comment as a warning (severity 1, no rule id) while the underlying violation stays an error; the flag turns the warning into a failure. The fixture harness maps that message to the id `inline-config-ignored`.
  7. **The exhausted-retry test uses a real session** (a work function throwing a labelled error three times) instead of a fake session; it also asserts `random` was called twice and that the driver error was logged.
  8. **Extra files:** `packages/contracts/src/errors/message-keys.ts`, `kernel/observability/to-loggable-error.ts`, `kernel/lifecycle/crash-handlers.ts`, `eslint/selectors.mjs` (selector lists moved out of `restrictions.mjs`, which hit the 300-line limit), `scripts/hooks/env-file-name.mjs`, `packages/*/tsconfig.build.json`.
