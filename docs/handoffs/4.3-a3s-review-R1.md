## 2. Invariant & Architecture Checklist

- [x] **Storefront source & placement:** Order is created in `PLACED` status with `ORDER_SOURCE.STOREFRONT`.
- [x] **Atomic sequence number:** `orderNumber` assigned from `SEQUENCE_KEY.ORDER` inside the transaction.
- [x] **Recipient snapshot contactability:** Pickup orders with provisional / null contact phone succeed when trusted `recipient` phone is provided.
- [x] **Payment summary initialization:** Placed order initializes `PaymentSummary` in payment module idempotently with total required amount.
- [x] **Stock reservation:** All tracked stock lines are reserved at placement via `dependencies.stock.reserve`.
- [x] **Rollback guarantee:** If stock reservation fails, the transaction aborts and neither order nor payment summary persists.
- [x] **Auto-confirmation:** If `autoConfirm` setting is enabled and `advanceRequired` is `NONE`, the order transitions to `CONFIRMED`.
- [x] **Checkout mapping & sparse index:** `checkoutId` indexed sparsely `{ organizationId: 1, checkoutId: 1 }` allowing fast checkout lookup without colliding on nulls.
- [x] **Limits & Multi-tenancy:** Monthly order limit `LIMIT_KEY.ORDERS_PER_MONTH` asserted; cross-organization access rejected.
- [x] **Code Quality:**
  - Zero TODOs, stubs, mocks in production code, or commented-out blocks.
  - All files <= 300 lines (longest production file is `storefront-order-commands.ts` at 288 lines).
  - All functions <= 60 lines.
