  1. **Renormalize commit is empty, so there is none.** The index already held LF blobs; `git add --renormalize .` changed nothing. Only the `.gitattributes` commit exists. The working tree of this worktree had CRLF (owner's `core.autocrlf=true`), so I converted tracked files to LF in place; `git diff` shows no content change.
  2. **`docs/`, `AGENTS.md`, `CLAUDE.md`, `.cursor/` are in `.prettierignore`.** Prettier flags all of them; reformatting the design docs would be a huge diff that conflicts with every parallel branch. `format:check` therefore covers code, JSON and package READMEs only. Owner decision needed if the docs should be formatted (then do it once, in its own commit, between branches).
  3. **`eslint-plugin-boundaries` v7 has no usable `entry-point` rule** (deprecated, no-op without options; the canonical rule is `boundaries/dependencies`). R18 and R19 use `boundaries/dependencies` with `checkInternals: true` (needed because layers live inside one module element). Rule id in the fixtures is therefore `boundaries/dependencies`.
  4. **Added dev dependency `eslint-import-resolver-typescript`** (4.4.5). Without it boundaries cannot resolve `./x.js` specifiers to `x.ts` (verified: the node resolver leaves the target unresolved and no rule fires). Also added `globals`, `@eslint/js` (needed by the flat config).
  5. **Local alias plugin `eslint/guard-plugin.mjs`** re-exports ESLint's built-in `no-restricted-imports`, `no-restricted-properties`, `no-restricted-syntax` under ten ids (`banijjik-guard/no-...`). Reason: flat config replaces rule options per block, so one `no-restricted-*` rule cannot carry concerns with different exemptions (R11, R13-R17, R21, R22). No rule logic was written. It imports `builtinRules` from `eslint/use-at-your-own-risk`; if a future ESLint removes it, the plugin throws a clear error at startup. Recorded in ADR-082.
  6. **Extra checks beyond the plan table (small):** R16 also catches `switch (x.industry*)`; R22 also blocks bare Node builtins (`fs`, `path`, ...) not only `node:*`; R10 allows PascalCase function names in `*.tsx` (React components) and proves that `.ts` still rejects them.
