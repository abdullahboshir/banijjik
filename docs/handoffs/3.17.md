# 3.17 Next.js security bump and booking test date fix (handoff)

Lead card (Opus 5.5, 2026-10-23), asked for by the owner. It unblocks CI on every branch.

## What changed
- `apps/admin`, `apps/platform`, `packages/web-client` `package.json`: `next` and `@next/eslint-plugin-next` `^16.4.0` → `^16.4.2`. 16.4.0 is hit by three advisories that `npm audit --omit=dev --audit-level=high` reports (critical): GHSA-2464-fhr4-w9xw (RCE in Image Optimization with SVG), GHSA-673q-mjm6-r5xr (RCE in `use cache` returning typed arrays), GHSA-p3m5-59mp-jv5r (Server Actions DoS).
- `package-lock.json`: the `next` family to 16.4.2 and `ip-address` 10.7.3 → 10.7.4 (moderate GHSA-rxp7-6hxx-x8q5). No other package moved.
- `apps/admin/src/bookings/booking-screens.browser.test.ts`: `nextMonday()` took the weekday from the runner's clock and formatted the date in Asia/Dhaka. On a UTC runner between 18:00 and 24:00 UTC (Dhaka midnight to 06:00) the Dhaka date is one day ahead, so the test picked a Tuesday, where the stylist has no hours (`expected +0 to be 1`). The weekday now comes from today's Dhaka date. Checked by simulating UTC times 19:15 Thursday, 09:00 Friday, 20:00 Sunday, 17:59/18:01 Monday: the old code gave Tuesdays at evening times, the new code always gives a Monday.
