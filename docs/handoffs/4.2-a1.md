## What this part does

The platform now has the one global record that answers "which organization owns this host name":
`HostClaim` in `modules/platform/operations`, on the platform database with tenancy NONE.

- `HostClaim` entity: enabled/generation/quarantine/version with the removal and re-claim rules.
  A disable stops routing at once, starts a 24-hour quarantine and refuses a job of another
  generation; a re-claim is only possible after the quarantine and takes a new owner and generation.
- `normalizeHostname`: IDNA/lower-case/one-terminal-dot normalization and refusal of URLs, ports,
  userinfo, paths, queries, commas, wildcards, IP literals, empty labels and single labels.
  `isReservedHostname` refuses the SaaS apex and the configured platform hosts.
- `HostClaims` port with `reserve`, `disable`, `resolve` (`application/host-claims.ts`).
- `MongoHostClaims`: race-safe reserve (the unique hostname index decides the winner), version-guarded
  updates, idempotent retry of the same site domain (generation moved on), idempotent disable.
- `registerOperationsModels` is called by `registerModuleModels` in `routes/v1.ts`.

No HTTP route, no event, no counter change: A1 is the registry only. Parts A2 (tenant `SiteDomain`
lifecycle), A3 (Cloudflare worker), B, C1 and C2 are still todo.

## Data

`host_claims` (platform database, tenancy NONE): `hostClaimId`, `hostname` (globally unique),
`organizationId`, `siteDomainId`, `enabled`, `generation`, `quarantineUntil`, `version`, audit fields.
Indexes: `{ hostname }` unique, `{ siteDomainId }` unique, `{ enabled, quarantineUntil }`.
The unique `siteDomainId` index is what stops one site domain from holding two hosts; the unique
`hostname` index is what makes the two-organization race end with exactly one claim.

## Deviations from the plan (frozen here, for the next parts)

1. **`resolve` returns the routing facts only.** The plan's `HostResolution` also carries
   `canonicalHostname` and `publishedWebsiteVersionId`, which belong to the tenant `Site` (A2/4.1).
   A1 therefore exposes `HostClaimResolution { organizationId, hostname, domainGeneration }`; A2/C1
   compose the full resolution from the claim plus the Site pointer. The platform registry never
   reads a tenant collection.
2. **Failures are domain errors, not results.** `reserve` keeps the planned `Promise<void>` and throws
   `HostClaimTakenError` (DUPLICATE), `HostClaimQuarantinedError` (CONFLICT) or
   `HostClaimGenerationMismatchError` (CONFLICT); an invalid or reserved host throws a
   `VALIDATION_ERROR` carrying `{ field: "hostname" }`. A2 maps these to the planned
   `WEBSITE_DOMAIN_TAKEN` / `WEBSITE_DOMAIN_INVALID` keys when it builds the API surface.
3. **`actorUserId` is an optional extra field** on `reserve`/`disable` inputs for the audit columns;
   the plan's required fields are unchanged.
4. **The normalizer lives in `application/`, not `domain/`**, because domain code may not import
   `node:url` (lint guard, ADR-011a). It is pure and has no I/O.
5. **`module.manifest.ts` is unchanged**: A1 adds no route, menu entry, setting, bot tool, storefront
   section, event, limit or sequence, so there is nothing to add.
6. **24-hour quarantine constant** (`HOST_CLAIM_QUARANTINE_MS`). The plan does not fix a duration;
   A3 reconciliation may release a claim earlier through an additive port method once it has proved
   the provider resource is gone.
7. **`SiteDomainId` is defined here** because the port references it; A2 owns the `SiteDomain` entity.

Behaviour specs now covered:

- two organizations racing one hostname produce exactly one claim (parallel reserve, unique index);
- the stored host is normalized, and any casing of it resolves;
- a reserved platform host and an unparseable host are refused with a validation error;
- a host another site domain holds is refused;
- an explicit retry of the same site domain takes the new generation (one row, new generation);
- a stale reserve cannot take a newer generation back (generations only move forward);
- removal stops routing at once and quarantines the host; a second claim is refused until the
  quarantine lapses, after which the host is re-claimed with a new owner and generation;
- a late disable of an older generation is refused and the newer claim keeps routing;
- disable of a domain with no claim is a no-op; unknown/malformed hosts resolve to undefined.
