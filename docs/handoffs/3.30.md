# Handoff: card 3.30 refund amount label

## Built
- New key `payments.refund.invalidAmount` in both screen catalogs (EN and BN, text from the plan). No existing key fitted: `payments.receive.amountInvalid` only says "greater than zero".
- `invalidAmount` added to the `refundDialog` labels type and builder (`payment-labels.ts`, `payment-labels-builders.ts`).
- `refund-dialog.tsx` passes `labels.invalidAmount` as `invalidAmountLabel` (was `labels.failed`).

## Deviations
- The refund allocation row only validates empty, unparseable and zero or negative amounts on the client. An amount above the refundable balance is rejected by the API and shows the server error, not this label. The plan said no other behaviour change, so no max check was added. The test therefore uses a zero amount.

## Tests
- `shows the amount message, not the refund failed message, for an invalid allocation amount` in `apps/admin/src/payments/refund-reversal.test.tsx` (jsdom config; the browser config only includes `*.browser.test.ts`). All 5 tests in the file pass.
