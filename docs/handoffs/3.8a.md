- **Done:**
  1. **Streams.** `publishEvent(type, payload, { orderingKey })`: with a key it takes the next number from `event_streams { organizationId, orderingKey, lastSequence }` with `$inc` in the publishing transaction (a rollback leaves no gap; concurrent publishers conflict on the counter and the transaction retry runs the loser again). The outbox event stores `orderingKey` and `streamSequence`. No key: nothing changes.
  2. **Ordered handlers.** `EventHandler.ordering` (`ORDERED | UNORDERED`, required). For an ORDERED handler and a keyed event the runner reads `event_stream_positions`: the next sequence runs and moves the position in the same transaction as the marker; an earlier one is ALREADY_PROCESSED; a later one returns WAITING_FOR_EARLIER_EVENT, and the worker re-queues the job (1 s doubling to 60 s) without spending an attempt, with `events.stream_waiting` at warn level after 24 h and about hourly. A module-off event still moves the position.
  3. **Dispatch order.** The claim sorts by `nextAttemptAt`, then `streamSequence`; index `{ status, nextAttemptAt, streamSequence }`.
  4. **Dead letters.** Status FAILED, REPLAY_REQUESTED, REPLAYED, SKIPPED (`organizationId`, stream coordinates, who, when and the skip reason are stored). Replay: the API sets REPLAY_REQUESTED (audited, `platform.eventDeadLetter.replayRequested`); the worker's new `DeadLetterReplayer` removes the failed queue job, adds a new one with fresh attempts and only then sets REPLAYED; a failed re-add is reported, logged (`events.dead_letter_replay_failed`) and left REPLAY_REQUESTED for the next poll. Skip: immediate, needs a reason, moves the position past the event only when the position is right before it (else `422 EVENT_STREAM_NOT_AT_EVENT`). DEAD outbox events: listed, replay sets them PENDING with attempts reset (the "tenth failed dispatch makes it DEAD" test already existed).
  5. **API and module.** New PLATFORM module `platform/operations` (no data of its own): `GET /platform/event-dead-letters`, `POST …/replay|skip`, `GET /platform/dead-outbox-events`, `POST …/{eventId}/replay`; permissions `platform.events.read` and `platform.events.replay`, SUPER_ADMIN only; all actions audited.
