# Handoff: 3.8 Part B2 — dues and store credit screens

Date: 2026-10-23. Tier: T2. Branch: `s/3.8-ui-dues-store-credit`.
Plan: `docs/plans/3.8.md`, Refresh 2 (B2 only).

## Built

- `apps/admin/src/dues/**` and `apps/admin/app/[orgSlug]/(app)/payments/dues/page.tsx`: permission-checked dues page, contact search and selection, request-type filter, 20-row pagination, mobile cards and empty state. The selected contact remains available when outside the first contact-choice page. Uses the existing `GET /dues` and contact reads.
- `apps/admin/src/store-credit/**`: server reads the contact summary balance, organization currency and first ledger page; a dynamically imported contact section renders the balance, dated signed history and paged history controls. Write permission and writable access control the adjustment form. Adjustments obtain a PIN approval bound to `STORE_CREDIT_ADJUSTMENT`, contact and amount, then submit the existing API with a UUID v7 idempotency key. A lost response retries the same body, key and approval token. The approval dialog is loaded only when needed.
- `apps/admin/src/contacts/contact-detail-page.tsx`: mounts the lazy section. Contact identity keys reset client form/history state when navigating between contacts.
- `packages/i18n/src/catalogs/screens/{bn,en}.json`: add-only dues and store-credit text; existing keys and translations retained.
- Both feature folders include short READMEs. B1's `apps/admin/src/payments/**`, payment routes and booking receive section are untouched. No API, contract, validation, manifest or dependency changes.
