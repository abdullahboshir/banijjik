## Deviations from the plan

1. **Amendment 1** was built exactly as written (contract, view, two API tests, edit screen). No ADR edit (ADR-131 does not list response fields).
2. **Sales refusals are shown by rule key, not by `messageKey`.** The API sends every sales refusal with the generic `errors.business_rule` message key and the reason in `details.ruleKey`, so `order-failure.ts` maps the rule key to its catalog message (`errors.order_contact_phone_required`, `errors.advance_needs_payments`, and so on). The first draft compared `messageKey` and would never have shown the totals and contact messages.
3. **Route budget (180 KiB).** The first build was 259 KiB (new order) and 200 KiB (detail). The fixes: the sheets and dialogs that use Radix load on demand (`lazy-order-cancel-sheet`, `lazy-order-delete-dialog`, `lazy-order-approval-dialog`, with the hook split from the dialog component), the toast library loads through `@banijjik/ui/toast` (`order-toast.ts`), and `@banijjik/validation` is imported only when a new contact is typed. Measured: list 168.5, new order 178.1, draft detail 175.0 KiB. The new-order margin is 1.9 KiB: keep Radix, sonner and zod out of its first load.
4. `placeOrder` in `order-api.ts` makes its own idempotency key (a parameter would be a fourth argument; the lint limit is three).

## Findings (not changed here, they belong to Part A)

- `GET /orders` echoes `meta.page` and `meta.limit` as the text of the query string (`"1"`, not `1`) when the client sends them. The list screen keeps its own page number instead of reading `meta.page`. A follow-up should coerce them in the controller.
- On the RETAIL template a pickup order cannot be placed without a contact that has a phone (`CONTACT_PHONE_REQUIRED`, 422). The screen shows the message; the browser tests create the contact inline on the new order page.
