## Deviations from the plan (and why)

1. **Validation HTTP 400 not 422.** Kernel `ERROR_HTTP_STATUS.VALIDATION_ERROR` is 400 (`validate.test.ts`). Availability span/date tests expect 400 `VALIDATION_ERROR`.
2. **Booking module-off uses RETAIL, not PLATFORM_REVOKE.** BOOKING is CORE; revoke does not turn it off. RETAIL `allowedModuleKeys` omits booking → 404.
3. **Local Zod query schema in `booking-storefront.router.ts`.** This worktree's `node_modules` is a junction into `banijjik-4.3-cod-s1a`, so `@banijjik/validation/booking` named exports were undefined at runtime and `validate({ query })` skipped checks. The package still exports `publicAvailabilityQuerySchema` for CI's fresh install. Router clones `{ ...request.query }` before parse.
4. **`ListPublicLocationsUseCase` is not re-exported from `website/index.ts`.** That barrel is already at `max-lines` 300. The website storefront factory imports the use case from its file. `buildBookingStorefront` **is** exported from `booking/index.ts` (R25).
5. **GYM browser seed POSTs enrollment custom field `notes`.** GYM template has no `notes` key; unknown customFields 400 the checkout. The UI still sends `customFields: { notes }` (B2). The test defines the field so "keep PLAN notes" can submit. Not offering-definition admin.
6. **Language route uses Referer + `Host`/`x-forwarded-host` for the redirect origin.** Required so `/language?to=en` does not 303 onto `http://localhost:3102` (no tenant).
7. **Parent prompt file name `booking-pages.browser.test.ts` is not used.** Frozen plan names `booking.browser.test.ts`. Viewport is **360** CSS px, two orgs SALON+GYM, not 375 / one education-like org.
