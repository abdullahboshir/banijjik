## 2. Invariant & Architecture Checklist

- [x] **Partial unique index preserved:** `contact.schema.ts` index `{ organizationId: 1, phoneE164: 1 }` with `partialFilterExpression: { status: "ACTIVE", phoneE164: { $type: "string" } }` is untouched.
- [x] **Provisional contact attributes:** `isProvisional` / provisional contact entities have `phoneE164: undefined`, `email: undefined`, `source: "STOREFRONT"`, and `status: "ACTIVE"`. Excluded from unique index in Mongo.
- [x] **Snapshot phone containment:** Submitted E.164 phone is retained strictly in `CheckoutContactSnapshot` and not published or claimed as verified contact phone.
- [x] **Privacy & Isolation:** Submitting the phone of an existing customer contact does not link or reveal customer `contactId`, orders, or personal history.
- [x] **Auth Guard:** Provisional contact cannot be used to sign in, request customer OTP, or resolve customer account. Customer OTP registration continues to work for phones previously submitted by guests.
- [x] **Tenant & Session Isolation:** Cross-org guest session linkage is rejected with 403 FORBIDDEN / 401 UNAUTHENTICATED.
- [x] **Optimistic Locking:** Session version checked during link with atomic `$inc: { version: 1 }` and 409 CONFLICT on race.
- [x] **Code Quality:**
  - No TODOs, FIXMEs, stubs, or mock data presented as finished code.
  - All files <= 300 lines (longest production file is `packages/validation/src/index.ts` at 299 lines; `contact/index.ts` at 288 lines).
