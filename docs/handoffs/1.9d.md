## Per decision: what changed, the proving test, failing-before

### 1. M6 login throttling
- **What:** an attempt is reserved in the bucket before the password check and given back on success, so only failures count. Buckets per surface: identifier + IP (5 / 15 min) and identifier (50 / 15 min), admin and platform separately. The per-IP bucket of 1.1 is unchanged. `RateLimiter` got `refund`.
- **Proof:** `register-and-login.use-case.test.ts` ("failed-attempt throttling (1.9d, review M6)", 4 tests), `auth-api.test.ts` and `platform-auth-api.test.ts` (new throttle describes), `mongo-rate-limiter.test.ts` (refund).
- **Failing-before (real run on the unchanged source, `git stash`):** 3 use-case tests failed, and in the API tests "keeps a stranger from locking out…", "locks the identifier after 50 failures" (admin and platform) and the Mongo refund test failed: 5 failures in the API and rate-limit files. After the change the iam and rate-limit suites were green (244 tests).

### 2. M7 trusted proxy hops
- **What:** `TRUSTED_PROXY_HOPS` (0 to 5), default 0 outside production, required in production, feeds `app.set("trust proxy", …)`. The hardcoded constant is gone. Documented in `.env.example` and `apps/api/README.md`.
- **Proof:** `load-config.test.ts` (new describe) and the new `app-proxy.test.ts` (with 0 hops a forged `X-Forwarded-For` does not change the rate-limit key; with 1 hop the last hop is used).
- **Failing-before:** 11 config tests and the "0 hops" app test failed on the old source.

### 3. M8 per-user limit

### 7. M20 config hardening and `localhost.`

## Mechanical choices (small, not in the plan)

- `RateLimiter.refund` was added to the kernel port. The plan did not say how a success can avoid consuming; reserving first and refunding on success is the only way that stays atomic against parallel guessing.
- `ALLOW_LOCAL_SERVICES` is accepted in production only when `CI=true` or `VITEST` is set, so a real deployment cannot switch the guard off.
- One marker check (`change-me`, lowercase compare) covers the exact placeholder and every variation.
- The per-user limiter is optional (not mounted without Redis) and does not count `logout-all` or the public auth routes (they have their own buckets).
- The Redis window starts at the first hit (`PEXPIRE`) rather than on aligned boundaries.
- `buildApp` option `isReady` was renamed `checkReadiness`, because it now returns details and not a boolean.
- The admin role screens now use `holdsPermissionEverywhere` for the role writes (the plan named only the `/me/config` change); it is what the locations screen already did, and it keeps the screen right even if the API list ever lags.
