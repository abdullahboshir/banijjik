### R1-1 · MAJOR · blocks merge: refused attempts still count against the identifier-wide bucket
- **Where:** `login.use-case.ts` `reserveAttempts`.
- **What happens:** it consumes the identifier+IP bucket **and** the identifier bucket on every request, then checks whether either refused. A request that the identifier+IP bucket refuses (429, no password check) still adds 1 to the identifier-wide bucket.
- **Measured** (temporary probe, removed afterwards, using `createIamWorld()`):
  - addresses `198.51.100.1` and `198.51.100.2` each send 30 wrong attempts (30 is the route's `LOGIN_PER_IP` maximum)
  - only **10** of those 60 reach a password check
  - the real person then signs in from `198.51.100.3` with the right password → `RATE_LIMITED`
- **Why it matters:** two addresses and ten guesses lock a person out for 15 minutes, which is what review M6 was meant to stop. With correct counting the identifier-wide limit needs 50 real failures, about ten addresses.
- **Fix:**
  - consume the identifier+IP bucket first; if it refuses, answer 429 **without** touching the identifier bucket
  - if the identifier bucket refuses, `refund` the identifier+IP attempt just taken, because that attempt was never evaluated
  - keep the success path as it is: reset identifier+IP, refund identifier
  - apply the same to the platform sign-in
- **Tests (fail first, then pass):**
  - the probe scenario above as a permanent use-case test
  - an API test through the real route (two addresses × the route maximum, then the right password from a third address → 200)
