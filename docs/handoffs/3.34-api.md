## Deviations from the plan (and why)

1. **`closeAtTotal` is `setTotal` plus a second write.** The plan's pipeline update (`closedAt: { $ifNull: [...] }`) is refused by the tenant plugin. Now: `setTotal`, then `updateOne({ ..., closedAt: null }, { $set: { closedAt: now } })`. A summary that is already closed matches nothing, so the first close time is kept. No test closes one request twice; this is a known test gap, listed below.
2. **Audit action renamed** `PAYMENT_DUE_WRITTEN_OFF` → `PAYMENT_DUE_WAIVED` (`payment.due.waived`). The audit vocabulary test (`packages/contracts`, "names every action") requires a past-tense last word, so `writtenOff` was rejected. The business term in the docs is still "write off".
3. **Bad-debt journal is one per reversal payment**, not one per `(paymentId, requestId)` as the plan says. The rows of one reversal are summed into one journal under `(PAYMENT, paymentId, bad_debt_written_off)`, which keeps the existing idempotency index. A reversal that writes off two booking fees posts one journal with the sum.
4. **Cross-location reversal answers 404, not 403.** The plan's test list says 403. The existing location rule hides a payment of another location (404), and the plan also says existing reversal rules stay unchanged, so the test asserts 404 and says so in a comment.
5. **Enrollment cancel closes every summary**, including a fully paid one. The old early return (`if total <= netPaid`) is gone, so the closure always sets `closedAt` (total `min(total, netPaid)`).
6. **Enrollment "no bad-debt journal" is tested at the rule level** (`write-off-posting-rules.test.ts`, "posts nothing for an enrollment write-off"), not in the HTTP enrollment test, because the enrollment test file has no accounting harness. The enrollment HTTP test covers the dues and the `writeOffs` row.

- No test closes one request twice (the first close time is kept by the `closedAt: null` filter).
- No screen shows written-off amounts (plan: a later report in 3.10). The admin payment screen shows the setting through the generic settings screen only.
- Refunds on enrollment cancel (3.32) and enrollment revenue (3.31) are not in this card. **3.31 must revisit the ENROLLMENT rule** (ADR-140, STATUS row 3.31).
