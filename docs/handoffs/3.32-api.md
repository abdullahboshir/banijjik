# 3.32 Part A handoff · Enrollment cancel refunds (API)

Branch `s/3.32-api-enrollment-refunds`. Plan `docs/plans/3.32.md` (Refresh 1), decisions 1–9. ADR-143. Implemented by the owner's Codex session; the handoff, the review fix below and the STATUS row were added by the lead (Opus 5.5), who reviewed the branch (T1).

## What was built
- **Enrollment domain** (`domain/refunds.ts`): `refundableByPeriod` per period (only PAID periods; a paid future period counts in full for `UNUSED_PERIODS` and `PRORATED`; `NONE` is zero), `refundableAmount` is its sum, `refundRemaining` = stored amount minus what was refunded since cancel, never below zero; currencies are compared.
- **Cancel** (`application/settle-cancellation.ts`, split out of `transition-enrollment.ts`): in the cancel transaction each period stores `refundableOnCancel` and `refundedAtCancel`, then the summaries are capped and the periods closed; `closeOnePeriod` stores `revenueClosedAs` (`REVENUE` / `CANCELLATION_FEE`, contract enum `ENROLLMENT_REVENUE_CLOSE`). The cancel response adds `refundableByPeriod`; the detail response adds `refundRemaining` per period (for Part B).
- **Payment** (request-neutral): `RequestReadSnapshot` has required `acceptsPayments` and `refundLimit`; booking and order readers set `true` / `null` explicitly. Receive refuses `acceptsPayments: false`; the refund validation now runs **inside** the refund transaction and refuses an allocation above `refundLimit` with `PAYMENT_REFUND_ABOVE_LIMIT`; `applyRefund` on a closed summary also lowers its total (never below allocated − refunded), so a refunded cancelled period never shows as a due.
- **Enrollment request reader**: a cancelled enrollment's period answers `acceptsPayments: false`, `revenueState: AFTER_REVENUE`, `refundLimit` from `refundRemaining`.
- **Books**: ORDERED handler `accounting.postEnrollmentRefunds` on `payment.payment.refunded` (`paymentAccount:` stream) posts one journal per refund (`PAYMENT`, refund payment id, `enrollment_period_refund_revenue`): Dr `REVENUE_PLAN` or `CANCELLATION_FEE_INCOME` / Cr `ACCOUNTS_RECEIVABLE` per allocation to a closed period; another currency fails as `postingSourceMissing`.

## Deviations
- Lead review fix (R1, item 1 below): a refund may allocate to each request only once (`assertOneAllocationPerRequest` in `payment/domain/payment-rules.ts`). Without it, two allocations to the same period in one refund were each checked alone against the paid amount and the refund limit, so together they could pass the limit.
- None else.

## Tests
- Unit: `refundableByPeriod splits UNUSED_PERIODS and PRORATED per period and ignores unpaid periods`, `the limit is the stored amount minus what was refunded since cancel` (`enrollment/domain/enrollment.test.ts`).
- API (`enrollment/presentation/enrollment-payment-api.test.ts`, "enrollment cancel refunds (3.32)"): `cancel stores each period's refundable amount and how it closed, and returns the amounts per period`, `a payment on a cancelled enrollment period is refused`, `a refund up to the limit works to store credit and by cash; above the limit is 422`, `two parallel refunds of the same period never pass the limit together`, `a refund that allocates twice to the same period is refused and refunds nothing` (lead), `a refund without the permission needs an approval token`, `a refund on a closed summary lowers its total, so the period never shows in dues; a refund on an open summary still reopens the due`, `a refund on an open summary still reopens the due`, `refunding a period kept as a cancellation fee lowers CANCELLATION_FEE_INCOME; refunding a recognised period lowers REVENUE_PLAN`, `the refund revenue entry posts once on event replay`, `policy NONE stores zero and refuses every refund of the cancelled periods`, `refuses foreign refund periods and a refund outside the caller's assigned location`.
- Readers (`routes/request-reader-payment-flags.test.ts`, "booking and order refunds and payments behave as before"): `the booking reader explicitly accepts payments without an extra refund limit`, `the order reader explicitly accepts payments without an extra refund limit`.
