# 4.4 A1D — Website template persistence

## Result

Implemented the A1D domain and persistence layer on `s/4.4-a1d-template-persistence`. Website templates and immutable revisions are stored in the platform database with `MODEL_TENANCY.NONE`; no application routes or use cases are added in this part.

## Files

- Added the `WebsiteTemplate` entity, guarded draft edits, publish/archive transitions, and UUID v7 revision creation.
- Added the `WebsiteTemplateRepository` port and Mongo implementation for inserts, versioned updates, lookups, maximum revision reads, and bounded template/revision pages.
- Added platform schemas for `website_templates` and `website_template_revisions`, including the planned unique and ordering indexes.
- Added mappers that validate Mixed content and snapshots with `websiteTemplateContentSchema` before persistence and after reads.
- Registered both collections as `DATABASE_KIND.PLATFORM` / `MODEL_TENANCY.NONE` beside industry-template models.
- Added conflict translation for duplicate template keys and revision pairs.
- Added entity and repository behaviour tests plus a valid shared test fixture.

## Decisions and deviations

- Followed A1D’s 8 production-file inventory; the shared add-only domain `errors.ts` and model registration are included.
- Applied `minimize: false` on these schemas, layered over `SCHEMA_OPTIONS`, because Mongoose otherwise removes empty objects inside Mixed snapshots. `allowedVariantsBySection: {}` is valid website policy data and must survive a publish/read round trip.
- Revisions are immutable through the persistence interface and immutable schema fields. Their unique `(websiteTemplateId, revision)` index is the D1 replay guard; duplicate revision insertion becomes a 409 conflict.
- `WebsiteTemplate.withEdits` rejects archived records, while edits to published templates retain PUBLISHED status and do not mutate stored revisions (C11).
- No tenant `organizationId`, migration, event, route, use case, ADR edit, or out-of-scope file was added.

## Tests and checks

- `website-template.entity.test.ts`: new draft starts at version 1; revisions preserve earlier snapshots; archived templates retain their revision reference and reject edits/publish; domain key, default preset, and image-file guards are enforced.
- `mongo-website-template.repository.test.ts`: duplicate key conflict; stale version conflict includes current version; revision pages are bounded and ordered with preserved revision IDs; duplicate template/revision pairs conflict.
- `industry-template-api.test.ts`: existing industry-template behavior remains green after model registration changes.
- Local API run: 3 files passed, 19 tests passed.
- `npx turbo run typecheck build --filter=@banijjik/api` passed.
- ESLint and Prettier passed on changed files. API-only part; no browser suite applies.
