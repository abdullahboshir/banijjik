- **Deviations from plan (and why):**
  0. **Member status tones:** `statusTone` has a `MEMBER` request type (ACTIVE success, INVITED info, SUSPENDED warning, REMOVED neutral; table test and a row in `11 §12`). The invitation status badge still uses the `ENROLLMENT` table.
  1. **`"sideEffects": false` in `packages/contracts/package.json` and `packages/i18n/package.json`:** without it the bundler keeps every unused enum object and the catalogs in the first load (1.9 KiB on `/[orgSlug]`). The packages have no import-time side effects.
  2. **Screen text is in a second catalog (`SCREEN_CATALOGS`, `packages/i18n/src/catalogs/screens/{bn,en}.json`)**, not in `bn.json` and `en.json`: the bundled catalogs travel to the browser in every first load, and about 100 new keys would cost about 4 KiB gzip. Server code merges the screen catalogs (`getTranslator`); client components receive text as props. Tests assert identical key sets, no shared key with the bundled catalogs, and no brand name. `banglaText` in `auth/test-helpers.tsx` reads both.
  3. **The config call is not parallel with `/me` and `/me/orgs`:** the path needs `organizationId`, which comes from `/me/orgs`. The profile (time zone) is loaded in parallel with the config. One cached load per request (`loadOrgContext`, React `cache`), shared by the layout and pages.
  4. **`/me/config` also needed the org time zone:** the plan says the trial banner counts days in it. It is read from `GET /profile` (any member may), UTC if that fails.
  5. **Icon:** Locations uses the existing `globe` icon (a new icon would cost bytes in the first load).
  6. **Only two of the three approved entitlement assertions changed:** the owner menu in `entitlement-api.test.ts` (twice: the revoked-workflow check and the owner check). The viewer assertion still holds because a viewer has no organization settings permission. New tests are in `me-config-menu-api.test.ts` (new file).
  7. **Wiring changes in existing tests and test-support (no assertion changed):** `entitlement-api.test.ts` and `test-support/module-contract/contract-world.ts` pass `...buildOrganizationConfigPorts()` to `buildOrgConfigService`; `organization-atomicity.test.ts` passes a `MongoConfigVersionBumper` to `CreateLocationUseCase`; `kernel/modules/manifest-schema.ts` accepts `visibility`. `browser-stack.ts` returns `mongoUri` and has `setTrialEndsInDays` (trial banner screenshot; no API changes a trial yet), which needed `mongodb` as an admin dev dependency (one line in `package-lock.json`).
  8. **`Sheet` and `SheetContent` exported from `@banijjik/ui`:** the lazy form sheets need them (`FilterSheet` is for filters).
  9. **`signOut(queryClient, returnTo?)`:** the accept page's "sign out and switch account" returns to the invitation after the next sign-in.
  10. **`serverPublicApiFetch`** (no cookie) added next to `serverApiFetch`, for the public invitation preview.
  11. **Single-location mode:** the select is hidden when the caller works at every location and sees exactly one; a caller limited to some locations keeps the select (they may see only part of the business). "All locations" is offered only to a caller who works everywhere.
  12. **Actions hidden for the owner and for oneself** (the API refuses both), besides permission, status and read-only.
  13. **Route-level `error.tsx` and `loading.tsx`:** `(app)/error.tsx` keeps the shell around a failed page; `settings/staff/loading.tsx` is the skeleton of the three staff screens.
