  2. Website-module and Site reads run **inside** `runInOrganizationContext`. Calling `isModuleEffective` before tenant context made `/resolve` return 503 (`missing_tenant_context`).
  3. `apps/storefront/package.json` test script is `vitest run src proxy.test.ts` so the freeze's root-level `proxy.test.ts` actually runs. `tsconfig.json` includes that file.
  4. `site.entity.test.ts` and `site-domain.use-cases.test.ts` pass `asId<SiteDomainId>(…)` into `setCanonical` after the getter became branded.
  5. Browser tests seed a Site with `publishedWebsiteVersionId` after `publishAboutPage` (upsert if a Site already exists). C1 host eligibility requires that pointer; About pages alone are not enough. Windows Node cannot resolve `*.sites.localhost`, so Node fetches use `127.0.0.1` plus `Host`. Chrome navigation uses `waitUntil: "load"` because C1's uncached `/resolve` never reaches `networkidle0`.

  7. `productionEnvironment` in `apps/api/src/test-support/spawned-process.ts` includes `STOREFRONT_RESERVED_HOSTNAMES` so `sync-indexes.test.ts` spawned production API processes pass config validation.
