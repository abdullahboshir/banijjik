## Fixed by the lead
**L1 · the limit could be passed by a manager of one location (billing).** `pos_devices` is an `ORGANIZATION_AND_LOCATION` model, so the location plugin limits every read, the count included, to the caller's locations. A manager assigned only at location A2 counted 0 devices while A1 already had one, so on SHOP (limit 1) they could add a second device, and their usage read showed 1 where the organization had 2. The usage test used the owner (every location), so it did not show this.
- Fix: a `PosDeviceCounter` port (`countActive(organizationId)`) used by both the limit and the usage read. `routes/pos-device-limit.ts` runs the count with `runInOrganizationContext(organizationId, …)`: the same organization with every location, refused for any other organization; the transaction session is kept, so the count stays inside the locked transaction. This is the pattern of `routes/organization-config-ports.ts` (location count for limits). No new system reason.
- The helpers moved out of `routes/pos-adapters.ts`, which now gains two lines only (it is at the 300-line limit).
- New test: "a manager of one location cannot pass the organization's limit with devices at another location" (422 `LIMIT_REACHED`, usage 1, one device stored). It fails on the old count (the second device got 201) and passes now.
