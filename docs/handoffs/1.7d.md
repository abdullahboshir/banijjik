- **Deviations from plan (and why):**
  1. **Profile "read-only form" is a read-only details list.** Without the permission the page shows the values and no Edit button; the form itself exists only in the lazy sheet. Loading the form for read-only viewers would have cost the budget for no gain.
  2. **Profile is a details page plus an Edit sheet**, not an always-open form page (`13 §4.3` says form pages): same reason, the budget.
  3. **Select all in a module selects the ordinary permissions only**, not the sensitive block, so a sensitive permission is never ticked by accident (`10 §7`).
  4. **Held permissions = the keys the caller holds at every location** (`permissions.allLocations`). A role has no location, so a key held at one location only is not offered.
  5. **Permissions of a module that is switched off are sent back unchanged** when a role is edited (`preservedKeys`), otherwise the edit would drop them silently.
  6. **Create, edit and archive of locations need the permission at every location** (`holdsPermissionEverywhere`), matching the API rule `requireAllLocations` of 1.7b. The default location still shows the archive action so the person reads the refusal.
  7. **Module group names** come from `roles.module.<moduleKey>` with the module key as the fallback, so a new module needs one catalog line, not code.
  8. **API files of the new screens live in the feature folders** (`profile-api.ts`, `location-api.ts`, `role-api.ts`), not in `src/lib/api/organization-api.ts`, because card 1.8b moves that folder. They take the request body types of `@banijjik/validation`.
