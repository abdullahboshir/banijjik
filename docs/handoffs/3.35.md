# Handoff 3.35 · Stable replay-then-follow test

## What was built
`apps/api/src/kernel/events/ordered-event-worker.test.ts`: in "runs a replayed event again with fresh attempts, and the stream continues behind it", once the replayed first event is handled the test promotes the follower's delayed job (when it is delayed), with a comment saying why (follower wake-up is bounded by the ADR-115 backoff cap, a replay does not wake it). The asserted scenario is unchanged (order `[1, 2]`, `REPLAYED`, `requeuedAt`). No production code changed.

## Deviations
None. Note: the promote happens only after the first event is handled, because promoting earlier would only re-delay the follower with a longer wait.

- `dead-letter-replayer.test.ts`: safe. It has no follower behind a dead letter; its waits are on a single job.
