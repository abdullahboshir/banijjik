- **Deviations from plan (and why):**
  - The kernel probe manifest moved from `MODULE_KEY.SETTINGS` to `MODULE_KEY.FILE` (`core/file`). The real settings module now owns `settings`. Expected module lists name the probe `file` and, after the rebase, also keep `custom-field`.
  - The location-override probe in the settings API test uses `MODULE_KEY.NOTIFICATION` (`notification.probeFlag`), because `file` is the kernel probe whenever a test builds its own router.
  - Industry defaults are read by mutating the stored RETAIL template in the test database. SALON cannot be selected at signup, and the seed JSON belongs to card 2.3.
  - Location existence uses the registered model name `Location` inside settings. The plan does not add an organization export.
  - Organization-level "ALL locations" is checked per item in the use case. `requireAllLocations` on the route would block a one-location manager from writing their own location.
  - `GET` reads the parsed query from `response.locals.validated`. Express 5 makes `request.query` read-only; `validate()` already documents this.
  - A batch that touches the same key at more than one scope resolves each scope and then sorts the keys. The response has one entry per key.
  - `apps/api/src/routes/core-tenant-routers.ts` builds the custom-field and settings routers. `routes/v1.ts` crossed the 300-line lint limit once both modules were mounted.
  - `packages/contracts/src/index.ts` combines some value and type exports from the same module so the public index stays within 300 lines. The names are unchanged.
  - `custom-field` `module.manifest.ts` and its contact probe say `settings: []`. They still said `settingKeys` after 2.3 merged, and the renamed manifest field would not typecheck.
- **Decisions made** (add an ADR if architectural): ADR-103. Mechanical choices, also listed so a review can reject them: duplicate `(settingKey, locationId)` in one batch is `400 validation.custom`; an empty batch is `400`; a blank `keys` query means every effective key; a missing version on an existing row is `409` with `currentVersion`; a version on a missing row is `404`; deleting a row that is already absent still writes the one audit entry, event and bump; `dependsOn` is `[organization]`; only the website contract probe declares a setting (`website.probeEnabled`); structured audit values are `JSON.stringify`'d and a location field key is `settingKey@locationId`. Rebase conflicts kept both sides. Permission catalogue length is 22 (16 existing + 4 custom-field + 2 settings).
