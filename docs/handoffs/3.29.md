# Handoff: card 3.29 booking and sales leftovers

Branch `s/3.29-booking-sales-leftovers`. Plan: `docs/plans/3.29.md`. CI: https://github.com/abdullahboshir/banijjik/actions/runs/40062541463

## Built
- Booking and sales time zone readers throw `DomainRuleError(NOT_FOUND)` when the organization row or its `timezone` is missing. The `"Asia/Dhaka"` fallback is gone (only the organization entity default and README keep the literal).
- `listUnsettledCancellations({ afterEventSessionId, limit })` sorts by `eventSessionId` with an `$gt` cursor. The session-cancel job walks pages until a short page, so failing sessions cannot starve later ones. `sessionPageSize` is an optional dependency (test hook, default 10).
- `runJobRow` logs a failed row at `error`; a raced row (409 or invalid transition) is still skipped silently.

## Decision 3
The session-cancel note stays in the audit entry only: a booking has no cancellation-reason field, so the A3 follow-up is closed without code.

## Deviations
None.

## Tests
- booking time zone reader fails when the organization has no time zone
- sales time zone reader fails when the organization has no time zone
- lists unsettled cancellations in eventSessionId order after the cursor
- the session-cancel job settles a later session even when ten earlier sessions keep failing
- a failing sales job row is logged at error
- skips a row a version conflict moved on without logging
- plus a read-happy-path test for each time zone reader

## Known gaps
- The cancel job's per-run work is unbounded in the number of failing sessions (one pass over all unsettled sessions); fine for current volumes.
- Locally the full booking and sales suites pass only with one worker (low RAM crashes parallel workers).
