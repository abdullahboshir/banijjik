# Review R1 · card 3.24 order and stock posting (T1)

Reviewer: lead (Opus 5.5) · Date: 2026-10-24 · Branch head: `a1e53101` · CI 40083458983 green · `card:check`: every line PASS except "rebased" (main moved by docs commits only: accepted).

**Result: changes requested.** The posting rules and the R3 completion write are right, and the entries balance by construction. Nine items must be fixed before merge: two plan tests do not test what their names say, and several money-path rules of `AGENTS.md` and guide §11 are broken.

## Must fix
1. **R3 test does not race anything.** `a payment racing completion is posted after revenue, and the settle covers every advance` (`accounting/post-orders.test.ts`) feeds a fake order source with a preset `advancesToSettle`. It proves only that a settle entry is written. Replace it with a test that uses the real `CompleteOrderUseCase` and the real payment use case on one order: show that a payment whose transaction read the order as CONFIRMED and commits after the completion either conflicts and retries as `AFTER_REVENUE`, or that its advance is in the settle. Two Mongo sessions with a hook between the payment's read and its commit is enough (Refresh 1 R3). Also assert that `CompleteOrderUseCase` wrote the payment summary (`updatedAt` moved) in its transaction.
2. **R6 test is a tautology.** `Business date uses the order stored businessDate (Dhaka 02:00 completion)` writes `businessDate: "2026-10-24"` into the fake and reads it back. Drive the real path with a fixed clock (`vi.useFakeTimers()` + `vi.setSystemTime(new Date("2026-10-23T20:00:00Z"))`, 02:00 Dhaka): place and complete an order (or an instant sale), run the handler, and assert the journal's `businessDate` is `2026-10-24`. Do the same for one stock receipt (§11 items 13–14).
3. **Fractional quantities (ADR-047).** Quantities are integers in the unit's precision. `quantityToBigIntFraction` parses a float through `toString()` (breaks on `1e-7`, and it is a float path in money math). Revert `lineValueMinor` to integer quantities only, throw `DomainRuleError(INTERNAL)` for a non-integer quantity, delete the helper, and replace the decimal test with an integer-precision one (for example 1,500 g at 5,000 micros/g).
4. **Silent money fallbacks.** In `accounting/domain/stock-posting-rules.ts`: `movements[0]?.paidVia ?? "CASH"` and `METHOD_ACCOUNT_CODE[...] ?? SYSTEM_ACCOUNT_CODE.CASH` post an unknown funding source to Cash. In `inventory/index.ts` (`buildStockPostingSourceAdapter`): `?? "BDT"` plus `as CurrencyCode`. A receipt without `paidVia`, an unmapped method or a missing currency must throw (`postingSourceMissing` / `INTERNAL`) so the outbox keeps the event and the error is visible, never post to a guessed account (§11 item 3, item 20). Use the organization currency reader as a required dependency; no `"BDT"` literal.
5. **String literals instead of contract constants** (§11 item 21): `"SALE"` (`sales/index.ts`), `"ON_CREDIT"`, `"PURCHASE"`, `"OPENING"`, `"ADJUSTMENT"`, `"DAMAGE_WRITE_OFF"`, `"DAMAGED"`, `"STOCK_RECEIPT"`, `"STOCK_OPENING"` (`stock-posting-rules.ts`, `post-stock.handler.ts`), `row.line.reason === "DAMAGE_WRITE_OFF"` (`adjust-stock.use-case.ts`). Use `STOCK_MOVEMENT_REASON`, `STOCK_RECEIPT_PAID_VIA`, `STOCK_STATE` and a contracts constant for the stock source types (move `SOURCE_RECEIPT/OPENING/ADJUSTMENT` values into `@banijjik/contracts/inventory`, add-only).
6. **Dead code.** `RecordOpeningStockUseCase` is exported from `inventory/index.ts` but no route, job or test uses it, and the plan does not ask for an opening-stock endpoint. Delete it. Keep the `stock_opening` posting rule with its rule-level test. (If you believe an endpoint is needed, stop and ask; do not add one.)
7. **`ensureSystemAccount` is not generic.** It hard-codes the payable name and `LIABILITY` for any code, in a file called `ensure-payable-account.ts`. Take the name and type for the given code from `system-account-seeds.ts` (one source of truth), and rename the file to match the function. If the duplicate-insert re-read returns nothing, throw instead of returning an unsaved entity.
8. **Optional dependency** (§11 item 20): `OrderPostingSourcePorts.orders?: OrderRepository` defaults to `new MongoOrderRepository()`. Make it required and pass it from `routes/accounting-event-handlers.ts`.
9. **Cast in the controller** (§11 item 19): `paidVia: body.paidVia as StockReceiptPaidVia`. Type the validation schema with the contracts enum so the parsed body already has the type.
