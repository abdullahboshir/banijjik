- **Deviations from plan (and why):**
  1. **Bottom nav is shown below 1024 px, not below 768 px.** The plan says "sidebar visible >= 1024 px, bottom nav < 768 px", which leaves tablets (768 to 1023 px) with no navigation at all. `13 §3` shows only phone and desktop layouts and says the sidebar appears at `lg`. I chose `lg:hidden` for the bottom nav. Please confirm.
  2. **Generator runs after `tsc`, not before.** `build` is `tsc && node scripts/build-tokens.mjs`. The generator is TypeScript (`src/tokens/render-css.ts`, so the drift test and the script share one function), and the script imports it from `dist`. Running it before `tsc` would need a TS loader. The committed `tokens.css` is unaffected; a test fails if it drifts.
  3. **CSS variable names.** Colours are `--color-<group>-<name>` as in the plan. All other scales use `--token-<scale>-<name>` (for example `--token-radius-md`), because the Tailwind theme names (`--radius-md`) would otherwise point at themselves inside `@theme inline`. Hex values in `tokens.css` are lowercase, because Prettier lowercases them and the file must pass `format:check`.
  4. **Extra props for accessibility** (text is props-only, so accessible names must be props): `navLabel` on `Sidebar` and `BottomNav`, `closeLabel` on `QuickCreateSheet`, `FilterBar`, `FilterSheet` and `ConfirmDialog`, `label` on `Toaster`. `BottomNavSlot.isActive?` is an optional extra for the current-page state. `ConfirmDialog.amount` is the `MoneyText` props (money + locale + digit script + grouping) so the dialog can format it.
  5. **`src/lib/icons.tsx`** instead of `icons.ts` (it renders JSX). `iconKey` values are lucide icon names (`docs/12`); unknown keys fall back to a circle. Only the icons the shell and menu groups need are registered.
  6. **Theme utility names.** `border-default` needs `--color-default`, so `bg-default`/`text-default` also exist and must not be used. `text-primary` is the text colour, not the brand colour (`bg-brand` / `text-brand` are the brand).
  7. **Error codes:** the plan and plan 0.4a say "22 codes", but `docs/14-API.md §3` lists 20 distinct codes (and the 0.4a branch's `ERROR_CODE` has 20). The catalogs have `errors.<code lowercased>` for all 20, plus `invalid_json`, `payload_too_large`, `not_ready`, `dedicated_not_supported` (`errors.internal` is the INTERNAL code itself). If a 21st/22nd code is added, add its key to both catalogs; the test list in `create-translator.test.ts` must be extended.
  8. **Extra catalog keys** `state.empty.contact|order|offering` (use `{term:…}` so term overrides are visible in real text). `common.*`, `nav.*`, `shell.*`, `state.*`, `validation.*`, `term.*` are as planned.
  9. **Test tooling:** `@testing-library/jest-dom` is not used (plain DOM assertions), to avoid global type augmentation. Test setup is `vitest.setup.mjs` (JS, so it sits outside the typed project) with stubs for `matchMedia` and pointer capture (sonner needs them in jsdom).
  10. **`"use client"`** is on `dialog`, `sheet`, `quick-create-sheet`, `filter-bar`, `bottom-nav`, `data-list`, `confirm-dialog`, `toast` (state, event handlers or Radix). `AppShell`, `TopBar`, `Sidebar`, `PageHeader`, `Form` primitives, `Skeleton`, `EmptyState`, `StatusBadge`, `MoneyText` are server-compatible.
- **Decisions made** (no ADR needed, all local to ui):
  - `cn()` uses `extendTailwindMerge` with the custom font-size utilities. Without it tailwind-merge treats `text-body` as a colour and drops it next to `text-primary` (this was a real bug caught by the input test).
  - `formatMoney` supports only BDT for now and throws `RangeError` for other currencies and for non-integer amounts. Negative amounts render as `-৳ 1,250`. `locale` is part of the option contract but does not change output yet (Latin digits in both locales).
  - `StatusBadge` draws the tone as text + border on the surface colour, because `status.neutral` on `bg.subtle` is below 4.5:1 in light mode.
  - `DataList` falls back to the first column on cards when no column is marked primary.
