# 3.7 Part B: enrollment screens

Branch `s/3.7-ui-enrollment` (tier T2, merge check). No API change. CI: https://github.com/abdullahboshir/banijjik/actions/runs/40090027090

## Built

- **Routes** (`apps/admin/app/[orgSlug]/(app)`): `enrollments`, `enrollments/[enrollmentId]`, `check-ins`. The earlier `enrollments/new` page is removed: the new-enrollment form is a sheet on the list (decision 9).
- **List** (`src/enrollment/enrollments-page.tsx`, `enrollment-filter-form.tsx`, `enrollment-card.tsx`, `enrollment-query.ts`): filters status, plan (word from the term `offering.PLAN`), overdue only; page links; card layout on all widths; contact and plan names resolved on the server.
- **New-enrollment sheet** (lazy, `new-enrollment-button.tsx`, `new-enrollment-sheet*.tsx`, `use-new-enrollment-sheet.ts`, `new-enrollment-form.ts`): contact-link input (search or add), plan then variant, start date (a select of the plan's dates for FIXED_DATES plans), location select when there are several, optional bed or resource of the chosen location. The idempotency key is reused on a retry of the same body (`keyForSubmit`).
- **Detail** (`enrollment-detail-*.tsx`, `enrollment-periods-section.tsx`, `use-enrollment-actions.ts`): facts, status badge, actions by status and permission (`enrollment-action-items.ts`), periods with fee, status and sessions used, one lazy receive-payment sheet per payable period (`requestType: ENROLLMENT`, `requestId: enrollmentPeriodId`, payer = `billToContactId`, remaining due from `GET /dues`), "updating" note and reload button after a payment, history.
- **Activate** shows the API's message; `PAYMENT_REQUIRED` adds a hint to the unpaid period's button. A 409 shows a reload notice.
- **Cancel**: lazy confirm dialog (`cancel-dialog*.tsx`), then the refundable amount from the response as information and "the refund is handled by staff later". No refund button.
- **Check-ins** (`check-ins-page.tsx`, `check-in-panel.tsx`, `use-check-in.ts`): find a person by name or phone, one tap (with `Idempotency-Key`), today's list for the first active location in the organization's timezone.
- **i18n**: about 85 add-only keys `enrollment.*` in `packages/i18n/src/catalogs/screens/{en,bn}.json`. Terms `enrollment`, `offering.PLAN` and `resource` come from the business's terms; no "member" or "student" literal.
- **Test support**: `seedMonthlyPlan`, `seedMember` in `test-support/browser-seed.ts`, `gym-industry-fixture.json`.

## Deviations

- No separate payer field in the sheet: the API already defaults `billToContactId` (guardian link); the detail shows the payer when it differs.
- An inline new contact (contact-link "add a new person") is created through `POST /contacts` first, so a template with a required contact field (GYM: emergency phone) refuses it with a validation message. The person must add that contact on the contacts screen first. The browser test seeds the member through the API. Gap for a follow-up (the sheet cannot ask for template fields).
- The check-in page uses the first active location (no `?location=` filter yet).

Browser (`src/enrollment/enrollment-screens.browser.test.ts`, 7 tests): GYM flow (enroll a member through the sheet, Activate refused with the payment-required message, receive period 1 in full, "updating" note, Activate shows ACTIVE without the worker, check in twice, the detail shows two sessions); per route (list, detail, check-ins) initial JavaScript under 180 KiB (measured 165.9, 171.2, 169.1) and no sideways scroll with 44 px touch targets at phone width. Catalog GYM scenario in `src/catalog/catalog-screens.browser.test.ts` ("the GYM catalog": add a one-month plan through the editor, publish it, and the enrollment sheet offers it).
