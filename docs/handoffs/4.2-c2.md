- **Deviations from plan (and why):**
  1. `app/robots.ts` and `app/sitemap.ts` export `dynamic = "force-dynamic"`. In Next.js App Router, metadata routes default to static build-time generation unless opted out; without `force-dynamic`, Next.js renders them once during build without request headers.
  2. `fetchStorefront` helper in `src/storefront.browser.test.ts` uses `node:http` request dispatcher rather than global `fetch`. Node.js global fetch (undici) automatically strips or overrides custom `Host` headers with the destination IP (`127.0.0.1`), which prevented loopback requests from reaching the storefront proxy with the virtual host under Windows.
  3. `apps/storefront/src/site/site-metadata.ts` passes `metadataBase` on `buildLayoutMetadata`; `src/storefront.browser.test.ts` normalizes the trailing slash on root canonical URL comparison because Next.js 16 metadata URL resolution strips the trailing slash when `metadataBase` matches `origin`.
