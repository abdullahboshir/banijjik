**The open question is a real defect, and it is answered here.** Turbo 2.11 runs tasks in strict env mode by default. A variable that `turbo.json` does not declare never reaches the test process. `apps/api/src/test-support/vitest.config.ts` reads three things that strict mode can drop:
- `TEST_REDIS_URL`
- `CI` (it decides between "skip with a warning" and "fail loudly")
- the `MONGOMS_*` variables of mongodb-memory-server (the system binary locally, the binary version check)

If CI drops `CI` and `TEST_REDIS_URL`, the Redis suites would be **skipped silently** on GitHub: the very thing `describeWithRedis` exists to prevent. The local concurrency-2 run shows it: 20 skipped instead of 1.

**Decision (planner):** declare them in `turbo.json`. Do not switch CI to `--env-mode=loose`: strict mode with an explicit list is the safer default, because nothing undeclared leaks into a task.

```json
"test": {
  "dependsOn": ["^build"],
  "passThroughEnv": ["CI", "TEST_REDIS_URL", "MONGOMS_*", "VITEST_MAX_WORKERS"]
}
```

`passThroughEnv` hands the values to the task without putting them into the cache hash. These are test-infrastructure settings, not inputs that change what a test asserts. Do the same for `@banijjik/lint-tests#test` only if it reads any of them; it does not today, so leave it.
