# Handoff: 3.11 Part B — commission screens

Date: 2026-10-24. Tier: T2. Branch: `s/3.11-ui-commission`.
Plan: `docs/plans/3.11.md`, "Refresh B".

## Built

- `apps/admin/src/commission/**` and `apps/admin/app/[orgSlug]/(app)/commission/**`: entries, my commission (`mine`), payouts, payout detail and rules pages. Each checks the `COMMISSION` module and its `commission.*` permission, then reads the existing commission API. Lists are paged and show mobile cards.
- Rule sheet (lazy): subject, target and amount field groups in their own files; the percent is typed as a percent and sent as integer basis points (`commission-percent.ts`). Edit locks who and what; archive uses the record version.
- Pay sheet (lazy): preview first, then pay the previewed total with `expectedTotal` and an `Idempotency-Key`. A 409 "total changed" shows the new total and needs a second confirmation. Splitting is in `use-commission-pay-form.ts` (totals and submit hooks) and `commission-pay-form.ts` (pure helpers).
- `apps/admin/src/commission/commission-client-text.tsx` and the commission `layout.tsx`: client components read their text from a nested `I18nProvider` that carries the `commission.*` and `catalog.kind.*` screen keys for these routes only, so the screen catalogs stay out of every other page's first load.
- Menu: `apps/api/src/modules/commerce/commission/module.manifest.ts` gets three admin menu entries (`commission.entries`, `commission.payouts` under money, `commission.rules` under settings); the account menu gets "My commission" (`apps/admin/src/shell/commission-menu-link.tsx`, lazy wrapper, shell wiring).
- i18n: add-only keys in `packages/i18n/src/catalogs/{bn,en}.json` and `screens/{bn,en}.json`.
- No contract, validation or dependency changes.
