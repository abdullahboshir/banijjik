## Result
Accepted. Two small items fixed by the lead on the branch (owner rule: at most three small items, no new round). The rebase on main (3.31) is also the lead's.

## Checked
- **Decision 4 (value per line):** cumulative share per line (`cumulativeShareMinor`), tax split the same way, delivery returned once, rounding only with the return that empties the order. The order discount is spread into the line totals by the quote, so the line values, delivery and rounding add up to the grand total.
- **Decision 5 (money):** `settleReturn`: the new total never drops below 0, the due drops first, the refund is `max(0, N − T')`, so it never exceeds the net paid. The total write and the refund run in the return's transaction (payment's `RefundPaymentUseCase` through its index, with the internal approval snapshot of Amendment 1; `POST /refunds` refuses a snapshot in the body: test `refuses an approval snapshot in the body of POST /refunds`).
- **Decision 6 (approvals):** REFUND token with subject `order:<id>` and amount R unless exempt; RETURN_NOT_RECEIVED always; both consumed inside the transaction.
- **Decision 7 (stock and cost):** restocked and damaged goods go back with `costFrom` = the order's SALE movement of the same item; a missing or ambiguous sale cost refuses the return instead of using the average. NOT_RECEIVED moves nothing. The order projection is one versioned update, so a race for the last unit leaves one winner (test `two returns racing for the last unit: one wins, the other is refused (409 or 422) and writes nothing`).
- **Decision 9 (books):** `sales_return_value` and `sales_return_cogs`, idempotent per (SALES_RETURN, salesReturnId, postingKey), ORDERED on the `order:` stream; the snapshot refuses a currency mismatch.
- **Decision 10 (commission):** return-based reconcile under the `(ORDER_LINE, orderId)` race marker; order refunds no longer touch order-line ledgers; only the three tests the plan names were rewritten.
- Every test name in the plan's A1 list exists in the test files. Local run of `order-return-api.test.ts`, `commission-accrual.test.ts` and `order-payment-api.test.ts` after the fixes: 60 passed.

## Fixed by the lead
1. **Currency was assumed (§11 item 3).** `readSettlementBase` returned bare minor amounts and the return settled in the order's currency without comparing it with the payment summary. The port now takes the order currency and the adapter refuses (INTERNAL) a summary in another currency.
2. **Dead branch** in `commission/application/reconcile-sources.ts`: `if (ORDER) return NOTHING_DONE; return NOTHING_DONE;` became one return with the comment kept.
3. Rebase on main (3.31): kept both sides in the posting keys, the accounting handler registration and index, ADR-142 next to ADR-145, and the journal source labels; split `registerAccountingEventHandlers` into required and optional streams to stay under 60 lines.
