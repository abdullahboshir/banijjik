## 2. Invariant & Architecture Checklist

- [x] **Storefront Tracking Authorization:** All request queries (`/checkouts/:checkoutId`, `/me/requests`, `/me/requests/:requestType/:requestId`) verify ownership via `CheckoutAccess` for calling principal (`CUSTOMER` or `GUEST`).
- [x] **Cache Control:** All private tracking and checkout responses include `Cache-Control: private, no-store` header.
- [x] **Dual Authentication on Claim:** `POST /checkouts/:checkoutId/claim` requires both the active `sf_guest` cookie (matching the current access owner) and the authenticated customer account (`sf_access` cookie or auth header).
- [x] **Verified Phone Matching:** Customer account's verified phone must match the checkout contact snapshot phone; mismatch returns `403 FORBIDDEN` (`CHECKOUT_CLAIM_PHONE_MISMATCH`).
- [x] **Immutable Creation Principal:** `creationPrincipalKey` on the `Checkout` aggregate remains permanently unchanged; customer claim mutates only `CheckoutAccess.owner`, revoking guest replay authorization and tracking access.
- [x] **No Contact Merging / Order Rewriting:** Historical orders, provisional contacts, and financial records are never modified or merged on claim.
- [x] **Enrollment Dues Projection:** Enrollment dues are projected using `currentEnrollmentPeriodId` as the payment request ID per ADR-139.
- [x] **Code Quality:**
  - Zero TODOs, stubs, or mock data presented as finished code.
  - All production files strictly <= 300 counted lines (`storefront.ts` = 289 lines, `read-own-requests.ts` = 254 lines, `checkout.router.ts` = 245 lines, `storefront-checkout-adapters.ts` = 245 lines).
  - Nesting depth <= 3, cyclomatic complexity <= 10.
  - Zero `any`, clean TypeScript and ESLint across all workspaces.
