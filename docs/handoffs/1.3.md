## Adaptations to the real kernel and module names (mechanical)
1. **Plugins are built-in.** `buildSchemaForCompile` calls `applyTenancyPlugins` itself, keyed on `tenancy`; `addGlobalSchemaPlugin` also gained the `tenancy` filter (`{ database?, tenancy? }`) and its plugins now receive `(schema, definition)`. The existing `database` filter works as before (`models.test.ts` relies on it).
2. **Policy structure.** The two plugins share one hook installer (`policy-hooks.ts`) over an `OperationPolicy` (filter, document, update, replacement, aggregate condition), so they cannot differ in which operations they cover. `bulkWrite` rules live in `bulk-write-rules.ts`.
3. **Stamping happens in `pre('validate')` as well as `pre('save')`.** Mongoose checks `required` before `pre('save')`, so a missing `organizationId` would have failed validation first.
4. **Mongoose types for the plugins** come from `kernel/db/mongoose-types.ts` (re-exported by `kernel/db/index.ts`), because lint R28 allows driver imports only in infrastructure and `kernel/db`, `kernel/sequence`, `kernel/rate-limit`. No lint allow-list was widened.
5. **Plugin markers** are `tenantPluginApplied` and `locationPluginApplied` (the plan's `banijjikTenantPlugin` trips the brand-name lint). `hasTenantPlugin(schema)` / `hasLocationPlugin(schema)` read them.
6. **`organizationId` is now `immutable: true`** in the schemas of `locations`, `members`, `roles` and `sequences` (needed by the registration check; no behaviour change).
7. **`ListMyOrganizationsUseCase`** now implements an exported `MyOrganizationsReader` interface (class name kept so its tests are untouched). The controller depends on the interface. `buildOrganizationRouters` takes `contextRunner` and `myOrganizationsReader`; `index.ts` also exports `buildMyOrganizationsReader()`, `buildMembershipDirectory()`.
8. **`createTwoOrganizations(app, connections, organizationFields)`** takes the extra create-body fields from the test file, because lint R16 bans the industry key identifier in `test-support`. It uses `ApiActor` objects (cookies kept inside) as the "authenticated agents".
9. `runInOrganizationContext` also throws `cross_organization_access` if the request already belongs to another organization (re-scoping is never legitimate). Not in the plan; tested.
10. Pipeline updates, and `aggregate` stages `$out`, `$merge`, `$geoNear`, `$collStats`, `$indexStats`, `$documents`, `$changeStream`, `$search`, `$searchMeta`, `$vectorSearch` (besides the three joins of the plan) also throw, because a `$match` in front cannot protect them.
