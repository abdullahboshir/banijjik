- **Done:**
  - **The period is the request** (decision 1): `requestType ENROLLMENT`, `requestId enrollmentPeriodId`, one summary per period with `total` = the period fee. The allocation's `enrollmentPeriodId` field is not used (recorded in ADR-139 and `docs/11 §7`).
  - **ENROLLMENT reader** (decision 2): `routes/enrollment-request-reader.ts`, registered with the one add-only line in `buildPaymentRequestReaders()`; built from `buildEnrollmentPeriodSnapshotReader()` exported by `enrollment/index.ts` (no Mongo class in the index). Refuses a missing, foreign, WAIVED or cancelled-enrollment period; EXPIRED and COMPLETED unpaid periods stay payable; `contactId` = bill-to contact, `locationId` = the period's; `revenueState` always `BEFORE_REVENUE` until card 3.31 (README and ADR say so).
  - **`EnrollmentPaymentPort`** (decision 3): `initializeSummary` / `readNetPaid` / `capTotalAtNetPaid` / `listPeriodIdsOfPayment` in `application/ports.ts`, required in `EnrollmentDependencies`; adapter `routes/enrollment-payment-adapter.ts` joins the caller's session like `order-payment-adapter.ts`.
  - **Summary lifecycle** (decision 4): create initializes period 1 and both renewal paths initialize the new period inside their transactions; cancel caps every non-WAIVED period's summary at its net paid (`capTotalAtNetPaid` never raises). No backfill: the first payment lazily recreates a missing summary with the reader's total (ADR-137 Amendment 1 pattern; `payment.applyAllocation` already does it).
  - **Derived period status** (decision 5): `application/sync-period-payment.ts` `syncPeriodPaymentStatus` → `PAID | PARTIAL | OPEN` from net paid vs fee, never touches `WAIVED`, saves only on change with the period `version`, and refuses (422 `enrollment.errors.currency_mismatch`, key added to contracts) when the summary currency differs from the fee.
  - **Callers** (decision 6): the UNORDERED, idempotent handler `enrollment.syncPayments` (`application/handlers/sync-enrollment-payments.handler.ts`) on received/refunded/reversed, registered in `routes/enrollment-worker-jobs.ts` next to the jobs; manual `activate` and the renew and mark-overdue jobs sync the period they check inside their own transaction before reading its status.
  - **Payment-driven transitions** (decision 7): PENDING activates when the current period is `PAID|WAIVED` and `today >= startsOn`; a paid future-start enrollment waits for `startsOn` in the renew job (`activateDuePending` in `enrollment-jobs.ts`); OVERDUE returns to ACTIVE — `assertTransition` now allows `activate` from OVERDUE and `activateEnrollment` from OVERDUE requires the current period paid regardless of `requirePaymentToActivate`. A refund never de-activates.
  - **Records** (decision 8): ADR-139 (Accepted (proposed)), `docs/11 §7`/`§8.2` notes, enrollment and payment READMEs, STATUS row 3.27.

## Deviations from the plan
- `enrollment-review.test.ts` gained a fake `EnrollmentPaymentPort` and `findPeriod` because the plan makes `payments` required (§11 item 20). The fake's `readNetPaid` mirrors the stored period status, so every sync stays a no-op and the suite's behaviour is unchanged.
- The handler loop carries no dedup set: recomputed status plus the transition table make a second activation impossible (activate from ACTIVE is refused), so the per-payment period ids can repeat harmlessly.
- `handlerKey` is the module literal `"enrollment.syncPayments"` — contracts enum event names only, and every existing handler key (commission included) is a literal.
- `buildEnrollmentWorkerRuntime` was exported from `routes/enrollment-worker-jobs.ts` (a file this card owns) so the presentation test builds the real handler without starting the worker.

## Known gaps (also in the STATUS note)
- Enrollment period revenue and settlement of the held `CUSTOMER_ADVANCES` are card 3.31; until then every enrollment payment is `BEFORE_REVENUE`.
- Executing refunds on cancellation (`UNUSED_PERIODS`/`PRORATED`) is card 3.32 — this card only caps summaries at net paid.
- Waiving a period has no endpoint yet; the reader already refuses payment for a WAIVED period.
- Enrollment screens (3.7 Part B), auto-pay and payment-link reminders stay out of scope.
