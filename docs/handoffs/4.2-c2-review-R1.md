### Security and tenancy (Items 15–18, P4-11, P4-12)
- **Verdict: Pass.**
  - **Host Spoofing / Header Injection:** In `apps/storefront/src/host/organization-header.ts`, `requestHeadersFor` deletes all client-supplied copies of `x-storefront-organization-id`, `x-forwarded-host`, `x-storefront-canonical-host`, `x-storefront-website-version-id`, and `x-storefront-domain-generation`. On unknown hosts, all controlled headers remain stripped.
  - **Authoritative Host Gate (P4-11):** `readPublic` in `storefront-api.ts` checks `currentSiteResolution()` before consulting `publicProjectionCache`. If host resolution is absent or inactive (e.g. deactivated organization or revoked `WEBSITE` module), `readPublic` completely bypasses the cache and fetches upstream with `cache: "no-store"`, preventing inactive or suspended sites from being served from memory cache.
  - **Private / Credential Isolation:**
    - Upstream proxy (`forward-headers.ts`) forces `Cache-Control: private, no-store` if the response carries `Set-Cookie` or omits `Cache-Control`.
    - API gateway (`routes/storefront.ts`) mounts `storefrontCacheGuard()`, setting `Cache-Control: private, no-store` by default and intercepting `setHeader` to enforce `private, no-store` whenever inbound requests carry `Cookie` or `Authorization`, or when outbound responses set `Set-Cookie`.
    - `readPublic` validates `response.status === 200`, `isPublicCacheable(cache-control)`, and `getSetCookie().length === 0` before caching. Responses with `Set-Cookie`, `private, no-store`, or 404/5xx errors are never cached.
  - **Host / Canonical URL Poisoning:**
    - `site-metadata.ts` constructs canonical URLs, robots sitemap references, and sitemap entries strictly using `resolution.canonicalHostname` from the server-side API resolution. It never reads `Host`, `X-Forwarded-Host`, `X-Forwarded-Proto`, or client query parameters for canonical URLs.
    - Disallowed paths in robots explicitly cover `["/api/", "/sign-in", "/my/", "/preview", "/cart", "/checkout"]`.
    - Directory listing detail pages remain protected with `robots: { index: false, follow: false }` and are excluded from the sitemap.
