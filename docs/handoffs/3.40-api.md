# Card 3.40 Part A — walk-in services as order lines (API)

Date: 2026-10-26. Branch: `s/3.40-api-walk-in-services`. Status: implementation complete, awaiting review. CI: pending.

## Built

- Added a required `SalesKindReader`, composed from the resolved organization config, and constrained effective kinds on the instant sale path. SERVICE is accepted for instant sales/POS/exchange; draft, placed and update flows remain product-only. PLAN, RENTAL and EVENT remain refused.
- Service lines use no stock components or cost snapshots and create no inventory movement, booking, slot, resource usage or time-off record.
- POS catalog snapshots include active PRODUCT and SERVICE offerings. Instant POS service lines preserve an optional assigned performer.
- Added service goods to the order posting snapshot and split the balanced `order_revenue` journal between `REVENUE_SERVICE` and `REVENUE_PRODUCT`. Return/refund and commission paths continue to reconcile service units without stock/COGS reversal.
- Added implementation notes to the sales README, `docs/11-OFFERINGS-AND-REQUESTS.md` §5.3, and ADR-044.

## Amendment and deviations

Amendment A-1 from the lead is applied: a fractional or otherwise invalid SERVICE quantity returns the existing `validation.invalid_type` at `lines.<i>.quantity`. No validation message key, shared validator, contract or catalog changed. No other plan deviation identified.
