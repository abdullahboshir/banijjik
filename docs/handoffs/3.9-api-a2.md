# 3.9 A2 handoff (POS extras: held carts, price override, due collections, cash returns, session reads, API, T2 with T1 money review)

Branch `s/3.9-api-pos-extras`. Plan `docs/plans/3.9.md` ("Plan detail for A2 and B" `A2-1` to `A2-5` and "Amendment 1" `A2-6` to `A2-7`).

## What was built

- **A2-1 Held carts (`pos_held_carts`):**
  - `POST /orgs/:organizationId/pos/held-carts`, `GET /orgs/:organizationId/pos/held-carts` and `DELETE /orgs/:organizationId/pos/held-carts/:posHeldCartId` (`pos.sale.create` + paired device).
  - Stores lines (`offeringId`, `variantId`, `quantity`, `modifierOptionIds`, optional `manualDiscount`, optional `performedByMemberId`), optional `contactId`, optional `orderDiscount` and optional `note` — never unit prices or totals (resumed carts re-quote through the pricing engine).
  - Enforces a 20-cart cap per device (`POS_HELD_CART_LIMIT`, 422) and a 24-hour expiry (`expiresAt: { $gt: now }` on reads plus a Mongo TTL index `{ expiresAt: 1 }` with `expireAfterSeconds: 0`).
- **A2-2 Price override:**
  - `unitPriceOverride?: Money` on `QuoteLineInput` and POS sale lines; `QuoteLineResult` and `OrderLineSnapshot` carry `listUnitPrice: Money` and `unitPriceOverride: Money | null`.
  - Promotion, manual line discount, order discount and tax are computed on the overridden unit price.
  - Requires `PERMISSION_KEY.POS_PRICE_OVERRIDE` (`pos.price.override`) at the device's location (`OWNER`, `MANAGER` hold it via `pos: "ALL"`).
  - When any line's `unitPriceOverride.amount < listUnitPrice.amount`, `POST /pos/sales` requires a `PRICE_OVERRIDE` manager approval token bound to the total reduction across overridden lines (`sum((listUnitPrice - unitPriceOverride) * quantity)`), or `approvalTokens: { discount?, priceOverride? }` when both a manual discount and a price reduction apply on the same sale. An override above list price needs the permission only.
- **A2-3 Collect due at the till:**
  - `POST /orgs/:organizationId/pos/collections` (`pos.sale.create` + paired device + `Idempotency-Key`).
  - Verifies every allocation's target (`ORDER`, `BOOKING`, `ENROLLMENT`) belongs to the organization and the device's location (403 `LOCATION_FORBIDDEN` across branches, 404 across organizations), requires `sum(payments) === sum(allocations)` (`POS_COLLECTION_MISMATCH`, 422), computes cash change from `cashTendered`, slices allocations across the tender rows and records `IN` payments through `ReceivePaymentUseCase` with the open `posSessionId` inside one transaction.
- **A2-4 Cash returns at the till:**
  - `POST /orgs/:organizationId/pos/returns` (`sales.return.create` + paired device + `Idempotency-Key`).
  - Checks `pos.requireShift` on the device, delegates to the sales return use case (`CreateSalesReturnUseCase`) inside the unit of work and tags the `REFUND` payment with the open `posSessionId` so cash refunds lower the register's `expectedCash`.
  - `POST /orgs/:organizationId/refunds` (`refundPaymentSchema` is `z.strictObject`) continues to reject `posSessionId` in its request body (400).
- **A2-5 Z-report `collections` and `returns`:**
  - `PosZReport` now carries `collections: readonly PosMethodTotal[]` (`IN` payments on the session whose allocations are not orders sold in that session, excluding `STORE_CREDIT`) and `returns: { count, value, refunds }` (`REFUND` payments on the session).
- **A2-6 `orders.posSessionId` and `OrderTotalsReader`:**
  - `posSessionId: string | null` stored on `Order` (`orders` collection) with partial index `{ organizationId: 1, posSessionId: 1 }` (`partialFilterExpression: { posSessionId: { $type: "string" } }`).
  - `OrderTotalsReader.readByPosSession(posSessionId)` reads `{ orderId, totals }` of the session's sold orders so `ClosePosSessionUseCase` computes `salesCount`, `gross`, `discount`, `tax`, `grandTotal` and `duesCreated` from the orders sold on that register.
- **A2-7 Session reads for Part B:**
  - `GET /orgs/:organizationId/pos/sessions/current` (`pos.sale.create` + paired device): returns the open `PosSessionResponse` of the paired device or `null`.
  - `GET /orgs/:organizationId/pos/sessions` (`pos.report.read`, no device cookie required): cursor-paginated session list (`locationId?`, `status?`, `cursor?`, `limit?`), restricted to the caller's allowed locations (403 `LOCATION_FORBIDDEN` when filtering by an unassigned branch).

## Deviations

1. **Permission key format (`pos.price.override` vs `pos.priceOverride`):** `PERMISSION_KEY.POS_PRICE_OVERRIDE` is defined as `"pos.price.override"` (`<moduleKey>.<entity>.<action>`) so it satisfies ADR-054, ADR-088, `PERMISSION_KEY_PATTERN` (`/^[a-z][a-z0-9-]*\.[a-z][A-Za-z0-9]*\.[a-z][A-Za-z0-9]*$/`), `role-contracts.test.ts` and `PermissionCatalog` startup validation. The two-segment shorthand `pos.priceOverride` in `10-MODULE-CATALOG.md` and the plan prose is the same permission.
