- **Done:**
  - **ORDER as a payment request** (decisions 1, 2): `routes/payment-request-readers.ts` (one factory, BOOKING and ORDER; used by `payment-tenant-router.ts` and `accounting-event-handlers.ts`), `routes/order-request-reader.ts` (built from a function exported by `sales/index.ts`; DRAFT, CANCELLED, missing and foreign orders read as `undefined`; COMPLETED is `AFTER_REVENUE`, the rest `BEFORE_REVENUE`).
  - **`OrderPaymentPort`** (decision 3) replaces the zero `PaymentSummaryReader` stub; adapter `routes/order-payment-adapter.ts` joins the caller's session. The stub `paymentReaderOf` and the "card 3.8 replaces" comments are gone.
  - **Summary lifecycle** (decision 4): place and instant sale call `initializeSummary`; an edit calls `updateTotal` (refuses a total below net paid with `ORDER_TOTAL_BELOW_PAID`) and, when the contact changes, `updateContact` (only while net paid is 0, else `ORDER_CONTACT_LOCKED_BY_PAYMENT`). Cancelling clears an unpaid summary so the order leaves the dues.
  - **Advance rule** (decision 5): `sales/domain/required-advance.ts` (`requiredAdvance`, integer math), setting `sales.advance.value`, confirm reads `readNetPaid` inside its unit of work and refuses with `ADVANCE_NEEDS_PAYMENTS`.
  - **Cancel settles what was paid** (decision 6): `payment/application/use-cases/settle-request-termination.ts` is the request-neutral settlement; `settle-booking-deposit.ts` stays as the thin booking wrapper. Cancel (and so the auto-cancel job) runs it in the cancel transaction; `ORDER_CANCEL_NEEDS_CONTACT` guards a paid order without a contact.
  - **Reads** (decision 7): `readTotals` everywhere; the list calls `readTotalsMany` once per page through the new `PaymentSummaryRepository.findByRequests` (one `$in` query). The summary index is `{ organizationId, requestType, requestId }` (unique, `payment-summary.schema.ts`), so the query starts with `organizationId`.
  - **Records** (decision 9): ADR-137 (Accepted (proposed)), `docs/11 §4.4` corrected, sales and payment READMEs. STATUS row 3.23.
  - **Settings test:** `settings-api.test.ts` listed the sales settings and did not know `sales.advance.value`; CI failed on it. Fixed in `0c053f8d`.
