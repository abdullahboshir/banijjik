- **Deviations from plan (and why):**
  1. **Request hash also covers validated `params`.** Plan said method + route + body. Without params, one key could be replayed against `/roles/A/archive` and `/roles/B/archive`.
  2. **Response is held back until the record is settled** (`response.json` is wrapped; the answer is sent after `complete`/`release`). This guarantees a retry right after the response finds the stored result. A failure to store is reported and the response still goes out.
  3. **`send` and `end` are wrapped to throw `errors.idempotency_unsupported_response`** (plan: "refuse unsupported response paths"). Tested.
  4. **`eslint/scopes.mjs` changed (one line):** `**/kernel/idempotency/**` added to `ORM_ALLOWED_FILES`, with a matching pass fixture `tools/lint-tests/fixtures/apps/api/src/kernel/idempotency/r28-mongoose-in-kernel-idempotency.pass.ts` and expectation. Why: the record schema is a kernel model that must import `Schema` from mongoose, exactly like `kernel/sequence` and `kernel/rate-limit`, which are already in that list. No rule is weakened for module code: modules still cannot import the driver (R28 fails for them), and the fixtures for module folders are untouched.
  5. **Audit read uses `occurredAt` range filters `from`/`to` inclusive**, plus a refine that rejects `from > to` (400). Not in plan, small validation choice.
