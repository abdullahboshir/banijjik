2. **Delivery Module (`apps/api/src/modules/commerce/delivery`):**
   - **Domain Layer:**
     - `delivery-assignment.entity.ts`: Domain aggregate for DeliveryAssignment with `attemptOrdinal`, active status, and UUIDv7 identity.
     - `rider-cash-handover.entity.ts`: Domain aggregate for RiderCashHandover enforcing positive amount, receivedVia, and reversal immutability.
     - `delivery-repository.ts`: Repository interfaces for Assignments and Handovers.
     - `errors.ts`: Domain errors (`riderCannotApproveOwnHandover`, `handoverAlreadyReversed`, etc.).
   - **Infrastructure Layer:**
     - `delivery.schema.ts`: Mongoose schemas with compound indexes (`organizationId + orderId`, `organizationId + riderMemberId`, `organizationId + reversesRiderCashHandoverId` with partial filter).
     - `mongo-delivery.repository.ts`: Mongo repository implementations respecting sessions, tenant isolation, and versioning.
     - `register-delivery-models.ts`: Registers `DeliveryAssignment` and `RiderCashHandover` tenant models.
   - **Application Layer:**
     - `CreateDeliveryAssignmentUseCase`: Verifies order exists and has `fulfillmentMethod === OWN_RIDER`, verifies rider member is active and assigned to the order's location, assigns attempt ordinal, creates assignment aggregate, optionally dispatches `shipOrder`, publishes `delivery.assignment.created`, and records audit.
     - `ListDeliveryAssignmentsUseCase`: Paginated query with location, rider, status, and orderId filtering.
     - `RecordRiderCashHandoverUseCase`: Verifies rider cannot approve/record their own handover, verifies payments belong to organization, verifies single currency, checks total matches payment amounts, inserts handover, publishes `delivery.handover.recorded`, and records audit.
     - `ReverseRiderCashHandoverUseCase`: Verifies handover exists, checks not already reversed, verifies approval token via `ApprovalVerifier.consume` inside UoW, inserts reversal handover record with `reversesRiderCashHandoverId`, publishes `delivery.handover.reversed`, and records audit.
   - **Presentation Layer:**
     - `delivery-tenant.router.ts`: Mounted tenant router with permission checks, request validation, and idempotency headers.
     - `delivery.manifest.ts`: Module manifest declaring CORE class, dependencies (`sales`, `payment`, `iam`, `organization`), permissions, and settings.

3. **Routing & Wiring Integration:**
