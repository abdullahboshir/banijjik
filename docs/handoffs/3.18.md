# 3.18 Delivery guardrails (handoff)

Lead card (Opus 5.5, 2026-10-23), asked for by the owner after a day lost to review round trips. CI itself takes about 10 minutes; the time went to sessions reporting "done" with uncommitted fixes, unpushed work or red CI, to review rounds with 10–20 findings that repeat across cards, and to shared failures that blocked every branch.

## What changed
- `scripts/card-check/card-check.mjs` + `npm run card:check`: the finish gate. It reads facts from git and `gh` and prints one PASS/FAIL line each: card branch, everything committed, pushed (local = origin), rebased on `origin/main`, a handoff changed (review files do not count), the STATUS row changed, no conflict markers, no added focused tests, CI green on the head commit. Exit code 1 on any FAIL. `evaluateCard` is pure, so the rules are tested without git.
- `scripts/card-check/card-check.test.mjs`: 7 behaviour specs (runs in `npm run test:tools`).
- `docs/plans/parallel-sessions-guide.md`:
  - §3: a T1 part is about 15 production files.
  - §6: the implement prompt asks for the §11 walk and the `card:check` output.
  - §8: step 9 `card:check`, and the §11 table in a T1 handoff.
  - §10: `card:check` is the entry ticket for a review; the lead fixes at most three small leftovers itself instead of another round (owner, 2026-10-23).
  - §11: the T1 self-review checklist, built from the 3.7, 3.8 and M.5 review findings.
- `docs/plans/_TEMPLATE.md`: a T1 test line pointing at §11.
- `.github/workflows/ci.yml`: nightly run on main at 21:30 UTC (03:30 Dhaka, inside the hours where UTC and Dhaka dates differ), so a new advisory or a date bug turns main red before it blocks card branches.

## Deviations
None. No plan file (process card).

## Tests
`card-check`: passes a committed, pushed, rebased card with a handoff and a green CI run; fails when a fix is left uncommitted; fails when the last commit is not pushed; fails when the branch is not rebased on origin/main; fails when CI is red, still running, missing or unreadable; does not count a review file as the session's handoff; fails on a missing STATUS row, conflict markers, focused tests and a non-card branch.

## Known gaps
- `card:check` needs `gh` logged in. A cloud session without `gh` cannot pass the CI line; the lead checks that line for it.
