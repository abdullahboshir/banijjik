## 1. Must-fix (block merge)

### M1 · Public availability router copies the Zod schema instead of using `@banijjik/validation/booking`

- **File:** `apps/api/src/modules/commerce/booking/presentation/booking-storefront.router.ts:13–59` (local `LOCAL_DATE`, `calendarDayNumber`, `publicAvailabilityQuerySchema`).
- **Package (unused by the router):** `packages/validation/src/booking/storefront-availability-schemas.ts` + add-only export in `packages/validation/src/booking/index.ts:33–37`.
- **Rule:** AGENTS.md single source of truth — request schemas live in `packages/validation`. Neighbouring booking routers already import from `@banijjik/validation/booking` (`booking-tenant-booking.routes.ts:11` + `validate({ query: availabilityQuerySchema })`).
- **Scenario:** the package schema and the router copy can drift; CI's `npm ci` never exercises the package schema on this route. The handoff's reason (worktree `node_modules` junction into `banijjik-4.3-cod-s1a`) is local hygiene, not a product rule.
- **Fix:** delete the local schema. Import `publicAvailabilityQuerySchema` from `@banijjik/validation/booking`. Cloning `{ ...request.query }` before parse is allowed if Express 5 query objects need it; do not fork the schema. Do not keep a junction as the design.

### M2 · `/language` now trusts `Referer` origin — open redirect + empty `catch`

- **File:** `apps/storefront/app/language/route.ts:9–26, 32–38`.
- **Scenario:** `GET /language?to=en` with `Referer: https://evil.example/phish`. `safeNextPath` keeps `/phish` (it is a relative path), `publicOrigin` returns `https://evil.example`, and the 303 leaves the tenant host. `x-forwarded-host` is also used without matching the request host.
- **Empty catch:** `refererUrl` `catch { return null; }` (`:14–16`) violates AGENTS.md “No empty `catch`”.
- **Other storefront tests:** `commerce.browser.test.ts` / `account-pages.browser.test.ts` / `storefront.browser.test.ts` do not click `/language`. Regression risk there is low. The new booking EN click depends on this route. Keep Host-based origin so `{slug}.{BASE_DOMAIN}` still works; do **not** take origin from an untrusted Referer.
- **Fix:** origin from `Host` / a same-host allow-list only. Use Referer **path** only when `referer.origin === publicOrigin`. Ignore invalid Referer without an empty catch.

### M3 · Check 4 cannot be dropped on PRODUCT-only checkout evidence
