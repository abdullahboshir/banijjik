## 2. Architecture & Design Rules Audit

1. **Zero Industry Branching (ADR-033, ADR-034):**
   - **Audited:** Full codebase search across `apps/storefront/src/booking`, `apps/storefront/src/enrollment`, and `apps/storefront/src/catalog` shows **zero** occurrences of `industry`.
   - Control dispatching in `OfferingKindControls` branches strictly on `offering.kind` (`SERVICE`, `RENTAL`, `EVENT`, `PLAN`, `PRODUCT`).
2. **Zero Hardcoded Industry Nouns:**
   - **Audited:** No instances of "Student", "Patient", "studentId", "patientId", or domain-specific roles. Nouns used are generic business SaaS concepts ("resource", "staff or resource", "session", "seats", "admission fee", "security deposit", "notes").
3. **Location Scoping (ADR-004):**
   - Location is resolved via props, query parameter (`?location=`), or active offering location. No scope contexts or global switchers.
4. **Money & Upfront Obligation Breakdown (ADR-013):**
   - All monetary amounts (`admissionFee`, `securityDeposit`, `firstRecurringFee`, `totalUpfront`) are maintained and summed strictly as integer minor units. Floating-point arithmetic is never performed on monetary totals; division by 100 is isolated solely to presentation-layer string formatting (`formatPrice`).
5. **Exact Optional Property Adherence (`exactOptionalPropertyTypes`):**
   - `customFields?: Readonly<Record<string, unknown>> | undefined` correctly declared in `cart-store.ts`, `use-offering-selection.ts`, and selector signatures, ensuring seamless TypeScript compilation.
6. **Selection DTO Adherence (`PublicSelection`):**
   - Payloads generated by all selectors strictly conform to the discriminated union `PublicSelection` defined in `@banijjik/contracts/website`:
     - `SERVICE`: `{ kind: "SERVICE", offeringId, variantId, startsAt, resourceIds }`
     - `RENTAL`: `{ kind: "RENTAL", offeringId, variantId, startsAt, endsAt, resourceIds }`
     - `EVENT`: `{ kind: "EVENT", offeringId, variantId, eventSessionId, quantity }`
     - `PLAN`: `{ kind: "PLAN", offeringId, variantId, startsOn, resourceIds }` + `customFields`

When the public availability API route is wired up in the integration phase (Part V), `fetchAvailability` can be triggered on date change to dynamically filter available slots.
