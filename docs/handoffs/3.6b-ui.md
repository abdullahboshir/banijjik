# 3.6b Part B — UI handoff (rental and event screens)

Branch `s/3.6b-ui-rental-event`. Code CI (green): https://github.com/abdullahboshir/banijjik/actions/runs/40097727312

## What was built
- **Catalog kind-details form** (`apps/admin/src/catalog/`): RENTAL fields (rate unit, min and max units, resource types, check-in and check-out for NIGHT, deposit) and EVENT fields (sales close minutes, allow waitlist), built and read back field by field against `packages/validation/src/catalog/kind-details.ts` (max below min and bad HH:mm are refused in the form).
- **Event sessions screen** (`apps/admin/src/bookings/event-sessions-page.tsx`, route `bookings/event-sessions`, manifest menu entry): list with seats sold of capacity read from the server; lazy create/edit sheet (`event-session-sheet.tsx`, versioned PATCH, capacity never below seats sold, time locked once a seat is sold) and cancel confirmation (`event-session-cancel-dialog.tsx`, states seats sold, says bookings are cancelled shortly, no refund promise). Buttons are lazy (`event-session-buttons.tsx`).
- **New-booking sheet modes**: rental mode (start, units, resource, computed end preview `rental-end-preview.ts`) and event mode (session picker from `GET /event-sessions`, seats). Price comes from `POST /quotes` (`use-new-booking-mode-data.ts`), never multiplied in the browser. Event sessions are listed with seats left from the session response.
- **Calendar**: rentals that started on an earlier day are loaded (31-day look-back, list filters by start) and drawn as bars that continue past the grid edge; mobile list shows "rented until"; event sessions of the day shown as blocks with seats sold.
- **i18n** add-only BN/EN. Screen labels reach client components as props through `screen-text.tsx` (the browser catalog holds only shared keys).
- No API change except the one manifest menu entry allowed by Refresh 3.

## Deviations from the plan
- The `bookings.eventSessions.seats` and `bookings.sheet.quantity` keys added by the earlier partial commit were replaced by the final key set (they were unused after the rewrite).
- The browser test seeds the COACHING template (its enabled kinds include EVENT; SALON does not allow EVENT offerings).
