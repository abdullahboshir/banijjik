## What was built

- **Endpoint** `POST /orgs/:organizationId/sales/returns/:salesReturnId/reverse`, permission
  `sales.return.reverse` (registered in the sales `module.manifest.ts`, so owner and manager hold it
  through their `ALL` grant for sales), `Idempotency-Key` required. Body `{ version, reasonKey,
  note?, payback?, approvalToken? }`; a missing token answers `403 APPROVAL_REQUIRED` with the
  action `SALES_RETURN_REVERSAL` (plan R3).
- **Use case** `sales/application/sales-return-reverse.ts` (own file): one unit of work for the
  approval, the stock reversal, the order payment total, the optional payback, the order lines and
  the return row (conditional `ACTIVE` to `REVERSED` update with `version`), then the
  `sales.return.reversed` event (`order:<orderId>` ordering) and the audit entry.
- **Stock** `StockLedger.reverseReturn` (inventory `stock-ledger-reversal.ts`): reverses each
  `RETURN` movement with `RETURN_REVERSAL` and each `RETURN_DAMAGED` movement with
  `RETURN_DAMAGED_REVERSAL`, at the stored unit cost, refusing a shortfall with
  `INSUFFICIENT_STOCK` (mapped to `SALES_RETURN_STOCK_GONE`) whatever `allowNegativeStock` says. The
  damaged bucket can never go below zero.
- **Money** `OrderPaymentPort.restoreReturnTotal` (summary total goes back up; another currency is
  the rule `SALES_RETURN_REVERSE_CURRENCY_MISMATCH`, a missing summary stays `INTERNAL`) and
  `OrderPaymentPort.receiveOrderPayment` (an IN payment allocated to one order through the payment
  module `ReceivePaymentUseCase`, with the body note or `null`; A3 reuses it).
- **Books** `accounting.postSalesReturns` also handles `sales.return.reversed` with the posting
  keys `reversal_sales_return_value` and `reversal_sales_return_cogs` (new contract keys, resolved
  by `reversalPostingKeyFor`). **Commission** `commission.accrue` also handles the reversed event.
- **Contracts, validation, i18n:** `SALES_RETURN_REVERSE_REASON`, `STOCK_MOVEMENT_REASON`
  `RETURN_REVERSAL` and `RETURN_DAMAGED_REVERSAL`, `APPROVAL_ACTION.SALES_RETURN_REVERSAL`, the
  permission, event, audit action, four rule keys with BN and EN messages. The record field
  `reversedBySalesReturnId` is replaced by `reversal`.
- ADR-145 got an "A2" sentence.

## Deviations

1. **Plan amendment (lead, review item 2):** a second stock reason `RETURN_DAMAGED_REVERSAL`
   (`onHandDelta 0`, `damagedDelta = quantityDelta`, state DAMAGED) in the movement helpers and the
   level projection. A reversed `RETURN` still uses `RETURN_REVERSAL`.
2. **Review item 8:** `receiveReturnPayback` is now `receiveOrderPayment` with a `note` input and
   returns `{ paymentId, paymentNumber, method, amount }`.
3. **Cross-location is 404, not 403** (plan Tests A2 said 403): location-owned rows are invisible
   outside the caller's locations (LOCATION tenancy), exactly as A1's create test records. The test
   is `a return at another location is refused to a manager of this location`.
4. **Stored cost on the reversal:** `outgoingUnitCostForMovement` used the current average cost for
   every outgoing movement. For `RETURN_REVERSAL` it now keeps the unit cost the reversal carries,
   so the goods leave at the cost the return brought them in at (plan R4). A test fails without it.
5. `approvalToken` is optional in the body schema so that a missing token is `403 APPROVAL_REQUIRED`
   with the action (plan R3), not a validation error. The use case still refuses without it.
6. `payback` when nothing was refunded answers `400 VALIDATION_ERROR` with `details.field =
   "payback"` (the app maps `VALIDATION_ERROR` to 400; the plan only said `VALIDATION_ERROR`).
7. Review item 4 turned out to be a missing manifest permission definition, not a missing grant
   (sales is `ALL` for owner and manager); the permission count tests in contracts went 129 to 130.

## Tests

API (`sales/presentation/sales-return-reverse-api.test.ts`, real Mongo):
- `reversing a cash-refunded return with payback restores the order total, takes the cash back and puts the goods back out at the returned cost`
- `reversing without payback leaves the refunded amount as a due on the order`
- `reversing a store-credit return with store credit payback debits the balance; a short balance refuses and writes nothing`
- `reversing a damaged return takes the goods out of damaged stock; a not-received line moves nothing`
- `refuses when the returned goods are no longer on hand` (both settings, also the damaged bucket)
- `refuses with its own rule when the order payment total is in another currency`
- `the delivery charge of a reversed return can be returned again`
- `a reverse always needs the SALES_RETURN_REVERSAL approval for the return value`
- `refuses the reason OTHER without a note`
- `a payback when nothing was refunded is a validation error that names the payback`
- `a second reverse of the same return is refused and writes nothing`
- `two parallel reverses: one wins, the other 409, stock and money moved once`
- `refuses to reverse an exchange return and a return of an order that is no longer completed`
- `the same Idempotency-Key returns the first reversal`
- `a cashier without sales.return.reverse gets 403`
- `a manager with sales.return.reverse at the location reverses the return`
- `another organization's return is 404`
- `a return at another location is refused to a manager of this location`

Accounting (`accounting/post-sales-returns.test.ts`):
- `the reversal posts the mirror of both return journals once, also on event replay`

Commission (`commission/commission-accrual.test.ts`):
- `a reversed return raises the line commission back`

Inventory (`inventory/application/level-projection.test.ts`):
- `a damaged return and its reversal leave sellable stock untouched and net damaged to zero`

Contracts: the permission count tests (129 to 130).
