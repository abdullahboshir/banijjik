# 3.5b A2 handoff

## Result

Implemented the sales-return reverse endpoint on `s/3.5b-api-return-reverse`.
The reverse path validates the active return, completed order, exchange exclusion and mandatory
`SALES_RETURN_REVERSAL` approval; reverses return stock at the original movement cost with a hard
negative-stock guard; restores the order payment-summary total; optionally collects payback through
the payment module; lowers returned quantities; conditionally changes the return to `REVERSED`;
publishes the reversal event and audit entry; and adds accounting and commission handling.

The old unused `reversedBySalesReturnId` field is replaced by the structured `reversal` record.
Contracts, validation, BN/EN messages and owner/manager permission wiring were added.
