## 1. Must-fix

1. **Leaked catalog price between browser cases (this is the CI failure).** `commerce.browser.test.ts:159-167` `raisePrice()` patches the shared offering to `RAISED_PRICE` (3000). The price-change case (`:335-360`) never restores `PRODUCT_PRICE` (2500) in its `finally` (`:358-359` only closes the browser context). The next case (`:363-388`, D7 session-lost recovery) then calls `proceedToCartQuote(page, "BDT 25.00")` at `:370` against the same `beforeAll` product.

   CI evidence, Storefront browser suite on [41325962908](https://github.com/abdullahboshir/banijjik/actions/runs/41325962908):

   ```
   FAIL  src/commerce.browser.test.ts > the public storefront commerce flow
     > recovers when the guest session is lost between quote and submit
   AssertionError: expected 'কার্ট (1)…' to contain 'BDT 25.00'
   Received: …সর্বমোটBDT 30.00…
     ❯ proceedToCartQuote src/commerce.browser.test.ts:250
     ❯ src/commerce.browser.test.ts:370
   ```

   The first two cases in that file passed. The third never reached `deleteMatchingCookies`. This is test isolation, not a guest-cookie restore bug.

   **Required fix:** restore `PRODUCT_PRICE` after the price-change case (and/or before the session-lost case), using the same `version` CAS path `raisePrice` already uses. Do **not** "fix" the assertion by reading whatever total the live quote JSON happens to show after the leaked raise — that would hide the isolation bug and weaken D7. Keep the expected cart total pinned to the original catalog amount (`CURRENCY_CODE.BDT` + `PRODUCT_PRICE`, not a `"BDT"` literal).

2. **D7 is unproven; the browser suite was not run locally.** Plan D7 requires the session-lost recovery to quote, delete `sf_guest`, see the BN quote-expired alert, refresh, submit, and reach the receipt. CI died at the cart-total assertion before any of that. The handoff (`docs/handoffs/4.3-v0.md` "Known gaps") states the storefront browser suite was **not run** locally and that "CI must be the first real run". That violates `docs/plans/parallel-sessions-guide.md` §8.2 and `.cursor/rules/speed.mdc` (screen cards run that app's browser suite before the first push). After must-fix 1, run the storefront browser suite (or at least `commerce.browser.test.ts`) locally against a fresh `@banijjik/i18n` + `@banijjik/api` build, then push **once** and get a green CI run on that head.

3. **Do not add an out-of-plan API cookie helper on this card.** `docs/plans/4.3-V0.md` "Session parts": screens only; Files table does not include API guest-session code. If, after must-fix 1, D7 still fails for a real missing/rotated guest cookie, **stop and ask** — do not invent `restoreCookieIfMissing` / `persistGuestSessionCookie` / `guest-session.service.test.ts`. Those files are not the CI failure on this head.
