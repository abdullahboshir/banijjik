## Scope Completed

1. **Real-API commerce scenarios (`apps/api/src/modules/commerce/website/storefront-commerce-scenarios.test.ts`, new, 892 lines)** — 7 tests against the real HTTP app, database, outbox dispatcher and hold-expiry worker:

2. **Browser suite (`apps/storefront/src/commerce.browser.test.ts`, new)** — 2 tests against a real API, real worker/outbox, a built storefront and Redis:

   2. **Price-change re-confirmation:** the operator raises the price after the quote; submit answers `CHECKOUT_PRICE_CHANGED`, the screen keeps `/checkout`, accepting re-quotes at `BDT 30.00`, the second submit places the order.

## Production defects found by the browser suite and fixed

These files are owned by B1, not by Part V; the fixes are small and are listed here as a **plan deviation** for the merge check.

| File | Defect | Fix |
|---|---|---|
| `apps/storefront/src/checkout/checkout-api.ts` | The cart quotes on first visit, before any guest cookie exists, so `POST /quotes` answered 401 and the cart never quoted. | `requestQuote` creates the guest session once on a 401 and retries; an existing session is reused, never rotated. |
| `apps/storefront/src/checkout/checkout-view.tsx` | Submit created a fresh guest session, so the quote's principal (`GUEST:<guestSessionId>`) no longer matched and the server refused the quote. | Submit runs under the session that created the quote; the session is only created where a session is genuinely absent (quote path). |
| `apps/storefront/src/checkout/cart-view.tsx` | `translatorFor(locale)` returns a new translator each render; `t` sat in `fetchQuote`'s dependency list, so every `setIsQuoting` render re-triggered the effect. The loop exhausted the checkout rate limit and interleaved guest-session creation. | The translator is memoised per locale with `useMemo`, so the effect runs once per cart total. |

## Known gaps

- `apps/storefront/src/catalog/use-offering-selection.ts` falls back to the literal location id `"default"` when a published offering has no location-availability row; such an offering cannot be quoted. The suite seeds real availability (`PUT /orgs/:org/offerings/:offeringId/locations/:locationId`). This is a catalog-data fallback outside Part V; it should be replaced with a hard "unavailable" state when the cart flow is next touched.
- The browser suite creates its own business, site, checkout setting, offering and location availability; it does not exercise customer sign-in, claim UI, COD, or the booking/rental/event/plan selectors (covered by B2 component tests and the API scenario suite).
- The API scenario suite trusts the shared storefront composition; it does not assert Cloudflare or live hosting.
