- **Deviations from plan (and why):**
  1. **Fix in `packages/ui` (0.5a defect that blocked the build).** `theme.css` mapped `--breakpoint-*` to `var(--token-breakpoint-*)` inside `@theme inline`. Tailwind then emits `@media (width >= var(--token-breakpoint-lg))`, which is invalid CSS, and Next/Turbopack fails with "Unexpected token Function(var)". The 0.5a Tailwind check compiled but did not parse the output. Fix: breakpoints moved to a separate non-inline `@theme` block with literal values, plus `src/styles/theme.test.ts` asserting the literals equal `breakpointTokens`. Small change outside the card; please confirm at merge check.
  2. **`ShellLink` adapter** instead of passing `next/link` directly. `Link` does not satisfy the ui `LinkComponent` type under `exactOptionalPropertyTypes` (`onClick?: (() => void) | undefined`). The adapter forwards only defined props.
  3. **No `.js` extensions** on relative imports inside `apps/admin`. Turbopack does not map `./x.js` to `./x.ts`; TypeScript uses the Bundler resolver here. Workspace packages keep NodeNext style.
  4. **`lighthouserc.json` has no `preset`.** lhci 0.15 accepts only `perf`, `experimental`, `desktop`; the Lighthouse default is already mobile emulation, so omitting it gives the planned mobile run.
  5. **CI Build step now sets the two `NEXT_PUBLIC_*` variables** (placeholders). `env.ts` validates at load, so `next build` fails without them (confirmed). Add-only edit to `.github/workflows/ci.yml`.
  6. **More slot** opens a sheet (reusing `QuickCreateSheet` with menu entries as actions) because 13-UX §3 says "More: all menu groups as a full-screen list" and the plan does not say how it opens. It is not full-screen yet. Work tab and Catalog slots use menu keys `inbox|orders|bookings|enrollments` (first present wins) and `offerings`; these keys are my choice (docs/10 §6 defines `menuKey` but not its values); confirm in 1.7 when real menu keys exist.
  7. The app `tsconfig.json` is not added to the root references (not composite, `noEmit`); root `package.json` and `tsconfig.json` are untouched.
