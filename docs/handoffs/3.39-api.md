## Done

- **Limit on create** (decision 1): `CreatePosDeviceUseCase` calls `deviceLimit.assertCanAdd(organizationId, () => devices.countActive())` inside the existing `unitOfWork.run`, before `devices.insert`. The adapter in `routes/pos-adapters.ts` takes `buildOrganizationLimitLock()`, then `buildLimitGuard(orgConfig).assertBelow(LIMIT_KEY.POS_DEVICES, count)`. At the limit the answer is `422 LIMIT_REACHED`.
- **What counts** (decision 2): every device with status `ACTIVE` (paired, waiting, or unused expired code). `REVOKED` devices do not count. A revoked device frees its slot.
- **Repository** (decision 3): `countActive()` uses `countDocuments({ status: ACTIVE })` with the active session. New index `{ organizationId: 1, status: 1 }` on `pos_devices`.
- **Usage read** (decision 4): `GET /pos/devices/usage` (`pos.device.manage`) → `PosDeviceUsageResponse { activeDeviceCount }`, counted over the whole organization. The limit itself stays on `/me/config` `limits.posDevices`.
- **Location scope** (decision 5): list and revoke take `allowedLocationIds` from `readTenantCaller()`. List filters `locationId ∈ allowed` (no filter for `"ALL"`). A `?locationId=` outside the allowed set → `403 LOCATION_FORBIDDEN`. Revoke reads the device first (`findById`; not found → 404). See deviation 1 for a cross-location revoke.
- **Packages** (decision 6): `ADDON_POS` seed now has `limitIncrements: { posDevices: 1 }` via `moduleAddOnWithIncrements`. New `PACKAGE_KEY.PACK_POS_DEVICE` is a limit pack `{ posDevices: 1 }`. i18n `package.PACK_POS_DEVICE.name`: EN "Extra POS device", BN "অতিরিক্ত পিওএস ডিভাইস". Seed never overwrites a stored package.
- **Docs** (decision 7): `10-MODULE-CATALOG.md` §9 (`ADDON_POS` `module pos + posDevices +1`, new row `PACK_POS_DEVICE`); POS README (limit rule, location scope).
- **Add-only:** `core/organization/index.ts` exports `buildOrganizationLimitLock()`. Contracts add `PACK_POS_DEVICE` and `PosDeviceUsageResponse`. i18n catalogs add the two name keys at the end.

## Platform admin (before launch)

The seed inserts a package once and never overwrites an edited one. Existing databases keep the stored `ADDON_POS` row without `posDevices +1`. **Edit `ADDON_POS` once in the platform package editor** so it adds `{ posDevices: 1 }` (and the POS module, which it already has). No migration.

## Deviations from the plan (and why)

1. **Cross-location revoke answers 404, not 403.** The plan's test list says 403. `ORGANIZATION_AND_LOCATION` tenancy hides a device of another location, so `findById` returns nothing and the use case answers 404. The device stays ACTIVE. List `?locationId=` outside the allowed set is still 403, as planned. Same pattern as card 3.34 (cross-location reversal). The test name is unchanged; the assertion is 404 with a comment.
2. **List query is `?locationId=`, not `?location=`.** The existing POS list already used `locationId`; this card did not rename it. Part B's page filter `?location=` is still the admin URL, not this API.
