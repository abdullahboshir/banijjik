## 1. Executive Summary

Card 4.3 Part A3E implements the customer enrollment command within the `enrollment` module, enabling public storefront customers and checkout flows to request enrollment into `PLAN` offerings. The implementation adheres strictly to the JIT plan specification in `docs/plans/4.3.md` (Part A3E, lines 802–851) and meets all `AGENTS.md` and `05-CONVENTIONS.md` standards.

Key architectural and behavioral invariants verified:
1. **Forced `ENROLLMENT_STATUS.PENDING` for Customer Requests:** Under `creationMode: "CUSTOMER_REQUEST"`, enrollments always initialize to `PENDING`, even when `startsOn <= today` and the organization setting `requirePaymentToActivate` is `false`.
2. **Staff Create Invariant Preserved:** Staff creation (`creationMode: "STAFF"` or omitted) retains the established behavior: creating an `ACTIVE` enrollment when `startsOn <= today` and payment is not required.
3. **Upfront Obligation Calculation:** Exported pure helper `calculateUpfrontObligation(plan, firstRecurringFee)` correctly sums `admissionFee + firstRecurringFee + securityDeposit` using minor-unit integer arithmetic (`addMoney`), setting the initial payment summary with `period.enrollmentPeriodId` as payment `requestId`.
4. **Idempotent Seat & Resource Hold Lifecycle:** Resource holds and seat increments execute atomically within `unitOfWork.run()`, rolling back cleanly if payment summary initialization or repository writes fail.
5. **Checkout Correlation:** `checkoutId` is added to `Enrollment` aggregate, entity schema, and persisted with a sparse compound index `{ organizationId: 1, checkoutId: 1 }`, queryable via `findByCheckoutId(organizationId, checkoutId)`.
6. **All 11 Planned Tests Implemented & Passing:** Real replica-set MongoDB integration tests verify all plan scenarios, including cross-org isolation, foreign payer refusal, and transactional rollback.
