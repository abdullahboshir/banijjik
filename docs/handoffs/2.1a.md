## Per decision

### 1. Template keys are data (ADR-097)
`IndustryTemplateKey` is a branded string, format `^[A-Z][A-Z0-9_]{1,39}$`. `INDUSTRY_TEMPLATE_KEY` is removed. `SEED_INDUSTRY_TEMPLATE_KEY` names the eight seeds and is used by seed data and tests only. Existence and status are database checks. `organization.schema.ts` matches the same pattern. `organizationCreateRequestSchema` uses `industryTemplateKeySchema`.

Proved by `industry-template-key` validation tests (accepts `FCOMMERCE` and `NEW_SHOP_2`; rejects `fcommerce`, `A`, `bakery-shop`, and 41 characters) and the signup cases below.

### 2–3. Module `platform/industry` and the stored shape
Layout follows `platform/package`. Collection `industry_templates`, platform DB, tenancy `NONE`, versioned, audit fields. Indexes: `industryTemplateId` unique, `industryTemplateKey` unique, `{ status, industryTemplateKey }`. Configuration is `Schema.Types.Mixed` and is schema-checked before write. `IndustryTemplateId` was added in `@banijjik/ids` so the id is a UUID v7 (`newId()`). The plan's file list did not name that package; the id convention required it.

`CONTACT_ROLE`, `RELATION_KEY`, `CUSTOM_FIELD_TYPE` (16 types), and `INDUSTRY_TEMPLATE_STATUS` are in contracts. `LocalizedText` is defined on the industry-template contract. The module README says terms, fields and settings registries belong to cards 2.2, 2.3 and 2.4.

### 4. Eight materialized seeds
JSON files live in `apps/api/src/modules/platform/industry/infrastructure/seeds/`. FCOMMERCE and RETAIL are PUBLISHED; the other six are DRAFT. Every module key, kind, role and field type in `docs/12` already existed in contracts, so nothing was dropped and the card was not stopped.

Proved by `industry-template-seeds.test.ts`: all eight parse, only FCOMMERCE and RETAIL are PUBLISHED, FCOMMERCE has 20 allowed modules, CLINIC kinds are `[SERVICE]`, COACHING has the guardian contact link with `GUARDIAN_OF`, RESTAURANT has the required single-choice Size group, and the common terms are in every file.

Mechanical fills, where `docs/12` is prose rather than a stored pair (not new product keys):

- Common terms are the table: contact "গ্রাহক / গ্রাহকরা" / "Customer / Customers", plus offering, order, booking, enrollment, resource and location. A prose pair such as "ক্লায়েন্ট/Client" is stored as bn "ক্লায়েন্ট" and en "Client". Coaching `offering.PLAN` is bn "কোর্স/ব্যাচ" and en "Course"; `offering.EVENT` is bn "ক্লাস/পরীক্ষা" and en "Class or exam". Retail order override is bn "বিক্রি" and en "Sale".
- Knowledge starters use topic keys DELIVERY, PAYMENT, RETURNS, HOURS, LOCATION. English blurbs come from the doc; Bangla is a direct translation. HOURS and LOCATION have no description in the doc, so they are "খোলার সময়" / "Opening hours" and "ঠিকানা" / "Location".
- Common handoff topics: "refund or complaint", "angry customer", "request for a human", "anything not grounded". Extras: FCOMMERCE "wholesale or bulk price requests"; RETAIL "credit requests"; CLINIC "medical advice", "diagnosis", "medicine or dosage question"; GYM "injury questions", "medical questions"; COACHING "exam result disputes"; HOSTEL "deposit refund". Personas: FRIENDLY_SELLER, POLITE_SHOPKEEPER, CARING_STYLIST, CALM_RECEPTIONIST, ENERGETIC_COACH, HELPFUL_ADMISSION_DESK, WARM_HOST, RESPECTFUL_MANAGER. SALON and RESTAURANT add no extra topic.
- Resource `termKey` is `resource` when that is the label. SALON STYLIST uses the overridden resource term; CHAIR uses `resource.CHAIR`. CLINIC ROOM has no label in `docs/12`, so it is `resource.ROOM` bn "রুম" en "Room". GYM, COACHING and HOSTEL resource rows that share the template's resource label use `termKey` `resource`. `isMember` is true only for STYLIST, DOCTOR, TRAINER and TEACHER.
- Coaching guardian: relation `GUARDIAN_OF`, `createIfMissingByPhone` true, `defaultBillTo` true. Hostel guardian: `defaultBillTo` false.
- PLAN defaults, bot-behavior prose, capacity notes, and restaurant delivery-charge zones are not stored. The doc gives no numbers for those charges, and they are not configuration fields. Restaurant `catalog.defaultStockTracked` is false. Common settings are merged into every file, then overlaid: `organization.digitScript` LATIN, `organization.numberGrouping` WESTERN, `sales.returnWindowDays` 7 (FCOMMERCE overrides to 3), `sales.advance.required` NONE, `booking.deposit.required` NONE, `enrollment.refundPolicy` NONE.
- Blood-group options use an ASCII hyphen (`A-`).
- Optional modifiers are their own group, selection SINGLE, `isRequired` false, min 0, max 1. Money stays integer minor units (7000 = ৳70).
- Draft templates have no one-line description in `docs/12`. `name` and `description` both use the heading pair. FCOMMERCE and RETAIL use the explicit descriptions.

### 5. Idempotent seed
`EnsureSeedIndustryTemplatesUseCase` inserts missing keys only. `main.ts` calls it next to `seedPackages`. `npm run seed:industry-templates -w @banijjik/api` runs the script.

Proved by `seed-industry-templates.test.ts`: first run inserts 8, second inserts 0, an edited name is not overwritten, and startup seeds an empty database.

### 6. Real reader
`CachedIndustryTemplateReader` answers any status, caches views for 30 seconds (`INDUSTRY_TEMPLATE_VIEW_CACHE_TTL_MILLISECONDS`), and throws `AppError` INTERNAL `errors.industry_template_missing` (and logs `industry.template.missing`) when the key has no row. It never allows everything. `InterimIndustryTemplateReader` is deleted. `templates` is a required argument of `buildOrgConfigService`. Production passes `buildIndustryTemplateReader(clock)` from `routes/v1.ts` and `routes/module-effectiveness.ts`. Entitlement does not import the industry module by value.

Proved by `cached-industry-template-reader.test.ts` (DRAFT and RETIRED, 30 second cache, missing key).

### 7. Signup accepts only PUBLISHED
`IndustryTemplateAvailability.isSelectableAtSignup` is checked before the transaction and again inside `storeAll`. Unknown, DRAFT and RETIRED answer 422 `INDUSTRY_TEMPLATE_NOT_AVAILABLE` / `errors.industry_template_not_available`. `routes/v1.ts` does not use the identifier `industryTemplateKey`; the adapter is passed as `industryTemplates`. `bakery-shop` stays 400 at `industryTemplateKey`. `BAKERY` is well-formed and is 422.

Proved by the organization API tests: RETAIL and FCOMMERCE return 201; SALON, a RETIRED fixture, and `BAKERY` return 422; `bakery-shop` returns 400. A unit test shows the second check returning false stores nothing.

### 8. `GET /api/v1/industry-templates`
Signed-in admin audience, mounted with `/me` and `/me/orgs` (not the tenant pipeline, not the PLATFORM manifest). PUBLISHED only, ordered by key, both languages, hard cap 100 (`PUBLISHED_INDUSTRY_TEMPLATE_LIST_CAP`). An operator cookie and a missing session are 401.

Proved by `industry-template-api.test.ts`.

### 9. Platform reads
`GET /platform/industry-templates` is paged (`paginationQuerySchema`, optional status, ordered by key). `GET /platform/industry-templates/{industryTemplateId}` returns configuration; an unknown id is 404. Permissions `platform.industry.read` and `platform.industry.write` exist. SUPER_ADMIN has both through ALL. SUPPORT and BILLING have `INDUSTRY_READ` only. Write is unused until 2.1b.

Proved by `industry-template-api.test.ts` and the role-table test in `platform-contracts.test.ts`.

### 10. Docs
ADR-097 is new (Accepted, proposed). ADR-076's seed path is amended (the files live in the module, not `packages/seed`). ADR-093 lists `industry.read` and `industry.write`. ADR-091's last sentence now says the reader is the real one, so the decision text matches the code. The plan did not name ADR-091; this is a one-line alignment. `09` §4.6 follows `12` §1 and notes that `defaultModuleKeys` and `websiteTemplateIds` are not stored. `14` §4 documents the public list and the 422 on `POST /me/orgs`. `14` §7 says reads are this card and writes are 2.1b.
