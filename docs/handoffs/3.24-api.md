## Review R1 fixes

1. **Real R3 race** (`accounting/posting-sources-api.test.ts`): drives the real draft/place/confirm/complete path and the real `POST /payments` use case on one order. `MongoPaymentSummaryRepository.prototype.applyAllocation` is gated after the payment read the order as CONFIRMED and before its commit. A sentinel `updatedAt` proves `CompleteOrderUseCase` wrote the payment summary inside its transaction (`total` 1000, `updatedAt` moved); after release the test accepts either an `AFTER_REVENUE` retry or a 300 advance, and then asserts the settle debits `CUSTOMER_ADVANCES` by 300. The two fake tests in `post-orders.test.ts` were deleted.
2. **Real fixed-clock date tests**: `harness.clock.setNow(2026-10-23T20:00:00Z)` (02:00 Dhaka on 2026-10-24) drives a real place/confirm/complete order and a real stock receipt; the order revenue journal and the stock receipt journal both carry `businessDate` `2026-10-24`. The stock movement `businessDate` is derived with an `Intl.DateTimeFormat` helper (default `Asia/Dhaka`) instead of a UTC ISO slice.
3. **Integer quantities**: `quantityToBigIntFraction` deleted; `lineValueMinor` accepts integers only and throws `DomainRuleError({ code: INTERNAL, messageKey: "errors.non_integer_quantity" })` otherwise. `moving-average.test.ts` covers 1,500 g at 5,000 micros/g exactly (750 minor) and the fractional rejection.
4. **No silent money fallbacks**: `stock-posting-rules.ts` requires `paidVia` and maps it with an explicit `switch`; an unknown value throws `postingSourceMissing`. `buildStockPostingSourceAdapter` requires the organization currency reader and throws `INTERNAL` (`errors.missing_currency`) when no known currency is available; no `"BDT"` literal and no `as CurrencyCode`.
5. **Contract constants**: production stock paths use `STOCK_MOVEMENT_REASON`, `STOCK_RECEIPT_PAID_VIA`, `STOCK_STATE`, `STOCK_ADJUSTMENT_REASON` and the add-only `STOCK_SOURCE_TYPE` values; the `SOURCE_*` constants in `stock-use-case-shared.ts` alias the contract values.
6. **Dead code removed**: `RecordOpeningStockUseCase` and its file are deleted and no route, job or test referenced it. The `stock_opening` posting rule and its rule test remain.
7. **Generic system-account seeding**: `ensure-payable-account.ts` is now `ensure-system-account.ts`; name and type come from `SYSTEM_ACCOUNT_SEEDS`, an unknown code throws, and a duplicate insert that cannot be re-read throws `errors.concurrent_system_account_creation_failed`.
8. **Required dependency**: `OrderPostingSourcePorts.orders` is required; `routes/accounting-event-handlers.ts` passes `buildOrderRepository()`. No default repository construction inside the adapter.
9. **Controller cast removed**: `stockReceiptRequestSchema` and the adjustment schema carry the contract enum types, so `StockController` passes `body.paidVia` and `line.reason` directly.

## Deviations from the plan

- `buildOrderRepository()` is exported from `sales/index.ts` (and used by `buildOrderSnapshotReader`) so the composition root can supply the required order port; this is the enabler for review item 8.
- The controller's second cast, `line.reason as StockAdjustmentReason`, is also removed (review item 9 named only `paidVia`); both validation schemas now enumerate the contract values explicitly instead of casting `Object.values(...)`.
- `buildStockMovementDocument` now derives `businessDate` with a local `Intl.DateTimeFormat` helper defaulting to `Asia/Dhaka` (was `toISOString().slice(0, 10)`), needed for the Dhaka 02:00 receipt test. Known gap below: it does not yet read a per-organization timezone.
- `MutableClock.setNow(date)` was added to `apps/api/src/test-support/mutable-clock.ts` for the fixed-clock API tests.
- The two fake tests were removed from `post-orders.test.ts` and replaced by `accounting/posting-sources-api.test.ts`, which exercises the real HTTP order, payment and stock paths on the API harness.
- The shared `receiveStock` test helper in `apps/api/src/test-support/sales-api-world.ts` now sends `paidVia: "CASH"`, matching the required receipt field; no other behaviour changed.
- `STOCK_SOURCE_TYPE` received the add-only values `STOCK_RECEIPT`, `STOCK_OPENING`, `STOCK_ADJUSTMENT`, `STOCK_TRANSFER` (REVIEW ITEM 5), and `stock-use-case-shared.ts` aliases them.
- New `INTERNAL` message keys (`errors.non_integer_quantity`, `errors.missing_currency`, `errors.unknown_system_account`, `errors.concurrent_system_account_creation_failed`) are log-only; the HTTP error handler still answers the generic `errors.internal` body, so no i18n catalog entry is needed.
