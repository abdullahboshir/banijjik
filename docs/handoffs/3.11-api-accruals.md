## Deviations from plan (and why)
1. **Payout permissions and the `commission.payout.*` keys are not in A1.** Only the four keys that have routes exist (`rule.read`, `rule.update`, `entry.read`, `entry.readOwn`). A2 adds `payout.read` and `payout.create`; the `ALL` grants then cover them. A key with no route would show in the role editor and do nothing.
2. **Two add-only lines in modules the plan does not list.** (a) `modules/core/organization`: a `MemberNameReader` port and `MongoMemberNameReader` (`buildMemberNameReader()` in its `index.ts`), because no existing export gives member display names or "does this member exist" for the rule checks and for `memberName` on entries. (b) `modules/commerce/catalog/index.ts` exports `MongoCategoryRepository` (like the existing `MongoOfferingRepository` export) for the category existence check. Please confirm or move them in review.
3. **`sourceNumber` is stored on the entry** (booking number at accrual time) instead of joined from the booking module per page. The booking repository has no batched read by IDs, so a join would be N+1 (forbidden), and a snapshot is stable for a ledger. `CommissionSourceReader` therefore has only `readBooking` (now also returning `bookingNumber`).
4. **Validation errors answer 400 `VALIDATION_ERROR`**, not 422: that is the code of `VALIDATION_ERROR` in this API. Business-rule failures answer 422 (`commission_kind_not_enabled`) and 409 (`commission_rule_duplicate`, stale version).
5. **The entries model is not registered `appendOnly`.** The `appendOnlyPlugin` refuses every update, but A2 sets `payoutId` once with a conditional update. The module has no code path that updates or deletes an entry otherwise (README and `register-commission-models.ts` say so).
6. **Writes use an upsert (`$setOnInsert`) instead of insert + catch of a duplicate-key error**, because a duplicate-key error aborts the surrounding transaction in MongoDB. `exists` on an adjustment makes the event fail and run again (delta then 0); two racing transactions get a transient write conflict and `withTransaction` repeats the loser.
7. Menu: `menu: []` in the manifest (no screens in A1). Part B adds the entries and the group.
8. The integration tests sit at the module root (`commission-accrual.test.ts`, `commission-api.test.ts`), like `expense-api.test.ts`, because the boundaries lint forbids tests in `application/` and `presentation/` from importing infrastructure.
- **ADR-135:** matches the code; not changed. Plan Amendment 1 is already in `docs/plans/3.11.md`.
