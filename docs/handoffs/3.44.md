# 3.44 Docs-only pushes skip CI · handoff

Lead card (Opus 5.5), T3, 2026-10-26. Owner asked to make delivery faster without lowering the checks. Branch `s/3.44-ci-skip-docs`.

## Why
Every card pushed its handoff and STATUS row after a green CI run, and that docs-only push ran the whole suite again (about 15 minutes). Every lead state save on `main` did the same. On 2026-10-26 the three open cards ran 13 CI runs in three hours.

## What changed
- **`.github/workflows/ci.yml`:** `push` has `paths-ignore: ["docs/**"]`. A push whose changes are all under `docs/` runs nothing. A push with any other file runs everything, as before. Pull requests and the nightly run are unchanged.
  - Safe because no test or script reads `docs/` (grep of every `.ts`, `.mjs`, `.js` and `.json` file); the pre-commit hook formats Markdown with Prettier; the secrets job scans every commit since its baseline, so the next run also scans the skipped docs commits.
  - Module `README.md` files are outside `docs/` and still run CI (the module contract test counts their lines).
- **`scripts/card-check/card-check.mjs`:** when HEAD has no CI run, the CI check uses the last commit that changed anything outside `docs/` (`git log -1 HEAD -- . ':(exclude)docs'`). The line then names that commit and says "later commits change docs/ only". If HEAD itself changes code, nothing changes: HEAD needs its own green run.
- **`docs/plans/parallel-sessions-guide.md` §8:** a new step 2 runs the changed tests, lint and typecheck, and for screen cards the app's browser suite, locally before the first push (Docker and Redis run on this PC again). Step 8 no longer waits for a second CI run after the handoff push.

## Deviations
None (no plan: lead card).

## Tests
- `scripts/card-check/card-check.test.mjs`: "accepts the green run of the last code commit when later commits change docs only"; "fails when the last code commit has no green run either"; the seven existing tests unchanged and passing.
- Local: `npx vitest run scripts/card-check` (9 passed), eslint and Prettier on the changed files.

## Known gaps
- GitHub runs the workflow anyway when it cannot compute the changed files (more than 1,000 commits in a push, or a diff timeout). That only costs time.
- The first push of a new branch that has only docs commits may still run CI. That also only costs time.
