## 3. Named tests

| Plan / DoD case | `it(...)` | Body checks |
|---|---|---|
| Happy / CRUD | `creates, reads, lists, and updates a delivery zone` | 201, GET 200, list meta `{page:1,limit:50,hasNext:false}`, PATCH version 2 / fee / name |
| Overlap rule + index | `refuses overlapping ACTIVE areaCodes as a rule error and as an index conflict` | in-body duplicate → 400 `VALIDATION_ERROR`; second ACTIVE zone → 409 `CONFLICT` |
| Same area after INACTIVE | `lets a new ACTIVE zone claim an area after the previous zone is INACTIVE` | 201 then INACTIVE then a new ACTIVE id |
| Empty / duplicate / fee | `refuses empty or duplicate areaCodes and a negative or non-integer fee` | all 400 `VALIDATION_ERROR` |
| Permission denied | `refuses every delivery-zone route without permission sales.deliveryZone.manage` | STAFF, all four routes 403 `FORBIDDEN` |
| One-location | `refuses a member whose permission is held at one location only on every zone route` | OWNER at `locationA1` only, all four routes 403 |
| Cross-org | `hides another organization's delivery zones with 404` | foreign org URL 404; foreign id on own org 404 `NOT_FOUND` |
| Stale 409 | `refuses a stale version with 409` | version 99 → 409 `CONFLICT` + `currentVersion: 1` |
| Pagination | `refuses a list limit above 100 and defaults to 50` | `limit=101` 400; `limit=1` hasNext; default meta.limit 50 |
| Idempotency create replay | `the same Idempotency-Key returns the first create and writes nothing twice` | same body, one `zoneKey` in the list |
| Idempotency update replay | `the same Idempotency-Key returns the first update and writes nothing twice` | version stays 2 |
| Changed-body replay | `refuses a replay of the same Idempotency-Key with a changed body` | create and update 422 `IDEMPOTENCY_MISMATCH` |
| Missing header | `requires an Idempotency-Key for create and update` | `{ path: "Idempotency-Key", messageKey: "validation.idempotency_key_required" }` |
| Concurrent unique index | `unique index refuses a second concurrent ACTIVE zone claiming the same areaCode` | `[201, 409]` + `CONFLICT` |

S1a unique index `{ organizationId: 1, areaCodes: 1 }` with `partialFilterExpression: { status: ACTIVE }` plus repository `isDuplicateKeyError → conflict({})` is what the overlap/concurrent tests exercise. ## 5. Accepted deviations (not must-fix)

1. **List/id schemas** appended to S1a-owned `sales-delivery-schemas.ts` (default 50, `deliveryZoneIdParamsSchema`). Plan did not list that file; every other tenant router imports query/params from `@banijjik/validation`. Add-only, proven by `deliveryZoneListQuerySchema` tests. Accept.
2. **Overlap “rule error”** is 400 `VALIDATION_ERROR` (in-body duplicate codes) plus unique-index 409. `SALES_DELIVERY_RULE_KEY` has no overlap key (S1a). Inventing one would be scope. Unique index is the concurrent-safe overlap guard (guide §11.2). Accept.
3. **`iconKey: "truck"`** — plan left the icon unspecified; inventory menu already uses that key. Accept.
4. **Entitlement / me-config menu tests** gained `sales.deliveryZones` so pinned owner menus stay green. Necessary, not a silent behaviour change. Accept.
5. **Full `SalesDependencies` on the use case** — plan said so; no test builds `SalesDependencies` literals. Accept.

## 6. Nits (do not block, do not start S1c)

1. Cross-org **PATCH** is not a named assertion. Foreign org URLs 404 from tenant middleware before the handler; foreign ids 404 from `findById(organizationId, …)`. Same as GET. Not a hole.
2. CASHIER is not a separate named actor. STAFF is the plan’s permission-denied case. CASHIER/STAFF are not `"ALL"`, so they do not receive the new module permission.
3. Happy-path test asserts `currency: "BDT"` for the RETAIL world. Production builds fee currency from `SalesCurrencyReader`. A non-BDT org is S1d’s mismatch case, not S1b’s.
