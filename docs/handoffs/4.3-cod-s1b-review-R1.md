## 6. Nits (do not block PASS or merge)

1. Permission-denied HTTP case uses `STAFF`, not also `CASHIER`. Grants already omit the key for both; STAFF is the stricter neighbour (has `sales.order.create`). A CASHIER line would only document D9.
2. Happy path asserts `fee.currency: "BDT"` rather than reading the org currency. Production does not hard-code `"BDT"`; RETAIL worlds are BDT. A reader assertion would survive a template currency change.
3. No HTTP assertion that a duplicate `zoneKey` is 409. S1a unique `{organizationId, zoneKey}` plus `isDuplicateKeyError` → `conflict({})` already maps it.
4. PATCH of `areaCodes` onto another ACTIVE zone’s area is not a separate case. Create overlap + concurrent unique-index tests cover the index.
5. GET of an unknown `deliveryZoneId` in the caller’s org is not named (foreign id in own org is). `requireZone` → `recordNotFound()` is 404.
6. `ManageDeliveryZonesUseCase` takes full `SalesDependencies` instead of `Pick<..., "deliveryZones" | "currency" | "clock">`. Matches other sales use cases; not a defect.
7. Name-only PATCH still calls `currency.read` even when `feeMinor` is absent (`changesOf` omits `fee`). Harmless extra read; D3 still leaves an unedited fee in its stored currency.
8. No grants unit test that CASHIER/STAFF lack `SALES_DELIVERY_ZONE_MANAGE` (the website-domain grants test is the precedent). HTTP STAFF case is the DoD proof.
9. `expect.any(String)` for `deliveryZoneId` does not assert UUID v7. Entity uses `newId()`.
10. Settings menu `path: "settings/delivery-zones"` 404s until S1e ships the page. Planned; do not build that screen in S1b.
