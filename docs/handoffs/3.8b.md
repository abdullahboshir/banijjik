## Implementation

- Accounting owns all account/journal operations and report aggregation. Bookkeeping owns no collections and uses accounting's public index. Removed broken deep imports, invalid request-context fields, invalid controller bindings, duplicate validation declarations and missing sequence mode/type exports.
- Custom accounts use per-organization `C-n`, optional active same-type parent codes, audited creation and atomic versioned name/status updates. Existing records without `version` read as version 1 and transition atomically to version 2 on their first edit. System names can change; system code/type/status remain protected. Account list pagination is bounded at 100, ordered by type/code, with balances.
- Manual entries validate positive one-sided lines (2–20), safe integer totals, balancing, organization currency, date and location assignments. Source and journal identifiers are UUID v7; the posting key is `manual:<journalEntryId>`. The separate internal `operationKey` binds actor and Idempotency-Key, with a unique organization-prefixed partial index. A canonical fingerprint rejects changed-payload retries even after the HTTP replay record is lost.
- Approval consumption, journal insertion, sequence, audit and outbox share the same transaction/session. Tokens bind the canonical memo/date/location/lines, total, requester and persisted approval location. `ALL` approval is available only to approvers with organization-wide approval grants. The OWNER exception comes from the real role assignments and resolved setting, never request flags.
- A unique partial index enforces one reversal per journal entry. Reversals mirror the original exactly and leave automatic source records unchanged; a concurrent second correction is a deterministic 409 instead of a possible replay. Account posting reservations serialize posting against archival. Journals remain append-only.
- P&L and balance sheet use organization-filtered journal aggregations, include archived accounts and apply debit/credit normal signs. Retained earnings are cumulative income minus expenses; the balance check includes them. The P&L location filter runs in the aggregation.
- BN/EN accounts, journal/detail/reversal, entry and statements screens use real APIs. They include mobile cards, decimal-to-minor-unit input conversion, paged account choices, retained form values and retry keys, lazy approval UI, period/location filters and a print layout. The trial-balance display uses mobile cards. The manifest moves its menu entry from Advanced settings to Money when bookkeeping is enabled.
- Added ADR-128, marked **Accepted (proposed)**. Added the generic manifest `hiddenWhenModuleEnabled` condition for the trial-balance replacement. Updated API/module catalog rows and the module README.
- The old entitlement test probe used the bookkeeping key. It now uses the still-unimplemented payment-gateway key so the real bookkeeping manifest does not collide with a synthetic test module.

## Final implementation pass (2026-10-22)

- **Reversal conflicts:** `postJournalEntry`/`postReversal` accept `rejectExisting`; `ReverseEntryUseCase` sets it. Any pre-existing or raced reversal now throws `entryAlreadyReversed()` (409) regardless of which unique index Mongo reports first, while payment-handler replays keep the idempotent return.
- **Manual duplicate operation:** a duplicate `operationKey` insert with a different generated source id now returns 409 CONFLICT (`{ operation }`) instead of an untyped 500; the client retry then finds the committed entry through `findManualOperation`.
- **Custom account duplicate:** a duplicate `C-n` insert returns a domain 409 with a new BN/EN `errors.accounting.account_code_conflict` message instead of `Error("Duplicate custom account code")`.
- **Account PATCH:** `accountUpdateRequestSchema` now requires `name` or `status` alongside `version`; a version-only update is rejected by request validation (`400`), and the API test asserts it.
- **Statement reads:** both statement routes now require ALL-location grants, matching accounts, journal, trial balance and the API catalog row; this closes a cross-location read gap.
