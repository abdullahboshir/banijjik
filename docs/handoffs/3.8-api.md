# Handoff: card 3.8, part A · Payments, dues and store credit API

Implemented by: Antigravity (Sonnet) · Date: 2026-10-22 · Plan: `docs/plans/3.8.md` · Branch: `s/3.8-api-payments`

## What was built
- **Contracts (`@banijjik/contracts/payment`):**
  - Payment method enum (`CASH | BKASH | NAGAD | BANK | CARD | STORE_CREDIT | GATEWAY | COD_COURIER | RIDER_CASH`), payment directions (`IN | REFUND | REVERSAL`), store credit entry kinds and directions, payment status (`UNPAID | PARTIAL | PAID | REFUNDED`).
  - Permissions: `payment.payment.{read,receive,refund,refundWithoutApproval}`, `payment.due.read`, `payment.storeCredit.{read,adjust}`.
  - Setting keys: `payment.methods` (structured), `payment.refund.managerWithoutApproval` (boolean), `payment.storeCreditExpiryDays` (number).
  - Sequence key: `PAYMENT`.
  - Audit actions: `PAYMENT_RECEIVED`, `PAYMENT_REFUNDED`, `PAYMENT_REVERSED`, `STORE_CREDIT_ADJUSTED`.
  - Contracts subpath export: `@banijjik/contracts/payment`.
- **Validation (`@banijjik/validation/payment`):**
  - Request and query schemas for `receivePaymentSchema`, `refundPaymentSchema`, `reversePaymentSchema`, `adjustStoreCreditSchema`, `listPaymentsQuerySchema`, `listDuesQuerySchema`, `listStoreCreditEntriesQuerySchema`.
  - Structured setting schema for `payment.methods` registered in `@banijjik/validation/settings`.
  - Validation subpath export: `@banijjik/validation/payment`.
- **Commerce / Payment Module (`apps/api/src/modules/commerce/payment`):**
  - **Domain:**
    - Aggregate root `Payment` (append-only, immutable).
    - Aggregate root `StoreCreditEntry` (append-only ledger).
    - Entity `PaymentSummary` (per-request balance projection: total, allocated, refunded, paymentStatus, due).
    - Domain rules in `payment-rules.ts`: `computePaymentStatus`, `validatePaymentAllocations`, `validateRefundAllocations`.
    - Errors in `errors.ts`.
  - **Infrastructure:**
    - Mongoose schemas with compound indexes (`PaymentSchema`, `StoreCreditEntrySchema`, `PaymentSummarySchema`). Unique partial index on `(organizationId, method, externalReference)` for mobile money idempotency/uniqueness.
    - Repositories: `MongoPaymentRepository`, `MongoStoreCreditRepository`, `MongoPaymentSummaryRepository`.
    - Adapters: `ContactStoreCreditAdapter` (atomic balance adjustment with optimistic concurrency locking), `PaymentPostingSourceAdapter` (for accounting posting engine), `MongoBookingPaymentStatusAdapter`.
    - Scheduled jobs: `expireStoreCredit` registered via `kernel/jobs`.
  - **Application Use Cases:**
    - `ReceivePaymentUseCase`: cash change handling, overpayment auto-credited to store credit when contact is provided, mobile money external reference uniqueness, idempotency key support.
    - `RefundPaymentUseCase`: manager/approval gating with `ApprovalVerifier`, refund to store credit or source method.
    - `ReversePaymentUseCase`: one-time reversal with `APPROVAL_ACTION.PAYMENT_REVERSAL`, mirrored allocations.
    - `AdjustStoreCreditUseCase`: staff manual adjustment with `APPROVAL_ACTION.STORE_CREDIT_ADJUSTMENT`.
    - `GetDuesUseCase`, `GetPaymentUseCase`, `ListStoreCreditEntriesUseCase`.
  - **Presentation & Routes:**
    - `PaymentController`, `buildPaymentTenantRouter`.
    - Tenant router mounted in `routes/v1.ts` and registered in `routes/tenant-module-routers.ts`, `routes/module-registry.ts`.
    - Handlers and scheduled jobs registered in `start-worker.ts`.
    - Grants: Cashier has `payment.payment.{read,receive}`, Manager/Owner has refund/reversal/adjust grants.
- **Booking Integration:**
  - `BookingPostingSourceAdapter` and `BookingPaymentStatusAdapter` wired.
  - Deposit check enforced on booking confirmation when `booking.deposit.required !== NONE`.
  - Payment status reflected on booking read endpoints.
