Implemented by: Qoder agent (Sonnet) · Date: 2026-10-25 · Plan: `docs/plans/3.32.md` (Refresh 1), decision 10 + Part B tests · Branch `s/3.32-ui-enrollment-refunds` (T2, merge check) · Based on `main ee8e6a10` (after Part A merged, `docs/handoffs/3.32-api.md`).

## What was built

- **Refund dialog takes any refund target and a maximum** (`apps/admin/src/payments/refund-dialog.tsx`):
  - `RefundTarget` (exported): `locationId`, `contactId`, `method`, `amount`, `allocations` — a `PaymentResponse` satisfies it, and an enrollment period answers it with the period as its only allocation. `RefundDialogProps.payment` is now `RefundTarget`, so payments and enrollment periods share one dialog.
  - New `maxAmount` prop: `isAboveRefundLimit` (exported; a currency other than the limit's counts as above) shows `payments.refund.invalidAmount` under the amount field and disables submit **before sending**. The API still enforces the same limit (`PAYMENT_REFUND_ABOVE_LIMIT`, Part A decision 5).
  - The method select and the footer actions moved to `refund-dialog-fields.tsx` (pure extraction, keeps the 60-line function budget). Store credit and every accepted payment method are offered, as before; approval-required answers still open the existing `ApprovalPinDialog` (`use-refund-flow` untouched).
  - `RefundDialogLabels` exported so a server page can build the dialog labels.
- **Cancel result names each refundable period** (`enrollment-detail-actions.tsx`, `use-enrollment-actions.ts`): the cancel outcome keeps `refundableByPeriod` from the Part A response; the result panel adds a "refundable per period" list (`enrollment.cancel.refundablePeriods`) with the period's name and amount for every period whose amount is above zero. The period names map (id → term) is passed in `EnrollmentActionLabels.periodNames`.
- **Refund button on cancelled periods** (`enrollment-periods-section.tsx`): a period row offers "Refund" only when the organization grants `PAYMENT_PAYMENT_REFUND` (new `canRefund`, built next to `canReceive` in `enrollment-detail-data.ts` **from the caller's permissions**, and the API enforces it too) and the period's Part A `refundRemaining` is above zero. The button opens the lazy refund dialog with that period as the one allocation (`requestType: ENROLLMENT`, `requestId: enrollmentPeriodId`), the enrollment's location and bill-to contact, and `maxAmount = refundRemaining`. On success the sheet state clears and the page reloads (the button disappears with the spent limit, rule 6: the page reloads, it does not race).
- **i18n** (add-only, both catalogs): `enrollment.detail.refund`, `enrollment.cancel.refundablePeriods` in `packages/i18n/src/catalogs/screens/{bn,en}.json`.
