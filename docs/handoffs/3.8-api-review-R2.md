## Blockers

B1. **A bKash or Nagad payment can never be reversed.** `buildReversalPayment` copies `externalReference` and `method` from the original. The unique partial index `{ organizationId, method, externalReference }` then rejects the reversal. `MongoPaymentRepository.create` maps that duplicate key to `paymentReversalAlreadyReversedError`, so the caller gets 409 "already reversed" for a payment that was never reversed. Every reversal test uses CASH, so CI does not see this.
   **Lead decision:** a REVERSAL stores `externalReference: null`. The original reference stays reachable through `reversesPaymentId`. Keep the index as it is.
   Test: receive with BKASH and a reference, then reverse → 201. Reverse again → 409.

B2. **The business date ignores the organization's timezone (R1 item 13).** `timeZone` is optional in the payment dependencies, and `buildPaymentTenantRouterFor` never passes it. Every payment therefore uses the literal fallback `"Asia/Dhaka"`. That is wrong for any organization in another zone, and it is a magic value.
   Fix: make the timezone reader **required** wherever a business date is computed (receive, refund, reverse, adjust, booking termination settlement, expiry job). Wire it from the organization's timezone, the same source booking uses, through the organization module's `index.ts`. Remove the fallback literal.
   Test: an organization in a zone other than Asia/Dhaka, and a clock just after local midnight → `businessDate` is the local date.
