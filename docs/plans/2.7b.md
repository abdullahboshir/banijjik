## Goal
A business owner manages, in the admin app, on a phone:
- the business's **settings**: organization level, and per location where a setting allows it
- the **words** the app uses (terms)
- its **custom fields**: its own fields, plus hiding, renaming and reordering the template's
- its **optional modules**

All of it runs on the existing APIs, with menu entries that come from the manifests.

## Decisions
**Menu entries come from the manifests** (`AGENTS.md`). These are small API changes in the two manifests, add-only.

1. Entries, all in group `settings`, labels as message keys:

   | Manifest | `menuKey` | `path` | Permission | `order` |
   |---|---|---|---|---|
   | `settings` | `settings.general` | `settings/general` | `settings.setting.read` | 50 |
   | `settings` | `settings.terms` | `settings/terms` | `settings.setting.read` | 60 |
   | `settings` | `settings.modules` | `settings/modules` | `settings.setting.read` | 70 |
   | `custom-field` | `customField.fields` | `settings/fields` | `custom-field.definition.read` | 80 |

   Use existing icon keys. Update the generated menu expectations and the `/me/config` menu assertions; list each.

**Pages** (`apps/admin`, mobile first, i18n keys in both catalogs, lazy sheets)

2. **`settings/general`:** the resolved settings from `GET /settings`.
   - Each row shows the label (message key `setting.<settingKey>`; add labels for the two registered settings), the current value, and a source badge (System / Industry / Business / Location).
   - "Change" opens a sheet with a spec-driven input (the same kinds as 2.6's setting-default inputs; share the small mapping through `@banijjik/web-client` if both apps need it, otherwise keep an app-local copy and note it), plus "Reset to default" (`value: null`).
   - Settings with `allowsLocationOverride` show a location filter (`?location=`, the usual page filter, ADR-004) and edit the location row.
   - Buttons need `settings.setting.update`. Organization-level edits need it at ALL locations, and the API refuses otherwise: show the API's 403 message, and hide the button when `/me/config` says the key is not held at ALL.
   - Versions are sent; a 409 shows the reload message.

3. **`settings/terms`:** `GET /terms`. One row per term: key label, Bangla and English texts, a source badge per language. "Change" opens a sheet with both texts; "Reset" sends `null`. Needs `settings.term.update` at ALL.

4. **`settings/fields`:**
   - **Entity tabs** from the keys of `/me/config.fields` (today `organization` and `member`, after 2.7a), labelled through terms or message keys.
   - Per tab, the effective list with scope badges (Industry / Business) and the required, sensitive and bot-asked badges.
   - **Business fields:** create, edit, archive, through sheets mirroring 2.3's rules:
     - key locked after create
     - type locked after create
     - options can only be added
     - labels bn/en
     - the 50-field limit message
   - **Template fields:** hide (only if not required; the API's 422 otherwise), rename (label override bn/en), and reorder (sort order) through `PATCH /custom-fields/preferences`.
   - Buttons need the matching `custom-field.definition.*` key at ALL.

5. **`settings/modules`:** `GET /modules`. Each row shows the module name (message key `module.<key>`; the platform catalog already names modules, so reuse the keys where they exist), class, and status (On / Off by you / Not in your package).
   - "Turn off" and "Turn on" sheets with a reason; only for `tenantCanDisable`.
   - A module that others need shows "Needed by …" from `requiredBy`, and its button is disabled.
   - Needs `settings.module.update` at ALL.
   - Today no production module can be turned off, so the page shows its rows read-only. That is correct, not a stub; say it in the handoff.

6. **Budget and phone:**
   - every new route **≤ 170 KiB** initial JS
   - no sideways scroll at 375 px
   - add them to the budget and phone checks of the admin browser suite

- [ ] **Unit (mocked API):** each sheet sends the right body (version, `null` for reset, `locationId` for a location row); a 403, a 409 and a 422 show their messages; the field editor locks key and type on edit; hide is disabled for a required template field.

## Out of scope
- Any API behaviour change beyond the manifest menu entries, location custom fields, template editing (2.6).

## Risks & checks
- **The menu is manifest-driven:** do not add hard-coded menu entries in the admin app.
- **ALL-locations rules:** a one-location MANAGER must never see an edit button that the API would refuse.

## Done when
- An owner manages settings, terms, fields and modules from the admin app on a phone, within the API rules.
- The Opus review passes. After this card, Phase 2 is ready for its phase review.
