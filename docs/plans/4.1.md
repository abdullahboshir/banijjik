## Goal

A site owns a bounded, validated design and pages. It can publish one immutable snapshot atomically; public readers never see a half-save. Templates supply initial copies and platform-authored lock policies, with real manifest-derived sections. Existing directory websites remain functional.

## Decisions

1. Extend the shipped website module. Site is ORGANIZATION tenancy, one per organization; no location-owned theme. Page sections may bind an allowed public location, but do not change the viewer's global location. Never duplicate the store's business models.
2. A draft contains design, pages, static content and policy. Published versions contain immutable render snapshots. Readers resolve the current published version through a single Site pointer. Page edits affect only draft. Publish locks the Site version, validates the entire document and file references, inserts WebsiteVersion, advances the pointer, writes audit and outbox in one transaction.
3. A WebsiteTemplate revision is platform-owned (4.4). Adoption copies the revision and records its provenance. Branding is used at first creation, then explicitly re-applied by an editor if desired. Later branding/template changes never silently overwrite the site's own design.
4. Policy is authored by a platform operator. Tenant requests never contain policy, ownership, provenance or publication metadata. Evaluate the **resulting full document** against the stored draft and current policy; a PATCH is not permission to bypass restrictions. Missing policy entries deny edits.
5. LOCKED regions cannot change content, variant, bindings or position; CONTENT_ONLY changes only declared content fields; FULL changes content/variant/order within the registered schema and allowed keys. Tenant cannot delete locked sections, move one into another region, reuse another sectionId, or hide it through an empty replacement. Token-group locks are independently enforced. Required regions remain present exactly once.
6. Strict structured JSON, no HTML/CSS/JS, CSS URLs, arbitrary attributes or expression bindings. Text is escaped; links allow relative local paths and HTTPS, with mailto/tel only in typed contact fields. Rich text uses the existing safe Markdown rendering policy. Image references are fileId values of active, public, organization-owned website assets; never protected directory photos. Reusable templates have empty media slots; copying never transfers another tenant's file. Page paths must be unique, normalized and below the public CMS route space; reserved /api, /account, /auth, /checkout, /checkouts, /cart, /offerings and existing directory/static routes cannot be shadowed. Header/footer must have the corresponding sectionKey. StaticContent edits use reserved policy regions static.ABOUT, static.FAQ, static.GUIDE, static.TERMS, static.PRIVACY, static.REFUND; omitted policy denies tenant changes there too.
7. Bounded schema version 1: at most 20 pages, 30 sections/page, 100 menu links, total encoded snapshot <=256 KiB; text bounds per registry field. These are implementation safety bounds, not new billed package limits. Reject, never silently truncate.
8. Colour validation checks every actual foreground/background pairing including buttons, links, focus and overlays: normal text >=4.5:1, non-text controls >=3:1. Presets obey ADR-114; custom background cannot defeat contrast. Typography is a pair of the existing local font families (Inter/Noto Sans Bengali); schema permits only registered font-pair keys. Adding more fonts is a separate performance-reviewed change.
9. Token values come from finite enums except validated hex colours. Density is COMPACT/COMFORTABLE/SPACIOUS; radius NONE/SMALL/MEDIUM/LARGE; shadow NONE/LOW/MEDIUM; image ratio SQUARE/PORTRAIT/LANDSCAPE; mobile columns 1 or 2, tablet 1–3, desktop 1–4. CSS emitted by the renderer is from a fixed mapping, never concatenated untrusted CSS.
10. Sections: website owns header, hero, rich-text, faq, testimonials, contact and footer; catalog owns offering-grid/category-strip; booking owns schedule; enrollment owns plans; directory owns directory-search/directory-list. Manifests remain the sole availability authority. Contracts own serializable section/variant descriptors, validation owns schemas, packages/ui owns React renderers, and application ports own data readers. API/domain never import a React registry. Startup rejects duplicate/unknown declarations. The public DTO, not just the JSX renderer, filters sections against current resolver output; old snapshots cannot leak a disabled module's data.
11. Unsupported live data (e.g. ratings without a ratings capability) is absent from the registry. Static testimonial content is clearly tenant-authored. Offering cards obtain real name/price/image and kind-specific facts from 4.3; no stub data ships. B renders static sections; A3 registers website sections and A3D registers existing Track M directory sections only. Catalog/booking/enrollment declarations are owned by 4.3 A1/A3 and are added together with real readers. Until then their schema keys are known but not available in manifests, adoption or publishing. This avoids a circular dependency: 4.1 infrastructure can finish before the public-commerce readers exist.
12. Static pages: preserve existing URLs and import ALL saved pages, including unpublished drafts, into staticContent with includeInPublication flags. SiteDesign.staticContent uses StaticPageDraft; published projection drops excluded entries and draft-only flags. Before first whole-site publish, public reads keep the frozen legacy published pages; migration cannot temporarily erase a live site. After first publish only WebsiteVersion serves public reads. Legacy save uses the Site version returned by the adapter and one shared policy evaluator; it never writes the frozen legacy rows. Add publicationState and siteVersion to admin DTOs; do not reinterpret an old page version as a Site version. C2 updates both editor and page list. Idempotent migration records imported key/version once.
13. Restore means copy a historical version into a new draft, validate against **current** locks, modules and file visibility, and then publish as a new version through the same command. It never rewinds policy or mutates history. Policy changes increment Site.version and apply to all subsequent tenant actions.
14. All-site writes require WEBSITE_SITE_UPDATE / PUBLISH and organization-wide location authority. Existing WEBSITE_PAGE_READ/UPDATE stay for the legacy bridge. Platform writes are separately authorized/audited in 4.4. Reads exclude internal policy/provenance from public DTOs.
15. Publication event carries identifiers only. Cache invalidation is durable in 4.2; no remote call inside transaction. Duplicate publish with the same Idempotency-Key returns the original version; a competing stale expectedVersion gets 409.

## Interfaces & types

Types below live in @banijjik/contracts/website; string aliases are constrained by schemas and contracts registries, not arbitrary runtime strings. Entity IDs come from newId(). Existing LocalizedText is reused.

```ts
type RegionLock = "LOCKED" | "CONTENT_ONLY" | "FULL";
type TokenGroup = "color" | "type" | "shape" | "spacing" | "size";
interface SiteTokens {
  color: { primary: string; accent: string; background: string; surface: string;
    text: string; mutedText: string; onPrimary: string; focus: string };
  type: { fontPairKey: "inter-noto"; scale: "SMALL" | "MEDIUM" | "LARGE" };
  shape: { cardRadius: "NONE" | "SMALL" | "MEDIUM" | "LARGE";
    buttonRadius: "NONE" | "SMALL" | "MEDIUM" | "LARGE";
    inputRadius: "NONE" | "SMALL" | "MEDIUM" | "LARGE";
    imageRadius: "NONE" | "SMALL" | "MEDIUM" | "LARGE";
    border: "NONE" | "THIN" | "MEDIUM"; shadow: "NONE" | "LOW" | "MEDIUM" };
  spacing: { density: "COMPACT" | "COMFORTABLE" | "SPACIOUS" };
  size: { imageRatio: "SQUARE" | "PORTRAIT" | "LANDSCAPE";
    cardSize: "SMALL" | "MEDIUM" | "LARGE";
    columns: { mobile: 1 | 2; tablet: 1 | 2 | 3; desktop: 1 | 2 | 3 | 4 } };
}
type SectionContentByKey = {
  header: { links: readonly { label: LocalizedText; path: string }[] };
  footer: { links: readonly { label: LocalizedText; path: string }[] };
  hero: { heading: LocalizedText; body: LocalizedText; imageFileId?: string;
    actionLabel?: LocalizedText; actionPath?: string };
  "rich-text": { body: LocalizedText };
  faq: { entries: readonly { question: LocalizedText; answer: LocalizedText }[] };
  testimonials: { entries: readonly { quote: LocalizedText; attribution: LocalizedText }[] };
  contact: { heading: LocalizedText; phone?: string; email?: string; address?: LocalizedText };
  "offering-grid": { heading: LocalizedText };
  "category-strip": { heading: LocalizedText };
  schedule: { heading: LocalizedText };
  plans: { heading: LocalizedText };
  "directory-search": { heading: LocalizedText };
  "directory-list": { heading: LocalizedText };
};
type SectionKey = keyof SectionContentByKey;
interface SectionBase {
  sectionId: string; variantKey: string; regionKey: string;
  binding: null | { categoryId?: string; offeringIds?: readonly string[];
    locationId?: string; limit: number };
}
type SiteSection = { [Key in SectionKey]: SectionBase & {
  sectionKey: Key; content: SectionContentByKey[Key]
} }[SectionKey];
interface SitePage {
  pageId: string; path: string; title: LocalizedText;
  seo: { description: LocalizedText; noIndex: boolean };
  sections: readonly SiteSection[];
}
interface StaticPageDraft extends StorefrontSitePageResponse {
  includeInPublication: boolean;
}
interface SiteDesign {
  schemaVersion: 1; tokens: SiteTokens; header: SiteSection; footer: SiteSection;
  pages: readonly SitePage[];
  staticContent: readonly StaticPageDraft[];
}
interface RegionPolicy {
  regionKey: string; lock: RegionLock; required: boolean;
  sectionKeys: readonly string[]; maxSections: number;
  editableContentKeys: readonly string[];
}
interface SiteEditPolicy {
  regions: readonly RegionPolicy[];
  tokenGroups: Readonly<Record<TokenGroup, boolean>>;
  allowedColors: readonly string[] | null;
  allowedVariantsBySection: Readonly<Partial<Record<SectionKey, readonly string[]>>>;
  pageRules: { allowCreate: boolean; allowDelete: boolean; allowReorder: boolean;
    allowPathChange: boolean; editableMetadataKeys: readonly ("title" | "description" | "noIndex")[] };
}
type PublishedSiteDesign = Omit<SiteDesign, "staticContent"> & {
  staticContent: readonly StorefrontSitePageResponse[];
};
interface SiteDraftResponse {
  siteId: string; version: number; publishedWebsiteVersionId: string | null;
  design: SiteDesign; policy: SiteEditPolicy;
}
interface SaveSiteDraftRequest { expectedVersion: number; design: SiteDesign }
interface PublishSiteRequest { expectedVersion: number }
interface RestoreSiteRequest { expectedVersion: number; websiteVersionId: string }
interface PublishedSiteResponse {
  siteId: string; websiteVersionId: string; revision: number;
  design: PublishedSiteDesign; publishedAt: string;
}
interface SitePublicationPayload {
  siteId: string; websiteVersionId: string; revision: number;
}
interface SitePublicationCommands {
  saveDraft(input: SaveSiteDraftRequest): Promise<SiteDraftResponse>;
  publish(input: PublishSiteRequest): Promise<PublishedSiteResponse>;
  restore(input: RestoreSiteRequest): Promise<SiteDraftResponse>;
  unpublish(input: PublishSiteRequest): Promise<SiteDraftResponse>;
}
interface SitePolicyEvaluator {
  assertAllowed(input: { previous: SiteDesign; next: SiteDesign;
    policy: SiteEditPolicy; effectiveSectionKeys: readonly string[] }): void;
}
```

Content is validated by sectionKey and variantKey using the discriminated registry above; no untyped extension escape hatch. Registry-specific schema rejects every extra field. Serialized media identifiers are strings validated as UUID v7. Registered variants at launch: header SIMPLE/CENTERED, footer SIMPLE/COLUMNS, hero SPLIT/CENTERED, rich-text STANDARD/NARROW, faq STACKED/ACCORDION, testimonials CARDS/QUOTES, contact CARD/SPLIT; offering-grid GRID/LIST/COMPACT/CAROUSEL; category-strip CHIPS/CARDS; schedule LIST/CALENDAR; plans CARDS/COMPARISON; directory-search INLINE/PANEL; directory-list GRID/LIST. Heavy interactive variants load lazily and must meet existing route budgets. Registry validates each pair, not a global variant string allowlist.

API under /orgs/:organizationId/website:
GET/PATCH /site; PUT /theme (typed tokens plus expectedVersion); GET/POST/PATCH /layout-pages[/:pageId]; POST /publish; POST /unpublish; GET /versions?page=&limit=; POST /versions/:websiteVersionId/restore. All mutation endpoints use the full-document evaluator. Existing /pages/:pageKey remains the static bridge. Public GET /published-site is WEBSITE-gated. /versions is projected metadata, not all snapshots in a list.

New contracts: WEBSITE_SITE_READ/UPDATE/PUBLISH, WEBSITE_POLICY_DENIED, WEBSITE_DESIGN_INVALID, WEBSITE_REFERENCE_INVALID, WEBSITE_VERSION_CONFLICT, WEBSITE_SITE_PUBLISHED; existing CONFLICT/NOT_FOUND reused where equivalent. Permission values website.site.read/update/publish; owner/manager all-location grants only. Manifest owns route prefixes, permissions, sections and site.published event. No broad role check in controllers.

## Data

Site: siteId, organizationId, draftDesign, editPolicy, sourceTemplateKey/revision, publishedWebsiteVersionId nullable, nextRevision, version, audit fields. Unique {organizationId}; unique {organizationId,siteId}.
WebsiteVersion: websiteVersionId, organizationId, siteId, revision, schemaVersion, design, sourceTemplateKey/revision, publishedByUserId nullable, publishedByPlatformOperatorId nullable, publishedAt, audit fields. Append-only; unique {organizationId,siteId,revision}; list {organizationId,siteId,publishedAt:-1,websiteVersionId:1}. No version deletion in this phase.
A versioned CAS on Site serializes save/publish/restore/policy changes. Publishing produces PublishedSiteDesign through a dedicated public projection; excluded static pages and disabled sections are never serialized. WebsiteVersion remains a private stored snapshot; public /published-site returns only the current projection, with no arbitrary historical-version route. File status is checked before public resolution; neutral placeholders do not select another tenant's asset.

Migration is opt-in, transactionally serialized with legacy writes through a Site migration fence keyed by organizationId. A legacy edit racing creation either commits before import or retries against the new draft adapter; it cannot be lost between collection reads. Keep legacy rows frozen for pre-first-publish public fallback and rollback evidence, never dual-write. Re-running migration cannot re-import stale values.

## Audit correction: media, registry and version safety (2026-10-28)

F adds FILE_PURPOSE.WEBSITE_IMAGE with PUBLIC visibility to packages/contracts/src/file/file-purpose.ts and validates it through apps/api/src/modules/core/file/domain/purpose-rules.ts, application/use-cases/upload-file.use-case.ts and presentation/read-upload.ts. Reuse existing image decoding/size/quota/variants; do not mislabel banners as OFFERING_IMAGE or change private purposes. Only staff with file-create plus website-edit authority can select this purpose. Add file upload/visibility tests; old file records need no migration. No infrastructure classes exported.

Section binding is a discriminated schema: static sections require binding:null; dynamic section IDs belong to the current organization/location and max item counts follow the assurance budget. Required metadata lives in one contract descriptor. Normalized page paths reserve all application routes; explicit unpublish operation (website.site.publish, version + idempotency) clears public pointer in a transaction while retaining history and writes an event. It must not reactivate legacy fallback after the first publication; Site.hasPublishedOnce records that one-way boundary.

Tests added: P4-07/P4-08/P4-09/P4-12/P4-18/P4-23 in [assurance](phase-4-assurance.md); publication replay after crash has one revision; concurrent migration/legacy edit loses no draft; changing a disabled section filters its payload before serialization. Snapshot readers support declared schema versions; unknown versions fail closed.

The policy evaluator also covers page metadata/path/order/create/delete, static publication inclusion and header/footer navigation, not only section content. Missing policy entries deny changes. allowedVariantsBySection is intersected with registry variants; FULL region editing never overrides this palette. Page deletion cannot remove a locked/required region; reparenting/renaming cannot bypass region identity. A first adoption supplies explicit conservative pageRules. Add direct API tests for each bypass. All setting/limit/error/unpublish-event constants are contracts-owned; Site stores hasPublishedOnce and canonicalSiteDomainId from 4.2, with no duplicate isCanonical flag. Largest risk is treating draft policy as client authority or letting legacy page saves bypass publication. API tests must call the routes directly. Bound actual encoded payload size and query count. Run touched contracts/validation/UI tests, API website integration tests, workspace typecheck/lint, and Track M browser regressions after C. Full gates in CI; report real output. No expensive full local suite for this docs plan.
