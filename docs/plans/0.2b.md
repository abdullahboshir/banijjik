# Plan: card 0.2b · CI, secret scanning, PR template, Claude Code hook

Tier: T2 · Planned by: Opus 5.5 · Date: 2026-10-10 · Based on commit: `b772501` (main) · **Starts after 0.2a and 0.3 are merged** (needs their scripts and the `apps/api` package).

## Goal
Every push and pull request on GitHub runs install, lint, format check, typecheck, test and build, plus a secret scan. A PR cannot be opened without the Definition-of-Done checklist in front of the author. Claude Code in this repo is blocked from editing `.env*` files.

## Inputs read
- `docs/03-ROADMAP.md` card 0.2, `AGENTS.md` (DoD, hard rules), `docs/05-CONVENTIONS.md` ("Git")
- Output of 0.2a (`lint`, `format:check` scripts) and 0.3 (`apps/api`)
- Owner answer 2026-10-10: CI runs on GitHub Actions. The repo is public on GitHub.
- ADR-020 (performance budgets are checked in CI from Phase 6, not here)

## Decisions
1. **One workflow `ci.yml`** with jobs `verify` (install, lint, format:check, typecheck, test, build) and `secrets` (gitleaks). Triggers: `pull_request` and `push` to `main`. `concurrency` cancels superseded runs on the same ref.
2. **Least privilege:** `permissions: contents: read` at workflow level. No secrets are needed or used.
3. **Node 22 LTS** via `actions/setup-node` with npm cache. `npm ci` (never `npm install`). Pin third-party actions to a **full commit SHA** with the version in a trailing comment. The implementer looks up the current SHA of each action tag at implementation time and records them. This protects a public repo from tag hijacking.
4. **Services for tests:** none yet. Tests in 0.1–0.3 need no database. Integration tests with Mongo/Redis service containers are added by the first card that needs them (0.4).
5. **gitleaks:** run the official CLI via the `gitleaks/gitleaks-action` (verify current licensing: it is free for personal-account repos; if the repo moves to an organization it needs a license key, in which case switch to running the gitleaks Docker image). Config `.gitleaks.toml` extends defaults and allow-lists only `.env.example` placeholders. `fetch-depth: 0` so history is scanned.
   - **Known finding:** history before `61496c1` contains the committed `apps/backend/.env` secrets. The scan on full history **will fail** until the owner rewrites history or accepts a baseline. Decision: scan **new commits only** (`gitleaks` `--log-opts` limiting to the range since the baseline commit `b772501`) and record the history problem as owner task P1. Do not hide it: the handoff states that old history still holds real secrets.
6. **PR template** `.github/pull_request_template.md`: summary, card id, plan link, DoD checklist (tests incl. cross-org, validation, permission, mobile check with screenshots for UI, i18n keys, no TODO/stub, STATUS + handoff updated), risk notes.
7. **Issue templates:** none.
8. **Claude Code hook:** `.claude/settings.json` with a `PreToolUse` hook for `Edit`, `Write` and `NotebookEdit` calling `node scripts/hooks/claude-block-env.mjs`. The script reads the hook JSON from stdin, and if `tool_input.file_path` matches `(^|/)\.env(\..*)?$` and is not `.env.example`, prints a reason and exits with code 2 (block). Follow the current Claude Code hooks documentation for the exact stdin/exit-code contract and verify by piping sample JSON. A `Bash` matcher is out of scope (shell commands are guarded by permissions, not this hook).
9. **Branch protection** is a GitHub setting the owner applies by hand. Document the exact steps in `docs/ops/github-setup.md` (require the `verify` and `secrets` checks, require PR, no force-push to `main`, linear history optional). Do not try to automate it.
10. **Dependabot** is out of scope here (decide in 6.3 hardening).

## Interfaces
`claude-block-env.mjs` contract:
- stdin: JSON `{ "tool_name": string, "tool_input": { "file_path"?: string, "notebook_path"?: string } }`
- block: exit code 2 and a message on stderr: `Blocked: .env files must be edited by the owner, never by an agent. Use .env.example for documentation.`
- allow: exit code 0, no output.

## Tests (must exist and pass)
- [ ] hook blocks `apps/api/.env`, `.env.local`, `C:\x\.env.production`, and a notebook path ending in `.env`
- [ ] hook allows `apps/api/.env.example`, `docs/env.md`, `src/environment.ts`
- [ ] hook allows (exit 0) malformed or empty stdin and calls without a path, so it never breaks other tools
- [ ] `npm run ci` passes locally from a clean install
- [ ] `npx gitleaks` (or the Docker image) finds nothing in the new-commits range and **does** find a planted fake AWS key in a temp repo (proves the config works)
- [ ] workflow YAML is valid (`actionlint` via Docker or `npx` if available; else state that it was not run)

## Risks & checks
- **First CI run can only be verified after a push.** The implementer cannot push (AGENTS.md). The handoff must say so, and the owner pushes and reports the run. Until then the card is `implemented (CI run unverified)`.
- **Action SHAs go stale:** record each SHA with its version in the workflow comments so the owner can update them.
- **gitleaks and old history:** see Decision 5. Verify the range limit really excludes the old `.env` commit.
- Paste in handoff: `npm run ci`, hook test output, gitleaks outputs, `actionlint` result.

## Done when
- Files exist, local checks pass, hook tests pass, handoff states exactly what was and was not verified (especially the unverified first CI run).
- `docs/ops/github-setup.md` lets the owner enable required checks in 5 minutes.

## Refresh · 2026-10-10 · Opus (banijjik-7b), based on main `5335ec5`
0.2a and 0.3 are merged. Changes to this plan:
1. **Audit gate:** the `verify` job runs `npm audit --omit=dev --audit-level=high` as a failing step. It then runs `npm audit --audit-level=high || true`, so dev-only findings are only reported. Why: 0.2a's review found 5 dev-only findings under `eslint-plugin-boundaries` with no non-breaking fix. Record this in `docs/ops/github-setup.md`.
2. **Hook scripts folder:** `scripts/hooks/` already exists (0.2a `block-env-commit.mjs`). Put `claude-block-env.mjs` and its test there, and follow the same test style (temp dirs, no real repo). The test must run in `npm test`: add it to the existing `tools/lint-tests` vitest config, which already runs the hook tests. Do not create a second test runner.
3. **CI cache:** add an `actions/cache` step for `node_modules/.cache/mongodb-memory-server` (key: OS + `package-lock.json` hash). Card 0.4b's tests download a MongoDB binary.
4. **`npm run ci`:** `lint && format:check && typecheck && test && build`. In CI, use `npx turbo run build typecheck test --force` style commands only if cache issues appear. Default is the plain scripts.
5. Runs **in parallel with 0.4a**. Shared files: root `package.json` (add-only) and `package-lock.json` (the second branch to merge regenerates it).
