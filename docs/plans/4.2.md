## Decisions

1. Keep the existing Next storefront and same-origin API proxy. Host→organization mapping is trusted only after server-side registry lookup. Never use a query/body organizationId, forwarded browser header or arbitrary Origin to select a site. API public paths still name organizationId and enforce it against customer/guest identity.
2. Normalize host to ASCII lower-case via the platform URL/IDNA utility; strip one terminal dot; reject URL schemes, userinfo, path/query, commas, wildcards, IPs, empty labels and production ports. Development localhost ports are a config-only exception. Reserved platform/API/admin hosts and the SaaS zone apex cannot be claimed.
3. Free subdomains resolve an active organization's exact slug. Custom domains resolve an enabled HostClaim plus active tenant/site eligibility. A provider API outage does not interrupt an already-active site: request routing never calls Cloudflare. Only an unavailable authoritative local lookup yields retryable 503; unknown/removed hosts yield 404. Health reconciliation records unknown provider status without pretending ownership loss or new verification success.
4. Globally unique HostClaim is **platform routing data** in platform/operations, tenancy NONE; SiteDomain is tenant-owned WEBSITE data with tenant plugin. The global record exists because organization-first unique indexes cannot enforce host uniqueness across organizations. Website calls a narrow HostClaim port; it never runAsSystem. Claim creation/removal and tenant state transition join one database transaction on today's shared connection.
5. Domain add reserves claim and writes SiteDomain + outbox transactionally; returns 202/PENDING. Only the worker talks to Cloudflare. Provider secrets are platform validated config and write-only; never in tenant DTOs. The worker stores provider reference, normalized status and safe diagnostic code.
6. State machine: PENDING→VERIFYING→ACTIVE; active proof loss→SUSPENDED; recovered fresh proof SUSPENDED→VERIFYING→ACTIVE; terminal provisioning refusal→FAILED; explicit retry FAILED→PENDING with a new operationGeneration; removal from every state→REMOVING→REMOVED. Persist reason and nextAttemptAt, not just a log. Version/generation CAS rejects late results. Removal quarantine includes outstanding remote requests: a late successful create must be discovered and deleted before releasing the claim.
7. Verify enqueues a rate-limited job, not a synchronous external call. Verify both ownership and TLS; mere CNAME presence or a successful TLS handshake is not proof. DNS checks use bounded resolver calls, not HTTP fetches to tenant-provided URLs (SSRF).
8. Deletion transactionally disables HostClaim and clears Site.canonicalSiteDomainId if it pointed at this domain. Fallback is the known free subdomain. Provider cleanup runs afterward; claim stays quarantined until reconciliation proves no pending/in-flight provider resource remains. Re-claim requires fresh ownership and generation. A delayed worker cannot delete a newer generation's hostname: compare claim ownership and provider reference before each external effect and reconcile uncertain results.
9. Reconcile provider state every five minutes with paged jobs; renewals/lost ownership suspend routing. Application routing uses the authoritative claim generation. Caches of immutable design can be long-lived; domain/organization availability is checked on every request before using cached content.
10. Start with exact subdomains such as shop.example.com or www.example.com. The wizard only promises root/apex support if the configured Cloudflare account and DNS arrangement demonstrably support it; otherwise show the supported www/subdomain route. Never promise all DNS providers work with one record. Return the provider's current ownership/TLS records separately.
11. No cross-domain session migration. Host-only cookies remain host-only; visitors sign in again on a different hostname. Canonical public links use the site's selected ACTIVE domain (fallback subdomain); auth/account/checkout endpoints never redirect across hosts and never put tokens in URLs.
12. One server resolve call per request returns authoritative organization eligibility, host generation and canonical pointer; request-local memoization shares it across layout/loaders. Cache only normalized parsing and <=30-second negative results, with LRU <=2,000 entries; a negative cache may delay a new site <=30 seconds. Never positively cache eligibility across requests. Do not make one database/resolve call per section. DB lookup failure remains 503 and is not negative-cached.
13. Cache immutable, public render/data projections only, keyed by organizationId + websiteVersionId + locale + locationId + projection/version. Cache key includes all normalized query dimensions. Authorization-dependent directory tiers, customer headers, account/tracking/checkout/quotes/availability/preview remain private,no-store; no Set-Cookie response is cached. Existing personalized root layout means rendered HTML is private until an explicitly separated anonymous shell exists.
14. CDN serves immutable public file variants and explicitly public version assets; do not cache HTML/API by a broad extension/path rule. Content/page removal, entitlement change and suspension have an authoritative gate outside stale data caches. A public catalog cache is a hint, never a stock/price authority.
15. Publication emits an outbox invalidation job with organization/version; repeats are harmless. If invalidation fails, origin reads the latest Site pointer, so old snapshot caches cannot become the new published design. Worker retries; platform operational diagnostics show persistent failures.
16. SEO: server-generated title/description/lang from LocalizedText; canonical uses trusted registry host and normalized path. Sitemap includes published public pages/offerings only, paginated sitemap index for large catalogs. Exclude preview/account/cart/checkout and directory listings whose existing noindex policy remains. robots is not access control. Structured data includes only real supported facts, no invented ratings or availability.
17. Preview route is authenticated, no-store, noindex and click-disabled. 4.4/4.5 use same-origin authenticated preview data and shared renderer; no bearer link in query strings and no public draft endpoint.
18. Domain management requires website.domain.manage and all-location authority. List is page/limit<=100. Host claims are never listed by ordinary tenant APIs.

## Data

SiteDomain: siteDomainId, organizationId, siteId, hostname, status, providerHostnameId nullable, operationGeneration, nextAttemptAt, lastVerifiedAt, safeDiagnosticKey nullable, version and audit fields. Indexes {organizationId,siteDomainId} unique; {organizationId,hostname} unique; {organizationId,status,nextAttemptAt,siteDomainId}. Site.canonicalSiteDomainId is the ONLY stored canonical selector; DTO isCanonical is computed. Never persist a second isCanonical boolean per domain.
HostClaim: hostClaimId, hostname globally unique, organizationId, siteDomainId, enabled, generation, quarantineUntil, version, audit fields; platform record explicitly documented. Remove public mapping before queue work. Worker scans registered organizations/jobs through approved kernel system reasons, then tenant context; no module-level bypass.
Outbox payloads do not carry DNS secrets. Ownership records are public DNS material but no credentials enter logs. Existing organizations need no custom-domain migration.

## Audit correction: bounded recovery and consistent routing (2026-10-28)

A3 worker uses keyset batches <=100, bounded provider concurrency/timeouts/backoff and one in-flight job per domain/generation; operator retry/removal is available after a terminal failure. Keep a durable DomainOperation record (domainOperationId UUID v7, organizationId/siteDomainId/generation, action, provider reference, state, nextAttemptAt, version/audit; unique org/domain/generation/action) so a response lost after remote creation can be reconciled by hostname. It is not a ledger or alternate domain authority. Include this model, repository and worker tests in A3's exact file budget before starting.

Canonical select is a CAS on Site, proving domain belongs to that site and is ACTIVE within the transaction. Delete, proof-loss suspension and select write the same Site pointer and domain version; suspension clears a matching canonical pointer to the free-subdomain fallback. Reactivation does not silently replace a subsequently selected canonical host. DomainOperation is platform/operations routing metadata, accessed through that owner's public port, never a tenant repository bypass. Provider callbacks/jobs are not browser routes. Secrets stay in validated platform config; adding a hostname never exposes or accepts tenant-selected provider base URLs. Require no-private-cache tests for direct API responses as well as Next proxy responses.

Shared tests: P4-10/P4-11/P4-12/P4-20/P4-21 in [assurance](phase-4-assurance.md). Also test provider outage with active site, recovery from SUSPENDED, FAILED retry, select-versus-delete, late create after delete and worker restart with uncertain external result. Budget verification costs/repeated requests without inventing new billed package limits.

### A2 behaviour (binding)

- Tenant plugin; `organizationId` never from the body. Site is ORGANIZATION; writes use `website.domain.manage` + `requireAllLocations`. Mutations take `Idempotency-Key`.
- No Site row → `NOT_FOUND` (4.5 creates the Site). Do not call `Site.create` here.
- `POST /website/domains` `{ hostname }`: normalize via `hostClaims.reserve` in one `withTransaction` with the SiteDomain insert; return **202** PENDING. Same key replays the first row.
- `POST /website/domains/:siteDomainId/verify` `{ version }`: CAS, enqueue `DOMAIN_VERIFICATION_REQUESTED`, do **not** call Cloudflare. A3 consumes the outbox.
- `DELETE /website/domains/:siteDomainId?version=`: same transaction `hostClaims.disable` + SiteDomain REMOVING + clear `Site.canonicalSiteDomainId` when it matches; event `DOMAIN_REMOVAL_REQUESTED`.
- `PATCH /website/domains/:siteDomainId` `{ version, expectedSiteVersion, isCanonical: true }`: CAS both SiteDomain (must be ACTIVE) and Site pointer. `isCanonical` is not stored on SiteDomain.
- `GET /website/domains?page=&limit=`: limit ≤ 100, metadata only.
- `Site.setCanonical` / `clearCanonical` bump `version`. Indexes: `{ organizationId, siteDomainId }` unique; `{ organizationId, hostname }` unique; `{ organizationId, status, nextAttemptAt, siteDomainId }`.
- Worker/provider files are A3. Fake HostClaims in unit tests; HTTP tests use `createMongoHostClaims` with test reservations.
