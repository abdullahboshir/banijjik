## Goal

A business staff member can manually record courier shipments (consignments) for orders across supported manual couriers (`STEADFAST`, `PATHAO`, `REDX`, `PAPERFLY`, `OTHER`) with tracking numbers, dispatching the order into `SHIPPED` status via `ShipOrderUseCase`, and record courier settlements that clear collection payment batches with verified fees and net received amounts, with append-only reversal support under manager approval.

## Decisions

1. **Manual carrier operations without third-party API automation (ADR-131, ADR-137):**
   This card implements manual consignment booking and manual courier settlement. Carrier automation (automated webhooks, live booking APIs, provider credentials) is Phase 5.2. Supported manual courier keys: `STEADFAST`, `PATHAO`, `REDX`, `PAPERFLY`, `OTHER`.
2. **Consignment lifecycle and identity:**
   Every consignment is identified by UUID v7 `consignmentId`. It binds `organizationId`, `locationId`, `orderId`, `attemptOrdinal`, `courierKey`, `trackingNumber`, `status` (`BOOKED`, `IN_TRANSIT`, `DELIVERED`, `FAILED`, `CANCELLED`), and audit fields. Compound index: `{ organizationId: 1, courierKey: 1, trackingNumber: 1 }` unique per organization.
3. **Dispatch Integration with Sales:**
   Creating a consignment for a confirmed/packed order dispatches the order into `SHIPPED` status via `ShipOrderUseCase` with `{ method: "COURIER", consignmentId }`. The write executes in a `unitOfWork` transaction.
4. **Courier Settlement mechanics (Plan 4.3-COD §5):**
   `CourierSettlement` clears up to 100 identified collection Payment IDs for a given courier and currency. Invariants:
   - All referenced payments belong to the organization and courier.
   - Exact balance: `grossAmount.amount = sum(payment.amount)`.
   - `courierCharges.amount >= 0` and `courierCharges.amount <= grossAmount.amount`.
   - `netReceived.amount = grossAmount.amount - courierCharges.amount`.
   - `currency` matches across all sums.
   - `receivedVia` must be one of `CASH`, `BANK`, `BKASH`, `NAGAD`.
   - Compound index: `{ organizationId: 1, courierKey: 1, externalReference: 1 }` unique.
5. **Settlement Reversals (Plan 4.3-COD §8):**
   Reversing a courier settlement is append-only by recording a reversal document referencing `reversesCourierSettlementId` with reason and manager approval token. Unique partial index `{ organizationId: 1, reversesCourierSettlementId: 1 }` prevents double reversals.
6. **Module Manifest and Entitlements:**
   Module `integration/courier` ships `module.manifest.ts` defining:
   - Category: `CORE`, group: `integration`.
   - Permissions: `courier.consignment.read`, `courier.consignment.create`, `courier.consignment.cancel`, `courier.settlement.read`, `courier.settlement.record`, `courier.settlement.reverse`.
   - Settings: `courier.defaultCourierKey` (default `"STEADFAST"`).
   - Events: `courier.consignment.created`, `courier.settlement.recorded`, `courier.settlement.reversed`.
7. **Readability & Limits (ADR-041):**
   Every file $\le 300$ lines. Every function $\le 60$ lines, cyclomatic complexity $\le 10$, nesting depth $\le 3$. No `any`, no nested ternaries. UUID v7 via `newId()`. Money in integer minor units.

## Interfaces & types

```ts
export const MANUAL_COURIER_KEY = {
  STEADFAST: "STEADFAST",
  PATHAO: "PATHAO",
  REDX: "REDX",
  PAPERFLY: "PAPERFLY",
  OTHER: "OTHER",
} as const;

export type ManualCourierKey = (typeof MANUAL_COURIER_KEY)[keyof typeof MANUAL_COURIER_KEY];

export const CONSIGNMENT_STATUS = {
  BOOKED: "BOOKED",
  IN_TRANSIT: "IN_TRANSIT",
  DELIVERED: "DELIVERED",
  FAILED: "FAILED",
  CANCELLED: "CANCELLED",
} as const;

export type ConsignmentStatus = (typeof CONSIGNMENT_STATUS)[keyof typeof CONSIGNMENT_STATUS];

export interface CreateConsignmentRequest {
  readonly orderId: string;
  readonly courierKey: ManualCourierKey;
  readonly trackingNumber: string;
  readonly shipOrder?: boolean;
}

export interface ConsignmentResponse {
  readonly consignmentId: string;
  readonly organizationId: string;
  readonly locationId: string;
  readonly orderId: string;
  readonly attemptOrdinal: number;
  readonly courierKey: ManualCourierKey;
  readonly trackingNumber: string;
  readonly status: ConsignmentStatus;
  readonly version: number;
  readonly createdAt: string;
  readonly updatedAt: string;
}

export interface RecordCourierSettlementRequest {
  readonly courierKey: ManualCourierKey;
  readonly paymentIds: readonly string[];
  readonly courierChargesMinor: number;
  readonly receivedVia: "CASH" | "BANK" | "BKASH" | "NAGAD";
  readonly externalReference: string;
  readonly businessDate: string;
}

export interface ReverseCourierSettlementRequest {
  readonly version: number;
  readonly reason: string;
  readonly approvalToken: string;
}

export interface CourierSettlementResponse {
  readonly courierSettlementId: string;
  readonly organizationId: string;
  readonly courierKey: ManualCourierKey;
  readonly paymentIds: readonly string[];
  readonly grossAmount: Money;
  readonly courierCharges: Money;
  readonly netReceived: Money;
  readonly receivedVia: "CASH" | "BANK" | "BKASH" | "NAGAD";
  readonly externalReference: string;
  readonly businessDate: string;
  readonly reversesCourierSettlementId: string | null;
  readonly version: number;
  readonly createdAt: string;
}
```

## Data

1. **`consignments` collection:**
   - Fields: `consignmentId`, `organizationId`, `locationId`, `orderId`, `attemptOrdinal`, `courierKey`, `trackingNumber`, `status`, `version`, audit timestamps & user IDs.
   - Indexes:
     - `{ organizationId: 1, courierKey: 1, trackingNumber: 1 }` (unique)
     - `{ organizationId: 1, orderId: 1, attemptOrdinal: 1 }`
     - `{ organizationId: 1, locationId: 1, createdAt: -1 }`

2. **`courier_settlements` collection:**
   - Fields: `courierSettlementId`, `organizationId`, `courierKey`, `paymentIds`, `grossAmount`, `courierCharges`, `netReceived`, `receivedVia`, `externalReference`, `businessDate`, `reversesCourierSettlementId`, `version`, audit timestamps & user IDs.
   - Indexes:
     - `{ organizationId: 1, courierKey: 1, externalReference: 1 }` (unique)
     - `{ organizationId: 1, reversesCourierSettlementId: 1 }` (unique partial: `where: { reversesCourierSettlementId: { $type: "string" } }`)
     - `{ organizationId: 1, createdAt: -1 }`

## Tests (must exist and pass)

- [ ] Create manual consignment for a confirmed/packed order with `shipOrder: true`: transitions order to `SHIPPED` via `ShipOrderUseCase`, links `consignmentId`, commits stock ledger.
- [ ] Create manual consignment with duplicate tracking number for the same courier rejects with 409 conflict.
- [ ] List consignments paginated, filterable by orderId, courierKey, or locationId.
- [ ] Record courier settlement: validates exact gross matches sum of payments, charges $\le$ gross, netReceived = gross - charges, verifies payments belong to org and courier.
- [ ] Concurrent or duplicate settlement of the same payment rejects with 409 conflict.
- [ ] Overcharges (`courierCharges > grossAmount`) or negative charges reject with 422/400 validation error.
- [ ] Reverse courier settlement: requires manager approval token, mirrors records, prevents second reversal on same settlement.
- [ ] Replay with same `Idempotency-Key` returns 200 with `Idempotency-Replayed: true`; changed body returns 422 `IDEMPOTENCY_MISMATCH`.
- [ ] Permission denied on missing `courier.consignment.*` or `courier.settlement.*` (403).
- [ ] Cross-organization isolation: reading or modifying other organization's consignment/settlement returns 404.
- [ ] Module-off test generated by `describeModuleContracts` passes automatically.

- Risk: Re-shipping order without valid consignment. Mitigation: `ShipOrderUseCase` enforces `consignmentId` for courier dispatch.
