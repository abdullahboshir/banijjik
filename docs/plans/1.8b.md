# Plan: card 1.8b · Platform web app (`apps/platform`)

Tier: T2 · Planned by: Opus 5.5 · Date: 2026-10-11 · Based on commit: `main b2c5e1b`

Second half of roadmap 1.8. Runs in parallel with **1.7d** (admin screens). This card owns `apps/platform/**`, the new shared package, and the **generic** client code it moves out of `apps/admin/src/lib/api` and `apps/admin/src/auth` (thin re-exports stay behind, so 1.7d's imports keep working). It does not touch `apps/admin/app/**` or the admin screens.

## Goal
Platform operators have their own small web app, desktop-first (ADR-060), with its own accent colour so nobody mistakes it for a tenant's dashboard. In it they can:
- sign in
- find a tenant and open it
- suspend or reactivate it
- see and change its subscription (extend the trial, change the package)
- grant or revoke a module
- list, create, edit and archive packages
- read the platform audit log (super admins)

It runs entirely on the 1.8a API.

## Inputs read

## Decisions
**Shared client code (no duplication)**
1. New package `packages/web-client` (`@banijjik/web-client`), framework-light: it may import `next/headers` only in its `server` entry.
   - `createApiClient({ baseUrl, apiPrefix, refreshPath, signInPath })` → `apiFetch` with the single shared refresh and one retry (moved from admin, behaviour unchanged)
   - `ApiError`, the envelope handling, `networkError`
   - `createServerApiFetch({ baseUrl, accessCookieName })` (entry `@banijjik/web-client/server`, `server-only`)
   - `safeNextPath`, the sign-in/session path builders, `sessionGuardTarget`, the renewed-marker helpers (cookie name as a parameter)
   - the moved unit tests
   - `apps/admin` keeps its file paths as thin re-exports configured for the admin (`/auth/refresh`, `access_token`). **No admin behaviour or bundle may change:** the admin unit and browser suites must pass unchanged, and the admin route sizes must stay within ±0.5 KiB of main (report them).
2. Why now: the platform app needs exactly this code with other cookie names and paths. Copying it would create a second security-sensitive implementation to keep in step.

**The app**
3. `apps/platform` (`@banijjik/platform`), Next.js App Router, same versions and configuration style as admin: port 3200, `NEXT_PUBLIC_API_BASE_URL`, `NEXT_PUBLIC_BRAND_NAME`, env validated in `src/config/env.ts`.
   - Root layout with the same fonts and locale cookie mechanism as admin.
   - **Accent:** a CSS override of the three brand tokens in the app's `globals.css` (`13 §12`), chosen so every text pair still passes AA. Add the pairs to the ui contrast test as a second theme case.
   - A persistent header band says "Platform" (i18n key) on every page.
4. **Auth:** `/sign-in` (identifier + password → `POST /platform/auth/login`), `/session` (silent renewal with the platform refresh path), the same loop guard, sign out.
   - The server layout of the app group calls `GET /platform/me` with `createServerApiFetch({ accessCookieName: "platform_access_token" })`. No session → the guard.
   - `me.permissions` drive which navigation entries and actions are shown. The API still enforces.
5. **Navigation:** a left sidebar (desktop-first; it collapses under 1024 px, and pages stay readable on a phone for the emergency read-only use of `13 §12`): Tenants, Packages, Audit log (only with `platform.audit.read`).
6. **Tenants**:
   - **List** (`/tenants`, `platform.tenant.read`): `DataList` (dense): name, slug, template key, status badge, subscription status, members; `?q=` search (debounced, in the URL), status chips, numbered pages.
   - **Detail** (`/tenants/{organizationId}`): header with name, slug, status; sections:
     - **Subscription:** status, package name, trial end, add-ons. Actions "Extend trial" (days 1–30 + reason) and "Change package" (selects of base packages and add-ons), each in a `ConfirmDialog`-backed form, shown with `platform.subscription.write`.
     - **Modules:** the active overrides table (module, effect, reason, expiry) with "Grant" / "Revoke" (module select limited to grantable modules; reason required; optional expiry) and "Remove" per row, with `platform.entitlement.write`.
     - **Suspend / Reactivate** with a required reason, with `platform.tenant.suspend`. The dialog states what the tenant's staff will see.
   - After each write the page reloads its data (`router.refresh()`), and a toast confirms. API refusals show their message keys.
7. **Packages** (`/packages`, `platform.package.read`):
   - **List:** base packages and add-ons in two groups: name (translated `nameKey` or `name`), module count, limits summary, status.
   - **Create / edit form** (`platform.package.write`): `name` (operator-made only; seed packages show their name read-only), `isAddOn` (create only), module checkboxes grouped by module class, limits per `LIMIT_KEY` with an "unlimited" toggle, limit increments for add-ons.
   - A closure-rule refusal shows which dependency is missing.
   - `unbuiltModuleKeys` from the response are listed as "not built yet".
   - Archive with `PACKAGE_IN_USE` shown as its message.
8. **Audit log** (`/audit`, `platform.audit.read`): a dense table (when, operator, action, target, organization, reason), with filters by action and organization id, paged.
9. **Text:** all from i18n keys. Platform strings go into server-only screen catalogs `platform/{bn,en}.json` in `packages/i18n` (same mechanism as 1.7c), bn + en with identical key sets, default locale `bn` with the same switch as admin.
10. **Budgets and rules:** the same as admin: no `ssr:false`, no web storage, ui components and semantic tokens only, initial JS ≤ 170 KiB per route (report sizes), forms and dialogs lazy.
11. **Tests:**
    - vitest + jsdom for forms and permission-driven visibility.
    - A real-stack browser test with its own stack helper (API + `next start` on 3201). Move the generic parts of the admin browser stack into `packages/web-client`'s test-support or a small shared dev folder only if that is mechanical; otherwise a second helper is acceptable, and say which.
    - The stack seeds a platform admin through the existing seed use case.
12. **CI:** the root scripts and turbo already build every workspace. Add `apps/platform` to the Build step's env (the same two `NEXT_PUBLIC_*` placeholders) in `ci.yml` if the build needs them.

## Out of scope
- Impersonation, industry templates, website templates, operator management, system health/queues, dead-letter replay (their cards)
- Billing and invoices (6.2)

## Risks & checks
- **Moving security code:** the admin suites are the proof that nothing changed. Any admin assertion that would need an edit → stop and report.
- **Cookies of two audiences on one host in development:** the admin and platform cookies have different names and coexist. The browser test signs in to both apps in one browser context to prove it.
- **Memory, disk and services:** E: has ~2 GB free and the machine runs out of memory under parallel load. Use `--concurrency=1`, `VITEST_MAX_WORKERS=2`, the installed Chrome, the system MongoDB binary, `TEST_REDIS_URL=redis://127.0.0.1:6380`. No downloads. If `npm install` for the new app needs more disk than is free, stop and report.

## Done when
An operator can do the tasks of the Goal in the browser test, a suspended tenant's user sees the suspended page, a granted module shows for that tenant, the admin app is unchanged, and all tests above pass with real output in `docs/handoffs/1.8b.md`. The merge check passes.
