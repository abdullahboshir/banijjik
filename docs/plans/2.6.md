## Goal
A SUPER_ADMIN builds an industry **from the platform panel alone** (the Phase 2 done-criterion):
- create a template, or clone a near one
- choose its kinds and allowed modules
- add custom fields with Bangla and English labels and options
- rename its terms
- set its setting defaults
- publish or retire it
- move a tenant onto another template

SUPPORT and BILLING see templates read-only. Everything runs on the 2.1b API.

## Decisions
**Small API additions** (`platform/industry`, `routes/platform.ts`)

1. **`GET /platform/setting-definitions`** (`platform.industry.read`). It lists every registered setting from the module manifests: `{ settingKey, moduleKey, value: SettingValueSpec, systemDefault, allowsLocationOverride, isClientVisible }`, ordered by key. The list is bounded by the code registry: a keyed read, not paged; say so in `14`.
   - It reads the manifests through the kernel module registry. It does not import `core/settings`.

2. **Setting defaults are checked when a template is written** (the gap left by 2.1b and 2.4). On create and PATCH, every `configuration.settingsDefaults` entry whose key is **registered** must pass its spec (`buildSettingValueSchema`). Otherwise → `422 BUSINESS_RULE`, ruleKey `INDUSTRY_TEMPLATE_SETTING_INVALID`, `details.settingKeys`.
   - **Unregistered keys stay allowed**: the seeds hold `sales.*`, `booking.*` and `pos.*` for modules not built yet (ADR-103). The detail response lists them as `pendingSettingKeys`, computed on read, not stored.
   - Add the rule key and messages.
   - Record this in ADR-106 together with decision 1.

**Platform app pages** (`apps/platform`, mobile first, every text an i18n key, both catalogs)

3. **Menu:** an "Industries" entry (`platform.nav.industries`), permission `platform.industry.read`, `iconKey` already registered (pick one from `icons.tsx`; no new icon), placed after Packages.

4. **`/industry-templates`:** the list, like `/packages`. Status chips All / Draft / Published / Retired, paged. Rows show name (in the user's language), key, kinds, module count, status and version. A primary "New industry" button needs `platform.industry.write`.

5. **`/industry-templates/new`:** key (format of ADR-097; the API's 409 message when taken), name and description in Bangla and English, icon key, and **either** "start empty" **or** "copy from" (a select of the existing templates; sends `cloneFromIndustryTemplateId`), plus the reason. It creates a DRAFT and opens its detail page.

6. **`/industry-templates/[industryTemplateId]`:** the template editor. One page with collapsible sections. Each section saves on its own, through **one PATCH** with the current `version` and a reason sheet. The sheets and the field editor are lazy-loaded.
   - **Basics:** name, description (bn and en), icon key.
   - **Kinds and modules:** the five offering kinds as checkboxes; the allowed modules with the existing `module-picker` (CORE and OPTIONAL only).
   - **Terms:** the rows `termKey | বাংলা | English`; add a term (the key format of 2.1a), edit the texts.
   - **Custom fields:**
     - The list is grouped by entity type and shows key, type, the label in the user's language, and required, bot-asked and sensitive badges.
     - Add and edit happen in a **field editor sheet**, with these inputs:
       - entity type (from `CUSTOM_FIELD_ENTITY_TYPE`)
       - offering kind (only for `offering`)
       - field key (locked after the first save)
       - type (from `CUSTOM_FIELD_TYPE`, locked once the template is locked)
       - label bn/en, required, `botAsk`, visibility (admin, storefront, bot), searchable, sensitive
       - options with option labels bn/en (SELECT, MULTI_SELECT)
       - reference entity, and the contact-link (`relationKey`, create-if-missing, default bill-to) for REFERENCE
     - Validate on the client with the same `industryTemplateConfigurationSchema` the API uses.
   - **Setting defaults:** every registered setting from decision 1, with an input that follows its spec (BOOLEAN checkbox, INTEGER/DURATION/MONEY numeric, MONEY through 2.5's `parseMoneyInput`, ENUM select, TEXT). Each row shows the system default and a "use system default" toggle. Unregistered keys are listed read-only as "waiting for their module" (`pendingSettingKeys`). STRUCTURED settings are shown read-only (none are registered yet).
   - **Roles, relations, resource types:** contact role and relation checkboxes from contracts; resource types as rows (`resourceTypeKey`, term key, is-member).
   - **Bot and knowledge:** persona key, handoff topics (a text list), knowledge starters (`topicKey`, bn, en), website template keys (a text list).
   - **The additive rule (ADR-101) made visible.** When the template is PUBLISHED, RETIRED or in use, the editor says so at the top. Removal controls are disabled where the API would refuse them. A 422 `INDUSTRY_TEMPLATE_CHANGE_NOT_ADDITIVE` shows every item of `details.removed` in plain words, through one formatter (`module:booking` → "Module: Booking", `fieldType:contact::skin_type` → "Field type of Skin type"). Unit-test the formatter.
   - **Publish / Retire** buttons with the reason sheet, following the 2.1b status rules. Without `platform.industry.write` the whole page is read-only.

7. **Tenant detail: "Change industry"**, a new action on `/tenants/[organizationId]` (`platform.industry.write`). A sheet with a select of the non-retired templates and the reason; it calls `change-industry-template` and shows the 422 removed list with the same formatter. Add it to `tenant-action-labels.ts` like the other actions.

8. **Budget and phone:**
   - every new route stays **≤ 170 KiB** initial JS
   - the editor's sections and sheets load lazily
   - no horizontal scroll at 375 px
   - add the routes to the budget, phone and screenshot lists of `panel.browser.test.ts`

  7. "Change industry" moves a RETAIL tenant onto `BAKERY`.

## Out of scope
- Website template building (Phase 4), package editing (exists since 1.8b), the tenant side (2.7a, 2.7b).
- Showing a template's fields as a live form preview (a later polish card).

## Risks & checks
- **One schema:** the editor validates with the API's schema; never re-implement field rules in the app.
- **Lock awareness:** test that a locked template's field type select is disabled and that the API's 422 still renders if a stale page tries.
- Stop and ask if a section needs an API that 2.1b does not offer.

## Done when
- An industry can be created, configured, published and assigned from the panel alone, with setting defaults validated against the registry.
- The Opus review passes.
