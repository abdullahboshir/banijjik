# Plan: card 4.3 V0 · storefront checkout session fixes

Tier: T2 · Planned by: Claude Opus 5.5 (lead) · Date: 2026-11-01 · Based on commit: `2117804c` (`origin/main`)

## Why this card exists

`s/4.3-v-commerce-scenarios` (Part V) found three real storefront checkout defects and fixed them inside a test card. Its review `docs/handoffs/4.3-v-review-R1.md` failed V (B1, B2) and found that those fixes are incomplete (must-fix 1, 2, 7). The owner decided on 2026-11-01 to carve the storefront half out of V as its own card, so `main` gets a working checkout before COD-S1e changes the same files:

- **V0 (this card):** the storefront production fixes, their unit tests, and the storefront browser suite `commerce.browser.test.ts`.
- **V (remaining, R2 lane):** only the API scenario test `storefront-commerce-scenarios.test.ts` and its R1 blockers. After V0 merges, the V branch takes `main`'s side for every file listed below. V0 does not touch the API scenario test.

Defects on `main` today:
1. The cart quotes on its first visit, before any guest cookie exists, so `POST /quotes` answers 401 and the cart never shows a total.
2. Submit calls `createGuestSession` first, so the quote's principal (`GUEST:<guestSessionId>`) changes and the server refuses the quote.
3. `translatorFor(locale)` builds a new translator on every call. `cart-view.tsx` lists `t` in `fetchQuote`'s dependencies, so every render quotes again until the rate limit is exhausted. There are 26 files with call sites.
4. Found while planning: `checkout-view.tsx:59-66` classifies the submit answer with `status === 409 || f.messageKey.includes("PRICE_CHANGED")` and `f.messageKey.includes("QUOTE_EXPIRED")`. Message keys are lowercase (`errors.checkout_price_changed`), and `fields` holds only validation issues, so the server's `CHECKOUT_QUOTE_EXPIRED` (400) is never recognised. Also, any 409, including `CHECKOUT_CAPACITY_UNAVAILABLE`, shows the "price changed, accept" alert, which loops.

## Decisions

- **D1 · Error code on client results.** `ClientResult` gains `readonly errorCode?: string | undefined`. `callStorefront` fills it from `error.code` of a non-2xx envelope, and leaves it `undefined` on success or when there is no envelope. The field is optional, so existing literal fixtures (`src/account/request-tracking.test.tsx:211-246`) stay unchanged. Every new branch in this card decides on `errorCode` (compared with `ERROR_CODE.*` from `@banijjik/contracts`), never on `messageKey` substrings and never on a bare status number.
- **D2 · Quote bootstraps a guest session once.** `requestQuote` sends the quote. Only when the answer has `status === 401` and `errorCode` is `UNAUTHENTICATED` or `WEBSITE_GUEST_SESSION_EXPIRED` does it call `createGuestSession` once and send the quote once more. If session creation fails, `requestQuote` returns **the session's own result** (for example 403 `WEBSITE_GUEST_CHECKOUT_DISABLED` or 429 `RATE_LIMITED`), never the stale 401 (R1 must-fix 1). A second 401 is returned as is, with no third call and no loop. Any other answer (403 `FORBIDDEN`, 429, 4xx, 5xx) is returned with no session call. A valid existing session is never rotated, because the session is created only after a 401.
- **D3 · Submit runs under the quote's session.** `executeCheckoutSubmit` no longer calls `createGuestSession`. The import is removed from `checkout-view.tsx`.
- **D4 · Submit outcome is one pure function.** `submitOutcomeOf(result)` in the new `checkout-outcome.ts` returns one of `PLACED | PRICE_CHANGED | QUOTE_EXPIRED | SESSION_LOST | CAPACITY_UNAVAILABLE | FAILED`:
  `ok && data` → `PLACED`; `CHECKOUT_PRICE_CHANGED` → `PRICE_CHANGED`; `CHECKOUT_QUOTE_EXPIRED` → `QUOTE_EXPIRED`; 401 with `UNAUTHENTICATED` or `WEBSITE_GUEST_SESSION_EXPIRED` → `SESSION_LOST`; `CHECKOUT_CAPACITY_UNAVAILABLE` → `CAPACITY_UNAVAILABLE`; anything else → `FAILED`.
  `useCheckoutSubmission` maps them: `PRICE_CHANGED` → price-changed alert; `QUOTE_EXPIRED` **and** `SESSION_LOST` → the existing quote-expired alert, whose "Refresh Quote" button calls `refreshQuote` → `requestQuote`, which bootstraps a new session by D2 and resets the Idempotency-Key (R1 must-fix 2). `CAPACITY_UNAVAILABLE` → inline error `storefront.checkout.capacityUnavailable` (new key). `FAILED` → `storefront.checkout.errorGeneral`.
  SESSION_LOST reuses the quote-expired alert on purpose. A quote bound to a lost session is unusable in exactly the same way, and the recovery is the same button, so there is no new alert state and no new title or message key.
- **D5 · Quote error message is one pure function.** `quoteErrorKeyOf(result)` in `checkout-outcome.ts` returns a storefront message key: `WEBSITE_GUEST_CHECKOUT_DISABLED` → `storefront.cart.guestCheckoutDisabled` (new key); `RATE_LIMITED` → `storefront.error.rateLimited` (existing); anything else → `storefront.cart.quoteError` (existing). `cart-view.tsx` and `fetchRefreshedQuote` in `checkout-view.tsx` both use it in place of the hard-coded `quoteError`.
- **D6 · One translator per locale, fixed at the root.** `translatorFor` keeps a module-level `Map<Locale, Translator>` and builds each locale's translator once (R1 must-fix 7). The function signature is unchanged, so none of the 26 call-site files changes. V's `useMemo` in `cart-view.tsx` is **not** carried over, because with a stable `t` it does no work. A server render reuses the same catalogs and empty brand name, so caching at module scope is safe (the translator holds no request data).
- **D7 · Browser suite moves here.** `apps/storefront/src/commerce.browser.test.ts` is taken from `origin/s/4.3-v-commerce-scenarios` (`git show origin/s/4.3-v-commerce-scenarios:apps/storefront/src/commerce.browser.test.ts`) and changed as follows (R1 §3):
  - The price-change case runs at `MOBILE_VIEWPORT` (360 px). `DESKTOP_VIEWPORT` is deleted if nothing else uses it.
  - `clickButton` uses real pointer input: `page.click(\`button::-p-text(${text})\`)` (puppeteer-core 24), not `element.click()` inside `evaluate`.
  - A new case, **"recovers when the guest session is lost between quote and submit"**: quote in the cart, open checkout, delete the `sf_guest` cookie (`page.deleteCookie`, name from `SF_GUEST_COOKIE_NAME`), submit, see the BN quote-expired alert, press refresh, submit again, and reach the receipt.
  - The golden path asserts that the receipt document response's `cache-control` header contains `no-store`. If it does not, **stop and report**: that is a privacy defect for the lead, not an assertion to weaken.
  - Per-test timeouts stay as they are. They boot a real stack, and shortening them is not part of this card.

## Interfaces & types

```ts
// apps/storefront/src/api/client-api.ts
export interface ClientResult<Data> {
  readonly ok: boolean;
  readonly status: number;
  readonly data: Data | undefined;
  readonly fields: readonly FieldProblem[];
  /** `error.code` of a failed answer; undefined on success or without an error envelope. */
  readonly errorCode?: string | undefined;
}

// apps/storefront/src/checkout/checkout-outcome.ts
export const SUBMIT_OUTCOME = {
  PLACED: "PLACED",
  PRICE_CHANGED: "PRICE_CHANGED",
  QUOTE_EXPIRED: "QUOTE_EXPIRED",
  SESSION_LOST: "SESSION_LOST",
  CAPACITY_UNAVAILABLE: "CAPACITY_UNAVAILABLE",
  FAILED: "FAILED",
} as const;
export type SubmitOutcome = (typeof SUBMIT_OUTCOME)[keyof typeof SUBMIT_OUTCOME];
export function submitOutcomeOf(result: ClientResult<CheckoutResponse>): SubmitOutcome;
export function isMissingSession(result: ClientResult<unknown>): boolean; // D2/D4 shared rule
export function quoteErrorKeyOf(result: ClientResult<unknown>): string;
```

`requestQuote(organizationId, body)` keeps its signature. `checkout-api.ts` imports `isMissingSession` from `checkout-outcome.ts`, so the "which 401 means no session" rule exists once. The `SUBMIT_OUTCOME` object is UI-local, not a domain enum, so it does not go to `packages/contracts`.
