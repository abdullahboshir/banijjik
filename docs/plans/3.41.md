## Decisions
1. **Tests only.** No production module, route, contract, i18n or schema change. Lint R16: template keys (`SALON`, `GYM`, `COACHING`, `RETAIL`) live only in the test files, never in `day-scenario-world.ts`.
2. **Harness** matches `order-walk-in-money-api.test.ts`, plus report handlers:
   - `startCatalogApi()` (production v1 routers)
   - `registerAccountingAndExpenseHandlers()`
   - `registerCommissionHandlers(systemClock, orgConfig)` with the same `buildOrgConfigService` wiring as the walk-in money file
   - `registerReportEventHandlers(systemClock)`
   Register once in `beforeAll`. Do not register a handler twice.
3. **Outbox.** After the day's writes, call `processOrganizationOutbox(organizationId)` twice. Snapshot home `periods.today`, daily `totals` for today, Z-report body (when a till ran), `trial.balances`, and commission summary **after the first pass**. The second pass must deep-equal those snapshots (replay does not change counts).
4. **Expected figures come from named amount constants**, not a second set of magic totals. After each sale/quote/enrollment the test asserts the API's returned totals equal the function of those constants (same integer rules as pricing: exclusive tax, percent of the discounted line, no float). Report, Z-report and commission assertions use **those same functions**, never a handwritten third number.
5. **Z-report** only where a till ran (SALON, RETAIL). GYM and COACHING skip it. Close the register with `countedCash = expectedCash` so variance is 0.
6. **Trial balance:** `GET /orgs/{organizationId}/accounting/trial-balance?asOf=2099-12-31` (same far date as existing accounting API tests). `balances === true`.
7. **Commission:** `writeModuleOverride` PLATFORM_GRANT on every world so `/commission/summary` is 200, not gated off.
   - SALON: one PERCENT 1000 bps SERVICE rule on the performer (GET `/sales/performers`). Walk-in line has `performedByMemberId`. Stylist resource is created with that `memberId` so a completed booking also accrues. Summary `open.amount` equals 10 % of (walk-in service base + booking base), bases = line/booking total after discount without tax.
   - GYM, COACHING, RETAIL: no rules. Summary is `[]`.
8. **Cashier 403 and cross-org** live in the RETAIL file (it already has org B): a cashier of A gets 403 on `/reports/home`; Bob reading A's home is 403 or 404; A's numbers never appear on B's home.
9. **Business date** is `businessDateOf(new Date(), "Asia/Dhaka")`. Do not fake the API clock (home "today" is now). Booking slot: seven weekdays `00:00`–`23:59`, `startsAt` = now + 1 hour rounded up to a 5-minute bucket (may fall tomorrow; completion still counts today because reports use the event time). Known gap, same as `report-api.test.ts`: a run that crosses Dhaka midnight can split a day.
10. **Worlds** (one `it` each, names below). `worldFor(harness, RETAIL, <template>)` except RETAIL which is `worldFor(harness, RETAIL)`.

    **SALON** — booking with performer (check-in + complete + CASH payment of the booking total), till: open register, sell one discounted+taxed `WALK_IN_ONLY` service (performer) plus one untaxed product, close, Z-report. Tax: `pricing.taxInclusive = false`, tax class 1500 bps on the service, ACTIVE PERCENT 1000 bps promotion on the service offering. Named constants: `WALK_IN_LIST`, `PRODUCT_LIST`, `PROMOTION_BPS = 1000`, `TAX_BPS = 1500`, `BOOKING_PRICE`, `COMMISSION_BPS = 1000`. Exclusive-tax functions:
    ```
    discount = floor(list * PROMOTION_BPS / 10_000)
    afterDiscount = list - discount
    tax = floor(afterDiscount * TAX_BPS / 10_000)
    walkInGrand = afterDiscount + tax
    tillGrand = walkInGrand + PRODUCT_LIST
    ```
    Home today: `ordersCompleted === 1`, `netSales === tillGrand`, `discountTotal === discount`, `taxTotal === tax`, `bookingsCompleted === 1`, `bookingsCompletedValue === BOOKING_PRICE`, `paidInByMethod.CASH === tillGrand + BOOKING_PRICE`. Daily today matches home today for those fields.

    **GYM** — monthly PLAN, enroll `startsOn = today`, pay the period fee in full (CASH), staff `activate` if still PENDING, two check-ins, `renew`. Named constants: `PLAN_FEE`. Home today: `enrollmentsCreated === 1`, `enrollmentsActivated === 1`, `enrollmentsRenewed === 1`, `checkIns === 2`, `paidInByMethod.CASH === PLAN_FEE`. No Z-report.

    **COACHING** — student contact with required `class_level` and `guardian: { create: { name, phone } }` (same shape as `booking-event-api.test.ts`). Enroll on a PLAN, pay **partial** CASH (`PARTIAL < PLAN_FEE`), leave the rest due. `GET /dues?requestType=ENROLLMENT` includes the period with remaining `PLAN_FEE - PARTIAL`. Home today: `enrollmentsCreated === 1`, `paidInByMethod.CASH === PARTIAL`. No Z-report. No till.

    **RETAIL** — one inventory item; receive enough grams; publish a packed offering (`quantity` per pack = `PACK_GRAMS`) and a loose offering (`quantity` per unit = `LOOSE_GRAMS`) from that item (same pattern as `order-stock-api.test.ts`). Open till, POS-sell 1 pack + 1 loose (CASH `POS_PACK_PRICE + POS_LOOSE_PRICE`), admin `instantOrder` of 1 pack (pay CASH `ADMIN_PACK_PRICE`), return that admin order in full (CASH refund), close register, Z-report. Named constants: `PACK_GRAMS`, `LOOSE_GRAMS`, `RECEIVE_GRAMS`, `POS_PACK_PRICE`, `POS_LOOSE_PRICE`, `ADMIN_PACK_PRICE`. Home today: `ordersCompleted === 2`, `netSales === POS_PACK_PRICE + POS_LOOSE_PRICE + ADMIN_PACK_PRICE`, `returnsCount === 1`, `returnsValue === ADMIN_PACK_PRICE`, derived `netSalesAfterReturns === POS_PACK_PRICE + POS_LOOSE_PRICE`, `paidInByMethod.CASH === POS_PACK_PRICE + POS_LOOSE_PRICE + ADMIN_PACK_PRICE`, `refundedByMethod.CASH === ADMIN_PACK_PRICE`. Z-report `salesCount === 1`, `grandTotal.amount === POS_PACK_PRICE + POS_LOOSE_PRICE`.
11. **Browser** (same file `report-screens.browser.test.ts`): a **new** org slug (do not reuse `acme`, which stays empty). Seed RETAIL, POST a PRODUCT offering, publish it, `POST /orders/instant` for quantity 1, pay it CASH `BROWSER_SALE = 1000` via `callApi`. Reload `/<slug>` with a deadline (copy `reloadUntilBadge`: interval + timeout, never race the worker with a click) until `main` contains `moneyText(BROWSER_SALE, "BDT", "bn")` and does **not** show `report.home.empty`. Timeout error includes a slice of `main` text.
12. **Helpers** live in `apps/api/src/test-support/day-scenario-world.ts` (owns). Split so every function is ≤ 60 lines, complexity ≤ 10, depth ≤ 3. The four API files only name constants, run the world, and assert. Reuse existing test-support (`shopOf`, `publishOffering`, `instantOrder`, `payOrder`, `pairedTill`, `openRegister`, `closeRegister`, `saleCall`, `postReturn`, `processOrganizationOutbox`, `writeModuleOverride`, `memberWithRole`, booking helpers). Do not import from other `*.test.ts` files. Add a GET helper in the **browser test file** (browser-stack `callApi` is POST-only); do not change `browser-stack.ts` unless a GET helper already exists and is the one-line call.
13. **No new ADR.** No contracts count-test updates (no new keys).
