# Plan: card 3.0 · Files and images

Tier: **T1** (uploads are an attack surface; tenant data) · Planned by: Opus 5.5 (Claude) · Implemented by: a Claude Code session · Date: 2026-10-17 · Based on commit: `main a04012d` (Phase 2 merged)

Phase 3, wave 1. It can start now, in parallel with card 2.8: no shared files except add-only indexes and catalogs. Read `docs/plans/phase-3-lanes.md` and `docs/ops/implement-with-cursor.md` first. Reserved ADR number: **ADR-109**.

## Goal
One owner for every uploaded file:
- business logos (3.12)
- offering images (3.2)
- FILE and IMAGE custom-field values (2.5's pending inputs)
- later, attachments

Uploads are checked by content, resized, stored outside the database through a storage port, and served either publicly (logos, product images for websites) or only to permitted members.

## Decisions
**Module and model**
1. **New module `core/file`** (SYSTEM; the key exists).
   - `FileAsset`: collection `file_assets`, tenant DB, tenancy `ORGANIZATION`, versioned, audit fields.

     | Field | Notes |
     |---|---|
     | `fileId` | UUID v7 |
     | `purpose` | `LOGO \| OFFERING_IMAGE \| CUSTOM_FIELD_IMAGE \| CUSTOM_FIELD_FILE \| ATTACHMENT`, new contracts enum |
     | `visibility` | `PUBLIC \| PRIVATE`, **derived from the purpose**, never from the request: LOGO and OFFERING_IMAGE are PUBLIC; the rest PRIVATE |
     | `mimeType`, `byteSize`, `originalName` | the name is sanitized and only shown, never used as a path |
     | `storageKey` | `org/{organizationId}/{fileId}/{variant}` |
     | `variants` | `[{ variantKey, byteSize, width?, height? }]` |
     | `status` | `ACTIVE \| DELETED` |

   - Index `{ organizationId, purpose, createdAt }`.
2. **Storage port** `FileStorage { put(key, bytes, mimeType); get(key); delete(key) }`:
   - **local disk** in development and tests, under a configured folder outside the repo
   - **S3-compatible object storage** in production (bucket, region, endpoint, credentials)

   Both are configured through the validated config. Production refuses the local driver, and refuses missing object-storage settings, like the other production checks (1.9d). No credential is logged.

**Upload rules (the security core)**
3. Accepted types, checked by **content (magic bytes)**, not by the declared type or the extension:

   | Group | Types | Limit |
   |---|---|---|
   | images | JPEG, PNG, WebP | 8 MB |
   | documents (CUSTOM_FIELD_FILE, ATTACHMENT only) | PDF | 10 MB |

   - Everything else is refused, explicitly including **SVG and HTML** (script carriers): `415`, messageKey `errors.file_type_not_allowed`.
   - Each limit is a named constant; a file over its limit → `413`.
   - The JSON body limit of `app.ts` is unchanged: the upload route has its own streaming parser.
4. **Image processing** with `sharp` (new dependency; the card needs it):
   - Re-encode every image. This **strips metadata (EXIF, GPS)** and neutralizes polyglot files.
   - Produce variants `thumb` (200 px), `medium` (800 px) and `large` (1600 px), longest side, never upscaled, in WebP. Do not keep an original.
   - PDFs are stored as received, with the type checked.
5. **Multipart parsing** with `busboy` (new dependency), streaming:
   - one file per request, plus the field `purpose`
   - the size is enforced while streaming (abort on overflow)
   - a timeout
6. **Quota:** at most **1 GiB of stored bytes per organization** for now (named constant). Over it → `422 BUSINESS_RULE`, ruleKey `FILE_QUOTA_EXCEEDED`. A package-based limit key comes with billing (6.2); write that in ADR-109. The running total is kept in a per-organization counter document, updated in the same transaction as the insert, so concurrent uploads cannot overshoot.

**API** (`/api/v1/orgs/{organizationId}/files`, the tenant pipeline)

7. The endpoints:

   | Endpoint | Permission | Notes |
   |---|---|---|
   | `POST /files` (multipart) | **`file.asset.create`** | `201 { fileId, purpose, visibility, mimeType, byteSize, variants, url? }`; `Idempotency-Key` optional (no money or stock) |
   | `GET /files/{fileId}` | `file.asset.read` | metadata |
   | `GET /files/{fileId}/content?variant=` | `file.asset.read` | streams a PRIVATE file with `Cache-Control: private`, `Content-Disposition: attachment` for PDFs, `X-Content-Type-Options: nosniff` |
   | `DELETE /files/{fileId}` | `file.asset.delete` | marks DELETED and removes the stored objects; a file still referenced is the caller's problem until reference tracking exists, so say so in the README |

   **Public serving:**
   - `GET /api/v1/public/files/{fileId}/{variant}` serves **only PUBLIC, ACTIVE** files, without a session, with long cache headers and `nosniff`.
   - It is mounted outside the tenant pipeline in `routes/v1.ts`, reading the file through `runAsSystem(SYSTEM_REASON.PUBLIC_FILE)`. That is a new system reason, added to contracts and to `SYSTEM_ACCESS_FILES` for this one use-case file only.
   - A PRIVATE id → 404, never 403, so the existence of private files is not revealed.

   **Grants** (add-only): OWNER and MANAGER ALL; CASHIER and STAFF create and read; VIEWER read; RIDER none.

**Custom-field inputs**
8. **`@banijjik/ui` gets `ImageInput` and `FileInput`** (no API knowledge; props: current preview URL, `onPick(file)`, uploading state, error).
   - `@banijjik/web-client` gets `uploadFile(purpose, file)` and `fileUrl(fileId, variant)`.
   - 2.5's block renders IMAGE and FILE through them, so `pendingFieldKeys` shrinks to REFERENCE only.
   - The value stored in the custom field stays the `fileId` (2.3's rule).
   - **Server rule** (2.3's builder only checks the UUID): when an entity saves a FILE or IMAGE value, the entity's use case checks that the file exists in the same organization with a matching purpose (`CUSTOM_FIELD_IMAGE` or `CUSTOM_FIELD_FILE`). Add that check to 2.7a's organization and member paths through a `FileReferenceChecker` port, adapted in routes.

9. **Records:** ADR-109 ("Accepted (proposed)") covers:
   - the storage port and drivers
   - content-checked types, no SVG
   - re-encoding and the variants
   - visibility from the purpose, public serving through `runAsSystem(PUBLIC_FILE)`
   - the interim 1 GiB quota

## Tests (must exist and pass)
- [ ] **Upload happy path:**
  - a JPEG becomes three WebP variants
  - EXIF GPS is gone in every variant (read back and assert)
  - metadata and `url` for a logo; a PDF is stored as is
- [ ] **Refusals:**
  - an SVG, an HTML file renamed `.jpg`, a PNG header followed by HTML → `415`
  - over 8 MB → `413`, aborted while streaming (the memory high-water mark stays bounded; assert the stream was destroyed)
  - a second file in one request → `400`
  - an unknown `purpose` → `400`
  - quota exceeded → `422`, including two concurrent uploads at the edge
- [ ] **Access:**
  - PRIVATE content needs `file.asset.read`; RIDER → 403
  - **another organization's fileId → 404** on every route
  - the public route serves a PUBLIC file without a session and answers 404 for a PRIVATE one
  - response headers include `nosniff`; PDFs download as attachments
- [ ] **Delete** removes the stored objects and the public URL stops working.
- [ ] **Custom fields:**
  - a member IMAGE field accepts a `fileId` of this organization with purpose `CUSTOM_FIELD_IMAGE`
  - it refuses another organization's id, a deleted file, or a LOGO file (400 at `customFields.<key>`)
  - the 2.5 block renders the image and file inputs (unit tests)
- [ ] **Config:** production refuses the local driver and a missing bucket.
- [ ] Every existing suite green; full "Done means" list.

## Out of scope
- Reference tracking and garbage collection of unused files, virus scanning (record as a STATUS gap with the reason: no scanner service chosen), video, bulk import, the logo screen (3.12), offering images (3.2), the storefront CDN setup (Phase 4/6).

## Risks & checks
- **Never trust the client's type or name;** never build a path from user input.
- **Memory:** a large upload must not be buffered whole before the size check.
- **`sharp` on Windows and Linux:** confirm it installs from the lockfile on both (CI is Linux).
- Stop and ask if a production storage provider must be chosen now. The plan only needs the S3-compatible interface.

## Done when
- Files and images upload, are checked by content, re-encoded and stored through the port, served publicly or privately as their purpose says, and isolated per organization.
- FILE and IMAGE custom fields work.
- The Opus review passes.
