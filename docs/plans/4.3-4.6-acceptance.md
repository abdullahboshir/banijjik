## Decisions

The implementer must not invent product rules. Every choice below is taken from `4.3.md` / `4.6.md` / existing code.

1. **No second booking app.** Use existing `/offerings?kind=SERVICE` and `/offerings?kind=PLAN` plus offering detail. Host is `{slug}.{BASE_DOMAIN}` as in `commerce.browser.test.ts`. Branding proof copies `storefront.browser.test.ts` (logo `img[alt=business name]` and `--color-brand-primary` after `seedBranding`).
2. **Public browse already listed these two GETs** (`4.3.md:118`, B1 client). This card implements them; it does not redesign catalog.
   - `GET /storefront/orgs/:organizationId/locations` — anonymous, website module on. Items are ACTIVE locations of the org. If `website.publicLocationIds` is non-empty, keep only those ids (same rule as `storefront-price-adapter.ts:44` and quote/submit: empty list means all locations). Response `{ items: [{ locationId, name }] }`. `Cache-Control: private, no-store` (live list; `storefrontCacheGuard` already sets this on the org surface).
   - `GET /storefront/orgs/:organizationId/availability` — anonymous, **booking** module on. Query `offeringId`, `variantId`, `locationId`, `startDate`, `endDate` (YYYY-MM-DD). Inclusive day span ≤ 31 (B2 client + `4.3.md:118`). Internally call existing `GetAvailabilityUseCase` once per local date with `allowedLocationIds` = public list or `"ALL"`. Response groups free slots by org-local date:
     `{ offeringId, variantId, locationId, days: [{ date, slots: AvailabilitySlot[] }] }`
     `AvailabilitySlot` is the existing contract (`startsAt`, `endsAt`, `resourceIds`). **Do not add an `available` boolean** — staff already omits taken slots. Align `apps/storefront/src/booking/availability-api.ts` to this shape (drop `PublicTimeSlot.available`). Staff tenant `GET /availability?date=` is unchanged.
3. **Public HTTP mapping (same as A1 catalog).** Unpublished / not bookable / no resource / other org's offering → 404 `NOT_FOUND` + `errors.storefront_not_available` (no staff rule-key leak). Location not in a **non-empty** public list → 400 `CHECKOUT_LOCATION_MISMATCH` (V already uses this code). Bad dates / span > 31 → 422 validation. Booking module off → 404 via `moduleSwitch(MODULE_KEY.BOOKING)`.
4. **SERVICE picker uses the API, never `DEFAULT_TIME_SLOTS`.** Delete that constant. Pass `locationId` from `useOfferingSelection` (query `?location=`, else first `activeLocationIds` / `publishedLocationIds`). Call `fetchAvailability` for the visible date (one-day range is enough in the UI; the API still accepts up to 31). Options are free slots' `startsAt` (ISO). Submit sends that `startsAt` unchanged — never `` new Date(`${date}T${slot}:00.000Z`) `` (ADR-013 dates are org-local; staff slots are already ISO instants in `Asia/Dhaka`). Empty days → existing `storefront.booking.noSlots`. In-flight → existing `storefront.booking.loadingSlots`. No new i18n keys.
5. **`resolveLocationId` never returns `"default"`.** If no location can be resolved, disable Book/Enroll (button stays `min-h-11`). This closes the V R1 leftover that V0 left in STATUS; it is required for location-aware 4.6, not a new product rule (AGENTS.md forbids magic ids).
6. **Deposit in the browser** = existing setting `booking.deposit.required = FIXED` + `booking.deposit.value` (V API already). Guest checkout of that SERVICE must show booking status `HELD` and a non-zero `paymentRequired` on `/checkouts/:checkoutId`. Do not drive admin `ReceivePayment` in the browser (API test `:914` already does that).
7. **PENDING enrollment** = existing A3E `CUSTOMER_REQUEST` (`enrollment-storefront.api.test.ts:186`). Guest and signed-in PLAN requests must show `PENDING` on the receipt. GYM template `emergency_contact` is `visibility.storefront: false` (`gym.json:176-184`); this card does **not** add a storefront emergency-phone field. V already creates a guest PLAN without it.
8. **Custom fields in the browser** = the PLAN notes input B2 already ships (`storefront.enrollment.customNotes` → `customFields: { notes }`). Do not invent offering field-definition admin. Hidden fields stay A1 (`never exposes … private custom fields`). The STATUS phrase `custom-fields` (V skip of non-empty offering definitions) stays named as **not this card**.
9. **Signed-in** = OTP customer on the GYM host, same helpers as `storefront.browser.test.ts` / `account-pages.browser.test.ts` (`enableCustomerLogin`, test-inbox code). One PLAN enroll, not a PRODUCT restage of V `:1163`.
10. **BN/EN, 44 px, private tracking** are asserted on the **booking/enrollment** journey, not by restaging matrimony `account-pages`. BN is the default locale (copy `commerce.browser.test.ts` `bnTextOf`). EN is one language click (`/language?to=en` in `site-chrome.tsx`) on the SERVICE detail, then `storefront.booking.bookNow` English text. 44 px: `bookNow` and `enrollNow` (`min-h-11` already). Tracking: reload the booking/enrollment receipt and assert `cache-control` contains **both** `private` and `no-store` (V0 only asserted `no-store` on a PRODUCT receipt).
11. **Capacity in the browser:** resource `capacity: 1`. After the guest HELD booking, a second browser context on the same date must not list that `startsAt`. Do not re-run V's last-seat/last-unit API races.
12. **Industries are test data, not feature branches.** Salon org (`SALON`) for SERVICE; gym org (`GYM`) for PLAN. Feature code still asks `resolveOrgConfig` / kind only.
13. **No new enums, permission keys, events, or error codes.** Reuse `CHECKOUT_LOCATION_MISMATCH`, `NOT_FOUND`, existing validation keys.
14. **File-disjoint from COD S1b.** S1b owns `manage-delivery-zones.use-case.ts`, `delivery-zone-tenant.router.ts`, add-only sales permission/manifest/i18n/`permission-key.ts`. ## Interfaces & types

```ts
// packages/validation/src/booking/storefront-availability-schemas.ts
export const publicAvailabilityQuerySchema = z.strictObject({
  offeringId: uuidV7Schema,
  variantId: uuidV7Schema,
  locationId: uuidV7Schema,
  startDate: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
  endDate: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
}).superRefine((query, context) => {
  // refuse if parse fails or inclusive day span > 31 (org-local dates, not UTC instants)
});

// apps/api/.../get-public-availability.use-case.ts
export interface PublicAvailabilityDay {
  readonly date: string; // YYYY-MM-DD in the organization timezone
  readonly slots: readonly AvailabilitySlot[];
}
export interface PublicAvailabilityResponse {
  readonly offeringId: string;
  readonly variantId: string;
  readonly locationId: string;
  readonly days: readonly PublicAvailabilityDay[];
}
export class GetPublicAvailabilityUseCase {
  execute(input: {
    readonly organizationId: OrganizationId;
    readonly publicLocationIds: readonly string[]; // empty => allowedLocationIds "ALL"
    readonly query: PublicAvailabilityQuery;
  }): Promise<PublicAvailabilityResponse>;
}

// website list-public-locations
export interface PublicLocationItem {
  readonly locationId: string;
  readonly name: string;
}
export class ListPublicLocationsUseCase {
  execute(input: {
    readonly organizationId: OrganizationId;
    readonly publicLocationIds: readonly string[];
  }): Promise<{ readonly items: readonly PublicLocationItem[] }>;
}

// organization/index.ts (add-only)
export function buildLocationManagementRepository(): LocationManagementRepository;
```
