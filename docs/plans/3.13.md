## Decisions
**Structure (topic-wise, easy to understand)**
1. **Settings home** at `/[orgSlug]/settings`.
   - A grid of **topic cards**: Business, Team, Website, Sales and catalogue, Payments, Automation, Advanced. Each card has an icon, a title and **one plain line** saying what is inside ("লোগো, ঠিকানা, ভাষা"), and lists its pages.
   - **Topics come from the manifests:** add an optional `settingsTopicKey` to `MenuEntry` (contracts, add-only). Each settings entry declares its topic:

     | Topic | Entries |
     |---|---|
     | Business | profile, general, terms |
     | Team | staff, roles, locations |
     | Advanced | fields, modules |

   - Topics without entries yet (Website, Sales, Payments, Automation) are hidden until a module adds one.
   - The sidebar's "Settings" group links to this home; the bottom nav "More" reaches it.
   - The topic labels and lines are message keys in both languages.

2. **One page layout** in `@banijjik/ui`:
   - `PageLayout`: title, optional subtitle line, primary action, optional filters
   - `PageSection`: title, one-line help text, content, optional section action
   - `StickyActionBar` stays for forms

   **Apply them to every existing admin and platform page**, as a mechanical restyle: no behaviour change, no assertion change except snapshots or labels that move. Group long pages (profile, general settings, the template editor) into titled sections.

3. **Help text:** every section has a short plain-language line, in Bangla first, natural and not word-for-word. Keep each to one sentence. The reviewer reads the Bangla.

**Visual quality**
4. **Tokens** (`packages/ui/tokens`; components keep using semantic names only, ADR-057):
   - a clearer type scale (page title, section title, body, caption), checked at 375 px with Bangla text
   - a 4-px spacing scale applied consistently
   - softer surfaces (card background, border, radius 12, subtle shadow)
   - stronger contrast for secondary text (WCAG AA)
   - status colours unchanged in meaning

   The brand primary stays the placeholder until P2. One file changes it later.

5. **Components refreshed:**
   - cards and list rows (larger touch areas, clearer hierarchy)
   - buttons (primary, secondary, ghost, danger sizes consistent)
   - inputs (label, help, error spacing)
   - badges
   - **empty states with a simple illustration:** inline SVG line art from a small set (no new image files; no external URLs), one per kind: no items yet, no results, no permission
   - skeletons matching the real layout
   - a dashboard frame (greeting, "today" cards area) for 3.10 to fill; it renders the existing banners

**Carry-overs**
6. Each carry-over has a fixed home:
   - **Setting-value inputs:** move the mapping into `@banijjik/web-client` (one copy), used by admin 2.7b and platform 2.6.
   - **The in-use draft lock (2.6 R1-3):** the platform template detail response gains `isInUse: boolean` (the existing usage count). The editor's lock banner then covers an in-use draft. This is the only API change; add it to `14`.
   - **The `next dev` agent files:** commit `apps/admin/AGENTS.md` and `apps/platform/AGENTS.md` as generated (Next.js says committing keeps the tree clean). Add one line to the root `AGENTS.md` saying they are generated.

7. **Usability check before done:**
   - The owner shows the admin app on a phone to two or three pilot owners (P3) with three tasks: find where to change the business name, add a staff member, rename "শাখা".
   - Write what they said in the handoff.
   - The card is done when the owner confirms the tasks were found without help. If that cannot happen soon, the card can merge with the check marked pending in STATUS, and the check moves to 3.12.

## Tests (must exist and pass)
- [ ] **Unit:** settings home groups entries by topic and hides empty topics; `PageLayout` and `PageSection` render titles, help and actions accessibly (heading levels in order); empty states per kind.
- [ ] **Every existing unit and browser test still passes.** Selector or label changes are listed one by one, with no weakened assertion.
- [ ] **Browser:** the settings home shows Business, Team and Advanced with their pages for an owner, and fewer for a staff member; at 375 px no sideways scroll on every admin and platform route (the existing checks plus the home).
- [ ] **Route sizes:** every route ≤ 170 KiB; report before and after for all routes. A token and component refresh must not grow routes by more than 2 KiB each.
- [ ] Contrast: secondary text and badges meet WCAG AA (a small token test computes the ratios).
- [ ] Full "Done means" list.
