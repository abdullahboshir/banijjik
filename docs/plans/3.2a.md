Phase 3, wave 2. Can start now. Read `docs/plans/phase-3-lanes.md` (wave 2) and your row in `docs/15-PORT-MAP.md` (`catalog` 3.2) first. Reserved ADR number: **ADR-116**. The screens are card 3.2b.

## Goal
One catalog for every business: a salon's services, a gym's plans, a coaching centre's courses, a grocery's products. Everything is an **Offering** with a kind (`PRODUCT | SERVICE | PLAN | RENTAL | EVENT`), at least one **variant**, and a sales **unit**, as `09 §5.3`, `11 §2` and ADR-098 define. The card also covers:
- categories
- add-on groups (ADR-072)
- images (3.0)
- per-location availability and price
- template custom fields per kind
- search by name, synonym, SKU and barcode

Stock components are defined but stay empty until inventory (3.3).

## Decisions
**Units and money**
1. **Unit registry in contracts** (`UNIT`): `unitKey`, `dimension` (`COUNT | WEIGHT | VOLUME | LENGTH | TIME`), `precision` (decimal places of a quantity), `factorToBase` (integer, to the dimension's base unit).

   | Dimension | Units | Notes |
   |---|---|---|
   | COUNT | `PIECE`, `SET`, `PAIR`, `BOX` | precision 0 |
   | WEIGHT | `GRAM`, `KG` | KG precision 3 = grams |
   | VOLUME | `ML`, `LITRE` | |
   | LENGTH | `CM`, `METRE` | |
   | TIME | `MINUTE`, `HOUR`, `DAY`, `SESSION` | |

   - A quantity is an integer in the unit's precision (ADR-047): `1.25 kg` is `1250`.
   - "Dozen" is a pack, not a unit (ADR-098).
   - `catalog.defaultUnitKey` (ENUM of unit keys, default `PIECE`) prefills new variants.

2. **Money** is `{ amountMinor: integer ≥ 0, currencyCode }`. The currency must equal the organization's currency, otherwise 400. No floats anywhere.

**Offering**
3. **Module `commerce/catalog`** (CORE; the key exists). `Offering` as `09 §5.3`: tenant DB, `ORGANIZATION` tenancy, versioned, audit fields.
   - `kind` must be in the organization's resolved `kinds` (400 at `kind`) and is immutable.
   - `status`: `DRAFT → ACTIVE` via publish, `→ ARCHIVED` via archive. ARCHIVED is read-only and frees nothing.
   - `slug`: optional in the request.
     - Generated from the name: Latin letters and digits kebab-cased; a name without Latin letters gives `o-<8 hex of the offeringId>`.
     - A taken slug gets `-2`, `-3`, …; the unique index is the final net, and a race retries once.
     - An explicit slug is checked against the slug rules and must be free (409 `errors.offering_slug_taken`).
   - `kindDetails` is a discriminated union with one Zod schema per kind in `packages/validation`, exactly the fields of `11 §2`. A field of another kind is 400. RENTAL and EVENT are accepted when the template allows those kinds; their behaviour comes with later cards.
   - `description` (≤ 5000), `synonyms` (≤ 20, each ≤ 40), `categoryIds` (≤ 10, ACTIVE categories of this organization), `modifierGroupIds` (≤ 10, ACTIVE groups), `imageFileIds` (≤ 10, ACTIVE files of this organization with purpose `OFFERING_IMAGE`, through 3.0's reader adapted in routes), `taxClassKey` (stored, not checked until 3.4).
   - `customFields` (entity `offering`): the effective fields whose `offeringKind` equals the offering's kind, or that have none. The 2.7a and 3.1a merge pattern applies, sensitive fields included.
   - **Limit:** `LIMIT_KEY.OFFERINGS` counts DRAFT + ACTIVE offerings. Enforce it with a per-organization counter document and a conditional `$inc` in the create transaction (the 3.0 quota pattern). Archive gives one back; over the limit is `422 LIMIT_REACHED` with `details.limitKey`.

4. **Variants** (embedded, 1 to 100). Fields: `variantId` (UUID v7, stable across edits), `name`, `optionValues` (`Record<optionName, value>`, ≤ 3 option names), `price`, `compareAtPrice?` (≥ price), `sku?`, `barcode?`, `unitKey`, `quantityRule?`, `stockComponents`, `status` (`ACTIVE | ARCHIVED`), plus per-kind overrides from the `11 §2` "variant may override" column only.
   - An offering created without variants gets one variant named "Default" with the request's price and unit.
   - `optionValues` are unique across the variants of one offering.
   - **SKU** is unique per organization: an application check across documents plus a unique partial multikey index; also unique within the offering. Conflict → 409 `errors.offering_sku_taken` with `details.offeringId`. Barcode is indexed, not unique (the same barcode can sit on two shops' labels).
   - **`quantityRule { min, step, max? }`:** integers in the unit's precision, `min ≥ step > 0`, `max ≥ min`. For example loose rice in KG: `{ min: 250, step: 250 }`.
   - **`stockComponents`:** stored as `[{ inventoryItemId, quantity }]`, but any non-empty list is `422 BUSINESS_RULE` `STOCK_COMPONENTS_NEED_INVENTORY` until card 3.3 adds inventory items. `catalog.defaultStockTracked` is declared (BOOLEAN, default false) for 3.3 to use.
   - Removing a variant archives it (`status ARCHIVED`). A variant id once used is never reused or deleted, because orders and bookings reference `(offeringId, variantId)`.

**Supporting records**
5. **Category:** `name`, `slug`, `parentCategoryId?` (depth ≤ 3, no cycles), `sortOrder`, `imageFileId?` (`OFFERING_IMAGE`), `status`, with custom fields (entity `category`). Archive is refused while ACTIVE offerings or child categories use it (422 `CATEGORY_IN_USE` with counts). The list returns a flat sorted list with `parentCategoryId`; the screen builds the tree.

6. **ModifierGroup (add-ons, ADR-072):** `name`, `selection` (`SINGLE | MULTIPLE`), `isRequired`, `minSelect`, `maxSelect` (consistent with `selection` and the option count), `options[{ modifierOptionId, name, priceDelta: Money (≥ 0), status }]` (1 to 30). It has no stock. An option is archived, never deleted.

7. **OfferingLocation:** `PUT /offerings/{offeringId}/locations/{locationId}` with `{ variantId?, isAvailable, priceOverride? }`, and `DELETE` to return to the defaults.
   - It is a location-scoped write: the location must be in the caller's assignments for `catalog.offering.update` (2.4 pattern).
   - Unique `(organizationId, offeringId, variantId, locationId)`.
   - `GET /offerings?location=` returns each row's effective availability and price for that location. No row means the organization defaults (ADR-005).

8. **SearchSynonym** (organization-wide): `GET` / `PUT /catalog/synonyms` (a keyed list, ≤ 200 terms, `catalog.synonym.update`). Used by search (decision 9) and later by the bot (`08 §4`).

**API** (`/api/v1/orgs/{organizationId}/…`, the tenant pipeline)

9. Endpoints:

   | Endpoint | Permission | Notes |
   |---|---|---|
   | `GET /offerings` | `catalog.offering.read` | `?q=&kind=&status=&categoryId=&location=&page=&limit=` (≤ 100). Lean rows `{ offeringId, kind, name, slug, status, firstImageUrl?, priceFrom, variantCount, categoryIds, updatedAt }`. `q` matches a name prefix (folded like 3.1a `nameSearch`), offering synonyms, organization synonyms (the term expands to its synonyms), an exact SKU and an exact barcode. Each branch is indexed |
   | `GET /offerings/{offeringId}` | read | full offering with variants, image URLs, category and group names (batched, no N+1), readable custom fields |
   | `POST /offerings` | `catalog.offering.create` | `201`; accepts `Idempotency-Key` (manoxen product-create idempotency) |
   | `PATCH /offerings/{offeringId}` | `catalog.offering.update` | with `version`; variants are sent as the full list (existing ids kept, new ones without id, missing ones archived) |
   | `POST /offerings/{offeringId}/publish` | `catalog.offering.publish` | DRAFT → ACTIVE; same state → 200 no write |
   | `POST /offerings/{offeringId}/archive` | `catalog.offering.archive` | |
   | `PUT`/`DELETE /offerings/{offeringId}/locations/{locationId}` | update (location-scoped) | |
   | categories and modifier groups | their own permission keys | `GET` list, `GET` one, `POST`, `PATCH` (version), `POST …/archive` |
   | `GET`/`PUT /catalog/synonyms` | read / `catalog.synonym.update` | |

   - **Events** (ids only): `catalog.offering.{created, updated, published, archived, priceChanged}`. `priceChanged` fires when any variant price changes. With `orderingKey: offering:<offeringId>` if card 3.8a is already merged; otherwise without, and 3.8a adds keys later.
   - **Audit:** one entry per write with field changes; prices appear in audit (not personal data).
   - **Menu** (2.8 convention): group `catalog`.

     | Menu key | Label | Path |
     |---|---|---|
     | `catalog.offerings` | `termKey: "offering"` | `catalog` |
     | `catalog.categories` | message | `catalog/categories` |
     | `catalog.modifierGroups` | message "Add-ons" | `catalog/add-ons` |

     Topic SALES for any catalog settings entry (3.13).

10. **Role grants** (add-only):

    | Role | Offerings | Categories | Add-ons |
    |---|---|---|---|
    | OWNER, MANAGER | ALL | ALL | ALL |
    | CASHIER, STAFF, VIEWER, RIDER | read | read | read |

    Only OWNER and MANAGER write, because prices are business decisions; a business can grant more through custom roles.

## Tests (must exist and pass)
- [ ] **Happy path per kind:**
  - a SALON service with duration and a long-hair variant overriding `durationMinutes`
  - a GYM plan with two billing-period variants and an admission fee
  - a RETAIL product with size variants, SKUs and images
  - loose rice in KG with a `quantityRule`
  - publish and archive
  - each write with one audit entry and its event
- [ ] **Validation:**
  - a kind outside the template's kinds
  - a SERVICE field on a PRODUCT
  - a price in another currency or as a float
  - `compareAtPrice < price`
  - duplicate option values
  - a bad `quantityRule` (step 0, min < step)
  - an unknown unit
  - more than 100 variants
  - a non-empty `stockComponents` → 422 `STOCK_COMPONENTS_NEED_INVENTORY`
- [ ] **Uniqueness and races:**
  - SKU taken in another offering → 409 with its id
  - two concurrent creates with one SKU → one 201, one 409
  - slug generation for a Bangla name and a duplicate name
  - an idempotent create replay returns the first 201
- [ ] **References:**
  - another organization's category, add-on group or image → 400
  - an image with purpose LOGO → 400
  - archiving a category in use → 422 with counts
- [ ] **Variants update:** ids kept, a new variant added, a missing one archived (not deleted), a used variant id never reused.
- [ ] **Location:**
  - availability and price override, read back through `?location=`
  - a location outside the caller's reach → 403
  - `DELETE` returns to the defaults
- [ ] **Search:** name prefix (Bangla and Latin), an offering synonym, an organization synonym ("চাল" finds "rice"), an exact SKU and an exact barcode; the list uses its indexes (explain test).
- [ ] **Limit:** at the package's offering limit → 422 `LIMIT_REACHED`; archive frees one; two concurrent creates at the edge → one 201.
- [ ] **Permission denied** (STAFF cannot create; RIDER read only), **cross-org** 404, **module off** (the generated suite includes `catalog`).
- [ ] **Ported manoxen catalog tests** (variant, unit precision, SKU and barcode) adapted, listed in the handoff.
- [ ] Every existing suite green; full "Done means" list.

- **Money:** integers only; reject `12.5` at the schema.
- Stop and ask if a `11 §2` kind field is ambiguous (for example `depositRule`): store it as specified, do not invent behaviour.
