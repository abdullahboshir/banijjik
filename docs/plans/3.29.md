## Session parts

## Goal
Three follow-ups from the 3.6b A3 and 3.5a reviews are closed:
1. Booking and sales never guess an organization's time zone. A missing time zone fails like the credit and payment readers do, instead of silently using `"Asia/Dhaka"`.
2. The session-cancel job reads cancelled sessions in index order and cannot be starved by sessions that keep failing.
3. Sales job rows that fail are logged at `error`, like booking jobs.

## Inputs read
- `apps/api/src/modules/commerce/booking/infrastructure/booking-org-adapter.ts` (`buildOrganizationTimezoneReader`, `?? "Asia/Dhaka"`)
- `apps/api/src/modules/commerce/sales/infrastructure/sales-org.adapter.ts` (`DEFAULT_TIME_ZONE`)
- `apps/api/src/modules/core/organization/index.ts` `buildOrganizationTimezoneReader()` (returns `string | undefined`) and how `routes/order-payment-adapter.ts` turns `undefined` into `DomainRuleError({ code: ERROR_CODE.NOT_FOUND })`
- `apps/api/src/modules/commerce/booking/infrastructure/mongo-event-session.repository.ts` (`listUnsettledCancellations` sorts by `startsAt`; the index is `{ organizationId, status, bookingsSettledAt, eventSessionId }`) and the cancel-session job that calls it
- `apps/api/src/modules/commerce/sales/application/jobs/run-job-row.ts` (`getLogger().warn`)

## Decisions
1. **Time zone, fail closed.** Both adapters keep their own port shape (`read(organizationId): Promise<string>`) but throw `DomainRuleError({ code: ERROR_CODE.NOT_FOUND })` when the organization row or its `timezone` is missing. Remove `DEFAULT_TIME_ZONE` and the `"Asia/Dhaka"` literal. Every organization gets a time zone at creation (organization entity default), so this only catches broken data. Do not import the organization module into booking or sales infrastructure; keep the local read (module boundary).
2. **Session-cancel job order.** `listUnsettledCancellations` takes `{ afterEventSessionId: EventSessionId | null; limit }` and sorts by `{ eventSessionId: 1 }` with `eventSessionId > after`, so the query follows the index. The job walks pages with the last id as the cursor until a page is short, so a session that fails every run (caught per row, logged, left unsettled) no longer sits in front of the others. Keep the per-row catch as it is.
3. **The cancel note stays in the audit entry.** The A3 follow-up "the session-cancel note is only in the audit entry" is closed **without code**: a booking has no cancellation-reason field, and the audit entry is the record. Write this in the handoff.
4. **Log level.** `run-job-row.ts` logs a failed row with `getLogger().error(...)`. A row skipped because another writer changed it (409) stays at `warn` if the helper distinguishes it today; otherwise keep one `error` call.
5. READMEs only where a sentence changes. STATUS row 3.29. Handoff `docs/handoffs/3.29.md`.
