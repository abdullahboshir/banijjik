## Decisions
1. **B1 access log:**
   - `serializers.res` keeps `statusCode` only.
   - The logged `url` is the path without the query string (`request.path`).
   - `REDACT_PATHS` gains `res.headers["set-cookie"]` and `req.headers["set-cookie"]` as defence in depth.
   - Tests: a route that sets an httpOnly cookie, and a request with `?token=…&email=…`. Neither value appears in any captured log line.
2. **J1 internal AppErrors:** in the error handler, an `AppError` whose `httpStatus >= 500` is passed to `reportError` (with stack, `code`, original `messageKey` and `details`) and answered as the generic `{ code: "INTERNAL", messageKey: "errors.internal", requestId }` without `details`. 4xx `AppError`s are unchanged. Test with `errors.unknown_model`.
3. **J2 message keys:**
   - `validate.ts` maps Zod issue codes through an allow-list: `too_small`, `too_big`, `invalid_type`, `invalid_format`, `invalid_value`, `unrecognized_keys`, `not_multiple_of`, `invalid_union`, `custom`. Any other code → `validation.custom`.
   - Add the missing keys to both catalogs: `validation.invalid_value`, `validation.unrecognized_keys`, `validation.not_multiple_of`, `validation.invalid_union`, `errors.invalid_body`, `errors.retry_later`.
   - The message-key lists are exported from `@banijjik/contracts`: `VALIDATION_MESSAGE_KEYS` and `KERNEL_ERROR_MESSAGE_KEYS` (the keys the kernel can emit to clients: one per `ERROR_CODE` plus `errors.invalid_json`, `errors.payload_too_large`, `errors.invalid_body`, `errors.not_ready`).
   - The i18n test asserts that every key in those lists exists in **both** catalogs, replacing the hand-copied list. `@banijjik/i18n` gets `@banijjik/contracts` as a devDependency for that test only.
4. **J4 sequences, two modes** (owner decision 2026-10-10; ADR-085):
   - Contracts: `SEQUENCE_MODE = defineEnum(["FAST", "GAPLESS"])` and `SEQUENCE_KEY_MODE: Record<SequenceKey, SequenceMode>`. `INVOICE`, `JOURNAL` and `ZREPORT` are `GAPLESS`. Every other key is `FAST`.
   - **FAST:** `nextSequenceValue` runs its `findOneAndUpdate` **without** the active session, even inside `withTransaction`. A number taken by a transaction that later aborts is lost: gaps are allowed, there are no duplicates and no conflicts.
   - **GAPLESS:** runs with the active session and **throws `AppError(INTERNAL, "errors.gapless_sequence_needs_transaction")` when no transaction is active**. The number is rolled back with the transaction.
   - `withTransaction`: default `maxAttempts` 5. Backoff is `min(800, 50 * 2^(attempt-1))` ms plus full jitter (random 0–100% of that value). Jitter comes from an injectable `random` (default `Math.random`), so tests are deterministic.
   - When transient retries are exhausted, throw `AppError({ code: ERROR_CODE.RETRY_LATER })` instead of the raw driver error.
   - **New error code `RETRY_LATER`** = HTTP 503, `messageKey: "errors.retry_later"`. The error handler adds the `Retry-After: 1` header. Add it to `ERROR_CODE`, `ERROR_HTTP_STATUS`, both catalogs and `docs/14-API.md §3` (one table row).
   - Tests on the real replica set:
     - 25 concurrent transactions, each taking a FAST number and inserting a document: all 25 succeed, numbers are unique.
     - 20 concurrent transactions each taking a GAPLESS number: all succeed with `maxAttempts: 8`, numbers are exactly 1…20.
     - An aborted transaction leaves a gap for FAST and no gap for GAPLESS.
     - Exhausted retries → `RETRY_LATER` (fake session).
5. **J5 guardrails:**
   - **(a)** R26 also bans importing `runAsSystem` by name in the same globs (`no-restricted-imports` `importNames`), and the member-call selector `CallExpression[callee.property.name="runAsSystem"]`. Fixtures: alias import; member call.
   - **(b)** `systemReason` leaves the public `RequestContext` type. `run-as-system.ts` stores the mark in its own `AsyncLocalStorage<SystemReason>` and exports `getSystemReason(): SystemReason | undefined` for the tenant plugin (1.3). New rule R27: `runWithRequestContext` may not be imported in `**/modules/**` (fixture). Kernel and `test-support` are unaffected.
   - **(c)** `addGlobalSchemaPlugin` and `registerModel` throw `AppError(INTERNAL, "errors.model_registry_sealed")` after the first model compile (`sealModelRegistry()` is called by the first `compileOnce`). Tests reset the registry through the existing test-support reset.
   - **(d)** New rule R28: importing `mongoose` or `mongodb` is allowed only in `**/infrastructure/**`, `**/kernel/db/**`, `**/kernel/sequence/**`, `**/test-support/**` and tests (type-only imports included, to keep the rule simple). Fixtures: fail in `application/` and `presentation/`, pass in `infrastructure/`.
   - **(e)** `linterOptions: { noInlineConfig: true, reportUnusedDisableDirectives: "error" }` for all source files. Fixture: a file with `/* eslint-disable */` plus `console.log` still reports `no-console`. Inline disables are forbidden project-wide; record it in ADR-082's row (append one sentence).
   - **(f)** R22 becomes an allow-list for `**/modules/*/*/domain/**`: imports may only be relative paths inside the same module's `domain/`, `@banijjik/contracts` and `@banijjik/ids`. Implement it with `no-restricted-imports` `patterns` using a negated group (`["*", "!@banijjik/contracts", "!@banijjik/ids", "!./*", "!../*"]`) and keep the existing boundaries rule for cross-layer relative imports. Fixtures: `date-fns` fails; contracts and a relative domain import pass.
   - `RULE_COUNT` becomes 28. Every new or changed rule has fail + pass fixtures.
