# Plan: card 1.1 · IAM: users and auth

Tier: **T1** · Planned by: Opus 5.5 · Date: 2026-10-11 · Based on commit: `main 59ed290`

## Goal
A person can create an account with a phone number or an email plus a password, log in, stay logged in for 30 days of activity through rotating refresh tokens in httpOnly cookies, read and edit their own profile, and log out (this device or all devices). Protected routes get an `authenticate` middleware that puts `userId` into the request context. A platform super admin can be seeded from the environment. This is the first real module (`core/iam`), so it also sets the module pattern every later module copies.

## Decisions
**Module pattern (copied by every later module)**
1. Folder `apps/api/src/modules/core/iam/` with `domain/`, `application/`, `infrastructure/`, `presentation/`, `index.ts`, `module.manifest.ts` (plain object per `10 §2`; `defineModule` arrives in 1.6), `README.md`.
2. **Wiring:** plain constructor injection. `index.ts` is the composition root: it builds repositories → adapters → use cases → router. It exports exactly three things: `registerIamModels(): void`, `buildIamRouters(dependencies): { authRouter: Router; meRouter: Router }` and `iamManifest`.
3. `routes/v1.ts` becomes the module list. `registerModuleModels()` calls each module's `register…Models()`, and `buildV1Router(dependencies)` mounts the routers. `main.ts` calls `registerModuleModels()` before `connectDatabases` / `initializeModels`.
4. Repositories get models only through `models(ctx)` and pass `getActiveSession()`. Domain entities never see `_id`.
5. Use cases are classes with one public `execute(input)` method, named `<Verb><Noun>UseCase`. Ports are interfaces in `application/ports/`. Domain errors are `AppError` subclasses created in `domain/errors.ts` with contracts codes.

**Identity**
6. **User** (platform DB, `users`), exactly `09 §4.1`: `userId`, `name`, `email?`, `phoneE164?`, `passwordHash`, `status` (`ACTIVE | LOCKED | DISABLED`), `emailVerifiedAt?`, `phoneVerifiedAt?`, `preferredLocale` (`bn` default), `avatarFileId?` (field exists, unused until files), `lastLoginAt?`, `version`, timestamps.
   - Invariants in the entity: at least one of email/phone; email lower-cased + trimmed; phone is E.164.
   - Indexes: `{ userId }` unique, `{ email }` unique partial, `{ phoneE164 }` unique partial.
7. **Identifiers.** `@banijjik/validation` gains:
   - `normalizePhoneToE164(input)`: accepts `01XXXXXXXXX`, `8801XXXXXXXXX`, `+8801XXXXXXXXX` with spaces/dashes → `+8801XXXXXXXXX`. It also accepts any other valid `+<8–15 digits>` number unchanged, and returns `undefined` when invalid. Ported from manoxen's `phoneCanonical` rule, `15 §3`.
   - `phoneE164Schema`, `emailSchema` (trim + lowercase, RFC-light regex, max 254).
   - `loginIdentifierSchema`, which classifies the input as `{ kind: "EMAIL" | "PHONE", value }` (an `@` means email).
8. **Password policy** (`domain/password-policy.ts`): length 8–128 after NFC normalization; not equal to the email, the phone digits or the name (case-insensitive). No composition rules (NIST 800-63B). A failure is a `VALIDATION_ERROR` field `password` with `validation.password_too_short | password_too_long | password_too_similar`.
9. **Hashing:** argon2id through the port `PasswordHasher { hash(password): Promise<string>; verify(hash, password): Promise<boolean> }`. The adapter is `infrastructure/argon2-password-hasher.ts`, using `@node-rs/argon2` (prebuilt binaries, no node-gyp) with OWASP parameters (memory 19 MiB, iterations 2, parallelism 1). If the package cannot install on Windows or in CI, stop and report; do not fall back silently.

**Sessions and tokens**
10. **Access token:** JWT (HS256, `jose`), TTL 15 min. Claims: `sub` = `userId`, `sid` = `refreshSessionId`, `aud` = `"admin"` (contracts `TOKEN_AUDIENCE = ADMIN | STOREFRONT | PLATFORM`; the other two are used by later cards), `iat`, `exp`. The secret is env `AUTH_ACCESS_TOKEN_SECRET` (≥ 32 chars).
11. **Refresh token:** 32 random bytes (base64url) from `node:crypto` `randomBytes`. Only its SHA-256 hash is stored.
    - **RefreshSession** (platform DB, `refresh_sessions`): `refreshSessionId`, `userId`, `familyId`, `tokenHash` (unique), `expiresAt`, `familyExpiresAt`, `rotatedAt?`, `revokedAt?`, `replacedByRefreshSessionId?`, `userAgent?` (max 200 chars), `ipHash?` (SHA-256 of ip + the access secret), timestamps.
    - Indexes: `{ refreshSessionId }` unique, `{ tokenHash }` unique, `{ userId, revokedAt }`, `{ familyId }`, TTL on `expiresAt` + 1 day.
12. **Rotation rules** (ported; each has a test):
    - **Login/register:** creates a new family: `expiresAt = now + 30 d`, `familyExpiresAt = now + 90 d`.
    - **Refresh with a valid, unrotated, unrevoked, unexpired token:** in one transaction, mark it `rotatedAt = now`, create the next session in the same family (`expiresAt = min(now + 30 d, familyExpiresAt)`), and issue new cookies.
    - **Refresh with a token that was already rotated:**
      - within 10 s of `rotatedAt` (two tabs racing) → `401 UNAUTHENTICATED`, nothing revoked
      - later → **reuse detected**: revoke every session of the family, `401`, and log `{ event: "auth.refresh_reuse_detected", userId, familyId }` at `warn` (the audit module arrives in 1.5)
    - **Unknown, expired or revoked token** → `401`, cookies cleared.
    - The user's `status` is checked at login and at every refresh (`LOCKED`/`DISABLED` → `403 FORBIDDEN`, `errors.account_locked` / `errors.account_disabled`; the family is revoked).
13. **Cookies** (`presentation/auth-cookies.ts`):
    - `access_token` (httpOnly, `Path=/api`, `Max-Age` 900)
    - `refresh_token` (httpOnly, `Path=/api/v1/auth`, `Max-Age` 30 d)
    - Both: `SameSite=Lax`, `Secure` when `NODE_ENV=production`, `Domain` from the optional env `COOKIE_DOMAIN`.
    - No token ever appears in a response body or a log.
14. **CSRF defence** (`kernel/http/origin-check.middleware.ts`, mounted in `app.ts` after CORS): for `POST/PATCH/PUT/DELETE`, when an `Origin` header is present it must be in `config.corsAllowedOrigins`, else `403 FORBIDDEN` (`errors.origin_not_allowed`). Requests without `Origin` (server-to-server, curl) pass. `SameSite=Lax` already keeps cookies off cross-site POSTs. Webhooks get their own pipeline later (`14 §8`) and are exempted then.
15. **`authenticate`** (`kernel/auth/authenticate.middleware.ts`): `authenticate({ audience })` reads the `access_token` cookie and verifies signature, `exp` and `aud`. On success it continues inside `runWithRequestContext({ ...current, userId })`. Anything else → `401 UNAUTHENTICATED`.
    - It does not hit the database: revocation takes effect within 15 min, or at once for `logout-all`'s own device because its cookies are cleared.
    - The token verifier is a kernel port; the `jose` implementation lives in `kernel/auth/`.

**Rate limits** (`14 §2`)
16. `kernel/rate-limit/`: port `RateLimiter { consume({ bucket, key, limit, windowSeconds }): Promise<{ allowed: boolean; retryAfterSeconds: number }> }`.
    - Implementation `MongoRateLimiter`: fixed window in platform collection `rate_limit_counters` (`{ bucket, key, windowStart }` unique, atomic `findOneAndUpdate $inc` with upsert, TTL index).
    - Why Mongo now: auth traffic is small, and Redis is not wired until 1.4/1.5. The port lets 1.4 swap in Redis without touching callers.
    - Keys are hashed (SHA-256), so identifiers are not stored in clear.
17. **Limits** (constants in `domain/auth-limits.ts`):
    - login: 5 failures per identifier per 15 min, and 30 attempts per IP per 15 min
    - register: 10 per IP per hour
    - refresh: 60 per IP per 15 min
    - Exceeded → `429 RATE_LIMITED` with `Retry-After`. A successful login clears the identifier's failure counter.

**Endpoints** (all under `/api/v1`, validated by `validate()`, contracts + Zod schemas named per `14 §2`)
18. | Method & path | Auth | Behaviour |
    |---|---|---|
    | `POST /auth/register` | public | `{ name, email?, phone?, password, preferredLocale? }` (one of email/phone required) → creates the user, starts a session, sets cookies, `201 { data: MeResponse }`. A duplicate identifier → `409 DUPLICATE` with `details.field` (`email` \| `phone`). |
    | `POST /auth/login` | public | `{ identifier, password }` → cookies + `200 { data: MeResponse }`. An unknown identifier and a wrong password give the **same** `401 UNAUTHENTICATED` (`errors.invalid_credentials`) and take the same time (a dummy hash is verified when the user does not exist). |
    | `POST /auth/refresh` | refresh cookie | rotation rules of decision 12 → `204` with new cookies |
    | `POST /auth/logout` | refresh cookie (optional) | revokes the current session if present, clears both cookies, always `204` |
    | `POST /auth/logout-all` | access cookie | revokes every session of the user, clears cookies, `204` (new row in `14 §4`) |
    | `GET /me` | access cookie | `MeResponse { userId, name, email?, phoneE164?, preferredLocale, isEmailVerified, isPhoneVerified, version }` |
    | `PATCH /me` | access cookie | `{ name?, preferredLocale?, version }` via `updateVersioned` → `MeResponse`; stale version → `409 CONFLICT` |

    `/auth/otp/*` and `/auth/password/*` in `14 §4` are **not** in this card (they need the SMS/email senders: card 5.13 or a 6.1 prerequisite). Record this in STATUS.
19. **Platform operator:** `PlatformOperator` model (platform DB, `platform_operators`: `platformOperatorId`, `userId` unique, `platformRoles[]` from contracts `PLATFORM_ROLE = SUPER_ADMIN | SUPPORT | BILLING`, `status`, `version`).
    - Seed: `apps/api/src/modules/core/iam/infrastructure/seed-platform-admin.ts`, run by the script `npm run seed:platform-admin -w @banijjik/api`.
    - When env `PLATFORM_ADMIN_EMAIL` and `PLATFORM_ADMIN_PASSWORD` are both set, it creates (or leaves unchanged) the user and the SUPER_ADMIN operator inside `runAsSystem(SYSTEM_REASON.SEED, …)`. It is idempotent: a second run changes nothing and never resets the password.
    - Platform login endpoints are card 1.8.
    - R26 forbids `runAsSystem` in module infrastructure. The seed entry therefore lives in **`apps/api/src/seeds/seed-platform-admin.ts`** (outside `modules/`) and calls an iam use case `EnsurePlatformAdminUseCase` through `index.ts`. Add a boundaries element `seeds` (may import modules' `index.ts`, kernel, config), with fixtures.
20. **Config keys** (add-only): `AUTH_ACCESS_TOKEN_SECRET` (required, ≥ 32 chars), `AUTH_ACCESS_TOKEN_TTL_SECONDS` (default 900), `AUTH_REFRESH_TOKEN_TTL_DAYS` (default 30), `AUTH_SESSION_FAMILY_MAX_DAYS` (default 90), `COOKIE_DOMAIN` (optional), `PLATFORM_ADMIN_EMAIL`, `PLATFORM_ADMIN_PASSWORD` (optional, both or neither). `.env.example` gets a clearly fake secret.
21. **Message keys:** contracts `IAM_MESSAGE_KEYS` (`errors.invalid_credentials`, `errors.account_locked`, `errors.account_disabled`, `errors.origin_not_allowed`, `validation.password_too_short`, `validation.password_too_long`, `validation.password_too_similar`, `validation.identifier_required`). Both catalogs get them, and the i18n key test includes the list (same mechanism as `KERNEL_ERROR_MESSAGE_KEYS`).
22. **Events:** `iam.user.registered` is declared in the manifest's `events.emits`, but nothing is emitted yet: the event bus and outbox are card 1.5. The card that merges after 1.5 wires it (noted in the handoff and STATUS).
23. **Manifest:** `key: "iam"`, `path: "core/iam"`, `moduleClass: "SYSTEM"`, `tenantCanDisable: false`, `routes.admin: ["/auth", "/me"]`. Permissions and settings are empty in this card (roles and `iam.sessionTimeoutMinutes` are 1.4).

## Interfaces & types
```ts
// contracts
export const USER_STATUS = defineEnum(["ACTIVE", "LOCKED", "DISABLED"]);
export const PLATFORM_ROLE = defineEnum(["SUPER_ADMIN", "SUPPORT", "BILLING"]);
export const TOKEN_AUDIENCE = defineEnum(["ADMIN", "STOREFRONT", "PLATFORM"]);
export interface UserRegisterRequest { name: string; email?: string; phone?: string; password: string; preferredLocale?: "bn" | "en" }
export interface LoginRequest { identifier: string; password: string }
export interface MeUpdateRequest { name?: string; preferredLocale?: "bn" | "en"; version: number }
export interface MeResponse { userId: string; name: string; email?: string; phoneE164?: string; preferredLocale: "bn" | "en"; isEmailVerified: boolean; isPhoneVerified: boolean; version: number }

// application ports
export interface UserRepository {
  findById(userId: UserId): Promise<User | undefined>;
  findByEmail(email: string): Promise<User | undefined>;
  findByPhone(phoneE164: string): Promise<User | undefined>;
  insert(user: User): Promise<void>;            // maps duplicate-key → DuplicateIdentifierError(field)
  saveProfile(user: User, expectedVersion: number): Promise<User>;
  recordLogin(userId: UserId, at: Date): Promise<void>;
}
export interface RefreshSessionRepository {
  insert(session: RefreshSession): Promise<void>;
  findByTokenHash(tokenHash: string): Promise<RefreshSession | undefined>;
  markRotated(refreshSessionId: string, replacedByRefreshSessionId: string, at: Date): Promise<boolean>; // false when already rotated (race)
  revokeFamily(familyId: string, at: Date): Promise<void>;
  revokeAllForUser(userId: UserId, at: Date): Promise<void>;
  revoke(refreshSessionId: string, at: Date): Promise<void>;
}
export interface TokenIssuer { issueAccessToken(claims: { userId: UserId; refreshSessionId: string }): Promise<string> }
export interface Clock { now(): Date }

// kernel/auth
export function authenticate(options: { audience: TokenAudience }): RequestHandler;
```
`markRotated` must be an atomic conditional update (`{ refreshSessionId, rotatedAt: null, revokedAt: null }`), so two concurrent refreshes cannot both succeed.

## Tests (must exist and pass)
Domain / unit:
- [ ] User invariants (needs email or phone; email normalized; phone must be E.164)
- [ ] password policy (short, long, equal to email/phone/name, a Bangla passphrase accepted)
- [ ] `normalizePhoneToE164` table: `01712345678`, `8801712345678`, `+880 1712-345678` → `+8801712345678`; a 10-digit BD number, letters, empty → invalid; `+14155552671` accepted
- [ ] use cases with in-memory fakes: register (duplicate email, duplicate phone), login (wrong password, unknown user, locked user), refresh (all rotation branches with a fake clock), logout, logout-all

API (supertest + in-memory replica set):
- [ ] **happy path:** register → `GET /me` with cookies → logout → `GET /me` is 401
- [ ] login by email and by phone in local format (`01…`) both work; the response body contains no token; cookies have `HttpOnly`, `SameSite=Lax`, the right `Path`s
- [ ] **validation error:** missing identifier, short password → `400 VALIDATION_ERROR` with field paths and `validation.*` keys
- [ ] wrong password and unknown identifier → identical `401` body
- [ ] **unauthenticated:** `GET /me` without a cookie, with a tampered token, with an expired token (fake clock), with a token of audience `STOREFRONT` → `401`
- [ ] **rotated refresh:** refresh → the old refresh cookie value no longer works; reuse after the grace period → `401` and the **new** token is revoked too (family revoked); reuse within 10 s → `401` and the new token still works
- [ ] **expired refresh** (fake clock past 30 d) → `401`, cookies cleared; the family max age (90 d) is enforced
- [ ] two concurrent refresh calls with the same token → exactly one succeeds
- [ ] rate limit: the 6th failed login for one identifier → `429 RATE_LIMITED` with `Retry-After`; a successful login resets the counter
- [ ] origin check: a `POST` with an `Origin` outside the allow-list → `403`; without `Origin` → passes
- [ ] `PATCH /me` happy path and a stale `version` → `409 CONFLICT`
- [ ] `logout-all` revokes the other session's refresh token
- [ ] seed: with the env set, run twice → one user, one operator, password unchanged; without the env → does nothing and exits 0
- [ ] logs: no password, token, cookie, email or phone value in any captured log line of the API tests (grep the capture for the test values)

Lint / contracts:
- [ ] `seeds` element fixtures; all existing fixtures pass
- [ ] the i18n key test covers `IAM_MESSAGE_KEYS`

## Risks & checks
- **Timing leak at login:** always run one argon2 verify (a dummy hash when the user is missing). The test asserts the dummy path is taken (a spy on the hasher), not wall-clock timing.
- **Token leakage:** the log grep test above is mandatory. `Set-Cookie` never reaches logs (0.6a B1).
- **Race on rotation:** the concurrent-refresh test must use the real replica set, not fakes.
- **`@node-rs/argon2` on Windows:** verify it installs and that the tests run. If not, stop and report.
- **Disk:** E: has ~3.7 GB free. Use the installed MongoDB binary for tests (`MONGOMS_SYSTEM_BINARY` → `C:\Program Files\MongoDB\Server\8.2\bin\mongod.exe`, `MONGOMS_VERSION_CHECK=false`, `turbo --env-mode=loose`) and state the version. Do not download the 750 MB binary.
