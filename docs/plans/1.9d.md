## Goal
- A known user cannot be locked out by strangers.
- Rate limits cannot be dodged with a forged header, and the authenticated API has a generous per-user limit.
- A Redis outage no longer takes healthy API instances out of the load balancer.
- An outbox event that can never be dispatched stops being retried forever.
- Development config works for both apps, and production refuses the known placeholder secret and local hosts in every spelling.

## Decisions
1. **M6, login throttling (lead; ADR-095 paragraph or a new ADR-096).** Count **failed** attempts only. A successful sign-in never consumes. Two buckets per surface (admin and platform separately):
   - **identifier + IP**: 5 failures per 15 min → `429 RATE_LIMITED` with `Retry-After`. A success resets this bucket.
   - **identifier alone**: 50 failures per 15 min → 429. This stops a distributed guess at one account while making it hard for one stranger to lock a person out.
   - The per-IP bucket of 1.1 stays.
   - Tests: 5 wrong passwords from IP A lock A but not IP B for the same identifier; a success in between resets A; 50 failures across many IPs lock the identifier; the platform has its own buckets.
2. **M7, proxy hops (lead).** New required config `TRUSTED_PROXY_HOPS` (integer 0–5; default 0 outside production; **required, no default, in production**). `app.ts` uses it for `trust proxy`.
   - Document in `apps/api/README.md` and `.env.example`: set it to the number of proxies in front of the API (1 behind a single load balancer).
   - Tests: with 0, a forged `X-Forwarded-For` does not change the rate-limit key; with 1, the last hop's address is used.
3. **M8, per-user limit on authenticated routes (lead).** A per-user limiter on `/orgs/*`, `/me/*` and authenticated `/platform/*`: **600 requests per minute per user**, keyed by `userId` (platform: `platformOperatorId`).
   - It needs to be cheap on every request, so it is **Redis-backed** (`RedisRateLimiter` behind the existing `RateLimiter` port, one `INCR` + `EXPIRE` per window).
   - **When Redis is unavailable it fails open** (the request passes, one warn log per minute at most). Abuse protection must not take the API down.
   - Mounted once in `routes/v1.ts` and `routes/platform.ts` after authentication. Record in `14 §2` and ADR-090.
4. **M9:** the organization-create limiter is mounted **after** `validate()` and `idempotency()`, so invalid bodies and replays do not consume it. Test both.
5. **M11, readiness (lead).** In the **API** role, `/ready` answers 200 when MongoDB is reachable, with `details: { redis: "ok" | "degraded" }`. In the **worker** role, Redis is required: 503 without it. Update ADR-090 and the tests.
6. **M12, dead outbox events.** After **10** failed dispatch attempts an event is set to `OUTBOX_STATUS.DEAD` and reported through `reportError` (event id, type, attempts). It is no longer claimed.
   - Event **ordering** is not changed here. Add one line to STATUS and to ADR-090: "per-organization ordering is required before card 3.8 (ledger posting)".
7. **M20 and the 1.9b note, config hardening.**
   - `.env.example` lists both dev origins (`http://localhost:3000,http://localhost:3200`).
   - In production, the config check rejects the example's placeholder `AUTH_ACCESS_TOKEN_SECRET` value (exact match, plus any value containing `change-me`).
   - The local-host check treats a trailing dot as the same host (`localhost.`, `127.0.0.1.`), and also rejects `::1` and `0.0.0.0`.
   - Tests for each. The spawned production tests of 1.9b used `localhost.`: change them to set the hosts through an explicit test-only allow flag that production config refuses (`NODE_ENV=production` with `ALLOW_LOCAL_SERVICES=true` is accepted **only** when `CI` or the test runner sets it; document it). If that cannot be done cleanly, stop and ask.
8. **Organization-wide keys in `/me/config`** (from the 1.9c review, deviation 2). The API enforces the location-write keys (`organization.location.create/update/archive`) and the role-write keys (`iam.role.create/update/archive`) at ALL locations, but `/me/config` still reports them per location, so the admin UI can offer actions the API refuses.
   - Add them to `ORGANIZATION_WIDE_PERMISSION_KEYS`, so `/me/config` reports them only when held at ALL.
   - Test: a one-location manager who holds them at that location does not get them in `/me/config`, and the admin locations and roles screens show no write action for that person (unit tests, plus one browser assertion).
9. **Records only** (STATUS and the ADRs named, no code):
   - **M4:** the idempotency scope is the organization, by design (ADR-089); the permission guard runs first.
   - **M10:** no membership cache for now. `tenantContext` does two indexed reads per tenant request; revisit with load measurements before scale. ADR-087 note.
   - **M21:** until billing (6.2) exists, every organization becomes READ_ONLY 21 days after signup unless an operator extends the trial. Pilots need that manual step.
