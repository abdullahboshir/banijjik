# Plan: card 3.8b · Bookkeeping add-on (chart of accounts, journal, manual entries, statements)

Tier: **T1** (manual journal entries change the books) · Planned by: Opus 5.5 (Claude) · Implemented by: Cursor or a Claude Code session · Date: 2026-10-20 · Based on commit: `main 8258669` (3.8c merged)

Phase 3. **Can start now**, beside 3.6: it only reads and writes through `commerce/accounting`, which 3.6 does not touch. Reserved ADR number: **ADR-128**.

## Goal
An owner who wants real books, or their accountant, can:
- see and extend the **chart of accounts**
- browse the **journal**
- post a **manual journal entry** (opening balances, owner's capital, a correction)
- read the **profit and loss** and **balance sheet** for a period

It is the OPTIONAL `bookkeeping` add-on (ADR-051). Businesses without it still get automatic postings (3.8c); they just do not see these screens.

## Inputs read
- ADR-014 (append-only), ADR-051, ADR-124 (3.8c accounting engine), `09 §5.6` (Account, JournalEntry), `11 §10`
- `10 §5` bookkeeping row: OPTIONAL, permissions `bookkeeping.account.{read,create,update}`, `bookkeeping.journal.{read,createManual}` (marked * = sensitive), `bookkeeping.statement.read`; menu `money › Accounts, Journal, Statements`; package add-on `ADDON_BOOKKEEPING`
- Code: `commerce/accounting/**` (accounts by `SYSTEM_ACCOUNT_CODE`, journal posting with the balance assertion, trial balance use case, read API), `core/iam` approvals (3.4b), `kernel/sequence` (`JOURNAL`)

## Decisions
1. **Module `commerce/bookkeeping`** (OPTIONAL, the key exists, `tenantCanDisable: true`). It owns **no collections**: everything goes through accounting's index. Add to accounting's index only what this card needs:
   - `createAccount`, `updateAccount`
   - `postManualEntry`, `reverseEntry`
   - `profitAndLoss`, `balanceSheet`

   Accounting stays the only owner of `Account` and `JournalEntry`.

2. **Custom accounts:**
   - `POST /bookkeeping/accounts` (`bookkeeping.account.create`): `{ name: { bn, en }, accountType, parentAccountCode? }`. The code is generated per organization (`C-<n>` from a sequence), so it never collides with system codes.
   - `PATCH …/{accountId}` (`bookkeeping.account.update`, with `version`): only the name, or `status` ACTIVE/ARCHIVED for custom accounts.
   - **System accounts** can be renamed for display but never archived or retyped (422 `SYSTEM_ACCOUNT_LOCKED`).
   - **Archived accounts** cannot receive new lines (422).
   - Account list: `GET /bookkeeping/accounts` (`bookkeeping.account.read`), with balances as of today from the trial balance, ordered by type then code.

3. **Manual entry:** `POST /bookkeeping/journal/manual` (`bookkeeping.journal.createManual`, `Idempotency-Key` required).
   - Body: `{ businessDate, locationId?, memo, lines[{ accountId, debit?, credit? }] }`.
   - Rules:
     - 2 to 20 lines, each with one side only and > 0
     - Σ debit = Σ credit (the engine's assertion)
     - accounts are ACTIVE accounts of this organization
     - the business date is not in a closed period (period close is later; for now any date not in the future)
     - `sourceType: MANUAL`, `postingKey: manual:<journalEntryId>`
   - **Approval:** a manual entry needs an approval token (3.4b, a new action `MANUAL_JOURNAL`) unless the caller is the OWNER. A setting `bookkeeping.manualEntryOwnerWithoutApproval` (default true) controls the owner exception.
   - Audited; event `accounting.journal.posted` as for any entry.

4. **Reverse:** `POST /bookkeeping/journal/{journalEntryId}/reverse` (same permission and approval rule). It posts the mirrored entry with `reversesJournalEntryId`, once per entry (409 on a second try). It works for manual and automatic entries alike; an automatic entry's source is not changed. The screen warns that reversing an automatic posting should normally be done by reversing its source (a refund, a void) instead.

5. **Statements** (`bookkeeping.statement.read`, OWNER and MANAGER):
   - `GET /bookkeeping/statements/profit-and-loss?from&to&locationId?`: income minus expenses by account, with totals.
   - `GET /bookkeeping/statements/balance-sheet?asOf`: assets = liabilities + equity + retained earnings (income − expense to date), and a check field `isBalanced`.
   - Both read journal lines with an aggregation on indexed fields (`organizationId`, `businessDate`, `accountId`). Dashboards (3.10) will use summaries; these on-demand statements are allowed to aggregate, limited to one organization and a date range.

6. **Grants** (add-only): OWNER all; MANAGER read accounts, journal and statements; nobody else. A business can grant more through custom roles.

7. **Screens** (`apps/admin`, group `money`; shown only when the module is on):
   - **Accounts:** a tree by type with balances; add or rename a custom account (sheet).
   - **Journal:** list with filters (date, source type, account) and a detail sheet with lines; reverse with confirmation and the approval dialog.
   - **New entry:** a page with lines (account picker, debit or credit with the money input from 3.2b), a live "debits = credits" check, memo, date, approval when needed.
   - **Statements:** P&L and balance sheet with a period picker and printable layout.
   - All ≤ 170 KiB per route, mobile cards.
   - The trial balance page of 3.8c moves under this menu when the module is on (and stays in Advanced settings when it is off).

8. **Records:**
   - ADR-128 ("Accepted (proposed)"): bookkeeping owns no data, custom account codes, manual entry rules and approval, reverse rules, statement formulas
   - `14` rows, `10` row notes, the module README, STATUS row 3.8b

## Tests (must exist and pass)
- [ ] **Manual entry:**
  - balanced entry posted with number, audit and event
  - unbalanced → 422
  - one-sided line rule
  - archived or foreign account → 400
  - idempotent replay returns the first entry
  - approval required for MANAGER (token consumed), not for OWNER with the default setting
- [ ] **Reverse:** mirrors exactly; a second reverse → 409; the trial balance still nets to zero after both.
- [ ] **Accounts:** custom account code generated and unique; a system account cannot be archived or retyped; rename works.
- [ ] **Statements:**
  - a scenario (owner capital, a sale posted by 3.8c rules with a fake source, an expense, a manual correction) gives the expected P&L
  - the balance sheet is balanced (`isBalanced: true`)
  - a location filter on P&L
- [ ] **Module off:** routes 403 `MODULE_DISABLED` and menu absent; accounting keeps posting.
- [ ] **Permission denied** (STAFF), **cross-org** 404.
- [ ] **Admin:** unit tests for the entry form's balance check and the account tree; browser: post an opening-balance entry with the owner, see it in the journal and the balance sheet.
- [ ] Every existing suite green; full "Done means" list.

## Out of scope
- Period close and fiscal year close
- Bank reconciliation
- Multi-currency
- Supplier and customer ledgers (sub-ledgers come with sales and purchases)

## Done when
- Owners with the add-on can manage accounts, post and reverse manual entries, and read P&L and balance sheet.
- The books stay balanced.
- The Opus review passes.
