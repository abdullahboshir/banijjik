# Plan: card 1.8a · Platform API: operator sign-in, tenants, packages, module grants

Tier: **T1** (operator access spans every tenant) · Planned by: Opus 5.5 · Date: 2026-10-10 · Based on commit: `main 1fa56bb`

Roadmap 1.8 is split:
- **1.8a (this card):** the `/api/v1/platform` API.
- **1.8b (after 1.8a):** the `apps/platform` web app.

1.8a runs in parallel with **1.7c**. Shared: `modules/core/organization/**` (this card adds suspend/reactivate use cases; 1.7c adds menu entries and a location counter: add-only), `routes/v1.ts` and contracts/i18n index files (add-only).

## Goal
Platform operators sign in with their own cookie and audience, separate from business staff (ADR-048). With permissions that come only from their platform roles, they can:
- list and inspect tenants, and suspend or reactivate them
- create and edit packages, with the closure rule checked on save
- grant or revoke modules for one organization
- see and adjust a tenant's subscription (extend the trial, change the package)

Every write is audited in a platform audit log. Roadmap Done:
- a suspended org's users get a clear "suspended" error
- granting a module shows in that org within one config refresh

## Decisions
**Operator authentication**
1. Same session machinery as 1.1, with the audience as data:
   - `RefreshSession` gains `audience` (contracts `TOKEN_AUDIENCE`; existing rows and code paths use `ADMIN`). A refresh token only renews a session of its own audience.
   - Endpoints `POST /platform/auth/login`, `/logout`, `/refresh`:
     - Login needs valid credentials **and** an ACTIVE `PlatformOperator` for that user. Anything else gives the same `401 errors.invalid_credentials` (no hint whether the person is an operator).
     - Rate limits as 1.1, in separate buckets.
   - Cookies: `platform_access_token` (Path `/`, 15 min), `platform_refresh_token` (Path `/api/v1/platform/auth`). Both httpOnly, SameSite=Lax, Secure in production.
   - Access tokens carry `aud = PLATFORM`. The admin `authenticate` already refuses other audiences, and the platform one refuses `ADMIN` tokens.
2. `authenticatePlatform` (kernel/auth + a port implemented by iam):
   - It verifies the platform token, loads the operator (NONE tenancy, no system access needed) and continues with `userId`, `platformOperatorId`, `platformRoles` in the request context.
   - A disabled operator → 401 on the next request (one indexed read per request; operator traffic is tiny).
3. **Platform permissions** (contracts `PLATFORM_PERMISSION_KEY`, pattern `platform.<module>.<action>`, ADR-054):
   - `platform.tenant.{read,suspend}`
   - `platform.package.{read,write}`
   - `platform.entitlement.{read,write}`
   - `platform.subscription.{read,write}`
4. **Role mapping** (code template, **ADR-093 "Accepted (proposed)"**, tell the owner):
   - `SUPER_ADMIN` = all
   - `SUPPORT` = `tenant.read`, `tenant.suspend`, `package.read`, `entitlement.read`, `subscription.read`
   - `BILLING` = `tenant.read`, `package.*`, `entitlement.*`, `subscription.*`

   The docs name the roles but not their rights; this mapping is the planner's proposal.
   - Middleware `platformPermission(key)` → `403 FORBIDDEN`.

**Tenant data access**
5. Platform use cases live in `modules/platform/**/application` and touch tenant-scoped records (overrides, subscriptions, member counts) through `runAsSystem(SYSTEM_REASON.PLATFORM_ADMIN, …)`. R26 already allows exactly this folder.
   - Every such write also writes a **platform audit entry** in the same transaction (decision 6). A read logs only the `system_access` line.
6. **Platform audit log:** `PlatformAuditLog` (PLATFORM DB, `platform_audit_logs`, tenancy NONE, append-only): `platformAuditLogId`, `actorPlatformOperatorId`, `actorUserId`, `action`, `targetType` (`organization | package | subscription | module_override`), `targetId`, `organizationId?`, `changes`, `reason?`, `requestId`, `occurredAt`.
   - A kernel port `PlatformAuditRecorder` requires an active transaction (as in 1.5a).
   - Actions are added to contracts (`platform.tenant.suspended`, …).
   - Read endpoint `GET /platform/audit-logs` (SUPER_ADMIN only, through `platform.tenant.read` + the role check), paginated.

**Endpoints** (`14 §7`; all under `/api/v1/platform`, behind `authenticatePlatform`)
7. **Tenants** (module `platform/tenant-admin`, PLATFORM class, new):
   - `GET /organizations?status=&q=` (name/slug prefix; paginated; index-backed) → summary with status, template key, subscription status, member count (one aggregate)
   - `GET /organizations/{organizationId}` → org, subscription, active overrides, locations count, owner contact (`displayName`, masked identifier)
   - `POST /organizations/{organizationId}/suspend` `{ reason }` and `/reactivate`, through use cases owned by `core/organization` (`SuspendOrganizationUseCase`, `ReactivateOrganizationUseCase`), called via the organization `index.ts`:
     - status change with `version`
     - event `organization.organization.suspended/reactivated`
     - platform audit
     - `configVersion` bump
   - Not in this card: impersonation, change-industry-template, close (later cards).
8. **Packages** (module `platform/package`):
   - `GET /packages`, `POST /packages`, `GET /packages/{packageId}`, `PATCH /packages/{packageId}` (`version`), `POST /packages/{packageId}/archive`
   - **Save-time rule** (`10 §3`): a base package's modules ∪ SYSTEM ∪ CORE must be closed under `dependsOn` over the registered manifests. Keys without a manifest are allowed (validated against `MODULE_KEY`), and listed in the response as `unbuiltModuleKeys`.
   - An add-on and a base package are never the same record (`isAddOn` immutable).
   - Every save increments `Package.version`, so the 1.6a package catalogue version picks it up within its 5 s refresh.
   - Archiving a package that an ACTIVE or TRIALING subscription uses → `422 BUSINESS_RULE PACKAGE_IN_USE`.
9. **Module overrides** (module `platform/entitlement`):
   - `GET /organizations/{organizationId}/module-overrides`
   - `POST …/module-overrides` `{ moduleKey, effect: PLATFORM_GRANT | PLATFORM_REVOKE, reason, expiresAt? }`
   - `DELETE …/module-overrides/{moduleOverrideId}` (`14 §7`; overrides are configuration, not ledger data, ADR-078)
   - Rules:
     - the module must have a registered manifest, and must not be PLATFORM or SYSTEM (those cannot be granted or revoked)
     - unique per effect
     - every write bumps the org's `configVersion` in the same transaction (1.6a rule), so the very next tenant request resolves the new config
10. **Subscription** (module `platform/saas-billing`):
    - `GET /organizations/{organizationId}/subscription`
    - `POST …/subscription/extend-trial` `{ days: 1..30, reason }`: only while TRIALING
    - `POST …/subscription/change-package` `{ basePackageId, addOnPackageIds }`: base must be a non-archived base package, add-ons must be add-ons; status unchanged

    Each bumps `configVersion` and writes a platform audit entry. Payment collection is 6.2.
11. Manifests: `tenant-admin` gets `routes.platform`, and package, entitlement and saas-billing add their platform route prefixes. The registry rule "PLATFORM modules declare only platform routes" holds. Platform routes are **not** behind the tenant entitlement gate; they are behind `authenticatePlatform` + `platformPermission`.
12. **Seeds:** the platform admin seed (1.1) already creates a SUPER_ADMIN operator. No new seed.

## Tests (must exist and pass)
- [ ] **operator auth:**
  - login works for an ACTIVE operator
  - a normal user with a valid password gets the same 401 as a wrong password
  - a platform token is refused by tenant routes and an admin token by platform routes
  - refresh renews only a platform session; logout; a disabled operator is refused on the next request
  - the rate limit
- [ ] **permissions:** a SUPPORT operator can suspend but not edit packages or grant modules; BILLING the reverse for suspend; table-driven over the mapping
- [ ] **Done 1, suspend:** the tenant's member gets `403 ORG_SUSPENDED` on the very next tenant request; reactivate → it works; event and platform audit written atomically (an injected failure leaves neither)
- [ ] **Done 2, grant:** a module outside the package (a probe OPTIONAL manifest) → `POST module-overrides PLATFORM_GRANT` → the member's next `/me/config` lists it and its probe route answers 200; `DELETE` → next request `403 MODULE_DISABLED`. Granting a SYSTEM or PLATFORM module → 422.
- [ ] **packages:** create, edit, archive; the closure rule refuses a base package missing a dependency; `unbuiltModuleKeys` lists catalogue-only keys; an archive while in use → 422; a stale version → 409; an edit is visible to resolution after the catalogue refresh (fake clock)
- [ ] **subscription:** extend-trial only while TRIALING, max 30 days; change-package validations; `configVersion` bumped
- [ ] **tenant list and detail:** paging, search, the member count aggregate (fixed query count), masked owner identifier
- [ ] every platform write has exactly one platform audit entry; reads write none and log `system_access`
- [ ] existing suites unchanged (the session audience default keeps 1.1 tests green)

All with `--force`: lint, format:check, typecheck, test, build; `npm run test:tools`.
