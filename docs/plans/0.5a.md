# Plan: card 0.5a · Design system (`packages/ui`) and i18n (`packages/i18n`)

Tier: T2 · Planned by: Opus 5.5 · Date: 2026-10-10 · Based on commit: `main 7766e90`

Card 0.5 is split:
- **0.5a (this card):** the shared packages: tokens, ★ components, formatting, i18n + terms
- **0.5b:** `apps/admin` (Next.js shell, providers, API client, Lighthouse)

0.5a can run in parallel with 0.2b/0.4a/0.4b: it touches only `packages/ui`, `packages/i18n`, root `package.json` (add-only) and `tsconfig.json` (add-only).

## Goal
`@banijjik/ui` provides:
- the semantic design tokens of `13 §8` as TypeScript, compiled to CSS variables (light + dark values; only light is applied)
- the Tailwind v4 theme mapping
- the ★ foundation components of `13 §9`
- the only money/number/date formatting functions
- `statusTone()` from `11 §12`

`@banijjik/i18n` provides BN/EN catalogs and a translator with **terms** overrides (template/org labels like Customer → "Student").

Both are tested, including with Bangla strings and a WCAG-AA contrast test on token pairs.

## Inputs read
- `13-UX.md` §1–§11 (principles, navigation, layouts, states, localization, tokens, components, a11y, performance)
- `10 §6` (MenuEntry shape, groups)
- `11 §12` (status tones)

- Existing package shape (ESM, NodeNext, tsc → dist, `vitest run --dir src`)

## Decisions
1. **Components are presentational and text-agnostic.** `packages/ui` never imports `@banijjik/i18n`. Every visible string (labels, "Undo", "Cancel", empty-state text) comes in through props, already translated by the app.
   - Why: ui stays pure and testable, and the same components serve admin, platform and storefront with different catalogs.
   - Accessible names are props too (`closeLabel`, `menuLabel`).
2. **Tokens:**
   - `packages/ui/src/tokens/{color,typography,space,radius,shadow,motion,z-index,breakpoints}.ts` export plain objects with the exact values of `13 §8`.
   - Each color token has `{ light, dark }`. Dark values are chosen now (ADR-058): slate-based, the same hue for brand/status, each pair AA. They are listed in the handoff.
   - `scripts/build-tokens.mjs` (in the package) generates `src/styles/tokens.css`:
     - `:root { --color-brand-primary: … }` with the light values
     - `[data-theme="dark"] { … }` with the dark values, never applied at launch
   - It runs before `tsc` in `build`. The generated file is committed and checked by a test, so drift fails CI.
3. **Tailwind v4, CSS-first:**
   - `src/styles/theme.css` uses `@theme inline` to map semantic variables to utility names (`bg-surface`, `bg-app`, `text-primary`, `text-secondary`, `border-default`, `bg-brand`, `text-on-brand`, `text-success` …), plus the spacing, radius, shadow, z-index and breakpoint scales.
   - The package exports `@banijjik/ui/styles.css` (tokens + theme + base layer: body font, Bangla line-height 1.6 via `:lang(bn)`, `prefers-reduced-motion`).
   - Apps add `@source` for the ui sources (0.5b).
4. **shadcn-style source components**, owned in `packages/ui/src/components/` (generated with the shadcn CLI, then adapted to the semantic tokens; no raw hex, no px font sizes). Primitives: `@radix-ui/react-dialog` (Dialog + Sheet), `@radix-ui/react-slot`, `class-variance-authority`, `tailwind-merge` + `clsx` (`cn()` helper), `lucide-react` (only icon set), `sonner` (Toast). Check current majors with `npm view` and record them.
5. **★ components and their contracts:**
   | Component | Contract (props, key behaviour) |
   |---|---|
   | `AppShell` | `{ topBar, sidebar, bottomNav, children }` slots. Sidebar visible ≥ 1024 px, bottom nav < 768 px, both CSS-driven (no JS breakpoint checks, so SSR has no hydration mismatch). Page padding 16/24. |
   | `TopBar` | `{ logo, organizationName, actions }`. Height 56, sticky (`z-sticky`). |
   | `Sidebar` | `{ groups: { groupKey, label, entries: { menuKey, label, href, iconKey, isActive }[] }[], collapsedAt1024: true }`. Empty groups are not rendered. Icons resolved from `iconKey` via a lucide map in ui. |
   | `BottomNav` | `{ slots: { slotKey, label, href?, iconKey, onSelect?, badgeCount? }[] }`, max 5. The center slot (`slotKey: "quickCreate"`) renders the [+] button. Targets ≥ 44 px. |
   | `QuickCreateSheet` | `{ open, onOpenChange, title, actions: { actionKey, label, href, iconKey }[], emptyText }`. Bottom sheet on mobile, dialog ≥ 768 px. |
   | `PageHeader` | `{ title, actions?, filters? }` |
   | `FilterBar` + `FilterSheet` | `{ chips: { value, label, isActive }[], onChipSelect, moreLabel, sheetContent }`. Chips inline, the rest in a sheet on mobile. URL state is the app's job. |
   | `DataList` | `{ columns: { columnKey, header, cell(row), isPrimary? , align? }[], rows, rowKey(row), onRowSelect?, emptyState }`. Table ≥ 768 px, cards below (both rendered, toggled by CSS). The card shows `isPrimary` columns. No virtualization yet (added when a list needs > 100 rows). |
   | `Form` primitives | `FormField { label, htmlFor, error?, hint?, required? }`, `TextInput`, `Textarea`, `Select` (native, for mobile), `Checkbox`, `SubmitBar { cancelLabel, submitLabel, isSubmitting }` (sticky bottom). Inputs have a 16 px font size (no iOS zoom). |
   | `Skeleton` | `{ variant: "line" | "card" | "row", count? }` |
   | `EmptyState` | `{ message, action? }`. One sentence + one action. No illustration. |
   | `Toast` | `toast.success/error(message, { undo?: { label, onUndo } })` via sonner; `<Toaster />` with `aria-live`. Undo lasts 5 s. |
   | `ConfirmDialog` | `{ open, title, description, amount?, confirmLabel, cancelLabel, tone: "default" | "danger", onConfirm }`. The amount is shown prominently when given (`13 §1` principle 6). |
   | `StatusBadge` | `{ requestType, status, label }`; colour from `statusTone`. |
   | `MoneyText` | `{ money: { amount, currency }, locale, digitScript?, grouping? }` → `format/format-money` |
6. **Formatting** (`src/format/`) is the only place that formats:
   - `formatMoney({ amount, currency }, { locale, digitScript = "LATIN", grouping = "WESTERN" })`:
     - `৳ 1,250` (thin space U+2009 after the symbol)
     - paisa shown only when non-zero (`৳ 1,250.50`)
     - minor units by currency precision (BDT 2)
     - SOUTH_ASIAN grouping `12,34,567`
     - Bengali digits only when `digitScript = "BENGALI"`
   - `formatNumber` with the same options.
   - `formatPhoneForDisplay("+8801712345678")` → `01712-345678`.
   - Integer math only on money (ADR-013). Never `amount / 100` floats for the display string: split integer and remainder.
   - Dates are deferred to the first card that shows dates (needs the timezone rules). Note it in the handoff.
7. **`statusTone(requestType, status)`** from `11 §12`, with `requestType ∈ ORDER | BOOKING | ENROLLMENT | PAYMENT | SALES_RETURN`. The table is the only source. An unknown status → `neutral` (and a test covers every listed status). The status string types are local `as const` lists in ui for now; when contracts gets the request status enums (D3 cards), ui switches to them (note in the handoff).
8. **i18n** (`packages/i18n`):
   - Catalogs `src/catalogs/bn.json` and `en.json`, flat dotted keys.
   - Keys in 0.5a:
     - shell labels (`nav.home`, `nav.more`, `nav.quickCreate`, `shell.search`, `shell.notifications`, `shell.account`, `shell.openMenu`, `shell.closeMenu`)
     - state texts (`state.empty.default`, `state.loading`, `state.offline`, `state.permissionDenied`, `common.cancel`, `common.save`, `common.undo`, `common.confirm`, `common.retry`)
     - all `errors.*` message keys for the 20 `ERROR_CODE`s of `14 §3` (`errors.not_found` …), plus `errors.invalid_json`, `errors.payload_too_large`, `errors.internal`, `errors.not_ready`, `errors.dedicated_not_supported`
     - a base set of `validation.*` keys for Zod issue codes (`validation.too_small`, `validation.too_big`, `validation.invalid_type`, `validation.invalid_format`, `validation.custom`, `validation.required`)
     - default terms `term.contact.singular/plural`, `term.order.singular/plural`, `term.offering.singular/plural`, `term.resource.singular/plural`, `term.booking.singular/plural`, `term.enrollment.singular/plural`
   - `createTranslator({ locale, catalogs?, terms?, brandName })`:
     - `t(key, values?)` interpolates `{name}`
     - catalog values may reference terms as `{term:contact.plural}`, resolved from `terms` overrides first, then the catalog's `term.*` defaults
     - `{brand}` resolves to `brandName` (ADR-038: no brand literal in catalogs)
     - a missing key returns the key and calls `onMissingKey` (default no-op)
   - `DEFAULT_LOCALE = "bn"`, `SUPPORTED_LOCALES = ["bn", "en"]`.
   - Pure TS, no React dependency. React bindings live in the app (0.5b).
9. **Fonts are not in ui.** `next/font` belongs to the Next app (0.5b). ui's CSS uses `var(--font-sans)` with a system fallback stack.
10. **Tests** use vitest + jsdom + `@testing-library/react` (+ `@vitejs/plugin-react` for JSX in tests), configured per package. They render with Bangla strings that are longer than the English ones (principle "+30%").

## Tests (must exist and pass)

- [ ] **token drift:** the committed `tokens.css` equals the generator output
- [ ] `formatMoney`: `125000 BDT` → `৳ 1,250`; `125050` → `৳ 1,250.50`; SOUTH_ASIAN `123456700` → `৳ 12,34,567`; BENGALI digits → `৳ ১,২৫০`; negative amounts; zero
- [ ] `formatPhoneForDisplay` for `+8801712345678`
- [ ] `statusTone` returns the `11 §12` tone for every listed status (table-driven), and `neutral` for unknown
- [ ] `DataList` renders a table with all columns and cards with only the primary columns; the empty state shows when there are no rows
- [ ] `BottomNav` renders at most 5 slots; the quick-create slot calls `onSelect`; each target has an accessible name
- [ ] `QuickCreateSheet` lists the given actions and shows `emptyText` with none
- [ ] `ConfirmDialog` shows the formatted amount and calls `onConfirm` once; Esc closes it
- [ ] `Sidebar` hides empty groups and marks the active entry with `aria-current="page"`
- [ ] `Toast` with undo calls `onUndo`
- [ ] i18n: bn and en catalogs have exactly the same key set; term override (`term.contact.plural` → "ছাত্র") is applied inside another key's text; `{brand}` interpolation; a missing key returns the key and calls `onMissingKey`; the default locale is `bn`
- [ ] lint clean (no brand literal in catalogs, no `export *` in index files)
- [ ] all with `--force`: lint, format:check, typecheck, test, build

## Risks & checks
- **Tailwind v4 + shadcn:** use the shadcn CLI's Tailwind v4 path, then replace every colour/spacing with semantic tokens. Grep for `#[0-9a-fA-F]{3,6}` and `px` font sizes in `src/components`: there must be none.
- **SSR safety:** no `window` access at module level, and no JS-driven responsive switching (the CSS does it).
- **Bundle:** ui must tree-shake. `sideEffects: ["*.css"]` in package.json.
