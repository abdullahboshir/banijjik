## Session parts
Single part: `s/4.3-cod-v-scenarios`.
End-to-end integration day scenarios through real workers asserting complete COD delivery, settlement, RTS, loss, recovery, trial balance, commission, and reports parity.

## Goal
Prove through end-to-end integration tests (`apps/api/src/modules/commerce/report/presentation/day-scenario-cod-api.test.ts`) that the full COD lifecycle operates correctly across all modules with real workers:
1. Midnight Asia/Dhaka business date anchoring matches settlement and report dates.
2. Advance payment + COD courier delivery + courier fee expense + courier settlement gives zero collection receivable and balanced trial balance.
3. Failed attempt + redelivery + delivered return leaves balanced trial balance and reversed commission.
4. Failed shipment + damaged RTS disposition + courier fee restores/reclassifies stock, records expense, and balances.
5. Own-rider delivery + rider cash handover + correction matches rider cash and cashier register.
6. Balanced day scenario with advance + delivery failure + partial return + delivery loss closure + carrier fee + physical recovery: ending inventory, COGS/loss expense, customer due, commission, daily summary reports, and trial balance reconcile.

1. **Real Outbox Worker Execution:**
   All events are emitted to outbox documents and processed with `processDayAndReplay` (dual-pass to guarantee idempotency and replay safety).
2. **Dedicated Test Suite:**
   Create `apps/api/src/modules/commerce/report/presentation/day-scenario-cod-api.test.ts` using `startDayScenarioApi()`.
3. **No Mocked Financial Ports:**
   Assert on real trial balance balance status (`trialBalances(actor, organizationId) === true`), real reports daily summary totals, and real commission summaries.
4. **Clean Code & Line Limits:**
   Keep file <= 500 lines by leveraging existing test-support helpers (`sales-api-world`, `catalog-world`, `day-scenario-world`).
