# Plan: card 3.1b · Contacts screens

Tier: **T2** · Planned by: Opus 5.5 (Claude) · Implemented by: a Claude Code session · Date: 2026-10-17 · Based on commit: `main a04012d`. **Start after 3.1a is merged.** If 3.13's layout pieces are merged first, use them; if not, follow the existing screens' patterns and 3.13 restyles later.

Reserved ADR number: **ADR-111**, only if needed.

## Goal
A business works with its contacts on a phone, under its own word for them ("ক্লায়েন্ট", "মেম্বার", "ছাত্র-ছাত্রী"):
- find
- add, which offers the existing contact when the phone is already known
- see the details
- edit
- archive
- fill the template's fields, including the guardian link for coaching

## Decisions
1. **Routes:** `/[orgSlug]/contacts` (list) and `/[orgSlug]/contacts/[contactId]` (detail). The menu entry comes from 3.1a's manifest with `termKey: "contact"`. Every title, button and empty state uses the term in the user's language ("নতুন ক্লায়েন্ট", "New member"), through `termLabel` with message keys as the fallback.

2. **List:**
   - a search box (name, phone, custom value); filter chips for roles (labelled with terms where a template names them, e.g. `contact` vs supplier)
   - cards on a phone and a table from `md`
   - paged; a skeleton while loading
   - an empty state with an add button

3. **Add:**
   - a sheet with name, phone (BD formats accepted, normalized by the API), email, roles, and the template's contact fields through the 2.5 block (the `fields.contact` of `/me/config`)
   - **on 409 `errors.contact_duplicate`**, the sheet shows "This phone already belongs to …" with an "Open" button to `details.contactId`

4. **The contact-link input** (2.5's last pending kind): a `ContactLinkInput` in `@banijjik/ui`, with the glue in web-client.
   - It searches existing contacts by name or phone, or creates one with name and phone; that sends 3.1a's `{ create: { name, phone } }`.
   - It shows the linked contact's name, and on the detail page, a link to them.
   - `pendingFieldKeys` becomes empty for these fields.
   - This makes a COACHING student form submittable (2.5's note).

5. **Detail page:**
   - header with name, phones (tap to call on a phone: `tel:`), roles and tags
   - sections: Details (custom fields, read-only, sensitive ones shown as "Hidden" without permission), Addresses (add, edit, set default), Relations (each linked contact by name, e.g. "অভিভাবক: …")
   - actions: Edit (sheet), Archive (confirm), Anonymize (owner only, typed confirmation and a reason, explained as irreversible)
   - every button follows the permissions of 3.1a

6. **Budget and phone:** each route **≤ 170 KiB** initial JS, sheets lazy; no sideways scroll at 375 px; touch targets ≥ 44 px.
