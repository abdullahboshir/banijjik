## Goal
Provides trusted Cash on Delivery (COD) collection and claim-fencing in the `payment` module for orders delivered via `COURIER` or `OWN_RIDER`. When an order is delivered with outstanding dues, an `IN` payment (`COD_COURIER` or `RIDER_CASH`) is recorded atomically alongside an append-only `CollectionClaim` in `OPEN` state. Payment collections are fenced so generic payment reversal is rejected while claimed by an active courier settlement or rider cash handover, and settlement reversals atomically reopen eligible collection claims.

## Decisions

1. **CollectionClaim Entity & Lifecycle:**
   - Identity: `collectionClaimId` (UUID v7 via `newId()`).
   - Fields: `organizationId`, `paymentId`, `orderId`, `carrierMethod` (`COD_COURIER` | `RIDER_CASH`), `carrierReference` (`consignmentId` or `deliveryAssignmentId`), `state` (`OPEN` | `CLAIMED` | `REVERSED`), `generation` (integer, starts at 1), `claimedByReference` (nullable string: `courierSettlementId` or `riderCashHandoverId`), `version`, audit fields (`createdAt`, `updatedAt`, `createdByUserId`, `updatedByUserId`).
   - Collection claim state transitions:
     - `OPEN` $\to$ `CLAIMED`: Claimed by a settlement or handover.
     - `CLAIMED` $\to$ `OPEN`: Released by a settlement or handover reversal, incrementing `generation`.
     - `OPEN` $\to$ `REVERSED`: Explicit collection payment reversal.

2. **CodCollectionPort / CollectCodUseCase:**
   - Input:
     ```ts
     interface CollectCodInput {
       readonly organizationId: OrganizationId;
       readonly orderId: OrderId;
       readonly locationId: LocationId;
       readonly contactId: ContactId | null;
       readonly expectedOrderVersion: number;
       readonly deliveryCompletionId: string;
       readonly carrier:
         | { readonly method: "COD_COURIER"; readonly consignmentId: string }
         | { readonly method: "RIDER_CASH"; readonly deliveryAssignmentId: string };
       readonly actorUserId: UserId;
       readonly now: Date;
     }
     ```
   - Flow:
     - Read order payment summary via `PaymentSummaryRepository`.
     - Calculate remaining unpaid due (`total - netPaid`).
     - If remaining due $\le 0$ (e.g. order was fully prepaid), return `{ paymentId: null }` (no payment, no claim).
     - Check natural collection key: if a claim already exists for `paymentId` linked to this completion, return existing payment (idempotent replay).
     - Inside active transaction:
       - Generate payment number via existing sequence.
       - Create `IN` Payment with method `COD_COURIER` or `RIDER_CASH`, amount = remaining due, allocated to `(ORDER, orderId)`.
       - Update payment summary (`allocatedAmount`, `status` $\to$ `PAID`).
       - Create and persist `CollectionClaim` in `OPEN` state with `carrierReference`.
     - Return `{ paymentId: persistedPayment.paymentId }`.

3. **Settlement Fencing (`claimCollections` & `releaseCollections`):**
   - `claimCollections(input: { organizationId, paymentIds, carrierMethod, referenceId, actorUserId, now })`:
     - Loads claims for all `paymentIds`.
     - Asserts all claims exist, match `carrierMethod`, and have `state: "OPEN"`.
     - Sets `state: "CLAIMED"`, `claimedByReference: referenceId`.
   - `releaseCollections(input: { organizationId, paymentIds, carrierMethod, referenceId, actorUserId, now })`:
     - Loads claims for all `paymentIds`.
     - Asserts all claims have `state: "CLAIMED"` and `claimedByReference: referenceId`.
     - Sets `state: "OPEN"`, clears `claimedByReference`, increments `generation`.

4. **Guarding Generic Payment Reversal:**
   - In `ReversePaymentUseCase`:
     - Query `CollectionClaimRepository.findByPaymentId(paymentId)`.
     - If claim exists and `state === "CLAIMED"`: reject with 409 `AppError` (`payment.collection_claim_active`), directing staff to reverse the courier settlement or rider handover first.
     - If claim exists and `state === "OPEN"`: allow payment reversal and mark claim `state: "REVERSED"`.

5. **DeliverOrder Integration:**
   - In `DeliverOrderUseCase`:
     - If order's fulfillment method is `COURIER` or `OWN_RIDER`, retrieve carrier details (`consignmentId` or `deliveryAssignmentId` from latest delivery attempt or order fulfillment snapshot).
     - Invoke `dependencies.payments.collectCod(...)` inside the same unit-of-work transaction.

## Tests to Verify
1. COD order delivery transitions to `DELIVERED` and creates `COD_COURIER` / `RIDER_CASH` payment and `OPEN` `CollectionClaim`.
2. Fully prepaid COD order creates no extra payment and no `CollectionClaim`.
3. Idempotent delivery retry does not duplicate payment or claim.
4. Claiming collections updates state to `CLAIMED` with settlement/handover reference.
5. Generic payment reversal is blocked when `CollectionClaim` is `CLAIMED`.
6. Settlement reversal releases `CollectionClaim` back to `OPEN` and increments generation.
7. Unsettled `OPEN` collection payment can be reversed with approval, moving claim to `REVERSED`.
8. Tenant isolation and location permissions enforced.
