## Goal
What an organization can do is decided by data, in one place:
- **Manifests** declare each module's routes, permissions, menu and events.
- **Packages and the subscription** say what was bought. Overrides adjust it.
- **`resolveOrgConfig`** computes the effective modules, kinds, limits and access mode (`10 §3`).
- **One entitlement gate** in the tenant pipeline answers `403 MODULE_DISABLED` for a route of a module that is not effective, and `403 ORG_READ_ONLY` for writes when the subscription lapsed.

A new organization starts with a 14-day BUNDLE trial. `GET /orgs/{organizationId}/me/config` gives the admin app everything it needs to draw itself.

## Decisions
**Contracts**
1. Add:
   - `MODULE_KEY`: all 37 keys of `10 §5`, kebab-case values
   - `MODULE_CLASS`, `OFFERING_KIND` (`PRODUCT, SERVICE, PLAN, RENTAL, EVENT`), `ACCESS_MODE` (`FULL, READ_ONLY`)
   - `SUBSCRIPTION_STATUS` (`TRIALING, ACTIVE, PAST_DUE, CANCELLED`), `MODULE_OVERRIDE_EFFECT` (`PLATFORM_GRANT, PLATFORM_REVOKE, TENANT_DISABLE`), `PACKAGE_STATUS` (`ACTIVE, ARCHIVED`)
   - `LIMIT_KEY` (`locations, members, offerings, ordersPerMonth, aiMessagesPerMonth, smsPerMonth, channels, posDevices`)
   - `TRIAL_DAYS = 14`, `PAST_DUE_GRACE_DAYS = 7`, `TRIAL_PACKAGE_KEY = "BUNDLE"`
   - the types `ModuleManifest` (exactly `10 §2`), `MenuEntry` (`10 §6`), `ResolvedOrgConfigResponse`

**Manifests and registry (`kernel/modules`)**
2. `defineModule(manifest): ModuleManifest` validates the shape with Zod and freezes it. The existing manifests (iam, organization, audit) switch to it.
   - `routes.admin` entries are full v1 paths: `/auth`, `/me`, `/me/orgs`, `/orgs/:organizationId/roles`, `/orgs/:organizationId/audit-logs`.
3. `createModuleRegistry(manifests)` checks, and throws at startup on a failure:
   - each key is in `MODULE_KEY` and unique
   - every `dependsOn` key is in `MODULE_KEY`, and there is no cycle
   - permission keys are in `PERMISSION_KEY` and start with the module key
   - PLATFORM modules declare only `platform` routes and PLATFORM menu entries
   - `tenantCanDisable` only on OPTIONAL modules
   - route prefixes are unique across modules

   It exposes `all()`, `find(key)`, `ownerOfRoute(path)` (longest prefix) and `registryHash` (sha-256 of the canonical JSON of all manifests).
   - The iam `PermissionCatalog` is now built from the registry instead of a hand-written list in `routes/v1.ts`.

**New modules (minimal, only what this card needs)**
4. **`platform/package`:** `Package` (PLATFORM DB, tenancy NONE, versioned) per `09 §4.6`, with `limits` over all `LIMIT_KEY`s (`null` = unlimited) and `limitIncrements` for packs.
   - `moduleKeys` are validated against `MODULE_KEY` (the catalogue), **not** against the registered manifests: seed packages name modules that are built in later phases. The resolver ignores keys without a registered manifest.
   - Seed data = the base packages and add-ons of `10 §9`, in `infrastructure/seed-packages.ts`. `EnsureSeedPackagesUseCase` inserts a package only when its `packageKey` is missing; it never overwrites an edited one. Prices stay empty (P2).
   - Entry `apps/api/src/seeds/seed-packages.ts` + script `seed:packages`.
5. **`platform/saas-billing`:** `PlatformSubscription` (PLATFORM DB, tenancy ORGANIZATION, versioned) per `09 §4.6`. Unique partial index: one non-cancelled subscription per org.
   - `StartTrialUseCase(organizationId)`: `status TRIALING`, `basePackageId` = the BUNDLE package, `trialEndsAt = now + TRIAL_DAYS`. It runs **inside the create-organization transaction**, through a port in `core/organization` (`TrialStarter`) wired in `routes/v1.ts`. A missing BUNDLE package → `AppError(INTERNAL, "errors.trial_package_missing")`.
   - Pure function `accessModeOf(subscription, now)` (`10 §8`):
     - TRIALING before `trialEndsAt` → FULL
     - TRIALING after it → treated as PAST_DUE since `trialEndsAt`
     - ACTIVE → FULL
     - PAST_DUE within `PAST_DUE_GRACE_DAYS` of the due date → FULL with `isPastDue: true`
     - PAST_DUE after the grace, or CANCELLED, or **no subscription** → READ_ONLY

     Because it is computed from dates on every read, no job has to flip statuses for the mode to be right.
6. **`platform/entitlement`:** `ModuleOverride` (PLATFORM DB, tenancy ORGANIZATION; unique `{ organizationId, moduleKey, effect }`; `expiresAt` honoured at resolve time), the resolver, the gate, and the `/me/config` endpoint.
   - No write endpoints here: platform grants are card 1.8, tenant disable comes with settings.
   - Every write of a subscription or an override must bump `Organization.configVersion` in the same transaction: add a port `ConfigVersionBumper`, implemented by organization, like `rolesVersion` in 1.4. This card's own writer is `StartTrial`.

**Resolver (`10 §3`, exactly)**
7. `resolveOrgConfig(organizationId)` implements steps 1–8 as written. Its inputs come through ports:
   - subscription and packages (base + add-ons)
   - overrides
   - the registry
   - `IndustryTemplateReader.find(industryTemplateKey)` → `{ allowedModuleKeys, enabledKinds, templateVersion }`
   - **Interim until card 2.1** (`platform/industry`): the reader returns "all module keys, all kinds, version 0". Write it in STATUS as a known gap: template filtering and the PUBLISHED check at signup arrive with 2.1. Steps 2–4 are still implemented and tested with a fake reader.
   - `settings`, `fields`, `terms` are empty objects until 2.3/2.4. `menu`, `botTools`, `storefrontSections` come from the manifests of the final set.
   - Step 5 logs `config.module.droppedMissingDependency` and never auto-enables.
   - Limits: step 6 (`null` wins).
8. **Cache:** move the 1.4 LRU to `kernel/cache/in-memory-lru-cache.ts` (generic; iam keeps using it, behaviour unchanged).
   - Key: `org:{organizationId}:config:{configVersion}:{registryHash}:{packageCatalogVersion}:{templateVersion}`.
   - `configVersion` is read fresh by `tenantContext` (extend `ActiveMembership` and the request context with it), so subscription and override changes apply on the very next request.
   - `packageCatalogVersion` = a hash of all ACTIVE packages' `(packageId, version)`, held in memory and refreshed at most every 5 s. A package edit therefore reaches every org within 5 s without a fan-out. Record this trade-off in **ADR-091**.
   - The cached value holds the subscription dates. `accessMode` is recomputed from them on every read (decision 5).

**Entitlement gate (`kernel/access/entitlement.middleware.ts`)**
9. Mounted **once** in the tenant pipeline, after `locationAccess` and before the module routers (`01 §3`). Kernel port `OrgConfigReader { current(): Promise<ResolvedOrgConfig> }`, implemented by entitlement.
   1. `accessMode READ_ONLY` and a method other than GET/HEAD/OPTIONS → `403 ORG_READ_ONLY`. The exemptions (billing, export) arrive with their routes: a manifest flag is added then, not now.
   2. Find the owner module of the request path with `registry.ownerOfRoute`. Not effective → `403 MODULE_DISABLED` with `details.moduleKey`.
   3. A tenant path with **no** owner → `AppError(INTERNAL, "errors.route_without_module")`. It fails closed: a router that forgot its manifest never serves.
   - The kernel allow-list holds exactly one path: `/orgs/:organizationId/me/config`.
   - SYSTEM modules are always effective (step 2 of the resolver), so iam and audit routes keep working with any subscription in FULL mode.
10. **Event handlers** (1.5b note): `registerEventHandler` gains `moduleKey`. The handler runner skips (and completes) a job when the module is not effective for the event's org. SYSTEM modules and null-org events always run. Tested with a probe handler.

**`GET /orgs/{organizationId}/me/config`** (any active member)
11. Response `ResolvedOrgConfigResponse`: `{ organizationId, configVersion, registryHash, accessMode, isPastDue, modules, kinds, limits, menu, terms, settings, permissions }`.
    - `permissions` = the caller's grant map (`{ allLocations: PermissionKey[], byLocation: Record<locationId, PermissionKey[]> }`) restricted to keys of effective modules. Extend the kernel `PermissionGate` port with `describeCaller()`.
    - `menu` = entries of effective modules, where the caller holds `permissionKey` somewhere. Empty groups are dropped.
    - It works in READ_ONLY mode (it is a GET).

**Wiring and docs**
12. `routes/v1.ts`: build the registry from the manifest list (iam, organization, audit, package, saas-billing, entitlement); the catalog from the registry; the resolver; the gate; mount order `authenticate → tenantContext → locationAccess → entitlement → routers`.
13. **ADR-091** ("Accepted (proposed)"): registry and gate (fail closed), package keys validated against the catalogue, the access mode computed from dates, the 5 s package catalogue version. Update `10 §2` with the route-path convention (one line) and `09 §4.6` Package limits (one line).
