# Plan: card 1.7c · Admin: menu from `/me/config`, home, staff and invitations

Tier: T2 · Planned by: Opus 5.5 · Date: 2026-10-10 · Based on commit: `main 1fa56bb`

The UI half of roadmap 1.7 is split again, because it is large:
- **1.7c (this card):** the menu from `/me/config`, the home page with subscription banners, staff list/detail/assignments, invitations (create, list, revoke) and the invitation **accept** page.
- **1.7d (after 1.7c):** business profile, locations and roles screens.

1.7c runs in parallel with **1.8a** (platform API). Shared API files: `modules/core/organization/module.manifest.ts` (this card adds menu entries; 1.8a adds platform suspend use cases to the same module: add-only), `routes/v1.ts` (add-only).

## Goal
Inside a business the shell shows the real menu for this person: only effective modules, only entries they have permission for, and the Locations entry only with ≥ 2 active locations. Home tells the owner where the subscription stands (trial days left, past due, read-only). Owners and managers can see their staff, change assignments, suspend, reactivate and remove members, invite people and share the link. An invited person can open the link, sign in or sign up, and join.

## Decisions
**API side (small)**
1. Contracts `MenuEntry` gains an optional `visibility: "ALWAYS" | "MULTIPLE_ACTIVE_LOCATIONS"` (default ALWAYS). Update `10 §6` with one line.
   - The organization manifest gets its three settings entries (`10 §6`): Business profile (`organization.profile.update`), Locations (`organization.location.read`, `MULTIPLE_ACTIVE_LOCATIONS`), Staff & roles (`organization.member.read`).
   - Paths: `settings/profile`, `settings/locations`, `settings/staff`. Icons from the lucide map; `labelTermKey`s are new i18n keys.
2. `/me/config` evaluates `visibility` server-side:
   - The entitlement config service gets a port `ActiveLocationCounter` (organization implements it) and filters while it builds the cached config.
   - Location create and archive **bump `configVersion`** in their transactions (the `ConfigVersionBumper` of 1.6a), so the cached menu follows the location count.
   - The three entitlement test assertions that expected an empty or exact menu are updated to the new entries. This is approved: the plan of 1.7b moved these entries here.
3. `/me/config` gains `subscription: { status, trialEndsAt, isPastDue }` for the banners. These are only the fields the subscription already has; no new data.

**Admin app**
4. **Menu:** the `[orgSlug]` layout loads `/me/config` with `serverApiFetch` (in parallel with `/me` and `/me/orgs`).
   - It builds the Sidebar groups (`10 §6` group order; empty groups hidden) and the bottom-nav slots with the existing `buildBottomNavSlots`, which now receives the real menu.
   - Labels come from term keys. Terms are empty until 2.4, so the catalog default keys apply.
   - `hasSidebar` follows the group count (0.6b).
5. **Banners** (`13 §5`), above the page content in the shell (server-rendered, no extra JS):
   - **trial:** "trial ends in N days", from `trialEndsAt` in the org timezone, shown in the last 7 days of the trial
   - **past due within grace:** a warning
   - **read-only:** a persistent banner, and write actions hidden. The admin reads `accessMode` once in the layout and passes `canWrite` down.

   There is no billing link yet (billing is card 6.2): the banner text only explains, so there is no dead link.
6. **Home** (`/{orgSlug}`): `PageHeader` with the business name, the banners, and an `EmptyState` saying the business is ready and modules arrive as they are built. The package-aware widgets (ADR-032) come with the report module (3.10). No fake numbers.
7. **Staff** (`/{orgSlug}/settings/staff`, permission `organization.member.read`):
   - **List:** `DataList` (`13 §4.1`): name, role names, locations (only with ≥ 2 locations), status badge; filter chips ACTIVE / SUSPENDED / REMOVED; `?q=` search; paging per `13 §4.1`.
   - **Detail** (`/settings/staff/{memberId}`, `13 §4.2`): key facts, assignments, a history link to the audit log (deferred; the audit screen is not in this card).
   - **Actions** in the sticky bar: edit assignments, suspend or reactivate, remove, each confirmed with `ConfirmDialog`. Actions are shown only when the caller holds the permission (from `/me/config` permissions); the API still enforces everything.
8. **Assignments form** (`13 §4.3`): rows of role + location (location select hidden with 1 location, then the row is "ALL").
   - Roles come from `GET /roles`; system roles show their translated `nameKey`; OWNER is not offered.
   - Validation errors from the API map to rows by field path, and `ROLE_NOT_GRANTABLE` shows on the row.
   - Saving sends `version`; a 409 shows "someone else changed this member; reload".
9. **Invitations** (`/settings/staff/invitations`, permission `organization.member.invite`):
   - The form takes one identifier field (phone or email) + display name + assignments rows (same component as decision 8).
   - On success it shows the link **once** in a sheet with a copy button and the text "share this link; it works for 7 days". The `Idempotency-Key` is generated per submit and kept for retries of the same submit.
   - The list shows pending, accepted, revoked and expired, with revoke.
10. **Accept page** (`/invitations/[token]`, outside the org shell, in the `(auth)` layout group):
    - It calls `GET /invitations/{token}`, then shows the business name, who invited, and the masked identifier.
    - Signed out: buttons to sign in or sign up, returning to this page (`next`).
    - Signed in: an accept button → `POST /invitations/{token}/accept` → full navigation to `/{slug}`.
    - An identifier mismatch shows `errors.invitation_identifier_mismatch` with a sign-out-and-switch hint. 404 → "this invitation is no longer valid".
11. **Budget** (`13 §11`, initial JS ≤ 170 KiB gzip per route):
    - The new pages are separate routes. Forms and sheets load lazily as in 1.7a.
    - `/[orgSlug]` must not grow: the menu rendering is server-side.
    - If any route exceeds 170 KiB, stop and report with the chunk breakdown. Do not raise the budget, and do not use `ssr:false`.
12. Every string comes from i18n keys (bn + en, identical sets). No hex, no px font sizes, ui components only.
    - New ui components only if `13 §9` lists them and the page needs them: `DetailHeader`, `StickyActionBar`. Each is added to `packages/ui` with a Bangla-text test.
