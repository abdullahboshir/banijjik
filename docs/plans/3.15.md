# Plan: card 3.15 · Test stability (flaky tests on CI)

Tier: **T3** · Planned by: Sonnet 5.5 (lead) · Date: 2026-10-22 · Based on commit: `main 5de077a`

One part, one branch `s/3.15-test-stability`, no screens. Safe to run beside any card (touches test files and test config only).

## Goal
CI stops failing for timing reasons. Every card today risks a "rerun failed jobs"; this card removes the known causes without hiding real bugs.

## Inputs read
- `apps/api/src/test-support/wait-for.ts` (polls every 25 ms, 15 s timeout) and `apps/api/src/test-support/vitest.config.ts` (`testTimeout` 30 s)
- `apps/api/src/kernel/events/ordered-event-worker.test.ts` (already uses `waitFor`; retry delay `SHORT_DELAY_MS = 20`)
- `apps/admin/vitest.config.ts` and `apps/platform/vitest.config.ts` (`testTimeout` 15 s)
- CI evidence: run `39736146807` (main, 2026-10-22): `apps/admin/src/branding/branding-form.test.tsx`, "the colour presets > shows every preset by name…" failed. Run `38379921676` (2026-10-13): `package-form.test.tsx` "Test timed out in 5000ms". `ordered-event-worker.test.ts` timed out three times on 2026-10-22.

## Decisions
1. **Evidence first.** For each flaky test, read the failed CI log (`gh run view <run> --log-failed`) of the runs above and write the exact failure message in the handoff. Do not guess.
2. **Fix the cause, not the number.** Allowed fixes, in this order of preference:
   - replace any fixed sleep or single-shot assertion with `waitFor` (condition-based wait);
   - make the test independent of timing (await the event or promise the code exposes);
   - for jsdom/React tests that are only slow under CI load, wrap the slow interaction in `findBy*` or `waitFor` from Testing Library rather than raising a global timeout.
3. **Raising a timeout is the last resort**, per test (the third argument of `it`), with a comment saying why. No global timeout increase.
4. **`ordered-event-worker.test.ts`:** the tests wait on `pickups(second) >= 2`, which depends on queue retry delays. Check that `SHORT_DELAY_MS` also applies to the BullMQ wait/retry path; if some wait still uses the default delay (1 s doubling), pass the short delay there. If the real worker has a race (not the test), stop and report it to the lead; do not change worker code in this card.
5. **No test is skipped, deleted or weakened** (no `retry:`, no `it.skip`). A test that cannot be made stable is reported, not hidden.
6. **Prove it:** run each fixed test file 20 times in a row locally (a shell loop) and write the pass count in the handoff. The environment for API tests is in `docs/LEAD-STATE.md` §5 "Local verify".
