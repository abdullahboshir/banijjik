## Goal
`apps/api` starts as a real HTTP server (Express 5) when `ROLE=api`. It answers `GET /health` and returns every error in the one envelope from `14 §2`:
- every request gets a `requestId` that appears in every log line and every error body
- request input is validated once, by `validate(schema)`
- unknown errors become `INTERNAL` without leaking internals
- `SIGTERM`/`SIGINT` close the server cleanly

`ROLE=worker` starts no HTTP server and waits for shutdown (the queue arrives in 1.5).

## Decisions
1. **Error codes in contracts first.** `packages/contracts/src/errors/error-code.ts` holds `ERROR_CODE = defineEnum([...])` with exactly the 20 codes of `14 §3` (corrected from "22", a planning error), and `ERROR_HTTP_STATUS: Readonly<Record<ErrorCode, number>>` with the status per code. The code is the source of truth; the status table is derived in one place.
2. **`AppError`** (`apps/api/src/kernel/http/app-error.ts`): `class AppError extends Error { code; messageKey; details? }`. `httpStatus` is a getter: `ERROR_HTTP_STATUS[code]`. Domain errors in later cards extend it or are mapped to it at the presentation layer.
   - Factories for the common ones: `notFound()`, `forbidden()`, `conflict(details)`, `validationFailed(fields)`. Each one sets the `messageKey`.
   - The default `messageKey` = `errors.<code lowercased>`, e.g. `errors.not_found`.
3. **Envelope helpers** (`kernel/http/envelope.ts`): `sendData(response, data, meta?, status = 200)` writes `{ data, meta? }`. The error body is built only by the error handler. Controllers never build error bodies.
4. **Error handler** (`kernel/http/error-handler.ts`), mounted last, in this order:
   - `AppError` → its status + `{ error: { code, messageKey, details?, requestId } }`
   - an Express/body-parser JSON syntax error → `400 VALIDATION_ERROR` with `details.fields = [{ path: "", messageKey: "errors.invalid_json" }]`
   - a payload too large → `400 VALIDATION_ERROR` with `messageKey: "errors.payload_too_large"`
   - anything else → `500 INTERNAL` with `messageKey: "errors.internal"`. The error is logged at `error` with stack and `requestId` through the central `reportError(error, context)` (`kernel/observability/report-error.ts`). For now it only logs; Sentry is 6.5. The response body never contains the message or stack.
   - **Not-found route** → `404 NOT_FOUND` (a final middleware before the error handler).
5. **`validate(schemas)`** (`kernel/http/validate.ts`): `validate({ params?, query?, body? })` takes Zod schemas.
   - It replaces `request.params/query/body` with the parsed values. Express 5's `req.query` is a getter, so the parsed query goes to `response.locals.validated.query`. All three parsed parts are always in `response.locals.validated` for uniformity, and controllers read from there.
   - On failure it throws `validationFailed(fields)`, where `fields = issues.map(issue => ({ path: issue.path.join("."), messageKey: "validation." + issue.code }))`. Zod's own messages are never sent (they are English text, and they can echo input).
   - Lives in the API kernel. Request schemas themselves live in `@banijjik/validation` (ADR-012).
6. **Request context** (`kernel/context/request-context.ts`): one `AsyncLocalStorage<RequestContext>`.
   - `RequestContext = { requestId: string; userId?: string; organizationId?: string; allowedLocationIds?: readonly string[] | "ALL"; systemReason?: SystemReason }`. The optional fields are filled by later cards (1.1 auth, 1.3 tenant context, 0.4b `runAsSystem`).
   - API: `runWithRequestContext(context, fn)`, `getRequestContext(): RequestContext` (throws `INTERNAL` when called outside a context), `findRequestContext(): RequestContext | undefined`.
   - Context is immutable. Later cards create a child with `runWithRequestContext({ ...current, organizationId }, next)`.
7. **Request id** (`kernel/http/request-id.middleware.ts`): uses incoming `X-Request-Id` only when it is a UUID (any version, max 36 chars), otherwise `newId()`. Sets the response header `X-Request-Id`. Wraps the rest of the request in `runWithRequestContext`.
8. **Logger** (`kernel/logger/`):
   - `createLogger({ level })`: pino, `base: { service: "api" }`, ISO time.
   - `redact` paths: `password`, `*.password`, `token`, `*.token`, `*.secret`, `authorization`, `cookie`, `*.phoneE164`, `*.email`, `req.headers.authorization`, `req.headers.cookie` (`05`: phone/email masked).
   - `getLogger()` returns the request-scoped child (`{ requestId, organizationId?, userId? }` from the context) or the root logger outside a request.
   - HTTP access log: `pino-http`, with `genReqId` reading the context's `requestId` and a custom `serializers.req` that drops headers except `user-agent`.
9. **Express app** (`src/app.ts`) `buildApp({ config, logger }): Express`:
   - `x-powered-by` off; `trust proxy` = 1 (behind one proxy in production; documented)
   - middleware order: requestId → access log → `express.json({ limit: "1mb" })` → CORS (`cors` package, `origin` = `config.corsAllowedOrigins`, `credentials: true`) → routes → not-found → error handler
   - Helmet is **not** added now (the API serves JSON only; CSP etc. is 6.3 hardening).
   - Rate limiting is per surface (`14 §2`) and arrives with auth (1.1). Not in 0.4a.
10. **Routes** (`src/routes/v1.ts`): `buildV1Router(): Router`, mounted at `/api/v1`. It mounts nothing yet and is the only place that will mount module routers and global middleware (AGENTS.md). `GET /health` is mounted on the app root, outside `/api/v1`, returning `200 { data: { status: "ok" } }`. `/ready` is 0.4b.
11. **`ROLE`** is added to config (0.3's schema; add-only): `ROLE` = `api | worker`, default `api`, exposed as `config.role`. Update `.env.example` and the README key table.
12. **`main.ts`** (`src/main.ts`), steps:
    1. `loadConfigFromProcess(<package>/.env)` (0.3)
    2. `createLogger`
    3. `ROLE=api`: `buildApp`, then `listen(config.port)`, log `{ event: "api.started", port }`
    4. `ROLE=worker`: log `{ event: "worker.started" }` and keep the process alive (a no-op interval of 1 hour, cleared on shutdown)

    On `ConfigError`: log `{ event: "config.invalid", issues }` at fatal and set exit code 1 (same contract as `check-config`).
13. **Graceful shutdown** (`kernel/lifecycle/shutdown.ts`): `registerShutdown({ logger, tasks, timeoutMs = 10_000 })`.
    - On the first `SIGTERM`/`SIGINT` it runs the tasks in order (for api: stop accepting with `server.close()` and close idle keep-alive sockets via `server.closeIdleConnections()`; 0.4b adds "close DB"), logs `{ event: "shutdown.completed" }` and sets `process.exitCode = 0`.
    - If the timeout passes: log `shutdown.timeout`, `server.closeAllConnections()`, exit code 1.
    - A second signal forces exit 1.
    - The task list is an array of `{ name, run: () => Promise<void> }` so 0.4b and later cards append to it.
14. **Package entry:** add `src/index.ts`, exporting nothing but `buildApp` and the config types (tests and later tools import from it). Point `@banijjik/api`'s `exports`/`types` at `dist/index.*` (fixes the 0.3 deviation). Scripts: `dev` = `tsx watch src/main.ts`, `start` = `node dist/main.js`.
15. **Lint gap from the 0.2a review:** extend `eslint/architecture.mjs` with elements `kernel` (`**/src/kernel/**`), `config` (`**/src/config/**`) and `routes` (`**/src/routes/**`).
    - kernel may import kernel, config, contracts, ids, validation, never modules.
    - config may import config, contracts.
    - routes may import kernel and modules' `index.ts` only.
    - Add fail + pass fixtures for each (R23 kernel→module, R24 config→kernel, R25 routes→module internals) in `tools/lint-tests`, and bump `RULE_COUNT` to 25.
16. **Dependencies** (apps/api):
    - `express@^5`, `cors@^2`, `pino@^9`, `pino-http@^10`
    - dev: `@types/express@^5`, `@types/cors`, `supertest@^7`, `@types/supertest`
    - Check the current majors with `npm view` first. If a major moved, use the latest stable and record it in the handoff.

## Interfaces & types
```ts
// @banijjik/contracts
export const ERROR_CODE: { readonly VALIDATION_ERROR: "VALIDATION_ERROR"; /* … 20 codes from 14 §3 */ };
export type ErrorCode = (typeof ERROR_CODE)[keyof typeof ERROR_CODE];
export const ERROR_HTTP_STATUS: Readonly<Record<ErrorCode, number>>;

// kernel/http
export interface ErrorDetails { readonly [key: string]: unknown }
export interface ValidationField { readonly path: string; readonly messageKey: string }
export class AppError extends Error {
  constructor(options: { code: ErrorCode; messageKey?: string; details?: ErrorDetails });
  readonly code: ErrorCode; readonly messageKey: string; readonly details?: ErrorDetails;
  get httpStatus(): number;
}
export function notFound(): AppError;
export function forbidden(): AppError;
export function conflict(details: ErrorDetails): AppError;
export function validationFailed(fields: readonly ValidationField[]): AppError;
export function sendData<Data>(response: Response, data: Data, options?: { meta?: object; status?: number }): void;
export function validate(schemas: { params?: ZodType; query?: ZodType; body?: ZodType }): RequestHandler;
export const errorHandler: ErrorRequestHandler;
export const notFoundHandler: RequestHandler;
export const requestIdMiddleware: RequestHandler;

// kernel/context
export interface RequestContext {
  readonly requestId: string;
  readonly userId?: string;
  readonly organizationId?: string;
  readonly allowedLocationIds?: readonly string[] | "ALL";
  readonly systemReason?: string; // typed as SystemReason in 0.4b
}
export function runWithRequestContext<Result>(context: RequestContext, work: () => Result): Result;
export function getRequestContext(): RequestContext;
export function findRequestContext(): RequestContext | undefined;

// kernel/logger
export function createLogger(options: { level: AppConfig["logLevel"] }): Logger;
export function getLogger(): Logger;

// kernel/lifecycle
export interface ShutdownTask { readonly name: string; run(): Promise<void> }
export function registerShutdown(options: { logger: Logger; tasks: ShutdownTask[]; timeoutMs?: number }): void;

// app
export function buildApp(options: { config: AppConfig; logger: Logger }): Express;
```
`getRequestContext` and `getLogger` are the only module-level singletons (the ALS store and the root logger set by `main`). No other global state.

## Tests (must exist and pass)
Kernel HTTP (supertest against a test app built with `buildApp` + a test-only router):
- [ ] **error envelope:** a route throwing `notFound()` → 404 `{ error: { code: "NOT_FOUND", messageKey: "errors.not_found", requestId } }`, where `requestId` equals the `X-Request-Id` response header
- [ ] an unknown thrown `Error("db password=…")` → 500 `INTERNAL`, and the body contains neither the message nor a stack. The error is logged once with the same `requestId` (capture stream).
- [ ] **validation error:** a body failing a Zod schema → 400 `VALIDATION_ERROR` with `details.fields[{ path: "items.0.quantity", messageKey: "validation.too_small" }]`. No Zod English text is in the body.
- [ ] invalid JSON body → 400 `VALIDATION_ERROR` (`errors.invalid_json`); a body over 1 MB → 400 (`errors.payload_too_large`)
- [ ] an unknown route → 404 envelope
- [ ] the validated body, params and query are available to the handler in `response.locals.validated` with coerced types
- [ ] an incoming `X-Request-Id` that is a UUID is kept; a non-UUID one (`<script>`) is replaced by a new UUID v7
- [ ] `GET /health` → 200 `{ data: { status: "ok" } }`
- [ ] CORS: an allowed origin gets `Access-Control-Allow-Origin` + credentials; an unknown origin gets no allow header

Context / logger:
- [ ] context survives `await` boundaries and is isolated between two concurrent requests (two in-flight requests with different ids each log their own id)
- [ ] `getRequestContext()` outside a request throws `AppError(INTERNAL)`
- [ ] redaction: `{ user: { email, password }, req: { headers: { cookie } } }` are all masked

Lifecycle / main:
- [ ] `registerShutdown` runs tasks in order on a simulated signal, and sets exit code 1 when a task exceeds the timeout (fake timers)
- [ ] `main.test.ts` (spawn with `process.execPath --import tsx src/main.ts`, env inline, `PORT=0` is invalid by 0.3 rules, so use a free port found by the test): `ROLE=api` logs `api.started`, `GET /health` works, `SIGTERM` exits 0 with `shutdown.completed`. On Windows, `SIGTERM` to a child is emulated; if signals cannot be delivered in the test runner, test `registerShutdown` directly and document it in the handoff. Missing env → exit 1 with `config.invalid`.

Contracts:
- [ ] every `ERROR_CODE` has a status in `ERROR_HTTP_STATUS` and matches `14 §3`

Lint:
