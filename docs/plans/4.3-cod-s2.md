## Goal
Enables receiving Return to Sender (RTS) shipments and delivering shipments in `apps/api/src/modules/commerce/sales`. When a delivery attempt has failed (`DELIVERY_FAILED`), staff can process RTS (`POST /orders/:orderId/rts`), which transitions the order to terminal `RETURNED_TO_SENDER`, unreserving/returning the original shipped items back to inventory at their original sale costs (to available restock or damaged quarantine), and settling any paid advances into store credit. Also marks orders as `DELIVERED` (`POST /orders/:orderId/deliver`), and extends `SalesReturn` eligibility to include `DELIVERED` orders with return window anchored at `deliveredAt`.

## Decisions

1. **State Machine Transitions:**
   - `receiveRts`: Validates status is `DELIVERY_FAILED`. Transitions to `RETURNED_TO_SENDER`. Terminal state (cannot reship, complete, cancel, or edit).
   - `deliverOrder`: Validates status is `SHIPPED`. Transitions to `DELIVERED`. Records `deliveredAt = now`.
   - Update `ORDER_IMPLEMENTED_STATUSES` to include `ORDER_STATUS.DELIVERED` and `ORDER_STATUS.RETURNED_TO_SENDER`.
2. **Stock Ledger Return on RTS:**
   - Shipped orders committed their reserved stock via `StockLedger.commitSale`.
   - On RTS, if `order.hasStockLines`, invokes `StockLedger.returnStock` with:
     - `sourceType: STOCK_SOURCE_TYPE.ORDER`, `sourceId: order.orderId`
     - `disposition`: `input.body.restockDisposition === "RETURN_DAMAGED" ? "RETURN_DAMAGED" : "RESTOCK"`
     - `costFrom`: `{ sourceType: STOCK_SOURCE_TYPE.ORDER, sourceId: order.orderId }` (exact cost preservation from original SALE movements).
     - Lines: original order lines with variant quantities.
3. **Advance Settlement on RTS:**
   - If order had partial/full advance payments prior to RTS, invokes `dependencies.payments.settleCancellation` inside the transaction. If customer has `contactId`, net paid advance is preserved as customer store credit; if no contact, advances remain recorded on the order request.
4. **Delivered Order Return Eligibility:**
   - `prepareSalesReturn`, `createSalesReturn`, `reverseSalesReturn`, and `Order.recordReturn` accept both `ORDER_STATUS.COMPLETED` and `ORDER_STATUS.DELIVERED`.
   - For `DELIVERED` orders, the return window calculation anchors at `order.deliveredAt ?? order.updatedAt` in the organization timezone (instead of `order.completedAt`).
5. **Delivery Attempt Synchronization:**
   - When RTS is received, if `order.currentDeliveryAttemptId` is present, updates the attempt status to `RETURNED_TO_SENDER` or marks it closed.
   - When order is delivered, updates the current attempt status to `DELIVERED`.
6. **Permissions & Security:**
   - `POST /orders/:orderId/rts`: requires `permission(PERMISSION_KEY.SALES_ORDER_UPDATE)`. Location-scoped to order location.
   - `POST /orders/:orderId/deliver`: requires `permission(PERMISSION_KEY.SALES_ORDER_UPDATE)`. Location-scoped to order location.
7. **Domain Events & Audit:**
   - Events: `SALES_EVENT_TYPE.ORDER_RETURNED_TO_SENDER`, `SALES_EVENT_TYPE.ORDER_DELIVERED`.
   - Audit Actions: `AUDIT_ACTION.ORDER_RETURNED_TO_SENDER`, `AUDIT_ACTION.ORDER_DELIVERED`.
