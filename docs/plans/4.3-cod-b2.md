# Plan: card 4.3 COD B2 · settlement-ui

Tier: T2 · Planned by: Opus 5.5 · Date: 2026-11-07 · Based on commit: a924c77af00b0965edef27fda8f91fbf93ebfa9c

## Session parts
Single part: `s/4.3-cod-b2-settlement-ui`.
Admin screens and sheets for courier settlement, rider cash handover, and reversal with dual-control approval PIN.

## Goal
Provide full staff administrative UI for:
1. Courier consignments list and settlement workflow:
   - View courier consignments table with filters (`courierKey`, `locationId`, pagination).
   - "Record Courier Settlement" sheet allowing staff to select the courier provider, enter external settlement reference, courier fee/charge, business date, payout method, and payment IDs being settled.
   - Courier settlement reversal dialog with reason and dual-control manager PIN verification (`APPROVAL_ACTION.COURIER_SETTLEMENT_REVERSAL`).
2. Delivery assignments list and rider handover workflow:
   - View delivery assignments table with filters (`riderMemberId`, `locationId`, `status`, pagination).
   - "Record Rider Handover" sheet allowing staff to select rider member, received method (cash/pos session), business date, and payment IDs being handed over.
   - Rider handover reversal dialog with reason and dual-control manager PIN verification (`APPROVAL_ACTION.RIDER_HANDOVER_REVERSAL`).
3. Admin navigation routing at `/[orgSlug]/(app)/courier/consignments` and `/[orgSlug]/(app)/delivery/assignments`.

## Decisions
1. **Separate Clean Modules:**
   Create `apps/admin/src/courier/` and `apps/admin/src/delivery/` with dedicated API clients, labels, models, screens, and test files.
2. **App Router Pages:**
   - Mount courier consignments & settlements at `apps/admin/app/[orgSlug]/(app)/courier/consignments/page.tsx`.
   - Mount delivery assignments & rider handovers at `apps/admin/app/[orgSlug]/(app)/delivery/assignments/page.tsx`.
3. **Dual-Control Approval Reversals:**
   Both courier settlement reversal and rider cash handover reversal are sensitive operations requiring dual-control manager approval. They will use the standard IAM approval dialog pattern (`grantApproval` -> retrieve approval token -> invoke reverse endpoint).
4. **File Length Constraints:**
   Strict adherence to <= 300 lines per file and <= 60 lines per function. Decompose screens and sheets into modular components where needed.
5. **Localization:**
   Add comprehensive BN and EN translations to `packages/i18n/src/catalogs/screens/bn.json` and `en.json`.
