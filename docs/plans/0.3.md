## Goal
`apps/api` exists as a real package whose only code so far is a strict, tested environment loader. `docker compose` starts a MongoDB **replica set** and Redis locally, so transactions work in development. A command validates the environment and, when something is wrong, prints exactly which keys are missing or invalid (never their values) and exits non-zero.

## Decisions
1. **Package `@banijjik/api`** in `apps/api`, same shape as the existing packages (ESM, `tsc` build to `dist/`, `vitest run --dir src`). Dependency: `zod`. Dev: `@types/node`, `tsx` (for running the check script without building).
2. **`process.env` is read only inside `apps/api/src/config/`** (lint rule R15 from 0.2a enforces this). `loadConfig(env)` takes the environment as an argument so tests never touch the real one.
3. **Config shape is minimal.** Only keys that 0.3/0.4 need exist now. Later cards add their own keys (auth secrets in 1.1, encryption key in 5.1, etc.) in the same file and in `.env.example`.
4. **Errors never contain values.** A `ConfigError` lists `{ key, problem }` pairs. A secret that fails validation must not appear in any message, log or stack.
5. **Env file loading** uses Node's built-in `process.loadEnvFile` in a small `loadEnvFile()` helper called only by the check script (and later by `main.ts` in 0.4). A missing file is fine (CI and production set real env vars); any other read error is reported.
6. **Local infrastructure in `infra/`**: `docker-compose.yml` with `mongo:8` (single-node replica set `rs0`) and `redis:7`, ports bound to `127.0.0.1` only, named volumes, health checks. Compose project name `banijjik`.
7. **Replica set bootstrap by health check**, no extra init container: the Mongo health check runs `mongosh` and initiates the set if it is not initiated yet. Host connections use `directConnection=true` so the driver does not try to follow the member's internal hostname.
8. **Root scripts** (add-only): `infra:up`, `infra:down`, `infra:reset` (removes volumes, asks nothing: documented as destructive for local dev data only), `config:check` (runs the check script in `@banijjik/api`).
9. **`.env.example`** lives at `apps/api/.env.example` with local-development values only (no real secrets). The real file `apps/api/.env` is git-ignored.
10. **Platform DB vs tenant DB (ADR-043).** Two logical databases on the same local server: `banijjik_platform` and `banijjik_tenant_shared`.

## Config schema (`apps/api/src/config/env.schema.ts`)

| Key | Rule | Default | Notes |
|---|---|---|---|
| `NODE_ENV` | `development \| test \| production` | `development` | |
| `PORT` | integer 1–65535 | `4000` | coerced from string |
| `LOG_LEVEL` | `fatal \| error \| warn \| info \| debug \| trace` | `info` | |
| `DB_PLATFORM_URL` | URL starting `mongodb://` or `mongodb+srv://`, includes a database name | **required** | |
| `DB_TENANT_SHARED_URL` | same | **required** | |
| `REDIS_URL` | URL starting `redis://` or `rediss://` | **required** | |
| `CORS_ALLOWED_ORIGINS` | comma-separated list of absolute `http(s)` origins, no wildcard when `NODE_ENV=production` | **required** | parsed to `string[]`, trimmed, no duplicates |

Extra production rules: in `production`, `DB_*_URL` and `REDIS_URL` must not point to `localhost`/`127.0.0.1`.

```ts
// apps/api/src/config/app-config.ts
export interface AppConfig {
  readonly nodeEnv: "development" | "test" | "production";
  readonly port: number;
  readonly logLevel: "fatal" | "error" | "warn" | "info" | "debug" | "trace";
  readonly database: { readonly platformUrl: string; readonly tenantSharedUrl: string };
  readonly redisUrl: string;
  readonly corsAllowedOrigins: readonly string[];
}

export interface ConfigIssue { readonly key: string; readonly problem: "MISSING" | "INVALID"; readonly hint: string }
export class ConfigError extends Error { readonly issues: readonly ConfigIssue[] }

/** Validates an environment object. Returns a frozen config or throws ConfigError. Never includes values in messages. */
export function loadConfig(env: Readonly<Record<string, string | undefined>>): AppConfig;

// loadEnvFile.ts
/** Loads KEY=VALUE pairs from a file into process.env if the file exists. Missing file is not an error. */
export function loadEnvFile(path: string): void;

// check-config.ts (script entry)
// 1. loadEnvFile("apps/api/.env") relative to the package, 2. loadConfig(process.env),
// 3. success: print "Config OK" and the NON-secret summary (nodeEnv, port, database NAMES only), exit 0
// 4. ConfigError: print one line per issue "KEY: MISSING|INVALID (hint)", exit 1
```
`hint` is a fixed human sentence per rule (for example "must be a mongodb:// URL with a database name"), never derived from the value.

**`infra/docker-compose.yml` requirements:**
- Service `mongo`: image `mongo:8`; command `["--replSet","rs0","--bind_ip_all"]`; port `127.0.0.1:27017:27017`; volume `mongo-data:/data/db`; health check runs `mongosh --quiet --eval` with a script that returns success when `rs.status().ok == 1`, and otherwise calls `rs.initiate({ _id: "rs0", members: [{ _id: 0, host: "localhost:27017" }] })`; `interval` 5s, `retries` enough for first start.
- Service `redis`: image `redis:7`; command `redis-server --appendonly yes`; port `127.0.0.1:6379:6379`; volume `redis-data:/data`; health check `redis-cli ping`.
- Named volumes `mongo-data`, `redis-data`. `restart: unless-stopped`.
- `.env.example` connection strings: `mongodb://127.0.0.1:27017/banijjik_platform?replicaSet=rs0&directConnection=true`, `mongodb://127.0.0.1:27017/banijjik_tenant_shared?replicaSet=rs0&directConnection=true`, `redis://127.0.0.1:6379`.

## Tests (must exist and pass) in `load-config.test.ts`
- [ ] a complete valid environment returns the expected `AppConfig` (frozen, `corsAllowedOrigins` parsed to an array)
- [ ] defaults apply for `NODE_ENV`, `PORT` (as number from string "4000"), `LOG_LEVEL`
- [ ] each required key missing → `ConfigError` with an issue `{ key, problem: "MISSING" }` (table-driven over `DB_PLATFORM_URL`, `DB_TENANT_SHARED_URL`, `REDIS_URL`, `CORS_ALLOWED_ORIGINS`)
- [ ] several problems at once → **all** issues listed in one error (not just the first)
- [ ] invalid values: `PORT=abc`, `PORT=70000`, `DB_PLATFORM_URL=http://x`, DB URL without database name, `REDIS_URL=foo`, `LOG_LEVEL=loud`, CORS entry without scheme → `INVALID` with the right key
- [ ] production: wildcard `*` in CORS rejected; `localhost` DB/Redis URLs rejected; the same values are accepted in development
- [ ] **no value leaks:** for a case where `DB_PLATFORM_URL` holds `mongodb://user:SuperSecret@host/db` plus another invalid key, `String(error)`, `error.message` and `JSON.stringify(error.issues)` do not contain `SuperSecret`
- [ ] `loadEnvFile` with a missing path does not throw; with a temp file it sets variables without overriding ones already set

## Risks & checks
- **Replica set init on first start** can take ~10–20 s. The handoff must show `docker compose -f infra/docker-compose.yml up -d` then `docker compose ps` healthy for both services.
- **Prove it is a replica set:** run `docker compose exec mongo mongosh --quiet --eval "rs.status().ok"` → `1`, and `... --eval "db.hello().isWritablePrimary"` → `true`. Paste both.
- **Prove transactions are possible:** run a one-off `mongosh` snippet that starts a session, begins a transaction, inserts into a temp collection, aborts. Paste the output.
- **Windows:** use forward slashes in scripts; do not rely on shell-specific syntax in `package.json` scripts (use `docker compose -f infra/docker-compose.yml …`).
- **Port clash:** if 27017 or 6379 is already used on the owner's machine, stop and report; do not change defaults silently.
- Paste in the handoff: `npm install`, `npm run build`, `npm run typecheck`, `npm test`, `npm run config:check` with a good `.env` and with a deliberately broken one (missing `REDIS_URL`, bad `PORT`), compose status, the three mongosh outputs, then `docker compose down` (keep volumes unless asked).
