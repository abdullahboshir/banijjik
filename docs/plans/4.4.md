## Goal

An authorized platform operator can publish reusable website templates, assign template availability through industry configuration, and design one business's website with independently controlled tenant editing permissions. The operator gets a warning about similar sites and can apply another preset.

## Decisions

1. WebsiteTemplate records live in platform/industry, tenancy NONE, because templates are platform content and compatibility is industry configuration. Extend that existing module's manifest/routes; do not create a second feature module that reads industry.
2. Template key is stable, lower-kebab-case; revision IDs are UUID v7 and revision numbers monotonic per template. Draft revisions are mutable/versioned; publication produces an immutable snapshot. Archive removes a template from new adoption choices but never changes sites already copied from it.
3. Template contains SiteDesign, SiteEditPolicy, named design presets and required modules/kinds. Same 4.1 validators and renderer on server/client. Validate all registered section keys and token limits, local font keys, content URL rules, assets and contrast before publication. No code/CSS upload.
4. Template selection is governed by effective websiteTemplateKeys projected by resolver; eligible template must also match effective modules/kinds. Do not read industry in website/editor/renderer. platform/industry alone selects same-industry comparison organizations for ADR-149.
5. Compatibility handles optional sections explicitly: template marks each region required or optional; a required module/kind absent makes template unavailable. Optional sections can be excluded only by the platform-authored template policy and are shown in an adoption preview. Never delete them silently after customer approval.
6. Platform operator has platform.website.read/write/publish/policy keys. SUPER_ADMIN receives all; SUPPORT/BILLING have no design-write/publish by default. Read can be granted separately. No granting operator permissions through tenant memberships.
7. To design a business, platform route validates operator permission and target org, enters runInOrganizationContext at the composition boundary, then invokes same website application commands with a trusted PLATFORM actor. No runAsSystem in website module. Platform audit records operator identity, target org/site, reason, changed groups and before/after version metadata; tenant public responses never reveal operator data.
8. A tenant and operator may edit concurrently. Both CAS the same Site.version. Policy updates and design updates occur in one transaction and return 409 on stale version. Operator cannot bypass schema/file/contrast/entitlement constraints, only tenant-edit restrictions; enabling a disabled capability is a separate entitlement operation.
9. Fingerprint is a versioned canonical digest of design-relevant tokens, preset, ordered section keys/variants and layout, excluding tenant copy, image IDs and business identifiers. Identical layout/tokens on the same template/preset generates a warning for same-industry sites. A fingerprint is a similarity heuristic, not proof of visual uniqueness; no block, no random unreviewed mutations.
10. Same-look comparisons run on indexed platform-owned SiteDesignSummary projections, populated by publication events, not full tenant scans. Only platform/industry selects candidates; website fingerprint helper knows no industry. Projection includes config/template revision and lastPublishedAt, so UI can label stale comparison data. Do not store industry in the website schema.
11. Apply different preset offers another existing compatible preset, preserving content/media/links and respecting required regions. A diff shows token/variant changes before save; no automatic publish. Deterministic choice from preset order, not runtime randomization.
12. Editor layout: pages/sections list, phone/desktop preview, inspector; on phone these are tabs/sheets with 44 px controls. Up/down buttons and keyboard sorting accompany drag handles. Region/token locks are visible with short explanations. Publish gives validation errors linked to the relevant field.
13. New template is a draft until explicitly published. Publish invalidates catalog eligibility but does not fan out to existing sites. Explicit site upgrade is 4.5, and must show a destructive-change diff.
14. Reusable templates contain no tenant file IDs. Hero image slots may be empty; preview renders a neutral shape, not fake content. On first adoption the site uses its own validated branding logo; the business/operator selects its own public images in that site's editor. No new platform file-ownership model is smuggled into this card. Template thumbnails are rendered previews, not arbitrary remote fetches. A future shared stock-asset library needs its own plan.

Index comparisonGroupKey/templateKey/presetKey/fingerprint/organizationId. Only platform/industry derives comparisonGroupKey from industry configuration; no unbounded candidate organization-ID array crosses a module boundary. Publication and relevant organization-config changes update their independently versioned projection fields; handlers ignore stale revisions per source. Read bounded indexed keyset pages, <=100, with a stable cursor and projected business label. Website only emits design facts; it neither selects industry candidates nor queries this model.
No tenant-wide update migration. Seed two distinct validated presets on a minimal template, with real empty states (no fictitious businesses/reviews). Existing industry templates gain explicit available keys only via platform-authorized write; no mass change without matching configuration.

## Audit correction: bounded comparisons and shared policy (2026-10-28)

TemplateCatalog lists summaries by contract; only its detail reader loads the bounded full immutable revision. Platform DTOs reuse WebsiteTemplateContent rather than embedding mutable draft identity/version in immutable snapshots. Default preset and baseline template design are validated together; preset variants are restricted by the shared section registry and SiteEditPolicy. The full policy includes page metadata/navigation/static publication flags, not merely palette and section controls.

A2 owns a resumable projection backfill/rebuild using public website/config ports and <=100-record batches. No cross-module model imports or full tenant scans in request handlers. Config-only industry changes refresh comparison grouping even if a website has never republished. Missing/stale comparisons are labeled unavailable/stale, never presented as proof of unique design. Tests cover event reorder across config/publication sources, unpublish removal, replay, restart, maximum-sized organization sets and bounded query counts (P4-19/P4-20). Fingerprint version upgrades build a separate versioned projection before switching comparisons; mixed versions do not compare as equal.

A3 is an application seam in website; A3I is its separate route-composition part. Freeze independent file lists within the one-module/file-count rule. Platform and tenant save/publish/unpublish/restore share the same website commands. Trusted platform actor bypasses only tenant edit policy, never tenancy/file/capability/schema checks. Same-look comparison is platform-only and exposes no private site copy or contact data.

## Out of scope

Marketplace, paid themes, AI-generated executable templates, arbitrary CSS, cloning private content between businesses, changing admin/platform branding, automatic site upgrades.

## Risks & checks

Template editor is a heavy widget: lazy-load on editor routes, measure bundles and existing browser regressions. Verify API with direct forged requests. Test preview/published rendering parity through the shared renderer. Local touched checks + platform browser suite, full CI and independent policy API review.

## Done when

Operator can publish a template, select it through industry configuration, design one business, set locks, see same-look warning and publish with correct audit; other sites remain unchanged. All tests/CI and applicable reviews pass.
