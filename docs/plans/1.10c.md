## What happened
The first push to GitHub started CI run `38379921676`:
- `secrets`: passed.
- `verify`: failed in the Test step. `@banijjik/platform#test` failed 5 of its 69 tests. Turbo then stopped, so the API, admin and UI results of that run are unknown.

The failing tests and their errors:

|---|---|
| `sign-in-form.test.tsx`: "asks for both fields …" | `Unable to find an element with the text: ইমেইল অথবা ফোন নম্বর দিন` |
| `package-form.test.tsx`: "shows what is missing …" | `Unable to find an element with the text: এই ঘরটি পূরণ করা আবশ্যক` |

The same tests pass on the owner's machine in every run, including the reviews of 1.9e and 1.10a. There they run with `--concurrency=1`.

On CI, `npm test` runs `turbo run test` with Turbo's default concurrency of 10 on a small runner. The jsdom suites then share the CPU with the API suite, which runs a MongoDB replica set. Testing Library's default async timeout is 1 s and Vitest's test timeout is 5 s. The lazy sheets and the user-event typing need more than that under that load.

**Diagnosis: timing under CPU contention, not a product defect.**

## Decisions
1. **CI runs the tests with bounded parallelism and shows every failure.**
   - Change the `Test` step to `npx turbo run test --concurrency=2 --continue`.
   - Keep `TEST_REDIS_URL` as it is.
   - `--continue` lets every package report in one run, so a failure no longer hides the others.
   - Keep the comment style of the workflow file: add a one-line comment saying why.

2. **The jsdom suites tolerate a slow machine.** In `apps/admin`, `apps/platform` and `packages/ui`:
   - Set `testTimeout: 15_000` in `vitest.config.ts`.
   - In `vitest.setup.ts`, add `configure({ asyncUtilTimeout: 5_000 })` from `@testing-library/react`.
   - Add a one-line comment: CI runners are slower than a developer machine, and `findBy*`/`waitFor` must not fail on load alone.
   - Use one named constant per file for each value; no magic numbers.
   - This changes no assertion. A test that is actually broken still fails, only later.

3. **Pin the runner image.** Change `runs-on: ubuntu-latest` to `ubuntu-24.04` in both jobs. The run printed: "The ubuntu-latest label will migrate to Ubuntu 26 beginning October 19, 2026". A pinned image keeps CI reproducible; moving to a new image becomes its own small card.

4. **Nothing else changes.** No test is skipped, no assertion is edited, no retry plugin is added. If a test still fails on CI after decisions 1 and 2, stop and report the failure with its log lines; do not patch around it.
