# Plan: card 3.21 · Organization currency in accounting and bookkeeping

Tier: T2 (money display and approval amounts) · Planned by: Opus 5.5 (lead) · Date: 2026-10-23 · Based on commit: `main b1cf16c`

## Session parts
One part, API only (no screen change), branch `s/3.21-accounting-currency`. Merge check by the lead.

## Goal
Accounting and bookkeeping answer in the organization's currency instead of a hardcoded `"BDT"`. The manual-journal approval amount carries the organization's currency.

Today an organization whose currency is not BDT can never post an approved manual journal: `consume` refuses the token on a currency mismatch (ADR-121).

## Inputs read
- `apps/api/src/modules/commerce/accounting/application/use-cases/`:
  - `get-trial-balance.use-case.ts`: falls back to `"BDT"` when there are no entries.
  - `balance-sheet.use-case.ts`, `profit-and-loss.use-case.ts`, `list-bookkeeping-accounts.use-case.ts`: `currency: "BDT"` on every money field.
  - `post-manual-entry.use-case.ts`: the approval `amount: { amount, currency: "BDT" }`.
- `apps/api/src/modules/commerce/bookkeeping/index.ts`: `BookkeepingTenantDependencies.currencies` already exists, wired in `apps/api/src/routes/bookkeeping-tenant-router.ts`.
- `apps/api/src/modules/commerce/accounting/index.ts`: `AccountingTenantDependencies` has no currency port yet; `routes/accounting-tenant-router.ts` builds it.
- `apps/api/src/modules/core/organization/index.ts`: `buildOrganizationCurrencyReader()`.

## Decisions
1. Each use case listed above gets a **required** port `currency: { read(organizationId: OrganizationId): Promise<CurrencyCode | undefined> }` and the `organizationId` from its caller.
   - Bookkeeping passes its existing `currencies`.
   - Accounting adds `currencies` to `AccountingTenantDependencies`, with the same shape. `routes/accounting-tenant-router.ts` wires `buildOrganizationCurrencyReader()`, the reader bookkeeping already uses.
   - The controllers pass the active organization id the same way the bookkeeping handlers already do for manual entries.
2. An organization without a currency is a data error: throw `AppError({ code: ERROR_CODE.INTERNAL })`. Never fall back to a literal.
3. The trial balance always uses the organization's currency, not the currency of the first entry. Every entry is already in the organization's currency, because ADR-128 validates journals against it.
4. The manual-journal approval amount uses the organization's currency, read in the same request: `amount: { amount, currency }`.
5. No `"BDT"` literal stays in `modules/commerce/accounting` or `modules/commerce/bookkeeping` outside tests.
