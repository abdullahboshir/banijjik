Card D6 · Status: **draft, waiting for owner approval** · Written 2026-10-09 · Based on `s/D2-module-catalog` (`f6770ed`)

## 1. UX principles (in priority order)
1. **One thumb, one hand.** The owner runs the shop from a phone while serving customers. Primary actions sit in the bottom third of a mobile screen.
2. **Instant feel.** Never a blank screen or a full-screen spinner. The shell stays mounted, skeletons appear within 100 ms, and saves are optimistic where safe.
3. **Simple until needed.** No location UI with one location. No module the org doesn't have. No empty menu groups. Advanced options sit behind "More options", not on the first screen.
4. **Bangla-first, plain words.** Short labels from terms ("অর্ডার", "গ্রাহক" / "ছাত্র" per template), no jargon ("SKU" appears only in the advanced section).
5. **One way to do each thing.** The same list, detail, form and filter patterns on every screen (§4). Users learn once.
6. **Safe by default.** Destructive or money actions ask for confirmation with the amount shown. Undo where possible. Read-only and limit states are explained, never silent.

## 3. Navigation model (ADR-056)

**URL:** `/{orgSlug}/{group}/{page}[/{id}]`, with list state in the query (`?location=&status=&q=&page=`). Back, refresh and shared links restore the same view.

**Shell (persistent, server-rendered; never remounts inside an org):**

```
MOBILE (< 768px)                                  DESKTOP (≥ 1024px)
┌────────────────────────────────┐                ┌──────────┬──────────────────────────────────────┐
│ [logo] Org name     🔍  🔔  (●) │ top bar        │ [logo]   │ 🔍 Search (Ctrl+K)        🔔   (●) ▾ │
├────────────────────────────────┤                │ Org name │──────────────────────────────────────│
│                                │                │──────────│ Page header: title · filters · [+ New]│
│          page content          │                │ Home     │                                      │
│                                │                │ Sales  ▸ │            page content              │
│                                │                │ Catalog ▸│                                      │
├────────────────────────────────┤                │ …groups  │                                      │
│ 🏠    📥/🧾    [ + ]   📦   ☰   │ bottom nav     │ (D2 §6)  │                                      │
└────────────────────────────────┘                └──────────┴──────────────────────────────────────┘
```

- **Bottom nav (mobile), 5 fixed slots:**
  1. **Home**
  2. **Work tab**, package-aware: Inbox when `messaging` is effective and has unread conversations; else Orders; Bookings when the template's main kind is SERVICE/RENTAL/EVENT; Enrollments when it is PLAN.
  3. **[+] Quick create** (center): opens a bottom sheet listing create actions of effective modules and permissions, such as "নতুন অর্ডার", "পণ্য যোগ", "বুকিং", "খরচ লিখুন", "গ্রাহক যোগ".
  4. **Catalog** (term label)
  5. **More**: all menu groups from `10 §6`, as a full-screen list
- **Sidebar (desktop):** groups and entries from `/me/config.menu` (resolved config × permission). Empty groups are hidden. Collapsible to icons at 1024–1279 px.
- **Account menu (●):**
  - org switcher (lists the user's orgs; switching = full navigation to the other `/{orgSlug}`, ADR-022)
  - language (বাংলা / English)
  - profile
  - log out
- **Global search** (🔍, Ctrl+K on desktop): offerings, contacts, orders/bookings by number, settings pages. One endpoint per module, results grouped.
- **Location filter:** only inside page filter bars and form fields, and only when the org has ≥ 2 active locations (ADR-004). Never in the top bar.
- **Home is package-aware** (ADR-032): widgets from effective modules (today's sales, unread inbox, today's bookings, low stock, dues). No package names in code.

## 4. Layout patterns (use these, don't invent new ones)

### 4.1 List page
```
MOBILE                                          DESKTOP
┌────────────────────────────────┐              ┌──────────────────────────────────────────────┐
│ অর্ডার                 [ফিল্টার]│ title        │ অর্ডার      [search……] [Status▾][Location▾] [+ নতুন]│
│ (আজ) (অপেক্ষমাণ) (ডেলিভারি)  ›  │ status chips │ ┌──────┬──────────┬────────┬─────────┬─────┐ │
├────────────────────────────────┤              │ │ #    │ গ্রাহক    │ মোট    │ অবস্থা   │ সময় │ │
│ ORD-000045          ৳ 1,250    │ card         │ ├──────┼──────────┼────────┼─────────┼─────┤ │
│ রহিম · 017…          [নিশ্চিত] │              │ │ …    │ …        │ …      │ [badge] │ …   │ │
├────────────────────────────────┤              │ └──────┴──────────┴────────┴─────────┴─────┘ │
│ … infinite scroll …            │              │ pagination · 20 / page                         │
└────────────────────────────────┘              └──────────────────────────────────────────────┘
```
- One `DataList` component: table at ≥ 768 px, cards below. The column list is declared once; the card shows the 3–4 columns marked `primary`.
- Filters: chips for the 3 most-used values. The full filter set is in a bottom sheet (mobile) or inline selects (desktop). All filters live in the URL.
- Paging: infinite scroll on mobile, numbered pages on desktop. Both use the same API pagination (limit ≤ 100). Lists over 100 rendered rows are virtualized.
- Primary create action: `[+]` in the header on desktop. On mobile, the bottom-nav [+] or a floating button on lists that are not in Quick create.
- Bulk actions (desktop only at launch): row checkboxes reveal an action bar.

### 4.2 Detail page
```
┌────────────────────────────────┐
│ ← ORD-000045        [⋯]        │  number + overflow menu (print, cancel, …)
│ রহিম · 01712-345678  [নিশ্চিত]  │  key facts + status badge
│ ৳ 1,250 · বাকি ৳ 250            │  money summary (due in warning color)
├────────────────────────────────┤
│ পণ্য (3)                    ▾  │  sections stacked on mobile,
│ পেমেন্ট                     ▾  │  tabs on desktop
│ ডেলিভারি                     ▾  │
│ ইতিহাস (timeline)           ▾  │  status changes, payments, notes, who and when
├────────────────────────────────┤
│ [ পেমেন্ট নিন ]  [ কুরিয়ারে পাঠান ]│  sticky action bar: max 2 primary actions for the current state
└────────────────────────────────┘
```
- Actions shown come from the request's state machine (D3) × permissions. Disabled actions are hidden, not greyed, except where the reason helps ("Stock কম").

### 4.3 Form
- Single column on mobile, two columns ≥ 1024 px only for short paired fields.
- Sections with headings: core fields first, then custom fields (rendered by `DynamicForm` from definitions, card 2.5), then "More options" collapsed.
- Sticky bottom bar: `[বাতিল] [সংরক্ষণ]`. The keyboard never hides the save button (scroll-into-view).
- Validation inline, on blur and on submit, with the same Zod schema as the API. Server errors map by `messageKey` to the field.
- Unsaved-changes guard on back/navigation.
- Inputs: `MoneyInput` (shows ৳, stores minor units), `QuantityInput` (unit precision, weight entry for KG), `PhoneInput` (accepts `01XXXXXXXXX`, stores E.164), `DateInput` (calendar sheet on mobile), `ImagePicker` (camera first on mobile).

### 4.4 Wizard
For onboarding, channel connect and courier setup: a stepper with one decision per step, progress dots, "Skip for now" where safe. Progress is saved server-side, so leaving and returning resumes.

## 5. States & feedback (ADR-059)

| State | Pattern |
|---|---|
| Loading | Skeleton of the target layout within 100 ms. **No full-screen spinners.** Buttons show an inline spinner during submit. |
| Empty | Illustration-free empty state: one sentence + one primary action ("এখনো কোনো পণ্য নেই · [পণ্য যোগ করুন]"). |
| Error (request) | Inline message near the cause + toast for background failures. Text from `messageKey`; a "Retry" button where idempotent. |
| Permission denied | Page: "এই পাতা দেখার অনুমতি নেই" + who to ask (owner name). |
| Module disabled / limit reached | Upgrade card: what is locked, which package or add-on unlocks it, CTA for the owner only. Others see "মালিকের সাথে কথা বলুন". |
| Read-only (ADR-053) | Persistent top banner + write buttons hidden; billing link for the owner. |
| Offline | Top banner "ইন্টারনেট নেই". Reads from cache. Writes are disabled except POS (offline queue, card 3.9 decides scope). |
| Success | Toast for background saves. Inline confirmation for big actions (order confirmed → receipt/next action). |
| Undo | Archive and status changes that are reversible show "Undo" in the toast for 5 s. |

Optimistic updates only for low-risk actions (status chips, notes, toggles). **Never** for payments, stock changes or confirmations that create money/stock effects. Those wait for the server.

### 6.2 Add offering (cards 3.2, 5.10, 5.11)
Entry from Quick create → "পণ্য যোগ" offers three paths:
```
┌────────────────────────────────┐
│ কীভাবে যোগ করবেন?               │
│ [📷 নিজে লিখুন]                 │ → Quick add
│ [f Facebook পোস্ট থেকে]         │ → only when `social` is effective
│ [📄 একসাথে অনেকগুলো (Excel/ছবি)]│ → bulk import (card 5.11)
└────────────────────────────────┘
```
- **Quick add:** photo (camera opens first), name, price, stock (PRODUCT) / duration (SERVICE) / period (PLAN), category (remembers the last one). `[সংরক্ষণ]` + `[আরেকটা যোগ করুন]`. Target: under 30 s per item. "More options" holds variants, SKU/barcode, custom fields, per-location price.
- **From Facebook:** grid of recent Page posts with an "already imported" badge. Tap → extracted draft (name, price, images) for review → save as ACTIVE or keep DRAFT. Auto-drafts from new posts appear as a "অনুমোদনের অপেক্ষায় (n)" chip on the catalog list.
- **Bulk:** download template · upload file or photo · review table (fix/skip/approve all). Nothing is saved without review (ADR-026).

### 6.3 Order list + detail (card 3.5)
- List per §4.1. Default chips: আজ · অপেক্ষমাণ · ডেলিভারিতে · বাকি আছে. The card shows number, contact, total, status badge, source icon (POS / web / chat).
- Detail per §4.2. Actions by state (D3): confirm, take payment, send to courier, assign rider, cancel, return. "Send to courier" opens a pre-filled sheet (address check, COD amount) and confirms in one tap.

## 7. Localization & formatting (ADR-055)
- **Default locale `bn`**, switch to `en` per user (`User.preferredLocale`), org default `Organization.defaultLocale`. All text from i18n keys + terms. No literals (`05`).
- **Digits:** Latin by default in both locales. Org setting `organization.digitScript = LATIN | BENGALI` switches display only. Stored and API values are always Latin numbers.
- **Money:** `৳ 1,250` (symbol + thin space). Minor units formatted by currency precision (`৳ 1,250.50` only when non-zero paisa). Grouping setting `organization.numberGrouping = WESTERN | SOUTH_ASIAN` (default WESTERN: 1,234,567; SOUTH_ASIAN: 12,34,567).
- **Dates:** `9 অক্টোবর 2026` (bn) / `9 Oct 2026` (en). Relative times for < 7 days ("২ মিনিট আগে" uses the digit setting). Time is 12-hour with a localized period. Timezone = location → org (`09 §4.3`).
- **Phone display:** `01712-345678`. Input accepts `01…`, `+8801…`, spaces and dashes.
- **Text length:** UI must tolerate +30% length (Bangla vs English). Never truncate primary labels or actions. Truncate secondary text with ellipsis + full text on long-press/hover.
- **Fonts:** Bangla **Noto Sans Bengali**, Latin **Inter**. Both self-hosted, subset, `font-display: swap`. Bangla body line-height 1.6 (taller glyphs with conjuncts).

## 8. Design tokens (ADR-057, ADR-058)
Tokens live in `packages/ui/tokens` as TypeScript, compiled to CSS variables. Components use **semantic** tokens only, never raw palette values. Storefront themes reuse the same semantic names with tenant values (ADR-029).

|---|---|---|
| `color.brand.primary` | `#0F766E` (teal 700, **placeholder**, ADR-057) | primary buttons, active nav, links |
| `color.brand.primaryHover` | `#115E59` | |
| `color.brand.onPrimary` | `#FFFFFF` | text on primary |
| `color.bg.app` | `#F8FAFC` | app background |
| `color.bg.surface` | `#FFFFFF` | cards, sheets |
| `color.bg.subtle` | `#F1F5F9` | table header, chips |
| `color.border.default` | `#E2E8F0` | |
| `color.text.primary` | `#0F172A` | |
| `color.text.secondary` | `#475569` | |
| `color.text.muted` | `#94A3B8` | placeholders only (not body text) |
| `color.status.success` | `#15803D` | paid, delivered, completed |

- Changing the brand color = edit 3 tokens (`primary`, `primaryHover`, `onPrimary`), then rerun the contrast test.

### 8.2 Status → color mapping (single source)
`packages/ui` exports `statusTone(requestType, status)` → `success | warning | danger | info | neutral`. All badges use it. The mapping table is filled from D3's state machines.

### 8.3 Typography
| Token | Size / line-height | Use |
|---|---|---|
| `font.display` | 24 / 32 (mobile) · 30 / 38 (desktop) | page titles |
| `font.title` | 18 / 28 | section headings, card titles |
| `font.body` | 16 / 26 (Bangla 1.6) | default text, inputs (16 px avoids iOS zoom) |

### 8.4 Space, shape, motion, layout
- Spacing scale (4 px base): `space.1`=4, `2`=8, `3`=12, `4`=16, `5`=20, `6`=24, `8`=32, `10`=40, `12`=48. Mobile page padding 16, desktop 24.
- Radius: `radius.sm` 6 (inputs, badges), `radius.md` 10 (cards, buttons), `radius.lg` 16 (sheets, dialogs), `radius.full`.
- Elevation: `shadow.sm` (cards), `shadow.md` (dropdowns), `shadow.lg` (sheets/dialogs). Flat by default; borders before shadows.
- Motion: 150 ms (hover/press), 200 ms (sheets, dialogs), ease-out. `prefers-reduced-motion` disables non-essential motion.
- Breakpoints: `sm` 640, `md` 768 (table ↔ cards), `lg` 1024 (sidebar appears), `xl` 1280.
- Touch targets ≥ 44 × 44 px (POS ≥ 56). Icon set: **lucide** only.
- Z-index scale: `base` 0, `sticky` 10, `nav` 20, `dropdown` 30, `sheet` 40, `dialog` 50, `toast` 60.

## 10. Accessibility
- WCAG 2.1 AA: contrast (§8.1), visible focus ring (`color.brand.primary`, 2 px), labels on every input, `aria-live` for toasts and async results.
- Desktop: everything works by keyboard. Sheets and dialogs trap focus and close on Esc.
- Text can scale to 200% without loss of function. Layouts use rem.
- Icons that act as buttons have bn/en accessible names.

## 11. Performance UX budget (ADR-020 applied to UI)
| Item | Budget |
|---|---|
| Shell first render (SSR) | LCP < 2.5 s on 4G mid-range phone |
| In-app navigation | content or skeleton < 100 ms, data < 300 ms (p75) |
| Interaction (INP) | < 200 ms |
| Initial JS per route | ≤ 170 KB gzip; heavy widgets (calendar, editor, charts) lazy-loaded |
| Fonts | ≤ 2 families, subset, ≤ 120 KB total |
| Images | CDN-resized WebP, `loading="lazy"` below the fold, fixed aspect ratios (no layout shift) |
| Lists | virtualize > 100 rendered rows |

- Prefetch the next likely route on hover/touch-start. Keep TanStack Query cache warm between pages.
- PWA (admin): installable, app-shell cached, offline banner. Background sync only for the POS offline queue (card 3.9).

## 12. Platform panel (ADR-060)
Desktop-first: dense tables, multi-column forms, side-by-side compare (package/template editors). It is still responsive down to 1024 px, and read-only views work on a phone for emergencies (tenant lookup, suspend). Same tokens and components. Its own brand accent may differ (`color.brand.primary` overridden per app) so operators always know which app they are in.

## 13. What implement sessions must do
1. Use only `packages/ui` components and semantic tokens. No hex values, no px font sizes, no one-off layout in pages.
2. Build every screen mobile-first, then check desktop. Each UI PR includes screenshots at 375 px and 1280 px (bn locale).
3. Use list/detail/form/wizard patterns from §4 and states from §5. A new pattern needs a change to this doc first.
4. All text from i18n keys + terms. Test with Bangla strings longer than the English ones.
5. Money, quantity, date and phone only through the display/input components (§9).
